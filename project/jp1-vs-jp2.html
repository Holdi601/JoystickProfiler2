From JoyPro 1 to JoyPro 2

Show:

JoyPro 1 (2021 to 2023) was a DCS tool: it made relations between the inputs of different aircraft and bound them to the same place on the stick. JoyPro 2 keeps exactly that idea and the same relation / bind / modifier model (a JoyPro 1 profile opens in JoyPro 2), and rebuilds everything around it: a new interface, an engine that also runs on its own, dozens of games, tests for every feature, and a lot of safety.

For beginners

#What is better for you

  • Many games, one profile. JoyPro 1 was for DCS. JoyPro 2 imports and exports 37 game titles: DCS, IL-2 (Great Battles, Korea, 1946, Cliffs of Dover), Star Citizen, MSFS 2020 and 2024, X-Plane 11 and 12, Falcon BMS, War Thunder, Elite Dangerous, X4, Arma, and more. One relation holds the same function in all of them.
  • Start from what you have. Import reads your existing binds from each game; the first-start setup finds your games by itself.
  • Nothing can break for good. Every export backs up the game files first, and Undo last export puts them back byte for byte. Every change in JoyPro is saved automatically and can be undone, even after a restart (profile history).
  • It tells you what would go wrong. The Check explains problems in game words and fixes them with one click.
  • It sets itself up. Set it all up for me puts the important functions on your stick, throttle and pedals. You look at the list and press Use these buttons and Write to my game.
  • Less clicking. Suggestions, Auto Group, Auto Assign, the setup wizard and a JoyPro assistant build relations and binds for you; a learned "your style" follows how you did it before.
  • It notices changes. When you rebind something inside a game, JoyPro asks after the game closes whether to take it into your profile.
  • Your language. The interface speaks 39 languages.
  • More than binds. Device pictures and cheat sheets, a HUD and stream overlay, force feedback from telemetry, a virtual joystick for games that read only one device, a pretend controller (virtual Xbox pad) for games that only know an Xbox controller, a cockpit database, statistics of what you fly.
  • Help on every button. F1 explains any button, tours point at the real buttons, and Easy words keeps it short.
  • No extra runtimes to hunt. The release is one zip with everything inside; no SlimDX, no C++ runtimes.

Technical internals

#Architecture and quality

  • Split into engine and GUI. JoyPro 1 was one WPF application with the logic in the window code. JoyPro 2 has an engine (engine.exe, .NET Framework 4.8, plain C#) that holds all profile, import/export and database logic as 458 commands, and an Avalonia GUI (.NET 9) that runs the engine for every action. Quick interactive commands go to one long-running engine serve, so the GUI stays fast without giving up the separation. Everything the GUI does can be scripted (see the engine command line).
  • Separate processes for permanent jobs: JoyPro.Ffb.exe (telemetry force feedback), JoyPro.VJoy.exe (the virtual joystick forwarder), JoyPro.Tray.exe (the watcher while the GUI is closed), each with resource budgets and soak tests so they stay unnoticeable in the background.
  • Tests: 1,537 automated tests (xUnit: engine logic, view models, offscreen renders of pages in light and dark), 89 engine smoke test parts that run the real engine against fixture folders, an opt-in quality gate with invariant checks on real data, and in-game end-to-end runs for the games that support them. Tests run in a write sandbox with a real-folder fingerprint check, so no test can touch real game folders.
  • Data: game command lists are built on the user's PC from the installed game into %LOCALAPPDATA%\JoyPro2\GameData; JoyPro ships only its own data (function catalog, device catalog, conversion tables, cockpit database).
  • Docs generated from the source: the game support matrix comes from the code (engine games support), the CLI reference from engine --help, and this site from the AXAML, the view models and the docs.
