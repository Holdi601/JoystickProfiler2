# JoyPro 2.4.1

## Fixed
- DCS import with **Include defaults** gave thousands of relations and errors (keyboard defaults lost their Ctrl, Shift
  and Alt, so many keys looked the same). It now adds the binds DCS gives by default only to actions you have not bound
  yourself: the keyboard keys and the binds DCS has for your exact device model, for the aircraft and devices you have
  binds for. Your own binds always win, defaults you removed in DCS stay removed, and the same default of several
  aircraft is one relation. DCS's general joystick defaults, which DCS puts on every device, are left out. The option
  explains this when you point at it.
- The check on the Export page froze JoyPro when it found thousands of problems. It now opens at once, shows the
  problems a page at a time with "Show more" and says where most of them are (for example the keyboard).
- The import and the check counted actions on in several relations differently (for example 206 after the import and
  103 in the check). Both now count the same: each action of an aircraft once. The check also says on how many cards
  they are.
- The import options are remembered: "Add to my profile", the keyboard box of each game, include defaults, the axis
  value boxes, *_easy aircraft, the aircraft and device lists and the ignored devices come back as you left them.
  Include defaults stays off until you tick it.
- DCS: exporting with "keep keyboard defaults" switched off no longer removes all of DCS's own keyboard keys from the
  aircraft. Your keyboard binds are written, and only a DCS key you use for something else loses its old job; every
  other default key stays. Keyboard files an older JoyPro wrote that way get their default keys back at the next DCS
  export.
- DCS: the options that switch off default binds in the DCS installation never touch the keyboard's files.
- The old data folder `%LOCALAPPDATA%\JoyPro` no longer stays behind as a link next to `JoyPro2`: JoyPro removes it
  (only the link; your data stays in `JoyPro2`). The check for it no longer writes a line into the log at every start.
