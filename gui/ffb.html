Force Feedback

Show:

JoyPro reads live telemetry from the game you fly (airspeed, angle of attack, G, gear, guns, hits ...) and turns it into forces on a force feedback stick such as the VPforce Rhino: stall buffet, stick weight under G, gear and flap rumble, gun bursts, runway rumble, and a centring spring that stiffens with airspeed and follows the trim. What the stick does is a graph of nodes that you can change. It works with DCS World, IL-2 Great Battles, IL-2 Korea and War Thunder.

For beginners

#Get forces in four steps

  1. Switch the page's toggle to On. JoyPro now looks every 5 seconds for a supported game; nothing runs before.
  2. Under Device and forces press Refresh and pick your force feedback stick. Leave Strength and Max force as they are for a start (the max force caps every effect, 60 % by default).
  3. Press ↔ Direction test. JoyPro gently pushes the stick and asks which way it went: answer with the buttons. It sets Invert X / Y for you and checks the centring spring and the trim.
  4. Under Game, pick your game and press Install under Telemetry export (close the game first). This makes DCS or IL-2 send its telemetry to JoyPro (War Thunder sends it by itself). Then fly.
Switch the game's own force feedback off

JoyPro drives the stick itself. Switch off the game's force feedback for that stick (DCS: the aircraft's FFB option; IL-2: Settings > Input devices; War Thunder: force feedback off), otherwise the game holds the device and JoyPro cannot send forces.

In the game: What you feel

Near the stall the stick shakes; under G it gets heavy; gear and flaps rumble while they move; on the runway it rumbles with speed; guns kick in bursts; hits (IL-2) jolt sideways. The centring spring gets stiffer the faster you fly, and trim (the game's, or JoyPro's own trim buttons) moves its centre. In menus or when the game pauses, JoyPro stops every effect and lets go of the stick (only the centring spring stays when JoyPro provides it).

Advanced

#The Settings tab

Device and forces: device, Strength (all effects), Max force (hard cap per axis: no effect and no sum of effects goes above it), Direction (Invert X / Invert Y, saved per device), ↔ Direction test, Centring ("JoyPro provides the centring spring", needed for trim) and Spring stiffness (the plain spring on axes the graph has no spring for).

Direction test, step by step (each step waits for ▶ Ready; ■ Cancel stops every force at any time):

  A["▶ Start"] --> B["Push RIGHT 2 s (20 %)<br/>Which way did it move?"]
  B --> C["Push FORWARD 2 s<br/>Which way did it move?"]
  C --> D["Centring spring<br/>Does it spring back?"]
  D --> E["Trim: centre 35 % forward<br/>Did it move and stay?"]
  E --> F["Invert X / Y saved<br/>for this device"]

"It did not move" keeps that axis's setting and says what to check (on a VPforce stick: the Configurator's own spring must be off for trim). ⏮ Start over begins again. The test needs the stick to itself: it refuses while JoyPro's force feedback runs for a game.

Game: pick a game, Force feedback for this game, its Strength, its Graph (built-in or one of your graph files; Open in editor), the switches of the built-in graph's effects (buffet, gforce, gear, flaps, speedbrake, runway, shake, guns, hits, spring), Aircraft with their own graph or strength (Add aircraft, Remove) and Telemetry export (Install, Remove, Dry run). Strength multiplies: global x game x aircraft, then the max force cap.

#The graph editor

The graph is how telemetry becomes force. Values flow left to right through wires, normalised to 0..1 (-1..1 where a direction matters):

  • Telemetry nodes read one key of the game (ac.ias, ac.aoa, ac.g ...) with min/max normalisation.
  • Group, Curve (a Bezier curve you drag), maths and stateful nodes (low pass, slew limit, threshold) shape them.
  • Outputs are the effects: constant force, periodic (sine, square, triangle, saw; strength and frequency mapped from the input), spring (stiffness, centre = trim), damper, friction. Outputs of one type on the same axis and slot compete (the strongest wins); different slots add up.
  • Inputs from your devices: Device button / hat (any device; ⏺ Press the button now... captures it), Stick position, Trim (⇕ Assign trim buttons asks for six buttons: trim to stick position, nose down, nose up, left, right, reset).

Pick a node type and Add to the graph, drag from a port to another to wire them, select and Delete selected. New from built-in starts from a copy of JoyPro's flight graph; Save / Save as write a graph file, Load / Rescan read them. Then pick that graph for a game or aircraft on the Settings tab.

#The telemetry inspector

Every telemetry key of the running game with its value, title and unit, live. Filter by key or title. Use it to see which key to put into a Telemetry node and what range it has.

Technical internals

#Behind the page

View model: MainWindowViewModel.FfbTelemetry.cs (settings, games, aircraft, setup, the process), MainWindowViewModel.FfbDirectionTest.cs (the test wizard), FfbGraphEditorViewModel.cs (the editor); Views/Controls/FfbGraphCanvas.cs, FfbCurveEditor.cs. The force feedback runs in its own process, JoyPro.Ffb.exe (gui/JoyPro.Ffb, graph engine in gui/JoyPro.Ffb.Core).

sequenceDiagram
  participant GUI as JoyPro
  participant P as JoyPro.Ffb
  participant Game
  participant Stick
  loop every 5 s while On
    GUI->>GUI: supported game process running?
  end
  GUI->>P: run --game DCS --game-pid N --parent-pid M --protocol
  Game-->>P: telemetry (UDP 41992 for DCS)
  P->>Stick: acquire (exclusive) on the first forces
  loop 50 Hz while telemetry arrives
    P->>Stick: changed effect parameters only
  end
  Game--xP: telemetry stops (menu, pause)
  P->>Stick: STOP ALL, release (springs kept with "centring spring")
  • Lifecycle: the process follows the game through its process handle and ends with the game or JoyPro. Every constant and periodic force has a duration of 0.3 s and is restarted, so a hung or killed process cannot leave a force on the stick. STOP ALL on telemetry timeout (0.5 s), game exit, JoyPro exit and any error.
  • Settings: <data>\Ffb\Telemetry\telemetry-ffb.json (<data> = %LOCALAPPDATA%\JoyPro2); graphs in <data>\Ffb\Telemetry\Graphs\*.jpffb.json (format joypro-ffb-graph); last status in status.json.
  • Engine: engine ffb telemetry status (the page's state), engine ffb telemetry config set / engine ffb telemetry config clear (--game, --plane: per game and aircraft), engine ffb telemetry effects, engine ffb telemetry setup dcs and the other games' setup (install, remove, --dry-run; the game file is backed up first).
  • Games: DCS (an Export.lua line, UDP), IL-2 Great Battles and Korea (the game's telemetry device output, UDP), War Thunder (the game's local web server on port 8111, no setup needed). Games hidden in Settings > Games are not shown and not looked for.
  • Direction: positive force pushes right on X and towards the pilot on Y; invert X / Y per device (by instance GUID) flips forces and the spring centre.
