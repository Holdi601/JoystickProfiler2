GUI pages

Dialogs and notices

Show:

Some windows and panels show over whatever page is open: a question before JoyPro changes game files or the profile, the changes a game made to its controls (the game watcher), Move to another button for a single action, and the update prompt. This page describes each of them and every button in them.

For beginners

#Confirmation windows

Before JoyPro does something that removes binds, overwrites files or replaces a lot of your profile, it asks. The window names what happens ("Export to DCS with Replace? Binds of your devices that are not in your profile are removed.") and offers:

  • the main answer (for example Export, Delete, Merge),
  • sometimes a second way (for example Export first),
  • Cancel: nothing happens.

Some questions have Do not ask again. Settings > Confirmations lists them and switches them back on.

#The game watcher: "DCS changed its controls"

When you change binds inside a game and close it, JoyPro notices (if the game watcher is on, Start page). A panel lists every change ("Landing Gear Up/Down: now on Throttle BTN 22") with a tick and the relation it belongs to:

  • Take over: the ticked changes go into your profile.
  • Not now: JoyPro keeps them and asks again later.
  • Ignore these: your profile stays as it is; the next export writes your profile over the game's changes.

#Move to another button

A relation is one button with all its actions. To move only one of them (one game's action) to another button, right-click the action (Relations page) or a bind row (Binds page) and choose Move to another button.... Press the new button (or pick device and input), then Move.

#Updates

At start (and with More > Check for updates) JoyPro asks GitHub for a newer version. The prompt shows what is new with Update now, Later, Skip this version and Release page.

Advanced

#Move to another button in detail

  • The action joins the relation that already uses the new button; if none does, it gets a relation of its own named after it.
  • Keep the modifiers (Shift): the action keeps the shift buttons of its old bind (shown only when it had some).
  • When the new button already has an action of the same aircraft, one aircraft cannot have two actions in one relation; you choose:
    • Swap: the other action goes to the old button.
    • Replace: the other action leaves that button and is unbound.
    • Keep both: the moved action gets its own relation on the same button; both fire when you press it.
  • A preview line says what will happen; Move is one undo step (Ctrl+Z).
flowchart TD
  A["Move to another button...<br/>(action or bind row)"] --> R["Record: press the new button<br/>or type device + input"]
  R --> T{"Is the button taken<br/>for these aircraft?"}
  T -->|no| J["Join the relation on that button<br/>or a new relation"]
  T -->|yes| C{"Swap / Replace / Keep both"}
  C --> J
  J --> E["engine relations item move-to-input<br/>(one undo step)"]
  E --> X["Next export: the action is<br/>on the new button in the game"]

#The game watcher in detail

sequenceDiagram
  participant G as Game
  participant W as JoyPro watcher
  participant E as engine
  participant U as You
  G->>G: you change binds, close the game
  W->>E: sync status / sync diff
  E-->>W: changes against the last export or import
  W->>U: panel "DCS changed its controls"
  U->>W: Take over (ticked changes, chosen relations)
  W->>E: sync apply
  E-->>W: profile updated (one undo step)

Where several relations use the changed button, each row has a box to pick the relation, or New relation with a name. Unticked rows count as ignored.

#Updates in detail

  • Update now downloads the installer, checks it and starts it; JoyPro closes and starts again. Profiles and settings stay.
  • Later asks again at the next start; Skip this version stops the question at start for this version (the manual check still shows it).
  • After a manual check without news, the prompt says so and has OK.
