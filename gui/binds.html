Binds

Show:

The Binds page puts each relation on a physical input: a button, a hat direction or an axis of one of your devices. A relation says what happens ("Gear Up/Down" in every game and aircraft); its bind says where you press it ("Throttle - HOTAS Warthog, button 22"). Relations are made on the Relations page; the binds reach the games when you export (Export to your games).

For beginners

#What you do here

  1. Pick a relation on the left. Each card shows the relation's name, its button ("Throttle - HOTAS Warthog · BTN 22") and a not bound chip when it has none yet.
  2. Press Record input on the right, then press the button (or move the axis) on your stick. JoyPro waits up to 6 seconds, takes the first input that changes and binds it at once. The card on the left now shows the new input.
  3. Optional: a modifier (a shift button held at the same time, so one button does two jobs) and, for an axis, its curve (dead zone, how soft or sharp the stick feels).
  4. When everything is bound, go to Export and write it into your games.

The page knows whether a relation is an axis or a button: an axis relation only takes an axis you move a long way, a button relation only a button, hat or switch. The line under the title says what it is waiting for ("Looking for: axis").

Follow input

Follow input (on by default) does the opposite: press any button on your devices and the list jumps to the relation bound to it. Press the same button again for the next relation on it. Handy to answer "what is this button doing?". It pauses while Record runs, while you type and while the device picture is open.

#Three ways to bind

Way When
Record input the usual way: press the real button
Bind on the picture (Visual assign) you see your device drawn with a marker on every button; click a marker, pick the relation, Bind here
Pick the input by hand the device is not connected, or you want to type the input (JOY_BTN22, JOY_X)

#Nothing to bind yet?

With no relations the page says Nothing to bind yet with Go to relations. Import a game on the Start page or make relations first.

In the game: What a bind means in the game

After the export, the game's own controls menu shows the bound button on that action, in every aircraft the relation covers. With a modifier, DCS shows it as a modifier combination (for example "JOY_BTN5 + JOY_BTN22"), IL-2 and Star Citizen as their own modifier form. The axis curve becomes the game's own axis settings (DCS: Axis Tune; IL-2: the response curve; Star Citizen: the axis's options), so you see the same curve in the game.

  • Set up my devices automatically...: the Setup wizard.

The selected bind (right side): the device picture (small), relation, device, input, axis or button, the modifiers. What it does lists the relation's actions per game (read-only; Open in Relations changes them, Move... sends one action to another button and leaves the rest here).

Bind with your device: Record input, Cancel Record, Clear Input (the relation keeps its modifiers and curve, only the input goes), Clear Modifiers. Pick the input by hand: device and input lists, Set Bind, Refresh Options, Clear Bind. Recording settings: timeout (ms), warm-up (ms), axis threshold (% of travel) and "Also take a button that rests pressed when it is released" (for the middle position of a 3-way switch).

Detent mode (throttles with an afterburner detent), see below. Bind behavior (advanced): inverted, slider, double tap. Unbind an input everywhere (advanced): free one physical input in the whole profile.

#Axis curves per game and aircraft

An axis relation has one base curve that every game gets. On top of it you can give a scope its own curve:

Scope Example Used for
Aircraft DCS · F-16C one aircraft of one game
Game IL-2 Korea every aircraft of a game
Game family IL-2 family (Great Battles + Korea) games that store curves the same way
All games (base) every game without its own curve

A game uses the most specific one: aircraft, then game, then family, then the base. The panel shows the scope's curve in blue and the base as a dashed orange line while the scope inherits. Each game has its own kind of curve (DCS: dead zone, saturation X/Y, curvature or an 11-point user curve; IL-2: its own sensitivity and dead zones; X-Plane: free curve points), so the sliders on the right change with the scope. When a game falls back to the base, JoyPro fits that game's parameters to the base curve as closely as the game can express it.

Drag the white points to shape the curve, or use the sliders. Every setting also has a number box with its range next to it: type the exact value, or press Up / Down (Shift: ten steps) or turn the mouse wheel over the box you are in. A number outside the range goes back to its nearest end when you press Enter or leave the box, and the line under the box says so. The user curve has 11 number boxes, one per 10 % of stick travel (0 % ... 100 %), in step with the white points on the curve.

The numbers are in each game's own units; the line above the boxes says which. For DCS (and the base) they are the ones of DCS's own axis tune dialog: dead zone, saturation X/Y and the user curve points 0 .. 100, curvature -100 .. 100, so you type 8 for a dead zone of 8. Your profile and the export keep what DCS's files keep (0.08), and a value with more decimals stays exact until you change it. Falcon BMS has the launcher's steps 0 .. 3, FSX 0 .. 127, and so on.

Edits preview at once (also with the live position of your stick as a dot); Save for this scope stores them. Inherit (clear) removes the scope's own settings. Reload reads them again.

Copy to another axis... puts the same settings on another bound axis in one step, e.g. Thrust Left to Thrust Right: pick the axis, tick Copy invert too only if both should invert alike, then Copy. It goes to the same scope of the other axis; one Ctrl+Z takes it back.

#Detent mode: one throttle for all aircraft

A throttle with an afterburner detent used to need one throttle relation per afterburner position. In detent mode one throttle relation serves every aircraft: JoyPro bends the curve per aircraft so your throttle's detent is exactly where that aircraft's afterburner starts (F-16C at 77 %, F-14 at 70 %, ...). Resting in the detent stays just below the afterburner; pushing over it lights it.

  • The calibration belongs to the device axis. Every throttle relation on that axis shares it; a left and a right lever are separate axes, each with its own. The line under the buttons says whether this axis is calibrated, and its values.
  • Without a calibration detent mode changes nothing on that axis: every aircraft keeps the relation's curve. The calibration is part of the profile, so Undo or a restored version can bring back the state before you made it.
  • Why "full power at the detent" is on by default: an aircraft without afterburner has nothing behind the detent, so it reaches full power there; otherwise you would have to push through the detent for the last part. Untick it and its curve runs over the whole travel.
  1. Calibrate detent...: move the throttle to idle, then to the detent, then fully forward, then (optional) behind the idle detent (cut-off). Confirm each position; JoyPro reads the axis live. Save calibration.
  2. Tick Detent mode on.
  3. Already have one throttle relation per aircraft? Merge my throttle relations... shows a plan per device axis; Merge joins them into one relation in detent mode; Undo merge takes it back.

The aircraft groups below show where each group's afterburner starts and where that number comes from; type your own value and Set, or Game data to go back.

In the game: Detent mode in the game

In every exported aircraft the throttle reaches the afterburner exactly at your device's detent. DCS gets a per aircraft curve (dead zone and saturation, or the user curve), X-Plane curve points; games with one curve for every aircraft get what most of the relation's aircraft need, and the export lists the rest.

#Tips

  • Ctrl+Z undoes every bind change, also after a restart (History).
  • A bind on a device that is not connected stays; the card shows it greyed and the export still writes it.
  • Replace the selected bind's device... (More) moves every bind of that device to another one, input by input, with a preview: for a new stick of the same kind or one that got a new id.
  • The same button on two relations is allowed; the Check tells you where that means two jobs in one aircraft.
