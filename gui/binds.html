GUI pages

Binds

Show:

The Binds page puts each relation on a physical input: a button, a hat direction or an axis of one of your devices. A relation says what happens ("Gear Up/Down" in every game and aircraft); its bind says where you press it ("Throttle - HOTAS Warthog, button 22"). Relations are made on the Relations page; the binds reach the games when you export (Export to your games).

For beginners

#What you do here

  1. Pick a relation on the left. Each card shows the relation's name, its button ("Throttle - HOTAS Warthog · BTN 22") and a not bound chip when it has none yet.
  2. Press Record input on the right, then press the button (or move the axis) on your stick. JoyPro waits up to 6 seconds, takes the first input that changes and binds it at once. The card on the left now shows the new input, and the line under the buttons names the device as the list does (your name for it, if you gave it one).
  3. Optional: a modifier (a shift button held at the same time, so one button does two jobs) and, for an axis, its curve (dead zone, how soft or sharp the stick feels).
  4. When everything is bound, go to Export and write it into your games.

The page knows whether a relation is an axis or a button: an axis relation only takes an axis you move a long way, a button relation only a button, hat or switch. The line under the title says what it is waiting for ("Looking for: axis").

Follow input

Follow input (on by default) does the opposite: press any button on your devices and the list jumps to the relation bound to it. Press the same button again for the next relation on it. Handy to answer "what is this button doing?". It pauses while Record runs, while you type and while the device picture is open.

#Three ways to bind

Way When
Record input the usual way: press the real button
Bind on the picture (Visual assign) you see your device drawn with a marker on every button; click a marker, pick the relation, Bind here
Pick the input by hand the device is not connected, or you want to type the input (JOY_BTN22, JOY_X)

#Nothing to bind yet?

With no relations the page says Nothing to bind yet with Go to relations. Import a game on the Start page or make relations first.

In the game: What a bind means in the game

After the export, the game's own controls menu shows the bound button on that action, in every aircraft the relation covers. With a modifier, DCS shows it as a modifier combination (for example "JOY_BTN5 + JOY_BTN22"), IL-2 and Star Citizen as their own modifier form. The axis curve becomes the game's own axis settings (DCS: Axis Tune; IL-2: the response curve; Star Citizen: the axis's options), so you see the same curve in the game.

Advanced

#Every part of the page

Header tools

  • Visual assign: opens the device picture in place of the editor (see below).
  • Unbind selected input: takes the selected bind's input off every relation that uses it.
  • Modifiers: the modifier library (Modifiers page): rename, delete, see where they are used.
  • Put relations on my buttons automatically... (Auto Assign): JoyPro places your relations on fitting controls (TMS on the TMS hat, gear on the gear lever, trim on the trim hat). Preview first, Apply changes, Ctrl+Z undoes it. Options: Keep my layout, Re-assign bound relations, Only the selected relations, how many modifiers at most, a mode switch for combat phases, devices that are not connected (Search Catalog, Add). Reference: auto-assign.
  • Lay out with AI...: say in words how you like your controls ("throttle and left-hand stick, trim on the hat, curves softer for helis"); JoyPro shows every change it would make, ticked, before Apply. Works without the optional AI model for English phrases like the examples. Reference: layout-with-ai.
  • Set up my devices automatically...: the Setup wizard.
  • More: refresh, show the selected bind in the Output panel, replace a device, import and export binds as JSON, save, merge another profile.

The selected bind (right side): the device picture (small), relation, device, input, axis or button, the modifiers. What it does lists the relation's actions per game (read-only; Open in Relations changes them, Move... sends one action to another button and leaves the rest here).

Bind with your device: Record input, Cancel Record, Clear Input (the relation keeps its modifiers and curve, only the input goes), Clear Modifiers. Pick the input by hand: device and input lists, Set Bind, Refresh Options, Clear Bind. Recording settings: timeout (ms), warm-up (ms), axis threshold (% of travel) and "Also take a button that rests pressed when it is released" (for the middle position of a 3-way switch).

Modifiers on this bind: tick modifiers and Attach Selected To Bind / Detach Selected From Bind, or create one (Create a modifier: name, device and input or Record Modifier Input, Invert for a switch that is "on" when released). Its x closes it down to the title line (remembered); Show opens it again.

Axis response: curve, dead zone, saturation (axis relations only; it opens by itself when you pick an axis, and stays closed for the next axis once you close it), see below. Detent mode (throttles with an afterburner detent), see below. Bind behavior (advanced): inverted, slider, double tap. Unbind an input everywhere (advanced): free one physical input in the whole profile.

#Axis curves per game and aircraft

One default curve, one per game, or one for the aircraft you tick. An aircraft uses its own curve, else its game's curve, else the default curve. Applies to lists them with checkboxes:

Row Example Used for
Default curve every game and aircraft without its own curve (up to 2.6.5 this row was called "All games")
A game DCS, IL-2 Korea every aircraft of that game in this relation without its own curve
An aircraft (DCS) AH-64D BLK.II CPG that aircraft only
A game family MSFS family (MSFS 2024, MSFS 2020) both games together; shown only when the relation has two of them (or a curve for the family is stored)

Next to each row stands what it uses today: own curve, same as ... (aircraft whose own curves are identical), uses DCS / uses the default curve (no curve of its own; a change there changes it too). Its tooltip says the same in a sentence. Only DCS has a row per aircraft: it is the only game whose curves are written per aircraft. The DCS row means this relation's DCS aircraft listed under it, not all of DCS; with a curve of its own it says own curve, for the aircraft below without one.

Games on the virtual Xbox pad (ACE COMBAT 8, Hell Let Loose: Vietnam, any game set to Xbox pad on the Virtual Joystick page) get no export, so JoyPro applies their curve itself on the pad; the panel says so in bold. Their invert never comes from DCS: it is the game's own (tick only that game and save), else the game's pad convention (ACE COMBAT 8's pitch is reversed by default).

What is ticked when you open a relation: the aircraft that use DCS's curve (for a fresh relation: all of them). Aircraft with their own curve stay unticked, so a save does not overwrite them by accident. The rows you last saved for this relation come back instead, also after a restart, with their curve shown.

What Save does is written above the buttons:

  • all the aircraft that use DCS's curve ticked (the default): "Save stores it for DCS: all 5 aircraft listed here." The curve is stored once for DCS, not once per aircraft, so these aircraft keep following DCS's curve later;
  • some of them: "Save stores it for these aircraft (3 of 5): ...". Each ticked aircraft gets this curve as its own, in one step;
  • an aircraft that has its own curve ticked as well: a line in orange says "This replaces the own curve of ...". With DCS's curve it then follows DCS again; ticked among a few aircraft it gets the curve shown;
  • the default curve, a game without aircraft rows, a family: that one row.

Several aircraft can be ticked together; any other row is ticked alone. Ticking aircraft one by one never ticks DCS by itself while one of them is left out: one aircraft ticked gets its own curve, even when it is the only one that used DCS's curve. Only when you tick all of them does the DCS row tick too. When the ticked aircraft have different curves today, the line above says so and shows the first ticked one's curve; nothing is merged. Curves now (click to tick) groups the aircraft by the curve they share ("AH-64D BLK.II CPG, AH-64D BLK.II Pilot, Ka-50 III: same curve", "SA342 Copilot, SA342 Pilot: uses DCS"); a click ticks that group.

The panel shows the curve in blue and the default curve as a dashed orange line while the curve shown is not its own. Each game has its own kind of curve (DCS: dead zone, saturation X/Y, curvature or an 11-point user curve; IL-2: its own sensitivity and dead zones; X-Plane: free curve points), so the sliders on the right change with the row. When a game falls back to the default curve, JoyPro fits that game's parameters to it as closely as the game can express it.

Drag the white points to shape the curve, or use the sliders. Every setting also has a number box with its range next to it: type the exact value, or press Up / Down (Shift: ten steps) or turn the mouse wheel over the box you are in. A number outside the range goes back to its nearest end when you press Enter or leave the box, and the line under the box says so. The user curve has 11 number boxes, one per 10 % of stick travel (0 % ... 100 %), in step with the white points on the curve.

The numbers are in each game's own units; the line above the boxes says which. For DCS (and the base) they are the ones of DCS's own axis tune dialog: dead zone, saturation X/Y and the user curve points 0 .. 100, curvature -100 .. 100, so you type 8 for a dead zone of 8. Your profile and the export keep what DCS's files keep (0.08), and a value with more decimals stays exact until you change it. Falcon BMS has the launcher's steps 0 .. 3, FSX 0 .. 127, and so on.

Edits preview at once (also with the live position of your stick as a dot); Save stores them for the ticked rows, in one step (one Ctrl+Z). Use the game's curve again removes the own curve of the ticked aircraft (for a game: Use the default curve again), also in one step. Reload reads them again.

In detent mode the curve of an aircraft that detent mode bends ("uses the default curve, bent at the detent") is shown as the game gets it, and it cannot be changed or saved here: a curve saved for it would win over detent mode and switch it off for that aircraft. To change it, tick Default curve (the curve detent mode bends) or change the detent settings below.

Copy to another axis... puts the same settings on another bound axis in one step, e.g. Thrust Left to Thrust Right: pick the axis, tick Copy invert too only if both should invert alike, then Copy. It goes to the same games or aircraft of the other axis (the ticked ones); one Ctrl+Z takes it back.

#Detent mode: one throttle for all aircraft

A throttle with an afterburner detent used to need one throttle relation per afterburner position. In detent mode one throttle relation serves every aircraft: JoyPro bends the curve per aircraft so your throttle's detent is exactly where that aircraft's afterburner starts (F-16C at 77 %, F-14 at 70 %, ...). Resting in the detent stays just below the afterburner; pushing over it lights it.

  • The calibration belongs to the device axis. Every throttle relation on that axis shares it; a left and a right lever are separate axes, each with its own. The line under the buttons says whether this axis is calibrated, and its values.
  • Without a calibration detent mode changes nothing on that axis: every aircraft keeps the relation's curve. The calibration is part of the profile, so Undo or a restored version can bring back the state before you made it.
  • Why "full power at the detent" is on by default: an aircraft without afterburner has nothing behind the detent, so it reaches full power there; otherwise you would have to push through the detent for the last part. Untick it and its curve runs over the whole travel.
  1. Calibrate detent...: move the throttle to idle, then to the detent, then fully forward, then (optional) behind the idle detent (cut-off). Confirm each position; JoyPro reads the axis live. Save calibration.
  2. Tick Detent mode on.
  3. Already have one throttle relation per aircraft? Merge my throttle relations... shows a plan per device axis with every throttle relation of that axis ticked. Untick the ones to keep apart (a helicopter collective, a propeller aircraft): they stay as they are, with their own curve and their own detent settings, and the plan is made again for the ticked ones. Merge joins the ticked ones into one relation in detent mode; Undo merge takes it back.

The aircraft groups below show where each group's afterburner starts and where that number comes from; type your own value and Set, or Game data to go back.

In the game: Detent mode in the game

In every exported aircraft the throttle reaches the afterburner exactly at your device's detent. DCS gets a per aircraft curve (dead zone and saturation, or the user curve), X-Plane curve points; games with one curve for every aircraft get what most of the relation's aircraft need, and the export lists the rest.

#Tips

  • Ctrl+Z undoes every bind change, also after a restart (History).
  • A bind on a device that is not connected stays; the card shows it greyed and the export still writes it.
  • Replace the selected bind's device... (More) moves every bind of that device to another one, input by input, with a preview: for a new stick of the same kind or one that got a new id.
  • The same button on two relations is allowed; the Check tells you where that means two jobs in one aircraft.

#More inputs

A relation can be on more than one input, each with its own device, modifiers and axis curve (the same grip on two bases, a second fire button). The card shows +1 (the other inputs in its tooltip), and the selected relation has the panel More inputs:

  • Record another input / Add the input picked by hand: one more input of this relation.
  • Make main: that input becomes the main input (games that keep one input per action get the main input).
  • Remove: takes the input off.
  • Copy every bind of a device to another device: pick the First device and the Second device, Preview shows which input goes where (matched like Replace device), Copy adds them in one step (Ctrl+Z undoes it). The first device keeps its binds.

Exports write every input where the game can hold several per action and name the relations where it cannot (Export). Details and the table per game: docs/multi-bind.md. A relation with one input is exactly as before; there is no setting to switch on (until 2.6.5 it was Settings > Experimental).

Every page finds a relation by any of its inputs: Follow input and the HUD on a press of the second stick, the Layout page's picture and tables, the Devices filter of this page and of the Relations page, the search with the scope Everything ("MOZA" finds the relations with an input on it), the Check page and Replace/Remove device. For an axis with several inputs the section Axis response has an Input list at the top: each input has its own curve, dead zone and saturation; pick the one to tune (the main input is input 1).

#Behind the page

Record input from the click to the saved bind:

# Who What happens
1 You Press Record input.
2 Binds page Starts the capture service (DirectInput, CaptureNextAsync): axis or button mode, time limit, warm-up, threshold.
3 You Press a button or move an axis.
4 Capture service Reports the device and the input (for example JOY_BTN22).
5 Engine binds set "Gear Up/Down" --device ... --input JOY_BTN22 saves the bind (profile autosave, history version).
6 Binds page binds list refreshes the cards.
  • Capture: Services/JoystickCaptureService.cs polls DirectInput; Services/RecordButtonTracker.cs takes only transitions, never a button that was already pressed when recording started (unless "Also take a button that rests pressed" is ticked). Analog keyboards' axes are ignored unless allowed in Settings > Devices. Details: Live input.
  • Binds: engine binds list, engine binds show, engine binds set (device, input, --inverted, --slider, --curvature, --deadzone, --saturation-x/-y, --double-tap), engine binds clear (--input-only for Clear Input), engine binds unbind, engine binds import / engine binds export (JSON).
  • Modifiers: engine binds modifier add, engine binds modifier remove, engine binds modifier list.
  • Axis tuning: engine binds tuning show, engine binds tuning set (--scope plane:DCS:F-16C_50 | game:IL2Korea | family:il2 | base, --param key=value, --curve-points), engine binds tuning clear. Stored per bind as TuningOverrides (scope -> inv=0;sl=0;dz=0.05;sx=1;sy=1;cv=0.2). Reference: axis-curves.
  • Detent mode: engine binds detent show, engine binds detent set (--on/--off, --no-ab full|linear), engine binds detent calibrate (--idle --detent [--full] [--cutoff], stored per device axis), engine binds detent merge (plan; --apply merges as one history version). Gate data: DB\Detents\throttle-gates.json.
  • Auto Assign: engine devices kb (identify, list, show), engine relations auto-assign (--dry-run for Preview, --explain, --overwrite [--include-missing], --relation, --max-modifiers, --add-device, --ignore-device).
  • Lay out with AI: engine arrange ask, engine arrange apply --proposal, engine arrange prefs.
  • Every changing command runs with the profile, saves it and adds one version to the profile history (Undo).
