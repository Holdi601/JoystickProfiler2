GUI pages

Export

Show:

The Export page writes your profile into the games. It is three numbered steps, then the expert options and the game config backups. The full story of the modes and what they do in each game is on Export to your games.

For beginners

#The page from top to bottom

  1. Check your profile: Check now runs the Check; its cards appear further down.
  2. How JoyPro writes into the games: four choices (Replace on my devices, Update keep the game's binds, Update my profile wins, Only add) and the tick Also clear my other devices.
  3. Export to games: one card per game with binds in your profile. Tick cards and press Export ticked games, or Export now on one card. Undo last export on a card restores that game's files.

Below: Options and paths (for experts), then Problems found by the check, Same button used twice and Game config backups.

Advanced

#Cards and remembered choices

  • A card starts ticked only when the game has bound relations and was started once (its control files exist). A tick you change stays, per profile.
  • The DCS card has Aircraft...: every aircraft (and input layer) of the profile with its picture and how many of its relations are bound; only ticked aircraft are written (All / None).
  • Each card shows its last result ("Exported 14:02" or the engine's error).
  • Games not installed get no card; the page names them with a link to Settings > Games.
  • Preview on a card (where offered) runs the export as a dry run and shows what would change.
Technical internals

#Behind the page

View model: MainWindowViewModel.ExportGames.cs (cards, export, undo), MainWindowViewModel.ExportDefaults.cs (mode defaults, marks), MainWindowViewModel.Backups.cs. Engine: engine profile games fills the cards; engine dcs export, engine il2 export, engine starcitizen export and engine <game> export write; engine backups list / engine backups restore for undo and the backups list; engine profile game-state for the "Import first?" question.

#Also clear my other devices (in the exported aircraft, devices without a bind in my profile lose all their binds)

Check boxwritten2 ×

Tooltip Removes every bind of the devices your profile does not use (asks first; a backup is made)

Connected devices that have no bind in your profile lose all their binds in the exported aircraft (DCS: their DCS defaults too). Devices that are not connected, the import's ignored devices and the vJoy device JoyPro tunnels into are never cleared. Not used with Only add. Engine: --nuke-untouched-devices true. In the game: a second stick you never bound in JoyPro is empty in those aircraft after the export.

Source MainWindow.axaml:6045 · ExportNukeUntouchedDevices in MainWindowViewModel.cs · setting ExportNukeUntouchedDevices

#MSFS 2024: write into my MSFS profiles

Check boxwritten

Tooltip The export puts the binds into the profile MSFS 2024 uses for each device and category (Steam or Microsoft Store), backed up first. Off: only import files.

Microsoft Flight Simulator 2024 only, on by default: the export writes your binds straight into the profile MSFS 2024 uses for each device and category (Steam or Microsoft Store version), after a backup. The box below the cards then says per device which profile got them. Off: JoyPro writes only import files (--user-profiles false). Remembered for the next start. In the sim: your own controls profile holds the binds; no import is needed for those devices.

From the code On: the export writes into the user's MSFS 2024 profiles (engine default; off: --user-profiles false).

Source MainWindow.axaml:6064 · MsfsWriteUserProfiles in MainWindowViewModel.MsfsProfiles.cs · setting MsfsWriteUserProfiles

#MSFS 2024: import files for every device

Check boxwritten

Tooltip Off: import files only where JoyPro could not write your profile.

Microsoft Flight Simulator 2024 only, off by default: the export also writes an import file for every device and category (--import-files), not only where JoyPro could not write your profile. Open folder in the MSFS box shows the files. Remembered for the next start.

From the code On: import files for every device and category (--import-files), not only where the profile could not be written.

#Open folder

Buttonwritten2 ×

Microsoft Flight Simulator 2024 only. Where JoyPro could not write your own MSFS 2024 profile, the export writes your binds as one file per device and category; this opens that folder in Explorer. In the sim: Settings > Controls, pick the device and the category (Airplanes or General), the cogwheel of your profile, Import, and choose the file of that device and category. Import a file again only when JoyPro's export says it changed.

#Export ticked games

Buttonwritten

Tooltip Exports every ticked game one after the other (DCS: only the ticked aircraft)

Writes your binds into every ticked game, one after the other, with the way chosen above. JoyPro keeps a backup first, so Undo last export puts each game back. A game exported for the first time by this profile asks "Import first?" before, and Replace on my devices or Nuke ask once whether binds may be removed. The status line ends with "Exported 5 of 6 games, 1 failed: ()" and notes binds the games did not take. In the game: the game's control files hold your binds; start the game to see them.

#Undo last export

Buttonwritten

Tooltip Puts the game's control files back from before JoyPro's last export (asks first; only after an export of this game)

Puts the game back the way it was before the last export: JoyPro restores the newest backup of this game: every file the last export changed comes back byte for byte, files it created are removed. The restore itself is backed up first, so it can be undone too. Refused while the game runs. Engine: engine backups restore latest --game <id>. In the game: the controls are exactly as before the export.
