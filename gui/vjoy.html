Virtual Joystick

Show:

Some games take only a few joysticks, pick up the wrong ones or mix up their order when you plug in another device. In virtual mode JoyPro puts every axis, button and hat that a game's binds use onto one virtual joystick (vJoy), or onto a virtual Xbox 360 pad for games that only read gamepads. The game sees one device whose inputs never move; your profile keeps your real devices. On top, virtual functions do what Joystick Gremlin does: axis bands as buttons, toggles, short/long press, shift layers, macros, modes.

For beginners

#Use it in four steps

  1. Under Games switch the game to vJoy (or Xbox pad for games that only take a gamepad). Games known to read only one device show a suggestion with Use it.
  2. Export the game again on the Export page. JoyPro writes the binds to the virtual joystick; your profile keeps your real devices.
  3. Press Start before you start the game. JoyPro hides your real devices from that game with HidHide (Windows asks once for administrator rights) and copies every input to the virtual joystick live. Exception: the Xbox pad of Hell Let Loose: Vietnam and ACE COMBAT 8 reaches the game only when you start it once the game's title screen shows (or press Stop and Start there). The page says so under this step and in the tooltips of Start and of the auto start: for the game you set to Xbox pad, or naming both games while the list of games is not loaded yet.
  4. Press Stop when you are done. HidHide gets back exactly the setup it had before; nothing stays hidden.

What this page needs shows the free drivers: vJoy (for games set to vJoy), ViGEmBus (Xbox pad) and HidHide. They are not part of JoyPro; install the ones you need with one click there.

Test first

Test reads your devices and shows on the Live test tab what the game would get, without touching vJoy or HidHide. Move your stick and watch the bars.

In the game: What changes in the game

The game's controls menu shows one device, "vJoy Device", with your binds on its buttons and axes. Your real devices are invisible to that game only while the virtual joystick runs; every other program keeps seeing them. Curves, dead zones and inverts still come from the game's own settings that JoyPro exports.

Advanced

#The four tabs

Overview: what it is and how to use it; Status of vJoy (version, devices), HidHide and JoyPro's session (Refresh, Set up vJoy for the table when a vJoy device lacks axes, buttons or hats, Restore HidHide after a crash, Set up vJoy for maximum: 8 axes, 128 buttons, 4 hats, needs a Windows restart); What this page needs; Games (Native / vJoy / Xbox pad per game, what the game reads of one joystick with warnings above it); Options: hide the real devices (HidHide, recommended), start and stop by itself when a virtual game starts and ends (JoyPro looks for it every 3 seconds; pressing Start before the game is still the safest for vJoy; the Xbox pad games above want it after their title screen).

Mapping: the table. Each physical input the virtual games use has a fixed place on the virtual joystick: an axis keeps its own axis where it is free (X stays X), buttons and hats take the next free number. Existing places never move, so the game's binds stay the same from run to run. Update mapping gives new inputs a place and saves the table in the profile.

Functions: virtual functions, their modes, the Gremlin import and the graph (below).

Live test: bars for the axes, the pressed buttons and hats of each vJoy device as the forwarder writes them, with the forwarder's log. Show the virtual joystick live switches the bars on or off.

#Virtual functions

Functions run inside the virtual joystick, between your devices and what the game gets. Pick the game, the type, Add function, then set its inputs and outputs in the editor.

Function What it does
Axis bands an axis split into up to 16 bands, each band a button (throttle detents)
Button cycle each press steps to the next output
Toggle (latch) a push button that stays on until pressed again
Switch to on/off pulses a maintained switch sends one pulse per position
Short / long / double press three jobs on one button
Shift layer while the shift button is held, inputs go to other outputs
Merge / split axes two pedals into one rudder; one axis into two
Axis curve dead zone, saturation, curvature, invert, slider
Axis ends to buttons, axes to hat, buttons to axis, axis to encoder pulses conversions
Turbo, macro repeat while held; a sequence of presses and keys
Hat to buttons, buttons to hat, remap hats and remaps
Mode switch changes the mode (switch to, hold, toggle, cycle, back)

The editor: name, On, Keyboard output (lets outputs and macro steps press keys; only while it runs for real), a node view (inputs → function → outputs, lit while an output fires), the axis band bar with draggable edges, the curve, Works in modes, Mode to switch to, inputs (device and input, Clear), outputs (vJoy button or axis, Xbox control or key; Bind relation binds a relation to that output), settings and macro steps. Try it runs the function in the editor with sliders and press buttons; nothing goes to vJoy or the game. Save stores it; a running virtual joystick takes it after Stop and Start.

Chaining: an input can read another function's output instead of a device: pick ⚙ f1 ... in the input's device list, or drag in the Graph of all functions from an output dot (right edge) to an input dot (left edge). Loops are refused. Click a wire, then its × to disconnect.

Modes (layers): give your inputs another job per situation (Combat, Landing ...). A mode can inherit from another; a function works in the ticked modes (none = every mode). Add mode, Rename, × (remove), At start (the mode the forwarder starts in). The running mode is marked live.

#Coming from Joystick Gremlin

Pick the game, optionally tick Replace the game's functions and modes, press Import a Gremlin profile... and choose the .xml (R13 or R14). JoyPro shows a report first: what it makes of it, what it cannot do (activation conditions, mouse actions, Python plugins, sounds ...) and what is imported, but different. Nothing is saved until Import. Modes, remaps, curves, macros, merged axes, tempo, chain and toggle containers become functions and modes. Then set the game to vJoy, keep or bind the relations on the vJoy outputs, export and Start: HidHide and the forwarder replace Gremlin's device hiding and its background program.

  • Mapping table: in the profile (Pr0file.VirtualJoystick); engine vjoy map (--prune, --reset), engine vjoy mode (native | virtual | xbox per game), engine vjoy status, engine vjoy settings (which vJoy devices JoyPro uses), engine vjoy configure-vjoy (vJoyConfig, never takes anything away except avoided axes), engine vjoy limits.
  • Export, import, sync: while a virtual game is exported, imported or synced, its binds point at the vJoy slots; afterwards the profile has its physical devices back. A missing vJoy device stops the export with a message.
  • HidHide session: engine vjoy apply-hidhide, engine vjoy restore-hidhide, engine vjoy recover: a journal is written before any change, so a crash can be restored (Restore HidHide).
  • Functions and modes: engine vjoy functions types, engine vjoy functions list, engine vjoy functions add --game, engine vjoy functions set --game, engine vjoy functions remove --game, engine vjoy functions test (simulate, nothing goes to vJoy), engine vjoy modes list. Stored per game in the profile (VJoySettings.Functions[game], VJoySettings.Modes[game]); their outputs are reserved in the table. The same evaluation code runs in the engine's test, the editor's preview and the forwarder; functions are evaluated in dependency order every pass, nothing is allocated per pass (about 10 µs per pass for 50 functions).
  • Gremlin: engine vjoy import-gremlin (--dry-run for the report, --replace, --vjoy-device).
  • Forwarder: gui/JoyPro.VJoy (JoyPro.VJoy.exe run --config ... --sink vjoy|dry), non-exclusive DirectInput in, vJoyInterface.dll / ViGEmBus out. Test uses the dry sink and no HidHide.

#Start

Buttonwritten
