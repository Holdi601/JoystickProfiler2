Étapes principales

La vérification

Afficher :

La vérification regarde votre profil comme le jeu le verra après une exportation, et liste ce qui irait mal : un bouton qui fait deux choses dans le même appareil, une commande qui finit sur deux boutons, une assignation que le jeu n'a pas prise. Chaque carte le dit avec les mots du jeu (l'appareil, « périphérique · bouton », la commande telle que le jeu l'appelle) et propose une correction que vous pouvez annuler.

Pour les débutants

#Lancer la vérification

Appuyez sur Vérifier dans la barre du bas (ou sur Vérifier maintenant sur la page Exporter). Les résultats s'affichent sur la page Exporter sous Problèmes trouvés par la vérification : « À regarder : 0 erreurs, 1 avertissements, 0 remarques ».

Les cartes rouges sont des erreurs : corrigez-les avant d'exporter, sinon le jeu fera quelque chose que vous ne vouliez pas. Les cartes orange sont des avertissements : à regarder, souvent sans souci. Les Remarques sont sans danger.

#Lire une carte

  1. Le titre dit ce qui ne va pas : « Un bouton fait deux choses », « Même commande sur deux boutons », « Non écrit dans DCS World ».
  2. Les boutons : "Throttle - HOTAS Warthog · BTN 22 ('Gear Up/Down')", le périphérique, le bouton et, entre parenthèses, votre relation.
  3. Une phrase sur ce qui se passe dans le jeu : « Dans le F-16C, les deux boutons font 'Display Management Switch - Down'. En général, un seul des deux est voulu. »
  4. Les corrections : le bouton bleu avec une coche est la suggestion de JoyPro. Les autres sont des alternatives ; Plus contient le reste. Ouvrir '' montre la relation avec exactement les commandes de la carte marquées ; Retour (Alt+Left) revient à la carte.

Chaque correction peut être annulée avec Ctrl+Z.

Avancé

#Sections et corrections

Les erreurs viennent d'abord, puis les avertissements, puis les remarques. La recherche trouve les cartes par relation, appareil, bouton et commande ; le filtre par type montre un seul type ; l'ordre (Par relation, Par appareil, Par jeu, Par certitude) regroupe aussi les cartes.

Section Type Ce que cela signifie dans le jeu Corrections
Un bouton fait deux choses erreur Une entrée est assignée dans deux relations qui ont toutes les deux une commande du même appareil activée : un seul appui déclenche les deux. Garder seulement 'X' sur ce bouton (l'appareil est désactivé dans les autres relations), Ignorer ; Plus : Déplacer 'X' vers un autre bouton, Toutes les désactiver
Un bouton déclenche deux commandes erreur Une relation a deux commandes du même appareil (ou jeu) activées. Garder seulement 'A', Ignorer ; Plus : En déplacer une vers un autre bouton, Toutes les désactiver
Autres erreurs erreur Par exemple un bouton modificateur qui est aussi un bouton normal. comme la carte l'indique
Même commande sur deux boutons avertissement Une commande d'un appareil est activée dans deux relations : le jeu la reçoit sur deux boutons. Garder seulement sur X (la suggestion de JoyPro), Ignorer ; Plus : La désactiver sur les deux boutons
Relations copiées avertissement Un import a créé des copies d'une relation sur le même bouton. Fusionner en une seule ; Fusionner toutes les relations copiées
Non écrit dans le jeu avertissement « Ajouter seulement » a laissé une assignation de côté parce que le jeu utilise le bouton pour autre chose, ou que le jeu n'a pas de place libre (Elite : Primary et Secondary occupés). Exporter avec 'Mettre à jour' pour le remplacer, Déplacer vers un autre bouton, Laisser tel quel
Remarques remarque Sans gravité, mais à regarder.
  • Ignorer garde les assignations telles quelles et masque la carte (enregistré dans le profil, un Ctrl+Z). Elle revient d'elle-même, marquée Nouveau avec « Affiché à nouveau : maintenant aussi sur ... », quand la commande arrive sur un bouton de plus (une relation de plus sur le bouton, une commande de plus dans la relation). Avertissements ignorés (n) liste les cartes masquées avec Afficher à nouveau et Tout afficher à nouveau.
  • Cause : quand l'historique du profil sait quel changement a amené un problème, la carte le dit (« Cause : Gérer avec l'IA (366 changements de relations) le 21.10.2026 »).
  • Commandes inconnues : une commande que la liste actuelle de l'appareil n'a plus (une ancienne version du module, un mod non installé) est marquée « commande inconnue » ; Plus propose Retirer la commande inconnue et Chercher des commandes proches.
  • Classes de véhicule : dans les jeux sans listes d'appareils (War Thunder, MSFS, Arma), la manette des gaz d'un avion et le collectif d'un hélicoptère sur un même axe ne sont pas une erreur ; seules les actions de la même classe de véhicule entrent en conflit.
Dans le jeu: Ce que chaque carte signifie dans le jeu
  • Un bouton fait deux choses : dans cet appareil, un appui déclenche les deux commandes (par exemple "Gear" et "Weapon release"). Après la correction, le bouton y fait une seule chose ; les autres appareils ne changent pas.
  • Même commande sur deux boutons : les deux boutons font la même chose dans cet appareil. Sans danger, sauf si vous vouliez le second bouton pour autre chose.
  • Non écrit dans le jeu : le jeu fait toujours sa propre fonction sur ce bouton. « Exporter avec 'Mettre à jour' » la remplace à la prochaine exportation ; « Laisser tel quel » garde la fonction du jeu et masque la carte.
  • Commande inconnue : le jeu ignorerait cette ligne ; la retirer ne change rien dans le jeu.
Détails techniques

#Comment ça marche à l'intérieur

  • Interface : ValidateProfileCommand (Vérifier dans la barre du bas, Vérifier maintenant sur la page Exporter) lance engine profile validate --fail-on-warnings false, puis les rapports de doublons et de conflits, et construit les cartes (MainWindowViewModel.CheckCards.cs, MainWindowViewModel.Duplicates.cs, Models/CheckIssueModels.cs, Views/Controls/CheckProblemsPanel.axaml). Les cartes sont paginées (5 détaillées, 25 légères par section, Afficher plus), et « Plus » et les détails ne sont construits qu'à l'ouverture, 3000 erreurs restent donc fluides (CheckResponsivenessTests : chaque étape sous 400 ms).
  • Moteur : relations conflicts (engine\EngineCheckConflicts.cs) donne en détail les deux erreurs de validate : InputConflicts (clé game:plane§device§input[§modifier]) et ActionConflicts (clé game|plane|relation). Corrections : --keep <relation>, --keep-action <id>, --off, --ignore (enregistré dans Pr0file.KeptDuplicates ; --list-kept, --forget-kept [--keys]), --remove-actions. relations duplicates trouve la même commande sur deux boutons et les copies ; export-marks list les assignations qu'une exportation a laissées de côté. Chaque correction est une version du profil (une étape d'annulation).
  • Contrôle des textes : CheckTextGate fait échouer un test quand le texte d'une carte montre un id, « node » ou un autre mot interne.

Commandes du moteur : engine profile validate, engine relations conflicts, engine relations duplicates, engine export-marks list, engine export-marks dismiss. Référence : La vérification (référence).
