VTOL VR

Afficher :

VTOL VR est un jeu de combat aérien uniquement en VR : vous volez avec les manettes VR sur le manche et la manette des gaz virtuels. Le jeu lui-même n'assigne que trois axes d'un périphérique physique, le palonnier et les deux freins au pied, et les garde dans un seul fichier pour tous les appareils. La prise en charge complète du HOTAS (manche, manette des gaz, chaque interrupteur, par appareil et par siège) vient du mod gratuit BYOJoystick. JoyPro traite les deux comme deux jeux : VTOL VR (BYOJoystick mod) écrit les fichiers d'assignations du mod, VTOL VR (native rudder and brakes) écrit le propre fichier du jeu et ses réglages de commandes.

Pour les débutants

#Le faire marcher en 3 étapes

  1. Tout configurer pour moi
    sur la page Accueil
  2. Utiliser ces boutons
    regardez d'abord la liste
  3. Écrire dans mon jeu
    gardez VTOL VR fermé

Avant : appuyez sur Installer BYOJoystick sur la carte VTOL VR (une fois, voir ci-dessous). Lancez VTOL VR une fois avec votre palonnier branché et quittez Paramètres avec OK.

Ensuite : activez Hardware Control Rudder dans les réglages du jeu, sinon le jeu ignore votre palonnier.

Vous avez déjà assigné des boutons dans VTOL VR ? Alors la page Accueil propose Importer, puis combler les vides. Vos assignations restent, et seuls les boutons libres reçoivent de nouvelles tâches. Voir Démarrage rapide : faire marcher mon manche.

#Ce que JoyPro fait pour VTOL VR

  • Avec BYOJoystick : chaque cible que le mod propose (axes du manche et de la manette des gaz, train, volets, armes, contre-mesures, radar, feux, boutons MFD et plus) pour chaque véhicule et siège, depuis vos manches, manettes des gaz et le clavier.
  • Sans le mod : les Palonnier, Wheel Brake L et Wheel Brake R propres au jeu, plus les réglages de son menu Controls (Hardware Control Rudder, zones mortes VR, retours haptiques).
  • Relations : une relation est une fonction ; l'exportation BYOJoystick l'écrit dans chaque fichier de siège dont le véhicule a cette cible.

#Installer BYOJoystick (une fois)

  1. Ouvrez Démarrer et appuyez sur Installer BYOJoystick sur la carte VTOL VR. Un panneau montre ce qu'est le mod, sa source officielle (le Steam Workshop, le code source sur GitHub), sa taille, et si le VTOL VR Mod Loader et le mod sont sur ce PC.
  2. Cochez la case indiquant que vous avez lu ce qu'est BYOJoystick et que vous voulez l'installer depuis le Steam Workshop, puis appuyez sur Installer BYOJoystick. JoyPro sauvegarde vos fichiers BYOJ et ouvre Steam : installez le Mod Loader si Steam le demande, puis appuyez sur Subscribe sur la page BYO Joystick. Steam télécharge le mod ; JoyPro n'en copie rien.
  3. Appuyez sur Revérifier : JoyPro trouve le mod et en tire sa liste de commandes VTOL VR.

#Importer vos assignations

Appuyez sur Importer sur la carte VTOL VR (BYOJoystick) ou sur la carte de la partie native, puis sur Importer maintenant. Pour BYOJoystick, Prendre aussi les touches du clavier importe aussi vos assignations clavier.

#Créer et vérifier les relations

Créez les relations comme pour tous les jeux (flux des relations) ; l'assistant de configuration et l'Assignation auto connaissent les cibles BYOJoystick. Lancez ensuite la vérification sur la page Exporter.

#Exporter vers VTOL VR

  1. Fermez VTOL VR. JoyPro refuse d'écrire tant que le jeu tourne (processus VTOLVR).
  2. Ouvrez Exporter et gardez Remplacer sur mes périphériques avec Effacer aussi mes autres périphériques si c'est dans JoyPro que vous configurez vos périphériques.
  3. Appuyez sur Exporter maintenant sur la carte VTOL VR (BYOJoystick) et, pour le palonnier, sur la carte native.
Dans le jeu: Ce que vous voyez dans VTOL VR

Dans le jeu, Paramètres montre Hardware Control Rudder activé quand votre profil le règle, et Bindings liste Palonnier, Wheel Brake L et Wheel Brake R avec votre périphérique et son axe. Les assignations BYOJoystick sont dans la propre fenêtre du mod, par siège de véhicule ; son bouton Charger relit les fichiers.

#Ce que vous faites vous-même dans VTOL VR

  • Lancez VTOL VR une fois avec votre palonnier branché et quittez Paramètres avec OK. Le jeu liste alors vos périphériques et crée gameSettings.cfg ; l'exportation native n'écrit que les périphériques que le jeu a listés et ne crée jamais le fichier de réglages.
  • Hardware Control Rudder doit être activé, sinon le jeu ignore les axes de palonnier et de frein. Activez-le dans le jeu, ou enregistrez-le dans JoyPro (Avancé) pour que l'exportation native l'écrive.
  • BYOJoystick a besoin du VTOL VR Mod Loader de Steam ; JoyPro ouvre seulement les pages Steam.

#Pièges courants

  • Le palonnier ne fait rien : Hardware Control Rudder est désactivé. Le jeu le lit quand un véhicule apparaît.
  • Un seul frein au pied marche, ou les deux suivent la gâchette de la manette des gaz : le jeu ne prend les freins de votre palonnier que si Wheel Brake L est assigné. Assignez les deux.
  • Un frein au pied ne freine que sur la seconde moitié de sa course : le jeu lit un frein de 0 à 1. Réglez la plage d'axe de cette relation sur Positive (Avancé) ; JoyPro prévient de ce cas.
  • Deux palonniers identiques : le jeu garde une carte par modèle de périphérique, les deux pilotent donc la même action.
  • Une assignation BYOJoystick a disparu : le mod supprime les cibles qu'un véhicule n'a pas quand il charge un fichier.
Avancé

#Fichiers que JoyPro lit et écrit

Fichier De quoi il s'agit
<install>\SaveData\BYOJ_<seat>.xml Les assignations BYOJoystick d'un siège de véhicule : AV42C, FA26B, F45A, AH94Front, AH94Rear, T55Front, T55Rear, EF24GFront, EF24GRear
%APPDATA%\Boundless Dynamics, LLC\VTOLVR\SaveData\inputbindings.cfg les assignations propres au jeu : des cartes joystick Rewired dans un fichier texte ; Steam Cloud le synchronise
%APPDATA%\Boundless Dynamics, LLC\VTOLVR\SaveData\gameSettings.cfg les valeurs de Settings > Controls (HARDWARE_RUDDER, ...) ; Steam Cloud le synchronise
<library>\steamapps\workshop\content\3018410\3276352374\BYOJoystick.dll le mod installé : en lecture seule, pour sa liste de cibles
<install>\VTOLVR_Data\level0 la liste d'actions Rewired du jeu : en lecture seule, pour la liste de commandes native

L'ancien fichier <install>\SaveData\inputbindings.cfg n'est jamais écrit. Chaque écriture est sauvegardée d'abord et faite de façon atomique (fichier temporaire, puis remplacement) : le jeu remplace un inputbindings.cfg cassé par un fichier vide.

#Les modes d'exportation dans VTOL VR

Mode BYOJoystick (fichier par siège) Natif (inputbindings.cfg)
Ajouter seulement Rien par-dessus les assignations du siège : une assignation sur une entrée qu'une autre cible utilise (avec le même état de modificateur) est listée comme non écrite. Axes libres uniquement ; un axe occupé est listé comme non écrit.
Mettre à jour, garder les assignations du jeu L'autre cible sur votre entrée la perd ; tout le reste demeure, y compris l'ancienne entrée d'une cible déplacée. L'action sur votre axe est remplacée ; tout le reste demeure.
Mettre à jour, mon profil l'emporte Comme ci-dessus, et vos cibles quittent leurs autres entrées sur les périphériques branchés (les touches seulement avec l'option clavier). Comme ci-dessus, et vos actions quittent leurs autres axes sur les périphériques branchés.
Remplacer sur mes périphériques Les périphériques que JoyPro écrit ne gardent que vos assignations. Les autres actions des périphériques écrits sont effacées.
+ Effacer aussi mes autres périphériques Les périphériques branchés sans assignation sont effacés. Les périphériques branchés sans assignation sont effacés.

#Ce qui n'est jamais touché

  • Les périphériques non branchés, les périphériques ignorés de l'importation et le périphérique vJoy alimenté par JoyPro.
  • BYOJoystick : les entrées que JoyPro ne peut pas lire, et le bouton modificateur du siège, sauf si votre profil apporte le sien.
  • Natif : les cartes de boutons, les cartes clavier et souris, les comportements d'entrée, les cartes de calibrage, l'attribution des contrôleurs et le joueur System. L'exportation BYOJoystick n'écrit pas gameSettings.cfg.
  • Le clavier, sauf si vous exportez des assignations clavier (BYOJoystick seulement).

#Sièges, axes, réglages

  • Granularité : BYOJoystick par siège de véhicule (une cible va dans chaque siège qui l'a) ; la partie native est globale.
  • Axes BYOJoystick : l'inversion et le nombre unique Zone morte du mod par assignation. Sur Joystick Pitch, Roll, Yaw et sur Throttle, Power, Collective, ce n'est pas une zone morte mais le débattement dont le HOTAS a besoin pour reprendre la commande à l'autre membre d'équipage en multijoueur ; sur SOI Slew X/Y et Articulate Tilt, il coupe les petites valeurs sans remise à l'échelle ; ailleurs le mod ne l'utilise pas. Pas de courbes. Voir axis-curves.
  • Axes natifs : l'inversion, et pour les freins différentiels la plage de l'axe (Full ou Positive). Les zones mortes et les courbes ne peuvent pas être écrites.
  • Modificateurs : BYOJoystick connaît un bouton modificateur par fichier de siège (les assignations qui en ont besoin n'agissent que tant qu'il est maintenu) ; une assignation clavier peut avoir une touche modificatrice. La partie native n'en a pas.
  • Réglages des commandes : Paramètres > Paramètres de retour de force des jeux, jeu VTOL VR (control settings, VR haptics) : Hardware Control Rudder, Thumb Control Rudder, Twist Rudder Deadzone, Thumbstick Deadzone, Thumbstick Mode, Toggle Grip, Flight Control Haptics, Overall Haptics. L'exportation native les écrit dans gameSettings.cfg, même quand le profil n'a pas d'assignations natives.
  • Retour de force : VTOL VR n'a pas de retour de force joystick ; les vibrations sont celles des contrôleurs VR.
  • Surveillance : les fichiers BYOJ, et gameSettings.cfg avec la partie native (la surveillance).
Détails techniques

#Dans l'intégration de VTOL VR

Code : engine\Games\VtolVrIntegration.cs (BYOJoystick), VtolVrMod.cs (état de l'installation, liste des cibles), ClrMetadata.cs, VtolVrNativeIntegration.cs, engine\AxisModels\VtolVr.cs (byoj, vtolnative), engine\FfbModels\VtolVr.cs (les réglages des commandes).

  • Format BYOJoystick : sérialisation XML .NET, racine <Bindings> avec <KeyboardBindings> (Target, Key, ModifierKey comme noms KeyCode d'Unity) et <JoystickBindings> (Target, JoystickId, Input, RequiresModifier, Invert, Deadzone, POVDirection). Input : X Y Z RX RY RZ, S1 S2, PoV1..PoV4, B1..B128. Périphériques par GUID d'instance DirectInput (JoystickId).
  • Format natif : un fichier texte avec la racine RewiredSaveData et des lignes {key} = {value} ; la carte joystick est en XML Rewired (déclaré UTF-16 dans un fichier UTF-8). Actions : 0 Rudder, 5 Wheel Brake L, 6 Wheel Brake R. Une carte est identifiée par le modèle du périphérique : hardwareIdentifier = WindowsRawInput + chaîne produit HID sans espaces + PID décimal + GUID produit, hardwareGuid à zéro pour les périphériques que Rewired ne connaît pas. L'élément est le n-ième axe du périphérique.
  • Listes de commandes : engine vtolvr refresh-db lit les cibles dans le BYOJoystick.dll installé sans le charger ni l'exécuter (ses métadonnées et ses chaînes littérales), puis vos propres BYOJ_*.xml ; sans le mod, il n'y a pas de liste. engine vtolvr-native refresh-db lit la liste d'actions Rewired dans level0.
  • Commandes : engine vtolvr mod (status, prepare --accept-license), engine vtolvr scan, engine vtolvr import, engine vtolvr export, engine vtolvr-native scan, engine vtolvr-native import, engine vtolvr-native export, les réglages avec engine ffb set --device * --game VTOLVR.

#Limites connues

  • Pas encore de passage dans le jeu ; BYOJoystick est testé avec une DLL de remplacement. On ne sait pas encore si le mod se charge dans la version actuelle du jeu.
  • Natif : l'ordre des axes des périphériques que Rewired ne connaît pas et l'identifiant exact du périphérique sont tirés du code du jeu, pas encore d'un fichier écrit par le jeu.
  • BYOJoystick : les diagonales de chapeau, un bouton sur une cible d'axe et un axe sur une cible de bouton sont ignorés avec un avertissement.
  • JoyPro ne fournit aucune partie de BYOJoystick ; sa liste de commandes n'existe que si le mod est installé.
  • Tests : engine\tests\smoke\vtolvr.ps1 (allers-retours d'import, valeurs propres, paramètres globaux du jeu, exportation des réglages seuls).
