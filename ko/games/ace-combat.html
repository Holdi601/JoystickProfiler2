ACE COMBAT

표시:

ACE COMBAT은 아케이드 공중전 시리즈이며, 현재 PC용 두 게임은 HOTAS 입장에서 완전히 다릅니다. ACE COMBAT 8은 비행 스틱을 읽지 않고 Xbox 컨트롤러만 읽습니다. JoyPro가 스틱, 스로틀, 페달을 가상의 컨트롤러(가상 Xbox 패드)로 바꾸며, 게임에는 아무것도 쓰지 않습니다. ACE COMBAT 7은 스틱을 직접 읽고 바인딩을 텍스트 파일 Input.ini에 저장합니다. JoyPro는 이 파일을 다른 게임과 똑같이 읽고 씁니다. ACE COMBAT Zero와 Assault Horizon은 문서로만 정리되어 있습니다.

초보자용

#3단계로 바로 사용하기

#ACE COMBAT 8

  1. 모두 알아서 설정
    그다음 이 버튼 사용
  2. 가상의 컨트롤러 설정
    그다음 테스트
  3. 게임 시작
    타이틀 화면에서: Alt+Tab, 시작

#ACE COMBAT 7

  1. 게임을 한 번 시작
    그다음 종료
  2. 모두 알아서 설정
    그다음 이 버튼 사용
  3. 내 게임에 쓰기
    게임은 닫아 둔 채로

#ACE COMBAT 8: 한 번만 설정하기

  1. 시작 페이지에서 모두 알아서 설정을 누르세요. 또는 환영 화면에서 비행 스틱으로 ACE COMBAT 하기를 고르세요. 짧은 안내가 모든 단계를 보여 줍니다.
  2. 무엇이 어디에 들어가는지 목록을 확인하세요. 이 버튼 사용을 누르세요.
  3. 가상의 컨트롤러 설정을 누르세요. 설정 창이 닫히고 가상 조이스틱 페이지가 열립니다.
  4. 가상의 컨트롤러에는 ViGEmBus라는 무료 도우미가 필요합니다. 라이선스 아래의 확인란을 체크하세요. 그런 다음 ViGEmBus 설치를 누르세요. Windows가 권한을 요청하면 예를 클릭하세요. 이 작업은 한 번만 하면 됩니다.
  5. 테스트를 누르세요. 스틱을 움직이면 컨트롤러 그림이 함께 움직입니다. 버튼을 누르면 불이 켜집니다.

따로 전환할 것은 없습니다. ACE COMBAT 8은 가상의 컨트롤러를 알아서 사용합니다. 페이지에는 "자동으로 Xbox 패드: 이 게임은 Xbox 컨트롤러만 읽습니다"라고 표시됩니다. 이 게임에는 HidHide가 필요 없습니다. 어차피 게임이 실제 스틱을 보지 못하기 때문입니다.

#ACE COMBAT 8: 플레이할 때마다

  1. ACE COMBAT 8을 시작하세요. 타이틀 화면이 나올 때까지 기다리세요.
  2. Alt를 누른 채 Tab을 누르세요. JoyPro로 돌아옵니다.
  3. 시작을 누르세요.
  4. 다시 Alt+Tab을 누르세요. 게임으로 돌아갑니다. 이제 비행하세요!
  5. 다 끝나면 중지를 누르세요.
시작은 게임 다음에

게임에 타이틀 화면이 나왔을 때만 시작을 누르세요. 너무 일찍 눌렀나요? JoyPro가 "너무 이릅니다"라고 알려 줍니다. 중지를 누른 다음 시작을 누르세요. 플레이할 때마다 이렇게 하세요.

#ACE COMBAT 8에서 무엇이 어디로 가나요

HOTAS에서 가상의 컨트롤러에서 게임에서
스틱 앞, 뒤, 왼쪽, 오른쪽 왼쪽 스틱 피치와 롤
스로틀 레버 앞으로: RT. 뒤로: LT. 가속과 감속
스틱 비틀기(또는 페달) LB와 RB, 약 30 %부터 왼쪽/오른쪽 요
스틱의 비어 있는 햇 오른쪽 스틱 주위 둘러보기
플레어 버튼 L3와 R3 동시에 플레어(게임에서 확인되지 않음)
통신 스위치 또는 AI 메뉴 햇 D-pad 윙맨 명령
"High-G"라는 이름의 버튼 관계 양쪽 트리거 끝까지 High-G 선회

가상 조이스틱 페이지의 실시간 테스트 탭에서 각 버튼이 무슨 일을 하는지 보여 줍니다. 예: "A: 기관총 발사".

플레어는 게임에서 확인되지 않았습니다

JoyPro는 플레어를 위해 L3와 R3를 동시에 누릅니다. 아직 게임에서 이를 확인한 사람은 없습니다. JoyPro도 그렇게 알려 줍니다.

#햇으로 주위 둘러보기

게임은 가상의 컨트롤러의 오른쪽 스틱으로 주위를 둘러봅니다. JoyPro는 이를 스틱의 비어 있는 햇에 넣습니다. 햇 방향을 누르고 있으면 시점이 그쪽으로 돌아갑니다. 보통 스틱 맨 위의 햇입니다. 이 햇은 다른 게임에서는 원래 역할을 그대로 유지합니다. 예를 들어 DCS의 트림입니다. 헤드 트래킹과 주위 둘러보기를 참조하세요.

#ACE COMBAT 7: 빠른 방법

  1. 모든 장치를 연결한 상태로 ACE COMBAT 7을 한 번 시작한 뒤 종료하세요. 게임은 종료할 때 Input.ini를 씁니다.
  2. 시작 페이지에서 모두 알아서 설정을 누르세요. 목록을 확인하세요. 이 버튼 사용을 누르세요.
  3. 게임을 닫으세요. 내 게임에 쓰기를 누르세요. JoyPro가 이전 파일의 사본을 보관합니다.

전에 ACE COMBAT 7에서 버튼을 바인딩한 적이 있나요? 그러면 시작 페이지에 가져온 후 빈 곳 채우기가 나타납니다. 기존 바인딩은 그대로 두고, 비어 있는 버튼에만 새 역할이 주어집니다.

#ACE COMBAT 7: 내 바인딩 가져오기

  1. 모든 장치를 연결한 상태로 ACE COMBAT 7을 한 번 시작한 뒤 종료하세요.
  2. 시작을 여세요. 이 파일이 생기기 전에는 JoyPro가 자체적으로 가진 비행 동작 20개 목록을 사용합니다. 카드의 업데이트를 누르면 파일에서 목록을 만듭니다.
  3. ACE COMBAT 7 카드에서 가져오기를 누르고, **내 프로필에 추가 (권장)**를 그대로 둔 채 지금 가져오기를 누르세요.

#관계 만들기와 확인

관계 하나에 같은 기능의 ACE COMBAT 7 동작과 ACE COMBAT 8 동작을 함께 담을 수 있습니다. 그러면 두 게임 모두 버튼 하나로 그 기능을 사용합니다(관계 흐름). 확인 기능은 ACE COMBAT 7에서 두 가지 일을 하는 버튼을 찾아냅니다. 하단 바의 확인 또는 내보내기 페이지의 지금 확인을 누르세요(확인).

게임에서: ACE COMBAT에서 보이는 것

ACE COMBAT 7에는 비행 스틱 바인딩을 다시 지정하는 메뉴가 없으며, Input.ini에서 읽어 옵니다. 조작 메뉴에 이 바인딩이 표시되는지는 아직 확인되지 않았습니다. JoyPro의 게임 내 테스트에서, 게임이 종료할 때 파일을 다시 쓰면서도 JoyPro가 쓴 값을 모두 유지한다는 것이 확인되었습니다.

고급

#가상의 컨트롤러가 작동하는 방식

  • HidHide 필요 없음. ACE COMBAT 8은 Xbox 컨트롤러만 읽으므로 실제 스틱을 절대 보지 못합니다. 아무것도 숨길 필요가 없고, Windows도 관리자 권한을 요구하지 않습니다. HidHide는 vJoy로 설정한 게임에만 필요합니다.
  • 모드는 저절로 바뀝니다. 모드를 고르지 않은 동안에는 게임이 Xbox 패드를 사용합니다. 가상 조이스틱 페이지에서 다른 모드를 고르면 JoyPro가 그 선택을 유지합니다.
  • 게임의 레이아웃이 우선: ACE COMBAT 8 동작에 걸린 각 관계(릴레이션)는 게임이 그 동작에 쓰는 패드 컨트롤에 고정됩니다(게임 세이브에서 읽음). 피치와 롤은 왼쪽 스틱으로, 둘러보기는 오른쪽 스틱으로 갑니다.
  • 스로틀: 스로틀 레버가 두 트리거를 모두 움직입니다. 앞으로 밀면 RT, 뒤로 당기면 LT, 가운데는 중립입니다. "감속"이 토 브레이크 같은 다른 관계(릴레이션)에 있어도 작동합니다.
  • 요: 스틱 비틀기(없으면 러더 페달)가 약 30 % 움직였을 때 LB와 RB를 누릅니다.
  • 둘러보기: 시점 동작에 축이 없으면, 비어 있는 햇이 오른쪽 스틱을 움직입니다("햇을 축으로"). 각 방향은 누르고 있는 동안 스틱을 끝까지 밀고, 대각선은 두 방향을 함께 움직입니다. JoyPro는 다른 게임의 둘러보기나 시점 관계(릴레이션)가 쓰는 햇을 고르고, 없으면 스틱의 맨 위 햇을 씁니다. 시점 동작에 비어 있는 미니스틱이 있으면 항상 그것이 우선합니다.
  • 플레어: 플레어 또는 대응책 관계(릴레이션)로 L3와 R3를 120 ms 동안 함께 누릅니다. 게임에서 아직 확인되지 않았습니다.
  • 윙맨 명령은 통신 스위치나 AI 메뉴 햇에서 D 패드로 갑니다.
  • 고G 선회: 이름이 "High-G"인 버튼 관계(릴레이션)가 두 트리거를 모두 누르고 있습니다. DCS의 ASC Direct Control(Su-27, Su-33, J-11A의 "코브라 버튼")이 있는 관계(릴레이션)도 마찬가지입니다. 트리거에 걸린 스로틀은 계속 작동합니다.
  • 입력 하나에 역할 하나: 이 기능 중 하나를 움직이는 입력은 표에서 빠지므로, 절대 두 컨트롤을 동시에 누르지 않습니다.
  • 곡선이 패드까지 전달됩니다. 축 응답(바인딩 페이지)의 데드존, 포화, 곡선, 반전이 패드 스틱이나 트리거에 적용됩니다. ACE COMBAT 8만의 곡선을 쓰려면 적용 대상에서 ACE COMBAT 8만 체크하세요. 그렇지 않으면 기본 곡선이 적용됩니다.
  • 피치: DCS의 반전은 패드에 전달되지 않습니다. 기본적으로 스틱을 앞으로 밀면 기수가 내려갑니다. 게임에서 "Pitch Controls: Inverted"를 쓴다면 ACE COMBAT 8에서만 반전 체크를 해제하세요(축 응답, 적용 대상: ACE COMBAT 8).
  • 롤이 반대로 움직일 때: JoyPro는 롤을 그대로 전달합니다. 롤 관계(릴레이션)에서 ACE COMBAT 8에만 반전을 체크하세요.
  • 패드(스틱 두 개, 트리거 두 개, 버튼 14개, D 패드)에 들어가지 않는 것은 가상 조이스틱 페이지에 표시됩니다.
  • 여러 게임이 패드 사용: ACE COMBAT 7과 8은 둘 다 패드를 쓸 수 있고, 각각 자기 표를 가집니다. 자동 시작을 켜면 실행 중인 게임의 표가 적용됩니다. 그렇지 않으면 "시작"와 "테스트"용 Xbox 패드 테이블에서 고르세요.
  • 자동 시작은 게임이 시작되고 약 3초 안에, 타이틀 화면보다 먼저 패드를 만듭니다. 이 게임에는 너무 이를 수 있습니다. 그럴 때는 타이틀 화면에서 중지와 시작을 누르세요.
  • 전문가용: vJoy, HidHide, 전달 속도, 모드는 전문가용 세부 정보 표시(vJoy, HidHide, 모드) 아래에 있습니다.
  • ACE COMBAT Zero는 ACE COMBAT 8 폴더 안에 함께 들어 있습니다(ACZero\acz.exe). 아직 조사되지 않았습니다. 시험해 보려면 ACE COMBAT 8의 시작을 직접 누른 다음 Zero를 실행하세요. 테스트되지 않았습니다.

#ACE COMBAT 7의 내보내기 모드

동작과 장치마다 입력 하나. 메뉴 키(UI_*)와 JoyPro가 읽지 않는 조합은 절대 바뀌지 않습니다.

모드 일어나는 일
추가만 그 장치에 이미 값이 있는 동작은 그 값을 유지합니다. 게임이 다른 동작에 쓰는 입력에 걸린 바인딩은 쓰이지 않고 "게임에 기록되지 않음" 표시가 붙습니다.
업데이트, 게임의 바인딩 유지 프로필의 값이 쓰이고, 같은 입력에 걸린 다른 동작은 풀립니다. 다른 장치에 있는 그 동작의 값은 남습니다(게임이 평균을 내는 축은 보고됩니다).
업데이트, 내 프로필 우선 위와 같고, 프로필이 바인딩하는 모든 동작은 연결된 다른 장치에서 비워집니다.
내 장치에서 교체 JoyPro가 쓰는 섹션에는 읽을 수 있는 값만 남습니다. 쓰인 축은 여전히 연결된 다른 장치에서 비워집니다.
+ 다른 장치도 지우기 연결된 다른 장치의 읽을 수 있는 값이 비워집니다.

Input.ini의 주석, 순서, 인코딩, 줄 끝은 그대로 남습니다. ACE COMBAT 8에는 내보내기 모드가 없으며, 아무것도 쓰지 않습니다.

기술 정보

#ACE COMBAT 연동의 내부

코드: engine\Games\AceCombat7Integration.cs, engine\Games\AceCombat8Integration.cs. virtual-joystick의 패드 플래너와 전달기, 패드 전용 기능은 engine\VJoy\XboxPadAutoSetup.cs에 있습니다.

  • ACE COMBAT 7 섹션: Joystick- + DirectInput 제품 GUID(PID 상위 워드 + VID, 그다음 504944564944, 즉 "PIDVID"). 오브젝트는 X Y Z Rx Ry Rz Slider1 Slider2, Button1-Button32, POV_U/D/L/R1-4. 옵션은 :P / :N(절반), :R(반전), :C(-1..1을 0..1로). 조합은 &, !, +, >, <. 빈 값은 바인딩 없음입니다. JoyPro는 축을 X 또는 Y:R로, 버튼을 ButtonN으로, 햇 방향을 POV_<U|D|L|R><n>으로 씁니다. 조합과 절반 축은 가져올 때 보고만 하고 읽지 않습니다.
  • ACE COMBAT 7 동작: 축 Flight_Pitch/Roll/Yaw/Throttle/CameraPitch/CameraYaw, 버튼 Flight_Gun/Missile/Target/Weapon/Radar/Flare/View/AccelerationDeceleration/AutoPilot/Pause와 Flight_HatSwitchUp/Down/Left/Right. engine ac7 refresh-db는 사용자 파일에서 Flight_* 키를 가져옵니다.
  • ACE COMBAT 8: System.sav는 Checksum이 있는 Unreal GVAS입니다. 게임패드 키 아홉 개를 Unreal 키 이름으로 담고 있습니다(YawLeftKey_Controller = Gamepad_LeftShoulder ...). engine ac8 refresh-db는 이것을 컨트롤마다 Pad_* 동작 하나로 읽고, 키는 목록의 5번째 열에 둡니다. 스틱은 JoyPro 자체의 표에서 옵니다.
  • 패드 모드: 게임이 MaxJoysticks 0과 추천 모드 xbox를 선언하므로, 저장된 선택이 없으면 모드는 xbox입니다(VJoySettings.ModeOf). engine vjoy mode AceCombat8 xbox로 선택을 저장합니다. engine vjoy map, engine vjoy forwarder-config --xbox-game AceCombat8. HidHide 단계는 없습니다. 이런 게임만 가상 모드에 있으면 engine vjoy apply-hidhide는 "HidHide is not needed"라고 알리고 관리자 권한으로 아무것도 실행하지 않습니다.
  • 패드 기능: 스로틀 분할(XB_TRIGGERS), 요("축 끝을 버튼으로", 끝 구간 0.35), 플레어 동시 누름(IGamePadChords.PadChords, Confirmed = false), D 패드, High-G 유지(PadHolds), 시점 햇(hat-axes, IGamePadConventions.PadLookActions = Pad_CameraYaw / Pad_CameraPitch)은 계획을 세울 때마다 새로 만들어집니다. Pad_Pitch는 기본적으로 반전됩니다(PadInvertDefault).
  • 확인: engine vjoy pad-check는 프로필이 패드에서 무엇에 닿는지(피치, 롤, 기총, 미사일, 타깃, 스로틀 분할, 요, 동시 누름, 유지, D 패드, 시점)를 점수와 함께 보고합니다.
  • 명령: engine ac7 paths, engine ac7 scan, engine ac7 import, engine ac7 export; engine ac8 scan, engine ac8 import, engine ac8 export(아무것도 쓰지 않음).

#알려진 한계

  • ACE COMBAT 7: 조작 메뉴에 스틱 바인딩이 표시되는지, 그리고 피치에 :R, 스로틀에 :C를 쓴 비행은 아직 확인되지 않았습니다.
  • ACE COMBAT 8: 플레어 동시 누름(L3 + R3)과 시점 버튼은 아직 게임에서 확인되지 않았습니다.
  • ACE COMBAT 8: 게임이 직접 지원하는 몇몇 스틱(Thrustmaster 하나와 HORI 모델 하나)만 패드 없이 작동합니다. JoyPro는 그 설정을 쓰지 않습니다.
  • 테스트: engine\tests\smoke\acecombat7.ps1, acecombat8.ps1. 게임 안에서는 tools\e2e\games\AceCombat7Settings.ps1(내보내기, 시작, 다시 쓴 파일에 모든 값이 남아 있는지, 가져오기)과 AceCombat8Xbox.ps1(가상 패드로 메뉴 조작, 타이틀 화면이 나타나면 한 번 생성).
