FSX와 Prepar3D

표시:

FSX, FSX: Steam Edition, Prepar3D v4, v5, v6는 조작 설정을 %APPDATA%에 있는 XML 파일 하나에 보관합니다. 장치마다 축, 버튼, 햇이 담긴 맵이 하나 있고, 키보드도 있습니다. JoyPro는 이 파일을 프로필로 읽어 오고, 관계에서 다른 게임과 묶고, 블록 단위로 다시 쓰며, 서식, 주석, 다른 맵은 그대로 둡니다. 시뮬레이터마다 파일이 따로 있으므로 JoyPro에서는 각각 별개의 게임입니다.

이 연동은 공개 자료를 바탕으로 작성했으며 합성 테스트 파일로만 검증되었습니다. 이 시뮬레이터들 중 어느 것도 아직 실제 설치 환경에서 JoyPro로 테스트하지 않았습니다. 첫 내보내기 후에는 시뮬레이터의 조작 설정을 열어 할당을 확인하고, 다른 점이 있으면 알려 주세요.

초보자용

#3단계로 바로 사용하기

  1. 모두 알아서 설정
    시작 페이지에서
  2. 이 버튼 사용
    먼저 목록을 확인
  3. 내 게임에 쓰기
    시뮬레이터는 닫아 둔 채로

먼저: 장치를 연결한 상태로 시뮬레이터를 한 번 시작한 다음 닫으세요.

그다음: 시뮬레이터의 조작 설정을 열어 할당을 확인하세요. 이 연동은 아직 실제 설치 환경에서 테스트하지 않았습니다. 다른 점이 있으면 알려 주세요.

전에 시뮬레이터에서 버튼을 바인딩한 적이 있나요? 그러면 시작 페이지에 가져온 후 빈 곳 채우기가 나타납니다. 기존 바인딩은 그대로 두고, 비어 있는 버튼에만 새 역할이 주어집니다. 빠른 시작: 내 스틱 작동시키기를 참조하세요.

#JoyPro가 FSX와 Prepar3D에서 하는 일

  • 가져오기: 장치의 축, 버튼, 햇이 축마다의 감도와 널 존과 함께 프로필로 들어옵니다. 키보드 키는 요청할 때 들어옵니다.
  • 관계: 관계 하나는 모든 게임에서 하나의 기능입니다(FSX, MSFS, X-Plane의 "Gear"가 같은 버튼에). 명령은 시뮬레이터의 공개 이벤트 이름입니다(GEAR_TOGGLE, AXIS_AILERONS_SET ...).
  • 내보내기: JoyPro는 내보내는 시뮬레이터의 활성 조작 파일을 씁니다.

#바인딩 가져오기

  1. 시작을 여세요. 시뮬레이터 카드에 이미지가 보입니다. 명령 목록을 요청하면 목록 생성을 누르세요. JoyPro가 자체 이벤트 목록과 조작 파일(및 시뮬레이터 자체 템플릿 파일)에 나오는 이벤트를 합칩니다.
  2. 카드에서 가져오기를 누르세요. 내 프로필에 추가를 고르고, 키도 원하면 키보드 키도 가져오기를 체크하세요.
  3. 지금 가져오기를 누르세요. 내 관계 보기를 누르면 들어온 내용이 열립니다.

#관계 만들기와 확인

관계 페이지에서 관계의 시뮬레이터 이벤트는 다른 게임의 같은 기능 옆에 놓입니다. 관계 흐름으로 이를 묶은 다음, 내보내기 페이지에서 지금 확인을 누르세요(확인).

#내보내기

  1. 시뮬레이터를 닫으세요. 시뮬레이터는 종료할 때 파일을 다시 씁니다. fsx.exe 또는 Prepar3D.exe가 실행 중이면 JoyPro는 거부합니다.
  2. 내보내기를 열고 해당 시뮬레이터의 카드를 사용하세요.
  3. JoyPro에서 장치를 설정한다면 내 장치에서 교체와 다른 장치도 지우기를 그대로 두세요. 카드의 지금 내보내기를 누르세요.
게임에서: FSX와 Prepar3D에서 보이는 것

시뮬레이터를 시작하고 조작 설정을 여세요. 장치의 할당이 그곳에 표시되고, 각 축의 감도와 널 존은 보정 페이지에 표시됩니다. 정확한 메뉴 경로와 시뮬레이터가 JoyPro의 파일을 어떻게 보여 주는지는 아직 확인되지 않았습니다.

#FSX와 Prepar3D에서 직접 해야 할 일

  • 장치를 연결한 상태로 시뮬레이터를 한 번 시작해서 조작 파일이 만들어지게 하세요.
  • 첫 내보내기 후에 결과를 확인하세요(위 참조). 내 PC에서 이 연동을 처음으로 실제 테스트하는 것입니다.
  • 햇은 통째로 할당되며 보통 시점 이동(PAN_VIEW)입니다. 햇의 개별 방향에 다른 이벤트를 넣은 것은 기록되지 않으니, 시뮬레이터에서 바인딩하세요.

#자주 하는 실수

  • "시뮬레이터가 실행 중입니다": 시뮬레이터를 닫고 다시 내보내세요.
  • 다시 꽂은 뒤 장치의 바인딩이 사라짐: Windows가 장치에 새 GUID를 줄 수 있습니다. 그러면 JoyPro는 그 이름을 가진 연결된 장치가 정확히 하나일 때 이름으로 맵을 찾습니다(경고와 함께).
  • 수정키를 쓰는 조이스틱 바인딩이 빠짐: 이 형식에는 조이스틱 버튼용 수정키가 없습니다. 키에는 Ctrl, Shift, Alt를 쓸 수 있습니다.

#JoyPro가 읽고 쓰는 파일

시뮬레이터 컨트롤 파일
FSX(패키지판) %APPDATA%\Microsoft\FSX\Controls\Standard.XML(활성 파일은 fsx.cfg의 [CONTROLS] Controls_Current에서)
FSX: Steam Edition 패키지판 FSX와 함께 있으면 %APPDATA%\Microsoft\FSX-SE\Controls\, 단독 설치면 %APPDATA%\Microsoft\FSX\Controls\
Prepar3D v4 / v5 / v6 %APPDATA%\Lockheed Martin\Prepar3D v<N>\Controls\Standard.xml(활성 파일은 Prepar3D.cfg의 [CONTROLS]에서)
모두 <file>.joypro.json(JoyPro가 쓴 입력), <file>.joypro-meta.json(다음 가져오기를 위한 이름, 그룹, 튜닝)

Prepar3D의 Standard.xmlx(장치 프리셋)와 설치 폴더에 있는 FSX의 템플릿은 명령 목록을 위해 읽기만 하고 절대 쓰지 않습니다.

#FSX와 Prepar3D의 내보내기 모드

모드 시뮬레이터에서 일어나는 일
추가만 블록을 절대 제거하거나 바꾸지 않습니다. 다른 이벤트가 있는 입력에 걸린 바인딩은 쓰이지 않고 목록에 표시됩니다.
업데이트, 게임의 바인딩 유지 사용자의 입력에 있는 이벤트(충돌)를 바꾸고 나머지는 모두 유지합니다.
업데이트, 내 프로필 우선 바인딩한 이벤트의 다른 입력도 제거합니다(연결된 장치. 키보드는 키보드 옵션이 있을 때만).
내 장치에서 교체 쓰는 장치의 주 맵에는 사용자의 바인딩만 남습니다.
+ 다른 장치도 지우기 연결된 다른 장치의 주 맵은 비워집니다(맵 자체는 남음).

#절대 건드리지 않는 것

  • 연결되지 않은 장치의 맵, 가져오기에서 무시한 장치, JoyPro가 입력을 보내는 vJoy 장치.
  • 슬루 맵(... SLEW {GUID}), Mouse Yoke, Mouse Look, Prepar3D의 SimObject별 맵, 그리고 키보드 바인딩을 내보내지 않을 때의 키보드 맵.
  • 일반 키 두 개로 된 키 조합, 주석, 서식, 알 수 없는 요소.

#곡선과 설정

  • 단위: 전체 공통, 모든 기체에 파일 하나.
  • 축 설정(축 모델 fsx): 장치 축마다 감도(0~127)와 널 존(0~127). 보정 페이지와 같습니다. 기본 곡선은 근사해서 맞춥니다(데드존은 널 존으로, 포화는 감도로). 곡선 형태에는 대응하는 값이 없습니다. 업데이트 모드에서는 JoyPro의 값이 그냥 기본값이면 시뮬레이터에서 정한 값이 남습니다.
  • 반전: 음수 감도.
  • 포스 피드백, 게임 설정, 텔레메트리는 없습니다. 감시 기능은 시뮬레이터가 닫힌 뒤 변경을 감지합니다.

#FSX와 Prepar3D 연동의 내부

코드: engine\Games\FsxIntegration.cs(클래스 하나, 시뮬레이터마다 게임 하나), engine\Games\FsxControlsFile.cs(블록 전체의 텍스트 편집), engine\Games\FsxEvents.cs(JoyPro의 이벤트 목록).

  • 형식: <SimControls.Map>에 <Name>, <Axis>(<Index> 0~7 = X, Y, Z, Rx, Ry, Rz, Slider, 두 번째 슬라이더. <AxEvent>, <AxScale>, <AxNull>), <Entry>(0부터 세는 버튼 <Index>, <Down> / <Up>, 반복 이벤트는 <DownRpt>1), <POV>(햇 전체)가 있습니다. 헤더 encoding="Windows-1252".
  • 장치: DirectInput 장치마다 <instance name>{<instance GUID>}라는 이름의 맵 하나. GUID로 맞추고, 그 이름을 가진 연결된 장치가 정확히 하나일 때는 이름으로 맞춥니다. 파일에 없는 장치는 새 맵을 받습니다. 장치마다 버튼 32개와 축 8개가 보고됩니다.
  • 매핑: JOY_X .. JOY_SLIDER2는 <Index> 0~7로, JOY_BTN<n>은 <Index> n-1로, 햇은 위쪽 방향(JOY_BTN_POV1_U)으로.
  • 명령 목록: engine fsx refresh-db(그리고 fsxse, p3d4, p3d5, p3d6): JoyPro의 제목이 붙은 약 150개 이벤트와, 사용자의 컨트롤 파일과 시뮬레이터 템플릿에 이름이 나오는 모든 이벤트. AXIS_* 이벤트는 축입니다.
  • 가져오기 / 내보내기: engine fsx paths(활성 파일이 먼저), engine fsx import, engine fsx scan, engine fsx export, 그리고 engine fsxse export, engine p3d4 export, engine p3d5 export, engine p3d6 export도 같습니다. 처음 쓰기 전에 백업합니다.

#알려진 한계

  • 모든 것을 실제 설치에서 확인해야 합니다. Prepar3D v4 이상의 헤더와 <Name>에 아직 GUID가 들어 있는지, 시뮬레이터가 쓰는 정확한 바이트, 두 번째 슬라이더의 축 이름, 그리고 아직 본 적 없는 장치를 위해 JoyPro가 추가한 새 맵을 시뮬레이터가 유지하는지.
  • FSX: Steam Edition의 설정 파일 이름은 추정한 것입니다.
  • 테스트: 문서화된 형식으로 만든 합성 파일을 쓰는 engine\tests\smoke\fsx.ps1.
