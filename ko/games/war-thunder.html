War Thunder

표시:

War Thunder는 조작 설정을 machine.blk에 저장합니다. 이 텍스트 파일에는 처음 시작한 프리셋과 다른 부분만 들어 있습니다. JoyPro는 항공기와 헬리콥터 조작을 프로필로 읽어 오고 제자리에 다시 써넣으며, 전차, 함선, 메뉴 조작은 그대로 둡니다. 게임은 이 파일의 사본을 Gaijin 서버에도 보관하는데, JoyPro는 다음 로그인 때 내보낸 파일이 우선되도록 씁니다.

War Thunder 기본(게임 자체 바인딩 파일)
지원
기본(게임 자체 바인딩 파일)

engine warthunder
바인딩 파일
Documents\My Games\WarThunder\Saves\<uid>\production\machine.blk(BLK 텍스트, 프리셋과의 차이)

기본값은 gui.vromfs.bin / lang.vromfs.bin. --no-game-archives를 쓰면 JoyPro 자체 목록(설정 > 게임)

#3단계로 바로 사용하기

    시작 페이지에서
  2. 이 버튼 사용
    먼저 목록을 확인
  3. 내 게임에 쓰기
    War Thunder는 닫아 두세요

시작 전: 한 번 로그인하세요. 장치를 연결하고 게임을 시작해 Controls를 한 번 여세요. 그런 다음 종료하세요.

그다음: 로그인하세요. 바인딩이 Controls에 있습니다.

전에 War Thunder에서 버튼을 바인딩했나요? 그렇다면 시작 페이지에서 가져온 후 빈 곳 채우기를 제안합니다. 기존 바인딩은 그대로 두고, 비어 있는 버튼에만 새 기능을 줍니다. 빠른 시작: 내 스틱 작동시키기를 참고하세요.

#JoyPro가 War Thunder에 해 주는 일

  • 가져오기: 장치에 있는 항공기 및 헬리콥터 단축키와 축이 게임의 Axis setup 대화 상자의 모든 값과 함께 프로필에 들어오고, 게임 전체 조작 옵션(감도, 반전, WEP, 자동 트림, 포스 피드백)도 들어옵니다.
  • 관계: 관계 하나는 모든 게임에서 하나의 기능입니다. "Gear"를 War Thunder, DCS, IL-2에서 같은 스위치로 만들 수 있습니다.
  • 내보내기: JoyPro가 machine.blk를 제자리에서 수정합니다. 전차, 함선, 잠수함, 보병, 메뉴는 절대 건드리지 않습니다.

#War Thunder 바인딩 가져오기

  1. 시작을 여세요. War Thunder 카드에서 명령 목록을 요청하면 목록 생성을 누르세요. JoyPro가 게임 아카이브에서 항공기와 헬리콥터 동작을 읽어 옵니다(읽기 전용, 동작 290개). 설정 > 게임에서 이 기능을 끌 수 있으며, 그러면 JoyPro는 자체적으로 가진 더 짧은 목록을 사용합니다.
  2. War Thunder 카드에서 가져오기를 누르세요. 내 프로필에 추가를 그대로 두세요. 비행 키도 JoyPro에 넣고 싶다면 키보드 키도 가져오기를 체크하세요.
  3. 지금 가져오기를 누르세요. 내 관계 보기를 누르면 들어온 내용이 열립니다.

#관계 만들기와 확인

관계 흐름으로 여러 게임의 같은 기능을 연결한 다음, 내보내기 페이지에서 확인을 누르세요. War Thunder에서는 비행기의 스로틀과 헬리콥터의 콜렉티브를 축 하나에 두어도 괜찮지만, 항공기 동작 두 개를 버튼 하나에 두면 안 됩니다.

#War Thunder로 내보내기

  1. War Thunder를 닫으세요. 게임은 실행 중에 수시로, 그리고 종료할 때 파일을 저장하므로, 실행 중에는 JoyPro가 써넣기를 거부합니다.
  2. 내보내기를 열고 War Thunder 카드를 체크하세요.
  3. JoyPro에서 스틱을 설정한다면 내 장치에서 교체와 다른 장치도 지우기를 그대로 두세요. 카드의 지금 내보내기를 누르세요.
게임에서: War Thunder에서 보이는 것

게임을 시작하고 로그인하세요. 격납고에서 Esc를 누르고 Controls를 여세요. 바인딩은 항공기와 헬리콥터 섹션에 있습니다. 축의 Axis setup 대화 상자에는 데드존, 비선형성, 배율, 보정, 반전이 표시됩니다. 감도 항목, 포스 피드백 배율, 자동 트림은 Realistic 및 Full-real 조작 모드에서만 표시됩니다. Mouse aim / Simplified / Realistic / Full-real 탭을 누르면 목록이 걸러지는 것이 아니라 조작 모드가 바뀝니다.

#War Thunder에서 직접 할 일

  • 게임이 모든 장치를 한 번씩 등록하게 하세요. War Thunder는 자체 표에서 장치마다 버튼과 축에 번호를 매깁니다. 장치를 연결하고 게임을 시작해 Controls를 열면 게임이 그 장치를 machine.blk에 추가합니다. 게임이 아직 등록하지 않은 장치는 JoyPro가 건너뜁니다.
  • 처음 내보내기 전에 한 번 로그인해서 계정의 파일이 생기게 하세요.

#자주 하는 실수

  • "War Thunder 실행 중입니다": 게임을 종료하고 다시 내보내세요.
  • 장치가 건너뛰어짐: 게임이 그 장치를 등록하지 않았거나, 연결된 장치 두 개가 같은 VID:PID를 쓰거나, 버튼 또는 축 개수가 게임에 기록된 것과 다릅니다(그러면 모든 번호가 어긋납니다). 장치를 연결한 상태로 게임에서 Controls를 여세요.
  • 로그인 후 예전 바인딩이 돌아옴: 사본을 직접 복원했기 때문입니다. 대신 마지막 내보내기 취소를 사용하세요. 그러면 JoyPro가 파일의 버전을 올려서 서버가 파일을 덮어쓰지 않습니다.
  • 햇 대각선, 마우스 버튼, 축 수정키는 써넣을 수 없습니다.
고급

#JoyPro가 읽고 쓰는 파일

파일 설명
%USERPROFILE%\Documents\My Games\WarThunder\Saves\<uid>\production\machine.blk 사용자의 조작 설정(hotkeys{}, axes{}, params{}, deviceMapping{})과 게임의 설정 블록. <uid>는 사용자 계정입니다(Saves\lastlogin.blk에 이름이 있음, 로그인 전에는 Saves\last)
...\production\machine.blk.joypro-meta.json 쓴 바인딩에 대한 JoyPro의 이름, 그룹, 튜닝. 다음 가져오기에서 다시 읽습니다
machine.blk.jpbak 처음 쓰기 전의 사본, 그리고 JoyPro의 버전별 백업 저장소
내보낸 조작 프리셋(맨 위에 controls{}) 이것도 가져오고 내보낼 수 있음. 게임 전체 옵션은 machine.blk에만 씀

machine.blk는 basePresetPaths에 지정된 기본 프리셋과의 차이(diff)입니다: 단축키의 첫 번째 블록은 그 단축키에 대한 프리셋의 목록 전체를 대신하고, 빈 ID_X{}는 바인딩 없음을 뜻하며, 축 속성이 없으면 "프리셋의 값"을 뜻합니다. JoyPro는 카탈로그에 있는 단축키 블록, 카탈로그에 있는 축의 axisId와 축 값, 그리고 사용자가 설정한 개별 옵션 키를 씁니다. 다른 모든 줄은 텍스트를 그대로 유지하며, deviceMapping{}은 읽기만 합니다.

#War Thunder의 내보내기 모드

카탈로그에 있는 비행기와 헬기 조종만 해당합니다. 충돌이란 같은 입력에 있는 그런 조종 중 다른 하나를 말합니다.

모드 machine.blk에서 일어나는 일
추가만 단축키는 다른 비행기나 헬기 조종이 그 입력을 쓰지 않을 때만 씁니다. 블록을 지우거나 바인딩된 축을 교체하는 일은 없습니다. 건너뛴 바인딩에는 "게임에 기록되지 않음" 표시가 붙습니다.
업데이트, 게임의 바인딩 유지 사용자의 단축키는 그 조종의 다른 단축키 옆에 들어갑니다. 충돌만 지워집니다(사용자의 축에 있는 다른 조종의 축은 axisId -1이 됩니다).
업데이트, 내 프로필 우선 위와 같고, 추가로 바인딩한 조종은 게임이 목록에 올린 연결된 장치에서 다른 단축키를 잃습니다(키보드는 키보드 옵션을 켰을 때만).
내 장치에서 교체 위와 같고, 추가로 쓰는 장치의 다른 비행기와 헬기 단축키와 축이 해제됩니다.
+ 다른 장치도 지우기 프로필에 바인딩이 없는 연결된 장치도 마찬가지입니다.

빈 ID_X{}는 JoyPro가 그 조종을 바인딩하면 교체됩니다. 파일에 없는 조종에는 경고가 표시됩니다. 이때 사용자의 단축키가 기본 프리셋의 기본값을 대신합니다.

#절대 건드리지 않는 것

  • 전차, 함선, 잠수함, 보병, 메뉴의 단축키와 축.
  • deviceMapping{}, config{}, 그리고 JoyPro가 설정하지 않는 모든 설정 줄.
  • 마우스 바인딩, 연결되지 않은 장치, 가져오기에서 무시한 장치, JoyPro가 터널링하는 vJoy 장치.
  • 키보드 바인딩을 내보내지 않는 한 키보드.
  • 상대 제어, 값 유지, 축 범위는 직접 설정하지 않는 한 파일에 있는 그대로 유지됩니다.

#기체, 곡선, 게임 옵션

  • 적용 범위: 모든 비행기에 조종 한 세트, 모든 헬기에 한 세트를 씁니다(게임에 기체별 바인딩이 없습니다).
  • 수정키: 단축키의 마지막 버튼이 주 입력이고, 블록의 다른 버튼과 키는 그 수정키입니다. 단축키마다 대안을 세 개까지 둘 수 있습니다.
  • 축 곡선은 게임 자체 단위로, Axis setup 대화 상자에 보이는 그대로입니다: 데드존(0~0.5), 비선형성(0~3, 화면에는 1~4로 표시), 배율, 보정, 반전, 감도와 단계가 있는 상대 제어, 비활성 축의 값 유지. War Thunder 값이 없는 관계는 JoyPro 곡선을 맞춰 변환합니다: 배율 = 1 / 포화 X, 데드존도 그에 맞춰 조정, 가장 가까운 비선형성. 슬라이더는 데드존과 포화 사이의 이동 구간을 전체 범위에 매핑합니다. 기본 프리셋과 같은 값은 게임 자체가 저장하듯 그 줄을 생략합니다.
  • 게임 옵션: 비행기와 헬기의 롤, 피치, 요 감도, Y 반전(비행기, 헬기), 스로틀 반전, WEP를 위한 스로틀 유지, 자동 트림, 포스 피드백 켜기(게임 재시작 필요)와 그 배율. 설정 > 게임의 포스 피드백 설정(War Thunder 선택) 또는 engine ffb set으로 설정하세요. War Thunder 바인딩이 없는 내보내기에서도 기록되며, 가져오기는 파일의 값을 받아들입니다.
  • 클라우드 사본: 게임은 로그인할 때 파일 첫 줄의 version:i=N을 서버의 것과 비교합니다. JoyPro는 버전을 유지하므로 새 내용이 업로드됩니다. 마지막 내보내기 취소는 복원한 파일에 교체되는 파일보다 높은 버전을 주므로 서버 사본이 되돌아오지 않습니다.
  • 텔레메트리 포스 피드백: 포스 피드백 페이지가 게임의 로컬 웹 서버(127.0.0.1:8111, 실행 중인 게임이 제공, 설정할 것 없음)의 데이터로 포스 피드백 스틱을 구동합니다. 그 스틱에 대해서는 게임 자체의 포스 피드백을 끄세요.
  • 텔레메트리 기록: JoyPro는 같은 서버에서 출격 하나를 기록해 CSV나 Tacview용으로 내보낼 수 있습니다(게임에 실제 지리 좌표가 없으므로 0/0 주변의 평면 지도).
  • 감시 기능: 게임에서 바꾼 바인딩, 축 값, 옵션은 게임이 종료된 뒤 감지됩니다. 키 순서가 바뀌거나 게임의 차이(diff) 저장 방식은 변경으로 보지 않습니다.
  • HUD: HUD는 프로세스로 게임을 찾아 War Thunder 바인딩을 보여 줍니다.
기술 정보

#War Thunder 연동의 내부

코드: engine\Games\WarThunderIntegration.cs, engine\Games\WarThunderVromfs.cs, 축 모델 engine\AxisModels\WarThunder.cs, 설정 모델 engine\FfbModels\WarThunder.cs.

  • 장치: deviceMapping{ joystick{ devId:t="0738:2215" name:t="..." buttonsOffset:i= buttonsCount:i= axesOffset:i= axesCount:i= } }. devId는 DirectInput 제품의 VID:PID입니다. 게임은 장치를 devId로만 구분하므로 똑같은 장치 두 개는 하나로 합쳐집니다. joyButton = buttonsOffset + 로컬 인덱스(버튼, 그다음 햇마다 위, 오른쪽, 아래, 왼쪽 네 개), axisId = axesOffset + DirectInput 순서의 로컬 인덱스(X, Y, Z, Rx, Ry, Rz, 슬라이더 두 개), 그다음 햇마다 두 개. engine games devices는 JoyPro가 장치마다 무엇을 보는지 보여 줍니다.
  • 형식: BLK 텍스트, name:type=value, 블록 이름이 반복됨(순서 있는 목록으로 파싱), CRLF. controls.version이 5 미만인 파일은 구형이라 읽지 않습니다.
  • 명령 목록: engine warthunder refresh-db는 gui.vromfs.bin에서 shortcutsgroupaircraft.nut와 shortcutsgrouphelicopter.nut를, lang.vromfs.bin(lang/controls.csv)에서 제목을 읽습니다. 임시 폴더에 풀었다가 나중에 삭제하며, ID와 제목만 남습니다. --no-game-archives(설정 > 게임: "War Thunder: 게임 아카이브에서 전체 명령 목록 읽기" 체크 해제)는 JoyPro 자체의 동작 116개 목록을 사용합니다. ID_가 없는 ID는 축입니다. --path는 제어 스크립트가 일반 파일로 들어 있는 폴더를 받습니다.
  • 가져오기 / 내보내기: engine warthunder import, engine warthunder scan; engine warthunder export --mode clean|add|merge|merge-overwrite --nuke-untouched-devices --include-keyboard --ignore-device <d> --dry-run.
  • 기본 프리셋: 공식 프리셋 값 표가 없으므로, 내보내기는 튜닝한 모든 축 속성을 명시적으로 씁니다("기본값과 같음"이라며 줄을 생략하지 않음). 그래서 기본 프리셋이 무엇이든 파일이 올바릅니다. 가져오기는 파일에 설정되지 않은 속성에 코드의 기본값을 사용합니다.
  • 게임 옵션: engine ffb set --device * --game WarThunder --param <key>=<value>(joyFX, forceGain 0..100, aileronsMultiplier ... %, invertY, invertYHelicopter, invertT, holdThrottleForWEP, autotrim).
  • 텔레메트리: engine ffb telemetry setup과 engine telemetry record. JoyPro는 게임이 실행 중일 때만 /state를 초당 20번, /indicators를 두 번째 요청마다 폴링합니다.

#알려진 한계

  • 기본 프리셋 값 표가 함께 제공되지 않습니다(위 참조).
  • 감시 기능 실행에서 "hold throttle for WEP" 변경을 한 번 놓쳤고, 감도 하나를 1만큼 다르게 읽은 적이 있습니다.
  • 장치당 버튼 128개와 햇 4개를 읽습니다. 햇 대각선, 마우스 버튼, 축 수정키는 쓰지 않습니다.
  • 테스트: 게임 안에서 tools\e2e\games\WarThunderSettings.ps1(vJoy 축의 바인딩, 피치와 스로틀의 Axis setup 대화 상자, Controls 페이지 값, 게임이 다시 쓴 파일의 가져오기).
