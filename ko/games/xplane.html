X-Plane 12 / 11

표시:

X-Plane은 모든 장치의 할당을 설치 폴더 안의 환경설정 파일 하나에 저장합니다. 하드웨어 축마다 축 "용도"(피치, 스로틀, 플랩 ...), 버튼마다 명령, 그리고 선택적으로 응답 곡선이 들어 있습니다. JoyPro는 이 파일을 프로필로 읽어 오고, 관계로 다른 게임과 연결한 뒤 다시 써넣으며, 자신이 관리하는 비행 관련 줄만 바꿉니다. JoyPro에서 X-Plane 12와 X-Plane 11은 각자 설치 폴더, 명령 목록, 설정을 가진 별개의 게임이며, 둘을 나란히 설치할 수 있습니다.

초보자용

#3단계로 바로 사용하기

  1. 모두 알아서 설정
    시작 페이지에서
  2. 이 버튼 사용
    먼저 목록을 확인
  3. 내 게임에 쓰기
    X-Plane은 닫아 두세요

시작 전: 장치를 연결한 상태로 X-Plane을 한 번 실행한 뒤 종료하세요.

그다음: X-Plane에서 장치를 보정하세요(Settings > Joystick). 할당 내용도 거기에 표시됩니다.

전에 X-Plane에서 버튼을 바인딩했나요? 그렇다면 시작 페이지에서 가져온 후 빈 곳 채우기를 제안합니다. 기존 바인딩은 그대로 두고, 비어 있는 버튼에만 새 기능을 줍니다. 빠른 시작: 내 스틱 작동시키기를 참고하세요.

#JoyPro가 X-Plane에 해 주는 일

  • 가져오기: 장치의 축 용도, 버튼 명령, 반전 플래그, 응답 곡선이 프로필에 들어옵니다.
  • 관계: 관계 하나는 모든 게임에서 하나의 기능입니다(X-Plane, MSFS, DCS의 "Gear"를 같은 버튼에). X-Plane의 비행 명령은 게임 자체의 Commands.txt에서 가져옵니다.
  • 내보내기: JoyPro가 내보내는 버전의 조이스틱 환경설정을 씁니다. X-Plane은 Settings > Joystick에 할당 내용을 표시합니다.

#X-Plane 할당 가져오기

  1. 시작을 여세요. X-Plane 12(또는 X-Plane 11) 카드에 게임 이미지가 표시됩니다. 명령 목록을 요청하면 목록 생성을 누르세요. JoyPro가 설치된 X-Plane의 Resources\plugins\Commands.txt를 읽습니다.
  2. 카드에서 가져오기를 누르고 내 프로필에 추가를 고르세요(X-Plane의 이 파일에는 키보드 바인딩이 없습니다).
  3. 지금 가져오기를 누르세요. 내 관계 보기를 누르면 들어온 내용이 열립니다.

#관계 만들기와 확인

관계 페이지에서는 관계의 X-Plane 명령이나 축이 다른 게임의 같은 기능 옆에 표시됩니다. 관계 흐름으로 연결한 다음, 내보내기 페이지에서 지금 확인을 누르세요(확인).

#X-Plane으로 내보내기

  1. X-Plane을 닫으세요. X-Plane은 설정 창을 닫을 때와 종료할 때 환경설정을 다시 씁니다. 두 버전 모두 X-Plane.exe로 실행되므로, 둘 중 하나라도 실행 중이면 JoyPro가 거부합니다.
  2. 내보내기를 여세요. 설치된 버전마다 카드가 따로 있습니다.
  3. JoyPro에서 장치를 설정한다면 내 장치에서 교체와 다른 장치도 지우기를 그대로 두세요. 카드의 지금 내보내기를 누르세요.
게임에서: X-Plane에서 보이는 것

X-Plane을 시작하고 Settings > Joystick을 연 다음 장치를 고르세요. 모든 축에는 JoyPro가 써넣은 용도가, 버튼에는 명령이 표시되며, 축의 Edit Response Curve에는 JoyPro가 써넣은 지점과 보간 방식이 표시됩니다.

#X-Plane에서 직접 할 일

  • 장치를 연결한 상태로 X-Plane을 한 번 실행한 뒤 종료하세요. 한 번도 실행하지 않은 버전에는 아직 환경설정 파일이 없습니다. 맨 처음 실행하면 튜토리얼 비행이 시작되며, X-Plane은 종료할 때 조이스틱 환경설정을 씁니다.
  • X-Plane에서 보정하세요. 보정과 널 존은 X-Plane이 관리하며(Settings > Joystick), JoyPro는 절대 써넣지 않습니다.
  • 플러그인 및 기체 명령은 JoyPro 목록에 없습니다. 이런 명령은 X-Plane에서 바인딩하세요. JoyPro는 건드리지 않습니다.

#자주 하는 실수

  • 축이 작동하지 않음("Multiple axes assigned to yaw"): 연결된 축 두 개가 같은 용도를 쓰면 X-Plane이 그 용도를 무시합니다. 내보내기에서 경고하며, 다른 장치도 지우기나 '교체'가 다른 축을 비웁니다.
  • 스로틀이 반대로 움직임: X-Plane은 스로틀 축을 알아서 반전합니다. JoyPro는 반전 설정을 바꾸지 않고 그대로 써넣으므로, 레버가 정말 반대로 움직이는 경우가 아니라면 반전을 꺼 두세요.
  • X-Plane에서 만든 곡선이 바뀜: 업데이트 모드와 '추가만'에서는 JoyPro의 튜닝이 선형이면 곡선이 그대로 남습니다(경고 표시). '내 프로필 우선'과 '교체'는 JoyPro의 곡선을 써넣습니다.

#JoyPro가 읽고 쓰는 파일

파일 설명
<install>\Output\preferences\X-Plane Joystick Settings.prf 모든 장치의 현재 할당(줄 단위)
<install>\Output\preferences\control profiles\<Name> - Joysticks.prf 저장된 조종 프로필, 같은 형식
<file>.joypro.json, <file>.joypro-meta.json JoyPro가 쓴 입력과 곡선, 다음 가져오기를 위한 이름, 그룹, 튜닝
%LOCALAPPDATA%\x-plane_install_12.txt / _11.txt X-Plane 설치 프로그램이 설치 위치를 기록하는 곳(읽기만 함)

X-Plane Keys.prf(키보드)는 절대 건드리지 않습니다. Steam으로 설치하고 한 번도 실행하지 않은 버전은 Steam 폴더에서 찾습니다. 다른 폴더는 설정 > 게임에서 지정합니다.

#X-Plane의 내보내기 모드

모드 X-Plane에서 일어나는 일
추가만 빈 입력에만 씁니다. 다른 용도나 명령이 있는 입력에 대한 바인딩은 쓰지 않고 목록에 표시합니다. X-Plane이 다른 축에 둔 축 용도는 그대로 남습니다(경고).
업데이트, 게임의 바인딩 유지 사용자의 입력에 있는 다른 용도나 명령을 교체하고 나머지는 모두 유지합니다. 축 용도는 옮겨집니다(X-Plane은 두 축이 공유하는 용도를 무시함).
업데이트, 내 프로필 우선 추가로, 바인딩하는 용도나 명령을 가진 연결된 장치의 다른 축과 버튼을 곡선과 함께 해제합니다.
내 장치에서 교체 추가로, 쓰는 장치의 다른 모든 비행 축과 명령을 해제합니다.
+ 다른 장치도 지우기 쓰지 않는 연결된 장치는 비행 용도와 명령을 잃습니다.

#절대 건드리지 않는 것

  • 연결되지 않은 장치의 슬롯, 가져오기에서 무시한 장치, JoyPro가 터널링하는 vJoy 장치.
  • 시점, 카메라, VR, 사용자 지정 명령 축, 플러그인과 기체 명령, 키보드.
  • 보정 키(_joy_center, _joy_null, 원시 보정 데이터), _eq_pfc_*, 그 밖의 모든 줄.

#곡선과 설정

  • 적용 범위: 모든 기체에 파일 하나(X-Plane은 기체를 조종 프로필에 연결할 수 있으며, JoyPro는 찾은 파일들에 씁니다).
  • 응답 곡선(축 모델 xplane): LINEAR, CATMULL_ROM 또는 CUBIC_AVG를 쓰는 임의 개수의 지점, 그리고 스로틀, 프로펠러, 혼합비 축의 고정 범위(beta, feather, cutoff, FADEC ...). 기본 곡선은 지점들로 바뀌며, 바뀌지 않은 곡선은 바이트 그대로 유지됩니다. 튜닝은 한 버전에만 또는 두 버전 모두에(family:xplane) 설정할 수 있습니다.
  • 반전: _joy_rev_axis. 사용자의 반전 그대로입니다(X-Plane이 스로틀을 스스로 반전함).
  • 게임 설정(설정 > 게임의 포스 피드백 설정): 피치, 롤, 요의 조종 응답. X-Plane 12는 부조종사 축과 포스 피드백 스틱용 "control-loaded axes"도, X-Plane 11은 안정성 증강도, 두 버전 모두 플랩 디텐트도 있습니다. 파일에 이미 있는 줄만 바꿉니다.
  • 포스 피드백: X-Plane 자체에는 없습니다. control-loaded 스위치만 있습니다.
  • 텔레메트리 기록: X-Plane의 UDP 데이터 출력(포트 49000)에서 위치와 함께 받으므로 Tacview 트랙을 만들 수 있습니다.
  • 감시 기능: 환경 설정의 변경은 X-Plane이 종료된 뒤 감지됩니다(감시 기능).
기술 정보

#X-Plane 연동의 내부

코드: engine\Games\XPlaneIntegration.cs(버전마다 인스턴스 하나), engine\Games\XPlanePrf.cs, engine\AxisModels\XPlane.cs, engine\FfbModels\XPlane.cs, engine\Games\LegacyGameIds.cs(두 버전으로 나뉘기 전의 프로필은 불러올 때 이전됨).

  • 줄: _joy_AXIS_use<i>(용도 코드), _joy_rev_axis<i>, _joy_BUTN_use<i>(명령 경로, sim/none/none = 비어 있음), axis_response_curve<i>. 전역 인덱스: 축 = 슬롯 × 25 + 축, 버튼 = 슬롯 × 160 + 버튼.
  • 장치: 슬롯 _joy_unique_id<slot> VID:<dec>PID:<dec>. 똑같은 장치가 있으면 DirectInput HID 인터페이스 경로가 _joy_location<slot>과 같아야 합니다. 버튼은 장치의 버튼, 그다음 첫 번째 햇이 위부터 시계 방향으로 버튼 8개입니다. 다른 햇은 매핑되지 않습니다. 장치당 버튼 160개와 축 25개를 읽습니다.
  • 용도 코드: 두 버전 모두 0~66. X-Plane 12는 스로틀 9, 부조종사 피치/롤/요/브레이크/틸러, 양쪽 휠 브레이크를 추가합니다. 코드 74~77과 시점 축은 카탈로그에 없습니다.
  • 명령 목록: engine xplane12 refresh-db / engine xplane11 refresh-db: 해당 버전의 축 표와 Commands.txt의 비행 명령 그룹(sim/flight_controls, engines, autopilot, lights ...; sim/view, operation, replay ...는 제외).
  • 가져오기 / 내보내기: engine xplane12 import, engine xplane12 scan, engine xplane12 export(--mode, --nuke-untouched-devices, --dry-run), engine xplane11 export도 마찬가지입니다. 먼저 .jpbak으로 백업합니다.
  • 설정과 곡선: engine ffb set --game XPlane12, engine binds tuning set --scope game:XPlane12 --curve-points 0:0,0.4:0.3,1:1, engine binds tuning preview(X-Plane 12.4.3에서 0.0001 이내로 측정).

#알려진 한계

  • 용도 코드 74~77의 의미. HID와 DirectInput의 축 순서 차이는 추정한 것입니다.
  • 곡선이 없을 때의 X-Plane Control Sensitivity는 미리보기에 반영되지 않습니다.
  • X-Plane 11은 설치된 파일로만 확인했습니다. 게임 내 메뉴 확인은 아직 남아 있습니다.
  • 테스트: engine\tests\smoke\xplane.ps1; 게임 안(X-Plane 12)에서 바인딩과 응답 곡선이 33단계 중 33단계를 통과했습니다. tools\e2e\games\XPlaneCurves.ps1은 모든 축을 JoyPro의 미리보기와 비교합니다.
