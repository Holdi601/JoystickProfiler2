Tiny Combat Arena

표시:

Tiny Combat Arena는 모든 기체가 하나의 바인딩 세트를 쓰는 전투 비행 게임입니다. 조작 설정은 Windows 레지스트리(Unity의 설정 저장소)에 저장되며, 장치마다, 그리고 Control Mapper의 탭(Flight, Weapons, Camera, View Select, Map UI, System)마다 Rewired 조이스틱 맵이 하나씩 있습니다. JoyPro는 이 맵을 프로필로 읽어 오고, 바인딩을 각 장치의 알맞은 탭에 다시 써넣습니다.

시작 전: Tiny Combat Arena를 한 번 실행하고 Control Mapper를 여세요. 그런 다음 게임을 닫으세요.

그다음: 바인딩이 게임 Control Mapper의 각 탭에 있습니다.

전에 Tiny Combat Arena에서 버튼을 바인딩했나요? 그렇다면 시작 페이지에서 가져온 후 빈 곳 채우기를 제안합니다. 기존 바인딩은 그대로 두고, 비어 있는 버튼에만 새 기능을 줍니다. 빠른 시작: 내 스틱 작동시키기를 참고하세요.

#JoyPro가 Tiny Combat Arena에 해 주는 일

  • 가져오기: 연결된 장치의 조이스틱 맵이 모든 탭에서 프로필로 들어옵니다. 반전 설정이 포함된 축, 버튼, 햇 방향, 축 위의 버튼(예: Throttle Up / Down)이 해당됩니다.
  • 관계: 관계 하나는 모든 기체에서 하나의 기능입니다.
  • 내보내기: JoyPro는 각 바인딩을 해당 탭의 맵에 써넣고(피치는 Flight, 기관포는 Weapons, 시점은 View Select), 각 맵의 나머지는 그대로 둡니다.

#바인딩 가져오기

  1. Tiny Combat Arena를 한 번 실행하고 Control Mapper를 연 다음(그러면 게임이 연결된 모든 장치의 맵을 저장합니다) 게임을 닫으세요.
  2. 시작을 열고 Tiny Combat Arena 카드에서 가져오기를 누른 다음 지금 가져오기를 누르세요.

#관계 만들기와 확인

다른 게임과 마찬가지로 관계를 만드세요(관계 흐름). 이 게임에는 아직 직접 만든 기능 표가 없어서, 설정 마법사와 자동 할당은 게임 자체의 명칭과 분류에서 만든 표를 사용합니다. 그런 다음 내보내기 페이지에서 확인을 실행하세요.

#Tiny Combat Arena로 내보내기

  1. Tiny Combat Arena를 닫으세요. 게임이 실행 중(프로세스 Arena)이면 JoyPro는 써넣기를 거부합니다. 게임은 Control Mapper에서 Done을 누를 때 모든 맵을 저장합니다.
  2. 내보내기를 열고 내 장치에서 교체와 다른 장치도 지우기를 그대로 둔 채 Tiny Combat Arena 카드에서 지금 내보내기를 누르세요.
게임에서: Tiny Combat Arena에서 보이는 것

게임의 Control Mapper를 열고 장치를 고르세요. 바인딩은 Flight, Weapons, Camera, View Select, Map UI 탭에 있습니다. 매퍼는 Rewired의 번호 체계로 입력 이름을 붙입니다. "Axis 0"은 X 축이고, 버튼 1은 "Button 0"으로, 첫 번째 햇의 위쪽은 "Hat 0 Up"으로 표시됩니다. 매퍼로 가는 메뉴 경로는 아직 확인되지 않았습니다.

#Tiny Combat Arena에서 직접 할 일

  • 게임을 한 번 실행하세요. 처음 가져오거나 내보내기 전에 실행해야 게임이 레지스트리 키를 만듭니다. 맨 처음 실행할 때 간단한 게임 설정과 헤드 트래킹을 묻는데, 원하는 대로 답하면 됩니다.
  • 곡선: 게임 자체의 조이스틱 및 러더 곡선과 스로틀 속도는 설정 파일에 있습니다. 게임에서 설정하세요. JoyPro는 이 값을 써넣지 않습니다.

#자주 하는 실수

  • "Tiny Combat Arena 실행 중입니다": 게임을 닫고 다시 내보내세요.
  • 장치가 건너뛰어짐: 같은 모델의 장치 두 개가 연결되어 있으면 게임의 맵에서 구분할 수 없습니다. JoyPro는 경고와 함께 그 장치들을 제외합니다.
  • Logitech Extreme 3D나 T.16000M의 트위스트 또는 스로틀: 게임의 Rewired가 이 장치들을 인식해 맵을 다른 키에 저장합니다. JoyPro는 아직 이 경우를 처리하지 않습니다.
  • 햇 대각선 방향이 없음: JoyPro는 햇의 네 가지 주요 방향만 써넣습니다.
고급

#JoyPro가 읽고 쓰는 것

위치 설명
HKCU\Software\TinyCombat\Arena 레지스트리에 있는 게임의 Unity 설정. Rewired 값은 바이너리(UTF-8 텍스트와 0 바이트 하나)이고, 이름은 _h<hash>로 끝남
장치와 탭마다 값 하나. 이름에 dataType=ControllerMap과 장치의 hardwareIdentifier가 들어 있음 한 탭에 있는 장치 하나의 조이스틱 맵(Rewired XML), 플레이어 Player용
<install>\Arena_Data\sharedassets*.assets 게임의 Rewired 동작 목록: 명령 목록용으로 읽기만 함
%USERPROFILE%\AppData\LocalLow\TinyCombat\Arena\Settings\Controls.cfg 게임의 곡선과 스로틀 속도: 쓰지 않음

쓸 때마다 그 전에 JoyPro는 플레이어의 컨트롤러 맵 값을 백업 저장소에 넣습니다. 마지막 내보내기 취소는 이 값을 다시 씁니다.

탭은 Rewired 맵 카테고리입니다: 0 System, 3 Flight, 8 Weapons, 11 Camera, 4 View Select, 9 Map UI. 각 동작은 동작 카테고리에 맞는 탭으로 갑니다(Flight Control은 Flight, Weapon Control은 Weapons, Camera Control은 Camera, View Control은 View Select, Map Control은 Map UI, Default는 System).

#Tiny Combat Arena의 내보내기 모드

Tiny Combat Arena는 비행 전용 게임입니다. 할당할 수 있는 모든 동작이 JoyPro의 관리 대상입니다.

모드 장치 맵에서 일어나는 일
추가만 게임의 내용은 바뀌지 않습니다. 입력이 이미 다른 동작(또는 축의 반대쪽 극)을 움직이는 바인딩은 빠지고 목록에 표시됩니다.
업데이트, 게임의 바인딩 유지 다른 동작에 준 입력에 있던 동작은 그 입력을 잃습니다. 그 동작의 다른 입력은 유지됩니다.
업데이트, 내 프로필 우선 위와 같으며, 추가로 바인딩하는 모든 동작은 JoyPro가 읽을 수 있는 연결된 장치에서 다른 입력을 잃습니다.
내 장치에서 교체 쓴 장치의 다른 모든 할당 가능한 동작이 모든 탭에서 해제됩니다.
+ 다른 장치도 지우기 연결된 다른 장치(모델당 하나)는 그 동작들을 잃습니다. 저장된 맵이 없는 장치는 빈 맵을 받는데, 게임은 알 수 없는 장치에 기본 바인딩을 주지 않으므로 게임에서는 아무것도 바뀌지 않습니다.

#절대 건드리지 않는 것

  • 플레이어가 할당할 수 없는 동작(메뉴 탐색과 몇 가지 고정 동작).
  • 키보드와 마우스 맵, 보정 맵, 입력 동작 방식(input behaviour), 컨트롤러 할당, 게임의 설정 파일.
  • 연결되지 않은 장치, 같은 모델의 장치 두 개 이상, 가져오기에서 무시한 장치, JoyPro가 입력을 전달하는 vJoy 장치.

#적용 범위, 곡선, 기타

  • 적용 범위: 전역. 모든 기체에 바인딩 한 세트를 씁니다.
  • 축 곡선: 쓰지 않습니다(게임의 곡선은 Controls.cfg에 있습니다).
  • 키보드와 수정키: 쓰지 않습니다.
  • 포스 피드백, 텔레메트리: 없음.
  • 감시 기능: 게임 키에 대한 레지스트리 변경 알림을 사용합니다(감시 기능).
  • HUD: HUD는 프로세스(Arena)로 게임을 찾습니다.

#Tiny Combat Arena 연동의 내부

코드: engine\Games\TinyCombatArenaIntegration.cs(레지스트리 키, 플레이어 이름, 탭, 카탈로그 구조)는 engine\Games\RewiredMapIntegration.cs(Rewired 조이스틱 맵 읽기와 쓰기, Nuclear Option과 공유) 위에서 동작합니다.

  • 장치: 알 수 없는 장치는 0인 hardwareGuid와 hardwareIdentifier = WindowsRawInput + 공백을 뺀 HID 제품 문자열 + PID + VID를 받습니다. 키가 장치의 HID 제품과 VID/PID로 만들어지므로, 내보내기를 하려면 장치가 연결되어 있어야 합니다.
  • 요소: 축 X, Y, Z, Rx, Ry, Rz = 0~5, 버튼 n = 31 + n, 햇 h(1부터 셈)의 Up / Right / Down / Left = 160 + 4(h-1) + 0~3. 매퍼는 버튼 요소에 axisRange 1을 씁니다. JoyPro도 1을 쓰며, 버튼을 비교할 때는 이 값을 무시합니다.
  • 명령 목록: engine tinycombatarena refresh-db는 파싱에 성공한 첫 번째 Arena_Data\sharedassets*.assets에서 Rewired InputManager를 읽습니다. 플레이어가 할당할 수 없는 동작은 빠지고, 축 동작은 게임의 극 이름으로 극별 행을 받습니다(DB\TinyCombatArena\actions.tsv).
  • 명령: engine tinycombatarena paths, engine tinycombatarena catalog, engine tinycombatarena scan, engine tinycombatarena import, engine tinycombatarena export(짧은 이름 engine tca); 실행 취소는 engine backups restore.

#알려진 한계

  • 게임의 Rewired가 인식하는 장치(0이 아닌 hardwareGuid)는 처리하지 않습니다.
  • 햇 대각선과 키보드 바인딩은 쓰지 않습니다.
  • 테스트: engine\tests\smoke\tinycombatarena.ps1; 게임 안에서는 tools\e2e\games\TinyCombatArenaSettings.ps1(무작위 vJoy 축에 둔 Pitch, Roll, Yaw, 버튼 두 개, 햇 방향 하나가 Flight, Weapons, View Select 탭에 표시되고, 게임을 종료한 뒤의 가져오기가 이를 모두 다시 읽어 옴).

이 게임에 대한 모든 기술 메모(저장소에서 생성됨): tiny-combat-arena.md.
