G-Rebels

표시:

G-Rebels는 Unreal Engine 5 기반의 사이버펑크 비행 전투 게임으로, 메가시티 위로 VTOL을 조종합니다. 게임은 켜 둔 조이스틱마다 채널(0~5)을 하나씩 주고, 채널마다 모든 축의 역할(피치, 롤, 요, 추력, 측면 이동, 상승 / 하강)과 버튼 바인딩을 저장 파일 두 개에 보관합니다. JoyPro는 이 역할과 바인딩을 프로필로 읽어 오고 다시 씁니다. 키보드, 게임패드, 마우스는 게임에 있는 그대로 둡니다.

초보자용

#3단계로 바로 사용하기

  1. 모두 알아서 설정
    시작 페이지에서
  2. 이 버튼 사용
    먼저 목록을 확인
  3. 내 게임에 쓰기
    G-Rebels는 닫아 둔 채로

먼저, 게임에서 장치마다 한 번씩: OPTIONS > INPUT > DEVICES에서 채널을 주세요. 그 장치의 JST 탭에서 축 역할 하나를 바꾸세요. 버튼 하나를 바인딩하세요. (자세한 내용은 아래 참조.)

그러면: 장치의 JST 탭에 바인딩이 표시됩니다.

전에 G-Rebels에서 버튼을 바인딩한 적이 있나요? 그러면 시작 페이지에 가져온 후 빈 곳 채우기가 나타납니다. 기존 바인딩은 그대로 두고, 비어 있는 버튼에만 새 역할이 주어집니다. 빠른 시작: 내 스틱 작동시키기를 참조하세요.

#JoyPro가 G-Rebels에서 하는 일

  • 가져오기: 모든 채널의 축 역할(어느 스틱 축이 피치, 롤, 요, 추력, 측면 이동, 상승 / 하강인지)이 반전과 함께, 그리고 JoyPro가 아는 버튼 바인딩이 실제 장치에 연결된 상태로 프로필에 들어옵니다.
  • 관계: G-Rebels의 "Pitch"는 다른 게임의 피치와 같은 관계가 될 수 있습니다.
  • 내보내기: JoyPro는 장치의 채널에 축 역할과 버튼 바인딩을 설정합니다. 채널이나 장치를 추가하지는 않습니다. 그 부분은 게임에서 한 번 직접 하세요.

#G-Rebels 바인딩 가져오기

  1. 시작을 여세요. G-Rebels 카드가 명령 목록을 요청하면 목록 생성을 누르세요. JoyPro가 게임의 축 역할과 버튼을 담은 자체 표를 씁니다.
  2. G-Rebels 카드에서 가져오기를 누르고, **내 프로필에 추가 (권장)**를 그대로 둔 채 지금 가져오기를 누르세요.
  3. 내 관계 보기를 누르면 들어온 내용이 열립니다.

#관계 만들기와 확인

관계 페이지에서 관계를 G-Rebels 동작에 바인딩한 다음(관계 흐름 참조), 내보내기 페이지에서 확인을 실행하세요. G-Rebels는 축마다 역할 하나, 동작과 채널마다 버튼 하나만 허용합니다. 확인 기능은 관계 두 개가 같은 입력을 원하는 곳을 보여 줍니다.

#G-Rebels로 내보내기

  1. G-Rebels를 닫으세요. 게임이 실행 중이면 JoyPro는 쓰기를 거부합니다.
  2. 내보내기를 열고 G-Rebels 카드를 체크하세요.
  3. JoyPro에서 스틱을 설정한다면 내 장치에서 교체와 다른 장치도 지우기를 그대로 두세요. 카드의 지금 내보내기를 누르세요.
게임에서: G-Rebels에서 보이는 것

OPTIONS > INPUT > CONTROLS와 장치의 JST<channel> 탭(채널 0이면 JST0)을 여세요. AXIS 아래에서 각 조이스틱 축(X, Y, Z, RX, RY, RZ, Slider, Dial)에 JoyPro가 설정한 역할(YAW, THRUST, ROLL, PITCH, SIDE STRAFE, UP / DOWN 또는 NONE)이 표시됩니다. BUTTONS 아래에서는 바인딩된 동작에 버튼이 표시됩니다. 예: "Enhanced Raw Input Controller 0 Button 5".

#G-Rebels에서 직접 해야 할 일

첫 내보내기 전에 장치마다 한 번씩 하세요.

  1. 장치 켜기: OPTIONS > INPUT > DEVICES에 모든 조이스틱이 DEACTIVATED로 표시됩니다. 사용할 장치마다 채널(0 - CHANNEL ... 5 - CHANNEL)을 주세요. 채널이 없는 장치는 내보내기에서 "OPTIONS > INPUT > DEVICES에서 켜세요"라는 메시지와 함께 건너뜁니다.
  2. 장치의 JST 탭에서 축 역할 하나를 바꾸세요. 그래야 게임이 그 채널의 축 행을 저장합니다. JoyPro는 이를 그 자리에서 바꿀 뿐 새로 추가하지 않습니다. 탭을 열기만 해서는 아무것도 저장되지 않습니다.
  3. 게임에서 버튼 하나를 바인딩하세요(한 번). 첫 바인딩과 함께 버튼 파일이 생깁니다.

#자주 하는 실수

  • 축 역할이 기록되지 않음: 채널에 아직 저장된 축 행이 없습니다. 게임에서 그 채널의 JST 탭에서 축 역할 하나를 바꾸고, 게임을 닫은 뒤 다시 내보내세요.
  • 버튼 바인딩이 빠짐: 지금까지 게임 버튼 중 확인된 것은 Primary Fire뿐입니다. 다른 동작은 이름이 알려지면 추가됩니다.
  • 여러 raw input 장치가 키를 공유함: 가상 조이스틱으로 HOTAS 전체를 장치 하나에 넣으세요. 그러면 채널 하나만 필요합니다.
고급

#JoyPro가 읽고 쓰는 파일

파일 설명
%LOCALAPPDATA%\G_Rebels\Saved\SaveGames\SaveOptions.sav 채널이 있는 장치(HID 경로로 구분)와 모든 채널의 축마다 축 행 하나: 역할, 반전, 데드존, 배율
%LOCALAPPDATA%\G_Rebels\Saved\SaveGames\EnhancedInputUserSettings.sav 버튼 바인딩. 동작과 채널마다 매핑 하나
...\SaveOptions.sav.joypro-meta.json 내보낸 바인딩의 JoyPro 데이터(이름, 그룹). 다음 가져오기에서 다시 읽음

두 세이브 파일 모두 처음 쓰기 전에 백업됩니다(옆의 .jpbak와 JoyPro의 백업 저장소).

#G-Rebels의 내보내기 모드

축마다 역할 하나, 동작과 채널마다 키 하나. 축 역할과 버튼에 같은 규칙이 적용됩니다.

모드 일어나는 일
추가만 역할은 역할이 없는 축에만 들어갑니다. 다른 역할이 있는 축은 건너뛰고 "게임에 기록되지 않음" 표시가 붙습니다.
업데이트, 게임의 바인딩 유지 프로필의 역할이 그 축에 들어갑니다(거기 있던 역할은 빠짐). 그 역할은 다른 축에도 남습니다. 버튼: 그 키에 있던 다른 동작의 매핑이 빠집니다.
업데이트, 내 프로필 우선 위와 같고, 연결된 채널에 있는 그 역할의 다른 축은 NONE이 됩니다.
내 장치에서 교체 쓰는 채널의 다른 모든 역할이 NONE이 됩니다.
+ 다른 장치도 지우기 JoyPro가 쓰지 않는, 켜져 있고 연결된 채널도 마찬가지입니다.

#절대 건드리지 않는 것

  • 키보드, 게임패드, 마우스, 게임의 다른 옵션.
  • 장치가 연결되지 않은 채널은 역할을 유지합니다.
  • 가져오기에서 무시한 장치와 JoyPro가 입력을 보내는 vJoy 장치.
  • 게임의 장치 목록: JoyPro는 장치를 절대 켜거나 끄지 않고, 채널을 절대 추가하지 않습니다.

#축과 기타 설정

  • 전체 공통: 채널마다 바인딩 한 세트, 기체 프로필 없음.
  • 반전은 역할과 함께 씁니다. 햇(POV 행), 데드존, 감도는 아직 쓰지 않습니다.
  • 게임 전체 설정도 포스 피드백도 없습니다.
  • 감시 기능: 게임에서 바꾼 역할이나 바인딩은 게임이 종료된 뒤 감지됩니다(감시 기능).
  • HUD: G-Rebels가 실행되는 동안 HUD가 누른 버튼마다 그 동작의 이름을 보여 줍니다.
  • 게임은 장치마다 버튼 최대 96개와 축 24개를 읽으며, 햇은 읽지 않습니다.
기술 정보

#G-Rebels 연동의 내부

코드: engine\Games\GRebelsIntegration.cs, engine\Games\GRebelsSaveOptions.cs, engine\Games\GvasKeyMappings.cs.

  • SaveOptions.sav: Unreal GVAS(UE 5.8, 타입 트리가 있는 속성 태그). Joysticks에는 S_Controller_Save { DeviceID (HID path), Enabled, MultiID (channel) }가, AxisOptions에는 S_Input_Axis_Save { Key, Offset, Multiplier, Role, Inverted, DeadZone }가 들어 있습니다. 키는 RawInput_Controller0_AxisY 같은 형태이고, 역할은 열거형입니다(0 Yaw, 1 Thrust, 2 Roll, 3 Pitch, 4 Side strafe, 5 Up/down, 6 None). 체크섬이 없으므로 JoyPro는 고정 크기 값을 제자리에서 편집합니다.
  • EnhancedInputUserSettings.sav: Unreal Enhanced Input의 플레이어 지정 키. 매핑 이름은 <ACTION>JST<channel>(PRIMARYFIREJST0), 키는 RawInput_Controller<channel>_Button<n>이며 n은 DirectInput 버튼 번호입니다. 매핑 목록은 다시 쓰이고, 나머지 바이트는 모두 그대로 남습니다.
  • 장치: HID 경로로, 게임이 지정한 채널과 맞춥니다.
  • 명령 목록: JoyPro 자체 표(DB\GRebels\actions.tsv, 축 역할과 버튼. 게임 파일은 읽지 않음). engine grebels refresh-db가 이를 게임 데이터 폴더에 쓰며, 이미 있는 행은 기존 항목을 유지합니다.
  • 명령: engine grebels paths, engine grebels catalog, engine grebels scan, engine grebels import, engine grebels export --mode clean|add|merge|merge-overwrite --nuke-untouched-devices --dry-run.

#알려진 한계

  • 햇, 데드존, 감도는 쓰지 않습니다.
  • 버튼 중에서는 Primary Fire만 게임에서 확인되었습니다.
  • 항목은 절대 추가하지 않습니다. 채널, 축 행, 버튼 파일은 게임이 만들어 두어야 합니다.
  • 테스트: engine\tests\smoke\grebels.ps1. 게임 안에서는 tools\e2e\games\GRebelsSettings.ps1(두 번 시작: 첫 번째는 vJoy에 채널을 주고 축 행을 저장하며, 두 번째는 JST0에서 무작위 역할과 Primary Fire를 확인합니다. 저장 폴더는 끝난 뒤 복원됨).

이 게임에 대한 모든 기술 메모(저장소에서 생성됨): g-rebels.md.
