Project Wingman

표시:

Project Wingman은 Unreal Engine 4 기반의 아케이드 공중전 게임입니다. 여러 DirectInput 장치를 동시에 읽고, 바인딩은 일반 텍스트 Input.ini에 저장하며, 각 바인딩에는 장치 이름과 게임 장치 목록에서의 순서가 붙습니다. 곡선과 데드존은 세이브 게임에 들어 있습니다. JoyPro는 둘 다 프로필로 읽어 오고 다시 써넣습니다. 키보드, 마우스, 게임패드, 햇은 게임에 있는 그대로 둡니다.

    Project Wingman은 닫아 두세요

시작 전: 게임을 한 번 실행한 뒤 닫으세요. 이 게임의 Steam Input을 끄세요.

그다음: 바인딩이 게임의 Controls에 있습니다. 컨트롤러를 추가하거나 뺐나요? 다시 내보내세요.

전에 Project Wingman에서 버튼을 바인딩했나요? 그렇다면 시작 페이지에서 가져온 후 빈 곳 채우기를 제안합니다. 기존 바인딩은 그대로 두고, 비어 있는 버튼에만 새 기능을 줍니다. 빠른 시작: 내 스틱 작동시키기를 참고하세요.

#JoyPro가 Project Wingman에 해 주는 일

  • 가져오기: 비행 동작(피치, 롤, 요, 추력, 시점 축 두 개, 버튼)의 모든 조이스틱 바인딩이 반전, 곡선, 데드존과 함께 실제 장치 기준으로 프로필에 들어옵니다.
  • 관계: Project Wingman의 "Fire missile"을 다른 게임의 무장 투하와 같은 관계로 만들 수 있습니다.
  • 내보내기: JoyPro가 바인딩은 Input.ini에, 곡선과 데드존은 세이브 게임에 써넣습니다.

#Project Wingman 바인딩 가져오기

  1. 게임을 한 번도 실행하지 않았다면 한 번 실행해서 게임 폴더가 생기게 하세요.
  2. 시작을 여세요. Project Wingman 카드에서 명령 목록을 요청하면 목록 생성을 누르세요. JoyPro가 게임 자체 파일에서 비행 동작을 읽어 옵니다.
  3. 카드에서 가져오기를 누르고, **내 프로필에 추가 (권장)**를 그대로 둔 채 지금 가져오기를 누르세요.

#관계 만들기와 확인

관계 페이지에서 Project Wingman 동작을 다른 게임과 연결하세요(관계 흐름). 그런 다음 내보내기 페이지에서 확인을 실행하세요. 게임에서 버튼 하나가 두 가지 일을 하는 경우를 찾아 줍니다.

#Project Wingman으로 내보내기

  1. Project Wingman을 닫으세요. 게임이 실행 중이면 JoyPro는 써넣기를 거부합니다.
  2. 내보내기를 열고 Project Wingman 카드를 체크하세요.
  3. 내 장치에서 교체와 다른 장치도 지우기를 그대로 두거나, 게임에서도 바인딩한다면 업데이트, 게임의 바인딩 유지를 고르세요. 카드에서 지금 내보내기를 누르세요.
게임에서: Project Wingman에서 보이는 것

게임의 Controls를 여세요. KEY BINDINGS와 AXIS BINDINGS에는 각 줄의 다음 빈 슬롯에 바인딩이 표시되며, 이름은 공백을 뺀 장치 이름과 번호로 붙습니다(예: "VJOYDEVICE 8 BUTTON 24" 또는 "VJOYDEVICE 8 AXIS 1"). 반전한 곳에는 Invert 상자가 체크되어 있습니다. CURVES + DEADZONES에는 JoyPro가 각 축에 써넣은 CURVE와 DEADZONE이 표시됩니다.

#Project Wingman에서 직접 할 일

  • 컨트롤러를 추가하거나 뺀 뒤에는 다시 내보내세요. 게임은 장치 목록에서의 순서로 장치 번호를 매기는데, 이 순서는 컨트롤러를 연결하거나 뺄 때 바뀝니다. JoyPro는 내보낼 때 연결된 장치를 기준으로 번호를 계산합니다.
  • 햇: 이 게임은 햇을 바인딩할 수 없습니다. Controls > Miscellaneous에서 Hat Function 1 / 2(WEAPON 또는 VIEW)를 설정하세요.
  • 이 게임의 Steam Input을 끄세요. Steam Input 패드가 추가 장치로 나타납니다.

#자주 하는 실수

  • 바인딩이 엉뚱한 장치를 가리킴: 내보낸 뒤 컨트롤러를 추가하거나 뺐습니다. 평소 쓰는 장치를 연결한 상태로 다시 내보내세요. 장치 번호가 바뀌면 가져오기에서 경고합니다.
  • 햇 바인딩이 거부됨: 의도된 동작입니다. 위의 Hat Function을 참고하세요.
  • 스로틀 아래쪽 절반에서 브레이크가 걸림: Project Wingman의 "Thrust Axis"는 중앙 기준 축입니다. 중앙보다 위에서는 가속하고, 아래에서는 브레이크를 겁니다.

#JoyPro가 읽고 쓰는 파일

파일 설명
%LOCALAPPDATA%\ProjectWingman\Saved\Config\WindowsNoEditor\Input.ini 바인딩. [/Script/Engine.InputSettings] 섹션의 ActionMappings=(...)와 AxisMappings=(...) 줄
%LOCALAPPDATA%\ProjectWingman\Saved\SaveGames\savegame.sav 축 동작마다 곡선과 데드존(<Axis>Curve, <Axis>Deadzone), 햇 기능
<install>\ProjectWingman\Content\Paks\pakchunk0-WindowsNoEditor.pak 읽기 전용: DefaultInput.ini, 게임의 기본 바인딩과 동작 목록
...\Input.ini.joypro-meta.json 내보낸 바인딩에 대한 JoyPro의 데이터(이름, 그룹, 튜닝), 다음 가져오기용

게임은 메뉴에서 바인딩이 바뀌는 순간 Input.ini를 쓰며, 바꾼 목록만 씁니다. 나머지는 pak의 기본값에서 옵니다. 쓰인 목록이 기본값을 대신하므로, JoyPro는 빠진 목록의 기본값을 먼저 씁니다. Steam Cloud가 저장 폴더를 동기화합니다.

#Project Wingman의 내보내기 모드

카탈로그에 있는 비행 동작의 조이스틱 매핑만 지웁니다. 키보드, 게임패드, 마우스, 메뉴 줄, 연결되지 않은 장치는 그대로 남습니다.

모드 일어나는 일
추가만 게임이 다른 비행 동작에 쓰는 입력에 대한 바인딩은 쓰지 않습니다("게임에 기록되지 않음"으로 표시). 바인딩의 게임 고유 형태(Invert)는 유지됩니다.
업데이트, 게임의 바인딩 유지 추가로, 프로필이 다른 동작에 주는 입력에 있는 게임 매핑도 지웁니다. 그 동작의 다른 매핑은 유지됩니다.
업데이트, 내 프로필 우선 추가로, 프로필이 바인딩하는 모든 동작의 다른 조이스틱 매핑도 지우므로, 옮긴 바인딩이 완전히 옮겨집니다.
내 장치에서 교체 내보낸 장치는 다른 조이스틱 매핑을 잃습니다(비행 전용 게임).
+ 다른 장치도 지우기 연결된 다른 장치에서도 마찬가지입니다.

#절대 건드리지 않는 것

  • 키보드, 마우스, 게임패드 매핑, 메뉴 줄, 햇.
  • 연결되지 않은 장치, 가져오기에서 무시한 장치, JoyPro가 입력을 보내는 vJoy 장치.
  • Input.ini의 다른 모든 줄(순서와 줄 끝 유지)과 savegame.sav의 다른 모든 바이트.

#곡선, 데드존, 기타 설정

  • 축 동작마다, 모든 장치 공통: 피치, 롤, 추력, 요, 두 시점 축에 대한 CURVE(메뉴의 0.00~2.00, 1.00 = 직선)와 DEADZONE(0~100 %). 게임 기본값: 피치와 롤 25 %, 시점 10 %, 추력과 요 0 %.
  • 바인딩마다 반전(슬롯의 Invert 상자).
  • 게임의 공식은 알려져 있지 않습니다. JoyPro의 미리보기는 재조정된 데드존과 지수로서의 곡선을 가정합니다(아직 확인되지 않음).
  • 전역: 기체별 프로필이 없습니다. 수정키 없음(게임에 없음), 포스 피드백 없음.
  • 감시 기능: 게임이 종료된 뒤 Input.ini와 savegame.sav를 감시합니다(감시 기능).
  • HUD: 게임이 실행되는 동안 HUD가 누른 버튼마다 그 동작의 이름을 보여 줍니다.
기술 정보

#Project Wingman 연동의 내부

코드: engine\Games\ProjectWingmanIntegration.cs, engine\Games\ProjectWingmanSaveGame.cs, engine\AxisModels\ProjectWingman.cs(축 모델 projectwingman).

  • 키: Joystick_<name>_<place>_Axis<n>, ..._Button<n>. <name>은 공백을 뺀 DirectInput 제품 이름이며(VPforce Rhino FFB Joystick은 VPforceRhinoFFBJoystick이 됨), HID 문자열이 아닙니다. <place>는 게임 목록(Controls > Miscellaneous)에서 장치의 위치로, DirectInput 순서를 뒤집은 것입니다. XInput 패드는 그 목록에 없습니다. Axis<n>은 장치에 있는 축을 X Y Z Rx Ry Rz Slider Slider 순서로 0부터 셉니다. Button<n>은 0부터 셉니다. 이름에 쉼표가 있는 키는 따옴표로 묶습니다.
  • 반전 = Scale=-1.000000.
  • 기본값: pak 기본값의 Android_* 키는 유지합니다. 메뉴는 매핑마다 슬롯 하나를 보여 주는데, 이 키들이 빈 슬롯이기 때문입니다.
  • savegame.sav: Unreal GVAS. FloatProperty <Axis>Curve(메뉴 값의 절반)와 <Axis>Deadzone(0..1)을 제자리에서 수정하거나, 닫는 None 앞에 추가합니다. 체크섬 없음.
  • 명령 목록: engine pw refresh-db는 pak의 DefaultInput.ini와 사용자의 Input.ini를 읽습니다: 축 6개와 버튼 14개.
  • 명령: engine pw paths, engine pw catalog, engine pw scan, engine pw import, engine pw export --mode clean|add|merge|merge-overwrite --nuke-untouched-devices --dry-run.
