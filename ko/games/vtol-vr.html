게임

VTOL VR

표시:

VTOL VR은 VR 전용 전투 비행 게임으로, VR 컨트롤러로 가상 스틱과 스로틀을 잡고 비행합니다. 게임 자체는 실제 장치의 축 세 개(러더와 토 브레이크 두 개)만 바인딩하며, 이를 모든 기체 공통 파일 하나에 저장합니다. 완전한 HOTAS 지원(스틱, 스로틀, 모든 스위치, 기체와 좌석별)은 무료 BYOJoystick 모드가 제공합니다. JoyPro는 이 둘을 별개의 게임 두 개로 다룹니다. **VTOL VR (BYOJoystick mod)**는 모드의 바인딩 파일을 쓰고, **VTOL VR (native rudder and brakes)**는 게임 자체 파일과 조작 설정을 씁니다.

#3단계로 바로 사용하기

  1. 모두 알아서 설정
    시작 페이지에서
  2. 이 버튼 사용
    먼저 목록을 확인
  3. 내 게임에 쓰기
    VTOL VR은 닫아 두세요

시작 전: VTOL VR 카드에서 BYOJoystick 설치를 누르세요(한 번만, 아래 참고). 페달을 연결한 상태로 VTOL VR을 한 번 실행하고 Settings에서 OK로 나오세요.

그다음: 게임 설정에서 Hardware Control Rudder를 켜세요. 켜지 않으면 게임이 러더를 무시합니다.

전에 VTOL VR에서 버튼을 바인딩했나요? 그렇다면 시작 페이지에서 가져온 후 빈 곳 채우기를 제안합니다. 기존 바인딩은 그대로 두고, 비어 있는 버튼에만 새 기능을 줍니다. 빠른 시작: 내 스틱 작동시키기를 참고하세요.

#JoyPro가 VTOL VR에 해 주는 일

  • BYOJoystick 사용 시: 모드가 제공하는 모든 대상(스틱 및 스로틀 축, 랜딩 기어, 플랩, 무장, 대응 수단, 레이더, 조명, MFD 버튼 등)을 각 기체와 좌석별로 스틱, 스로틀, 키보드에서 바인딩합니다.
  • 모드 없이: 게임 자체의 Rudder, Wheel Brake L, Wheel Brake R과 Controls 메뉴의 설정(Hardware Control Rudder, VR 데드존, 햅틱).
  • 관계: 관계 하나는 하나의 기능입니다. BYOJoystick 내보내기는 그 대상이 있는 기체의 모든 좌석 파일에 관계를 써넣습니다.

#BYOJoystick 설치(한 번만)

  1. 시작을 열고 VTOL VR 카드에서 BYOJoystick 설치를 누르세요. 모드가 무엇인지, 공식 출처(Steam Workshop, GitHub의 소스 코드), 크기, 그리고 VTOL VR Mod Loader와 모드가 이 PC에 있는지를 보여 주는 패널이 열립니다.
  2. BYOJoystick이 무엇인지 읽었고 Steam Workshop에서 설치하겠다는 상자를 체크한 다음 BYOJoystick 설치를 누르세요. JoyPro가 BYOJ 파일을 백업하고 Steam을 엽니다. Steam이 요청하면 Mod Loader를 설치한 뒤 BYO Joystick 페이지에서 Subscribe를 누르세요. 모드는 Steam이 내려받으며, JoyPro는 모드의 어떤 파일도 복사하지 않습니다.
  3. 다시 확인을 누르세요. JoyPro가 모드를 찾아서 그것으로 VTOL VR 명령 목록을 만듭니다.

#바인딩 가져오기

VTOL VR 카드(BYOJoystick)나 기본 기능 쪽 카드에서 가져오기를 누른 다음 지금 가져오기를 누르세요. BYOJoystick의 경우 키보드 키도 가져오기를 체크하면 키보드 바인딩도 함께 가져옵니다.

#관계 만들기와 확인

다른 게임과 마찬가지로 관계를 만드세요(관계 흐름). 설정 마법사와 자동 할당은 BYOJoystick 대상을 알고 있습니다. 그런 다음 내보내기 페이지에서 확인을 실행하세요.

#VTOL VR로 내보내기

  1. VTOL VR을 닫으세요. 게임이 실행 중(프로세스 VTOLVR)이면 JoyPro는 써넣기를 거부합니다.
  2. 내보내기를 열고, JoyPro에서 장치를 설정한다면 내 장치에서 교체와 다른 장치도 지우기를 그대로 두세요.
  3. VTOL VR 카드(BYOJoystick)에서, 그리고 페달은 기본 기능 카드에서 지금 내보내기를 누르세요.
게임에서: VTOL VR에서 보이는 것

게임에서 프로필이 켜도록 설정했다면 Settings에 Hardware Control Rudder가 켜진 것으로 표시되고, Bindings에는 Rudder, Wheel Brake L, Wheel Brake R이 장치 및 축과 함께 표시됩니다. BYOJoystick 바인딩은 모드 자체 창에 기체 좌석별로 있으며, 그 창의 Load를 누르면 파일을 다시 읽습니다.

#VTOL VR에서 직접 할 일

  • 페달을 연결한 상태로 VTOL VR을 한 번 실행하고 Settings에서 OK로 나오세요. 그러면 게임이 장치 목록을 만들고 gameSettings.cfg를 생성합니다. 기본 기능 내보내기는 게임이 목록에 올린 장치만 써넣으며, 설정 파일을 직접 만들지는 않습니다.
  • Hardware Control Rudder가 켜져 있어야 합니다. 꺼져 있으면 게임이 러더와 브레이크 축을 무시합니다. 게임에서 켜거나, JoyPro(고급)에 저장해 두면 기본 기능 내보내기가 써넣습니다.
  • BYOJoystick에는 Steam의 VTOL VR Mod Loader가 필요합니다. JoyPro는 Steam 페이지를 열어 주기만 합니다.

#자주 하는 실수

  • 러더가 작동하지 않음: Hardware Control Rudder가 꺼져 있습니다. 게임은 기체가 생성될 때 이 설정을 읽습니다.
  • 토 브레이크가 하나만 작동하거나, 둘 다 스로틀 트리거를 따라감: 게임은 Wheel Brake L이 바인딩되어 있을 때만 페달에서 브레이크를 받습니다. 둘 다 바인딩하세요.
  • 토 브레이크가 움직임의 뒤쪽 절반에서만 걸림: 게임은 브레이크를 0~1로 읽습니다. 그 관계의 축 범위를 Positive(양수)로 설정하세요(고급). JoyPro가 이 경우를 경고합니다.
  • 똑같은 페달 두 개: 게임은 장치 모델마다 맵을 하나만 두므로, 두 페달이 같은 동작을 움직입니다.
  • BYOJoystick 바인딩이 사라짐: 모드는 파일을 불러올 때 해당 기체에 없는 대상을 버립니다.

#JoyPro가 읽고 쓰는 파일

파일 설명
<install>\SaveData\BYOJ_<seat>.xml 기체 좌석 하나의 BYOJoystick 바인딩: AV42C, FA26B, F45A, AH94Front, AH94Rear, T55Front, T55Rear, EF24GFront, EF24GRear
%APPDATA%\Boundless Dynamics, LLC\VTOLVR\SaveData\inputbindings.cfg 게임 자체 바인딩: 텍스트 파일 안의 Rewired 조이스틱 맵. Steam Cloud가 동기화함
%APPDATA%\Boundless Dynamics, LLC\VTOLVR\SaveData\gameSettings.cfg Settings > Controls 값(HARDWARE_RUDDER, ...). Steam Cloud가 동기화함
<library>\steamapps\workshop\content\3018410\3276352374\BYOJoystick.dll 설치된 모드: 대상 목록용으로 읽기만 함
<install>\VTOLVR_Data\level0 게임의 Rewired 동작 목록: 기본 게임 명령 목록용으로 읽기만 함

예전 파일 <install>\SaveData\inputbindings.cfg는 절대 쓰지 않습니다. 모든 쓰기는 먼저 백업한 다음 원자적으로(임시 파일 후 교체) 이루어집니다. 게임은 손상된 inputbindings.cfg를 빈 파일로 바꿔 버리기 때문입니다.

#VTOL VR의 내보내기 모드

모드 BYOJoystick(좌석별 파일) 기본 게임(inputbindings.cfg)
추가만 좌석의 바인딩을 덮어쓰지 않습니다. 다른 대상이 (같은 수정키 상태로) 쓰는 입력에 대한 바인딩은 쓰지 않은 것으로 표시됩니다. 빈 축만 씁니다. 이미 쓰이는 축은 쓰지 않은 것으로 표시됩니다.
업데이트, 게임의 바인딩 유지 사용자의 입력에 있던 다른 대상은 그 입력을 잃습니다. 나머지는 모두 유지되며, 옮긴 대상의 이전 입력도 남습니다. 사용자의 축에 있던 동작이 교체됩니다. 나머지는 모두 유지됩니다.
업데이트, 내 프로필 우선 위와 같으며, 추가로 사용자의 대상은 연결된 장치에서 다른 입력을 잃습니다(키는 키보드 옵션을 켰을 때만). 위와 같으며, 추가로 사용자의 동작은 연결된 장치에서 다른 축을 잃습니다.
내 장치에서 교체 JoyPro가 쓰는 장치에는 사용자의 바인딩만 남습니다. 쓴 장치의 다른 동작은 지워집니다.
+ 다른 장치도 지우기 바인딩이 없는 연결된 장치는 비워집니다. 바인딩이 없는 연결된 장치는 비워집니다.

#절대 건드리지 않는 것

  • 연결되지 않은 장치, 가져오기에서 무시한 장치, JoyPro가 입력을 보내는 vJoy 장치.
  • BYOJoystick: JoyPro가 읽을 수 없는 입력, 그리고 프로필에 자체 수정키 버튼이 없는 한 좌석의 수정키 버튼.
  • 기본 게임: 버튼 맵, 키보드와 마우스 맵, 입력 동작 방식, 보정 맵, 컨트롤러 할당, System 플레이어. BYOJoystick 내보내기는 gameSettings.cfg를 쓰지 않습니다.
  • 키보드 바인딩을 내보내지 않는 한 키보드(BYOJoystick만 해당).

#좌석, 축, 설정

  • 적용 범위: BYOJoystick은 기체 좌석마다(대상은 그 대상이 있는 모든 좌석에 들어감), 기본 게임 부분은 전역입니다.
  • BYOJoystick 축: 반전과, 바인딩마다 모드의 데드존 숫자 하나. Joystick Pitch, Roll, Yaw와 Throttle, Power, Collective에서는 이것이 데드존이 아니라, 멀티플레이에서 다른 승무원에게서 조종을 넘겨받는 데 HOTAS가 필요로 하는 움직임의 크기입니다. SOI Slew X/Y와 Articulate Tilt에서는 재조정 없이 작은 값을 잘라 냅니다. 그 밖에서는 모드가 이 값을 쓰지 않습니다. 곡선은 없습니다. axis-curves를 참고하세요.
  • 기본 게임 축: 반전, 그리고 토 브레이크의 축 범위(Full 또는 Positive). 데드존과 곡선은 쓸 수 없습니다.
  • 수정키: BYOJoystick은 좌석 파일마다 수정키 버튼 하나를 압니다(이를 필요로 하는 바인딩은 누르고 있는 동안에만 작동). 키보드 바인딩에는 수정 키 하나를 둘 수 있습니다. 기본 게임 부분에는 수정키가 없습니다.
  • 조작 설정: 설정 > 게임의 포스 피드백 설정에서 게임 VTOL VR (control settings, VR haptics): Hardware Control Rudder, Thumb Control Rudder, Twist Rudder Deadzone, Thumbstick Deadzone, Thumbstick Mode, Toggle Grip, Flight Control Haptics, Overall Haptics. 기본 게임 내보내기는 이 값들을 gameSettings.cfg에 쓰며, 프로필에 기본 게임 바인딩이 없어도 씁니다.
  • 포스 피드백: VTOL VR에는 조이스틱 포스 피드백이 없습니다. 햅틱은 VR 컨트롤러의 것입니다.
  • 감시 기능: BYOJ 파일, 그리고 기본 게임 부분이 있으면 gameSettings.cfg(감시 기능).
기술 정보

#VTOL VR 연동의 내부

코드: engine\Games\VtolVrIntegration.cs(BYOJoystick), VtolVrMod.cs(설치 상태, 대상 목록), ClrMetadata.cs, VtolVrNativeIntegration.cs, engine\AxisModels\VtolVr.cs(byoj, vtolnative), engine\FfbModels\VtolVr.cs(조작 설정).

  • BYOJoystick 형식: .NET XML 직렬화. 루트 <Bindings> 아래에 <KeyboardBindings>(Target, Key, ModifierKey는 Unity KeyCode 이름)와 <JoystickBindings>(Target, JoystickId, Input, RequiresModifier, Invert, Deadzone, POVDirection)가 있습니다. Input: X Y Z RX RY RZ, S1 S2, PoV1..PoV4, B1..B128. 장치는 DirectInput 인스턴스 GUID(JoystickId)로 지정합니다.
  • 기본 게임 형식: 루트 RewiredSaveData와 {key} = {value} 줄로 된 텍스트 파일. 조이스틱 맵은 Rewired XML입니다(UTF-8 파일 안에서 UTF-16으로 선언됨). 동작: 0 Rudder, 5 Wheel Brake L, 6 Wheel Brake R. 맵의 키는 장치 모델입니다: hardwareIdentifier = WindowsRawInput + 공백을 뺀 HID 제품 문자열 + 10진수 PID + 제품 GUID. Rewired가 모르는 장치는 hardwareGuid가 0입니다. 요소는 장치의 n번째 축입니다.
  • 명령 목록: engine vtolvr refresh-db는 설치된 BYOJoystick.dll을 로드하거나 실행하지 않고 대상을 읽은 다음(메타데이터와 문자열 리터럴), 사용자의 BYOJ_*.xml을 읽습니다. 모드가 없으면 목록도 없습니다. engine vtolvr-native refresh-db는 level0에서 Rewired 동작 목록을 읽습니다.
  • 명령: engine vtolvr mod(status, prepare --accept-license), engine vtolvr scan, engine vtolvr import, engine vtolvr export, engine vtolvr-native scan, engine vtolvr-native import, engine vtolvr-native export, 설정은 engine ffb set --device * --game VTOLVR.

#알려진 한계

  • 아직 게임 안에서 실행해 보지 않았습니다. BYOJoystick은 대체 DLL로 테스트했습니다. 현재 게임 버전에서 모드가 로드되는지는 아직 확인되지 않았습니다.
  • 기본 게임: Rewired가 모르는 장치의 축 순서와 정확한 장치 식별자는 게임 코드에서 가져온 것이며, 아직 게임이 쓴 파일에서 확인하지 않았습니다.
  • BYOJoystick: 햇 대각선, 축 대상에 할당한 버튼, 버튼 대상에 할당한 축은 경고와 함께 건너뜁니다.
  • JoyPro는 BYOJoystick의 어떤 부분도 포함하지 않습니다. 명령 목록은 모드가 설치되어 있을 때만 있습니다.
  • 테스트: engine\tests\smoke\vtolvr.ps1(가져오기 왕복, 자체 값, 게임 전체 설정, 설정만 내보내기).
