Falcon BMS

표시:

Falcon BMS 4.38은 런처에서 장치를 설정합니다. 런처는 장치마다 XML 파일을 하나씩 보관하고, Launch를 누를 때마다 이 파일들로 키 파일과 축 설정을 만듭니다. JoyPro는 바로 이 런처 장치 파일을 쓰므로 런처가 계속 주도합니다. 런처가 JoyPro의 바인딩을, 마치 런처에서 직접 만든 것처럼 BMS가 읽는 파일로 바꿉니다. Falcon 4.0과 Allied Force는 지원하지 않습니다. Falcon BMS를 사용하세요.

Falcon BMS 기본(게임 자체 바인딩 파일)
지원
기본(게임 자체 바인딩 파일)
엔진 명령
engine bms
바인딩 파일
<BMS>\User\Config\Setup.v100.<device> {GUID}.xml(런처 XML) + User.cfg, Feedback.ini, .pop
게임이 읽는 입력
조이스틱 하나당 버튼 128개, 축 8개, 햇 2개를 읽음(문서 기준)
명령 목록 출처
BMS - Full.key

  • ◐ 수정키Falcon BMS: DX 시프트 레이어는 하나뿐이며 축에는 수정키를 쓸 수 없습니다.

#3단계로 바로 사용하기

  1. 모두 알아서 설정
    시작 페이지에서
  2. 이 버튼 사용
    먼저 목록을 확인
  3. 내 게임에 쓰기
    BMS와 런처는 닫아 둔 채로

먼저: BMS와 런처를 닫으세요.

그다음: 런처를 시작하고 Launch를 누르세요. 그때서야 런처가 BMS가 읽는 파일을 만듭니다.

전에 Falcon BMS에서 버튼을 바인딩한 적이 있나요? 그러면 시작 페이지에 가져온 후 빈 곳 채우기가 나타납니다. 기존 바인딩은 그대로 두고, 비어 있는 버튼에만 새 역할이 주어집니다. 빠른 시작: 내 스틱 작동시키기를 참조하세요.

#JoyPro가 Falcon BMS에서 하는 일

  • 가져오기: 장치의 버튼, 햇, 축이 런처의 장치 파일에서 들어옵니다. 시프트 레이어는 수정키로, 축마다의 반전, 데드존, 포화 단계도 함께 들어옵니다.
  • 관계: 관계 하나는 모든 게임에서 하나의 기능입니다(BMS, DCS, IL-2의 "Gear"가 같은 버튼에). 명령은 BMS - Full.key에 있는 BMS의 콜백입니다.
  • 내보내기: JoyPro가 런처의 장치 파일을 씁니다. 다음에 Launch를 누르면 런처가 이 파일들로 키 파일과 축 설정을 만듭니다.

#BMS 바인딩 가져오기

  1. 시작을 여세요. Falcon BMS 카드에 게임 이미지가 보입니다. 명령 목록을 요청하면 목록 생성을 누르세요. JoyPro가 설치된 BMS - Full.key의 콜백을 읽습니다.
  2. 카드에서 가져오기를 누르고 내 프로필에 추가를 고르세요(키보드 키는 BMS의 키 파일에 남으므로 키보드 확인란은 여기서 해당하지 않습니다).
  3. 지금 가져오기를 누르세요. 내 관계 보기를 누르면 들어온 내용이 열립니다.

#관계 만들기와 확인

관계 페이지에서 관계의 BMS 콜백은 다른 게임의 같은 기능 옆에 놓입니다. 관계 흐름으로 이를 묶은 다음, 내보내기 페이지에서 지금 확인을 누르세요(확인).

#Falcon BMS로 내보내기

  1. BMS와 런처를 닫으세요. Falcon BMS.exe 또는 FalconBMS_Alternative_Launcher.exe가 실행 중이면 JoyPro는 거부합니다.
  2. 내보내기를 여세요. Falcon BMS 카드에 관계 중 몇 개가 바인딩되었는지 표시됩니다.
  3. JoyPro에서 장치를 설정한다면 내 장치에서 교체와 다른 장치도 지우기를 그대로 두세요. 카드의 지금 내보내기를 누르세요.
게임에서: Falcon BMS에서 보이는 것

런처를 시작하고 Launch를 누르세요. 런처가 JoyPro의 장치 파일로 키 파일과 축 설정을 만듭니다. 시뮬레이터의 Setup > Controllers > Advanced > Flight Control에서 내보낸 각 축이 JoyPro가 설정한 데드존과 포화 단계와 함께 장치에 표시되며, 버튼과 햇은 프로필대로 작동합니다.

#Falcon BMS에서 직접 해야 할 일

  • 내보낼 때마다 런처에서 Launch를 누르세요. 그때서야 런처가 BMS가 읽는 키 파일, axismapping.dat, joystick.cal, DeviceSorting.txt를 씁니다.
  • "Launch without any Setup override"는 체크하지 마세요. 체크하면 런처가 설정을 쓰지 않습니다.
  • 키보드 키는 BMS가 관리하는 키 파일에 남습니다. 런처에서 설정하세요. JoyPro는 조이스틱 입력만 씁니다.
  • Enable Force Feedback는 파일럿 파일(<callsign>.pop, BMS 4.36 이상의 468바이트 파일)에 기록됩니다. 크기가 다른 파일럿 파일이면 JoyPro는 경고와 함께 이 설정 하나만 건너뜁니다.

#자주 하는 실수

  • "Falcon BMS 실행 중입니다": 시뮬레이터와 런처를 닫고 다시 내보내세요.
  • 수정키 바인딩이 빠짐: BMS에는 모든 장치에 공통인 시프트 레이어가 하나 있으며, SimHotasPinkyShift가 있는 버튼으로 누릅니다. JoyPro는 이 수정키를 쓰는 바인딩을 시프트 슬롯에 쓰고, 다른 수정키는 경고와 함께 건너뜁니다.
  • "추가만"에서 축이 다른 장치에 남음: BMS는 각 기능을 축 하나에만 주며, 추가만은 이를 옮기지 않습니다. 옮기려면 업데이트 모드를 사용하세요.
  • 시뮬레이터에서 바인딩이 바뀌지 않음: 내보낸 뒤 런처를 Launch로 시작하지 않았습니다.
고급

#JoyPro가 읽고 쓰는 파일

파일 설명
<BMS>\User\Config\Setup.v100.<device> {<GUID>}.xml 런처의 장치별 파일: 축, 햇, 버튼, 스로틀 디텐트
<BMS>\User\Config\Falcon BMS User.cfg 곡선 값과 게임 설정. 런처의 표시 줄 위쪽에만
<BMS>\User\Config\Feedback.ini 포스 피드백 효과 게인과 센터링 스프링
<BMS>\User\Config\<callsign>.pop 파일럿 파일: Enable Force Feedback 바이트만
<BMS>\User\Config\JoyPro.joypro.json JoyPro가 쓴 입력

<BMS>는 HKLM\SOFTWARE\WOW6432Node\Benchmark Sims\...\baseDir이나 Falcon BMS* 폴더로 찾습니다. axismapping.dat, joystick.cal, DeviceSorting.txt, 키 파일, User.cfg 안의 런처 블록은 Launch할 때마다 다시 만들어지므로 JoyPro는 절대 쓰지 않습니다. 장치 파일이 없는 연결된 장치는 파일을 받습니다. 그 모델의 런처 기본 파일에서 만들고, 없으면 런처의 형식으로 빈 파일을 만듭니다.

#Falcon BMS의 내보내기 모드

모드 BMS에서 일어나는 일
추가만 빈 슬롯에만 씁니다. 다른 콜백이 있는 슬롯에 걸린 바인딩은 쓰이지 않고 목록에 표시됩니다. BMS가 다른 축에 둔 기능은 거기 그대로 남습니다(경고).
업데이트, 게임의 바인딩 유지 사용자의 슬롯에 있는 콜백(충돌)을 바꾸고 나머지는 모두 유지합니다. 축 기능은 사용자의 축으로 옮겨집니다.
업데이트, 내 프로필 우선 바인딩한 동작이 있는 연결된 장치의 다른 누르기 슬롯, 햇, 축도 풀어 줍니다.
내 장치에서 교체 쓰는 연결된 장치의 나머지를 모두 풀어 줍니다(놓기 슬롯에 있는 목록의 콜백도).
+ 다른 장치도 지우기 내보내기에 바인딩이 없는 연결된 장치는 비워집니다.

#절대 건드리지 않는 것

  • 연결되지 않은 장치의 장치 파일(거기 있는 예전 축 지정은 남으며, 런처는 가장 새 지정을 따릅니다).
  • 가져오기에서 무시한 장치와 JoyPro가 입력을 보내는 vJoy 장치.
  • 키보드 키와 키 파일, 런처가 만드는 파일, User.cfg 안의 런처 블록.

#곡선, 설정, 포스 피드백

  • 단위: 전체 공통, 모든 기체에 설정 하나.
  • 축(축 모델 bms): 반전, 런처의 데드존 단계(None, Small, Medium, Large)와 포화 단계, 데드존 없는 한쪽 방향 축(스로틀, 토 브레이크, 밝기, 볼륨). 피치, 롤, 요, 커서 X/Y에는 User.cfg의 지수 곡선(0~100)과 지수 포화(0~99)도 있습니다. 기본 곡선은 가장 가까운 런처 단계를 정하지만 지수는 정하지 않습니다.
  • 스로틀 디텐트: 스로틀 장치마다 AB와 IDLE 디텐트 위치. 그 장치 파일에 저장됩니다.
  • 게임 설정(설정 > 게임의 포스 피드백 설정): 센터링 스프링, 활주로 진동, 떨림 방지 데드밴드, 아날로그 아이들 컷오프, AB 디텐트에서 클릭, 가상 러더, Depr-Ret 축을 브레이크로.
  • 포스 피드백: Enable Force Feedback, 기관포, 바운스, 센터링 스프링, 폭탄 투하, 실속의 게인, 포스 피드백 데드밴드. BMS 바인딩이 없는 내보내기도 설정과 디텐트는 씁니다.
  • 텔레메트리 기록: BMS의 공유 메모리에서 읽기만 하며, 위치가 포함됩니다(Tacview 트랙 가능). 텔레메트리 포스 피드백은 없습니다.
  • 감시 기능: 장치 파일, User.cfg, Feedback.ini, 파일럿 파일의 변경은 BMS가 닫힌 뒤 감지됩니다(감시 기능).
기술 정보

#BMS 연동의 내부

코드: engine\Games\FalconBmsIntegration.cs, 축 모델 bms, 설정 모델 FalconBMS. 텔레메트리 gui\JoyPro.Ffb.Core\Telemetry\Bms\BmsTelemetry.cs.

  • 장치 파일: 루트 <JoyAssgn>에 <detentPosition>, <axis> 항목 8개(X, Y, Z, Rx, Ry, Rz, Slider0, Slider1: <AxisName>, <AssgnDate>, <Invert>, <Deadzone>, <Saturation>), <pov>(햇 4개 × 방향 8개, 일반과 시프트), <dx>(버튼 128개 × 슬롯 4개: 누르기, 누르기+시프트, 놓기, 놓기+시프트)가 있습니다. <profileDefaultF16> 안의 사본도 똑같이 씁니다. 선언, 공백, 줄 끝, BOM은 유지되며, 바뀐 파일만 씁니다.
  • 장치: 파일 이름에 들어 있는 DirectInput 인스턴스 GUID로 구분합니다.
  • 버튼: 누르기는 슬롯 0. 시프트 레이어는 슬롯 1이며 수정키 BMS Shift가 됩니다. 놓기 슬롯은 절대 가져오지 않습니다. 새 콜백은 Invoke = Default를 받습니다.
  • 축: 새 지정은 AssgnDate = 현재 시각을 받고, 같은 기능의 예전 지정은 풀립니다(런처는 기능을 가장 새 지정에 줍니다).
  • 명령 목록: engine bms refresh-db: BMS - Full.key의 보이는 콜백(조종석과 HOTAS 섹션)과 런처의 축 기능(FOV와 카메라 거리 제외).
  • 가져오기 / 내보내기: engine bms paths, engine bms import, engine bms scan, engine bms export(--mode, --nuke-untouched-devices, --dry-run). 먼저 .jpbak와 백업 저장소에 백업하며, 읽기 전용 속성은 복원됩니다.
  • 설정과 디텐트: engine ffb set --device * --game FalconBMS --param flightControlsDeadband=0.05, 스로틀마다 --device "<throttle>" --param abDetent=80 --param idleDetent=5. engine binds tuning preview --game FalconBMS.
