Nuclear Option

표시:

Nuclear Option은 제트기, VTOL, 헬기가 나오는 전투 비행 게임으로, 모든 기체에 바인딩 세트 하나를 씁니다. 조작 설정을 파일이 아니라 Windows 레지스트리에 보관합니다. 장치마다 Rewired 조이스틱 맵이 하나씩 있고, 게임의 Control Mapper가 이를 씁니다. JoyPro는 이 맵을 프로필로 읽어 오고 Flight Controls 바인딩을 다시 씁니다. 카메라, 게임플레이, 채팅 바인딩은 그대로 둡니다.

  2. 이 버튼 사용

    Nuclear Option은 닫아 둔 채로

먼저: Nuclear Option을 한 번 시작한 다음 닫으세요.

그러면: 바인딩이 Settings > Controls > Open Control Bindings Menu의 장치 탭에 들어가 있습니다.

전에 Nuclear Option에서 버튼을 바인딩한 적이 있나요? 그러면 시작 페이지에 가져온 후 빈 곳 채우기가 나타납니다. 기존 바인딩은 그대로 두고, 비어 있는 버튼에만 새 역할이 주어집니다. 빠른 시작: 내 스틱 작동시키기를 참조하세요.

#JoyPro가 Nuclear Option에서 하는 일

  • 가져오기: 연결된 장치의 조이스틱 맵이 프로필로 들어옵니다. 반전 설정이 있는 축, 버튼, 축 위의 버튼(예: "Increase Throttle")이 포함됩니다.
  • 관계: 관계 하나는 하나의 기능입니다. Nuclear Option에는 기체 목록이 없으므로 관계는 모든 기체용입니다.
  • 내보내기: JoyPro는 각 장치의 맵을 그 자리에서 편집하며, Flight Controls 동작만 씁니다. 게임에 저장된 맵이 없는 장치는 바인딩이 담긴 새 맵을 받습니다.

#바인딩 가져오기

  1. Nuclear Option을 한 번 시작하고(레지스트리 키가 생기도록) 닫으세요.
  2. 시작을 열고 Nuclear Option 카드에서 가져오기를 누른 다음 지금 가져오기를 누르세요.

#관계 만들기와 확인

모든 게임과 마찬가지로 관계를 만드세요(관계 흐름). 설정 마법사와 자동 할당은 이 게임의 기능을 압니다. 그런 다음 내보내기 페이지에서 확인을 실행하세요.

#Nuclear Option으로 내보내기

  1. Nuclear Option을 닫으세요. 게임이 실행 중이면 JoyPro는 쓰기를 거부합니다. 게임은 바인딩 메뉴를 닫을 때와 장치를 분리할 때 맵을 씁니다.
  2. 내보내기를 열고 내 장치에서 교체와 다른 장치도 지우기를 그대로 둔 채 Nuclear Option 카드의 지금 내보내기를 누르세요.
게임에서: Nuclear Option에서 보이는 것

Settings > Controls > Open Control Bindings Menu를 여세요. Control Mapper에는 장치마다 탭이 하나씩 있습니다. 맨 위에서 장치를 클릭하면 그곳에 Flight Controls 바인딩이 보입니다(게임의 이름으로, 예: Pitch, Roll, Yaw, Throttle). 카메라, 게임플레이, 채팅 바인딩은 바뀌지 않습니다.

#Nuclear Option에서 직접 해야 할 일

  • 첫 가져오기나 내보내기 전에 게임을 한 번 시작해서 레지스트리 키가 생기게 하세요.
  • 게임 조작 설정의 Use Throttle Axis Negative Region: 전체 스로틀 축을 쓰려면 켜 두세요. 이 옵션이 꺼져 있는데 프로필에 스로틀 축이 바인딩되어 있으면 JoyPro가 경고합니다.
  • 햇: 햇 방향은 당분간 게임에서 바인딩하세요. JoyPro는 아직 이를 쓰지 않습니다.

#자주 하는 실수

  • "Nuclear Option 실행 중입니다": 게임을 닫고 다시 내보내세요.
  • 장치가 건너뛰어짐: 같은 모델의 장치 두 개가 연결되어 있으면(또는 게임 컨트롤러로도 보이는 키보드가 있으면) 게임의 맵에서 구분할 수 없습니다. JoyPro는 경고와 함께 이를 제외합니다.
  • 장치에 게임 기본 바인딩이 남음: 게임에 저장된 맵이 없는 연결된 장치는 게임의 기본 맵을 쓰는데, JoyPro는 이를 읽을 수 없습니다. 다른 장치도 지우기도 이 장치는 건드리지 않습니다. JoyPro에서 그 장치에 무언가를 바인딩하거나, Control Mapper에서 그 장치의 탭을 한 번 비우세요.
  • 스로틀이 가운데에서 멈춤: Use Throttle Axis Negative Region을 확인하세요(위 참조).
고급

#JoyPro가 읽고 쓰는 것

위치 설명
HKCU\Software\Shockfront\NuclearOption 레지스트리에 있는 게임의 Unity 설정. Rewired 값은 바이너리(UTF-8 텍스트와 0 바이트 하나)이고, 이름은 _h<hash>로 끝남
장치마다 값 하나. 이름에 dataType=ControllerMap과 장치의 hardwareIdentifier가 들어 있음 장치 하나의 조이스틱 맵(Rewired XML), 플레이어 Player0용
같은 이름에 dataType=ControllerMap_KnownActionIds 맵이 아는 동작 ID. JoyPro는 새 맵과 함께 이것을 씀
<install>\NuclearOption_Data\resources.assets 게임의 Rewired 동작 목록: 명령 목록용으로 읽기만 함
%LOCALAPPDATA%\JoyPro2\GameMetadata\HKCU_Software_Shockfront_NuclearOption.joypro-meta.json 내보낸 바인딩에 대한 JoyPro의 이름, 그룹, 튜닝(다음 가져오기용)

처음 쓰기 전에 JoyPro는 Player0의 컨트롤러 맵 값의 스냅샷을 백업 저장소에 저장합니다. 마지막 내보내기 취소는 이 값을 다시 쓰고 JoyPro가 추가한 맵 값을 지웁니다. 일부 값 이름은 255자보다 길어서 JoyPro는 레지스트리 API를 사용합니다(Regedit와 reg export는 이를 모두 보여 주지 않습니다).

#Nuclear Option의 내보내기 모드

모드 장치 맵에서 일어나는 일
추가만 게임의 내용은 바뀌지 않습니다. 버튼이나 축이 이미 다른 동작(또는 축의 반대쪽 극)을 움직이는 바인딩은 빠지고 목록에 표시됩니다.
업데이트, 게임의 바인딩 유지 다른 동작에 할당한 입력에 있던 Flight Controls 동작은 그 입력을 잃습니다. 그 동작의 다른 입력은 유지됩니다.
업데이트, 내 프로필 우선 위와 같으며, 추가로 바인딩하는 모든 동작(또는 극)은 JoyPro가 읽을 수 있는 모든 연결된 장치에서 다른 입력을 잃습니다.
내 장치에서 교체 쓰는 장치의 다른 모든 Flight Controls 동작이 해제됩니다.
+ 다른 장치도 지우기 연결된 장치의 다른 저장된 맵에 있는 Flight Controls 동작이 해제됩니다. 저장된 맵이 없는 장치는 게임의 기본 맵을 유지합니다.

#절대 건드리지 않는 것

  • Flight Controls 밖의 모든 동작: 카메라, 게임플레이, 채팅, 디버그, 미션 에디터 바인딩.
  • 키보드와 마우스 맵, 보정 맵, 입력 동작 방식(input behaviour), 컨트롤러 할당, 모든 게임 설정(그래픽, ThrottleUseNegative 및 기타 조작 옵션).
  • 연결되지 않은 장치, 같은 모델의 장치 두 개 이상, 가져오기에서 무시한 장치, JoyPro가 입력을 전달하는 vJoy 장치.
  • 편집된 맵에서 JoyPro가 바꾸는 요소 맵 밖의 모든 것(모드 동작의 바인딩 포함).

#적용 범위, 곡선, 기타

  • 적용 범위: 전역. 모든 기체에 바인딩 한 세트를 씁니다(Throttle 동작은 헬기 콜렉티브이기도 합니다).
  • 축 곡선: 쓰지 않습니다. 게임의 보정 데드존은 그대로 유지됩니다.
  • 키보드와 수정키: 쓰지 않습니다. 게임의 조이스틱 바인딩에는 수정키가 없습니다.
  • 햇: 아직 읽거나 쓰지 않습니다. 슬라이더는 경고와 함께 씁니다.
  • 포스 피드백, 텔레메트리: 없음.
  • 감시 기능: 게임 키에 대한 레지스트리 변경 알림을 사용합니다. 지문(fingerprint)은 Player0의 컨트롤러 맵만 다룹니다(감시 기능).
  • HUD: HUD는 프로세스(NuclearOption)로 게임을 찾습니다.
기술 정보

#Nuclear Option 연동의 내부

코드: engine\Games\NuclearOptionIntegration.cs(레지스트리 저장소, 게임 고유 사항, 카탈로그 구조)는 engine\Games\RewiredMapIntegration.cs(Rewired 조이스틱 맵 읽기와 쓰기, Tiny Combat Arena와 공유) 위에서 동작합니다.

  • 값 이름: Unity는 모든 키에 _h<hash>를 붙입니다(UTF-8 키에 XOR을 쓰는 djb2, 10진수).
  • 장치: 흔히 쓰는 HOTAS 장치는 게임의 Rewired가 하나도 알지 못하므로, 그 맵에는 0인 hardwareGuid와 hardwareIdentifier = WindowsRawInput + 공백을 뺀 HID 제품 문자열 + PID + VID(각각 대문자 16진수 4자리)가 들어갑니다. duplicate는 같은 모델의 장치 수를 셉니다. JoyPro는 모델당 하나만 처리합니다.
  • 요소: 축 X, Y, Z, Rx, Ry, Rz = 0~5, 슬라이더 6과 7, 버튼 n = 31 + n. 축 동작에 할당한 버튼은 <Action>.Positive / .Negative(axisContribution 0 / 1)입니다. 게임의 기본 맵은 Pitch, Roll, Yaw, Throttle, Brake를 축 0~4에 바인딩하고, 버튼 11개를 바인딩합니다.
  • 쓰기: 건드린 ActionElementMap 블록만 바뀝니다(버튼은 <buttonMaps>, 축은 <axisMaps>). 새 맵에는 sourceMapId -1과 알려진 동작 ID 목록이 들어가므로, 게임이 기본 바인딩을 추가하지 않습니다.
  • 명령 목록: engine nuclearoption refresh-db는 첫 동작("Pitch")을 기준으로 resources.assets에서 Rewired InputManager를 찾아 DB\NuclearOption\actions.tsv(동작 이름, 제목, 카테고리, Rewired ID. 축 동작에는 극별 행도 추가)를 씁니다.
  • 명령: engine nuclearoption paths, engine nuclearoption catalog, engine nuclearoption scan, engine nuclearoption import, engine nuclearoption export; 실행 취소는 engine backups restore.

#알려진 한계

  • 게임의 Rewired가 인식하는 장치(0이 아닌 hardwareGuid, 예: T.16000M)는 처리하지 않습니다.
  • 저장된 맵에서 햇 요소 ID를 확인하지 못해 햇은 건너뜁니다. 슬라이더 ID는 Rewired의 일반 정의를 따릅니다.
  • 바인딩은 게임 메뉴에서 확인했지만 비행 중에는 아직 확인하지 않았습니다. 게임이 Pitch에 기대하는 축 부호도 아직 확인되지 않았습니다.
  • 테스트: engine\tests\smoke\nuclearoption.ps1(실제 vJoy 맵과 카메라 및 게임플레이 바인딩); 게임 안에서는 tools\e2e\games\NuclearOptionSettings.ps1(무작위 vJoy 축에 둔 Pitch, Roll, Yaw가 Control Mapper의 vJoy 탭에 표시되고, 게임이 다시 저장한 뒤의 가져오기가 이를 다시 읽어 옴).
