JoyPro 1에서 JoyPro 2로

표시:

JoyPro 1(2021~2023)은 DCS 도구였습니다. 여러 기체의 입력 사이에 관계를 만들고 스틱의 같은 자리에 바인딩했습니다. JoyPro 2는 바로 그 아이디어와 같은 관계 / 바인딩 / 수정키 모델을 그대로 유지하고(JoyPro 1 프로필이 JoyPro 2에서 열립니다), 그 주위의 모든 것을 새로 만들었습니다: 새 인터페이스, 단독으로도 실행되는 엔진, 수십 개의 게임, 모든 기능의 테스트, 그리고 많은 안전 장치.

#숫자로 보기

모든 숫자는 두 프로젝트의 소스에서 측정했습니다(git으로 추적되는 파일, 코드 줄 = 주석이 아니고 비어 있지 않은 C# 줄). JoyPro 2의 숫자는 이 사이트를 빌드할 때의 값입니다.

초보자용

#여러분에게 좋아진 점

  • 여러 게임, 프로필 하나. JoyPro 1은 DCS용이었습니다. JoyPro 2는 게임 타이틀 37개를 가져오고 내보냅니다: DCS, IL-2(Great Battles, Korea, 1946, Cliffs of Dover), Star Citizen, MSFS 2020과 2024, X-Plane 11과 12, Falcon BMS, War Thunder, Elite Dangerous, X4, Arma 등. 관계 하나가 이 모든 게임에서 같은 기능을 담습니다.
  • 가진 것에서 시작합니다. 가져오기는 각 게임에 이미 있는 바인딩을 읽습니다. 처음 시작할 때의 설정이 게임을 알아서 찾습니다.
  • 영영 망가지는 일은 없습니다. 내보낼 때마다 먼저 게임 파일을 백업하고, 마지막 내보내기 취소는 그 파일을 바이트 하나까지 똑같이 되돌립니다. JoyPro의 모든 변경은 자동으로 저장되며, 다시 시작한 뒤에도 실행 취소할 수 있습니다(프로필 기록 내역).
  • 무엇이 잘못될지 알려 줍니다. 확인은 문제를 게임의 말로 설명하고 클릭 한 번으로 고칩니다.
  • 알아서 설정합니다. 모두 알아서 설정은 중요한 기능을 스틱, 스로틀, 페달에 둡니다. 목록을 보고 이 버튼 사용과 내 게임에 쓰기를 누르기만 하면 됩니다.
  • 클릭이 줄어듭니다. 추천, 자동 그룹, 자동 할당, 설정 마법사, JoyPro 도우미가 관계와 바인딩을 만들어 줍니다. 학습된 "내 스타일"은 예전에 했던 방식을 따릅니다.
  • 변경을 알아챕니다. 게임 안에서 무언가를 다시 바인딩하면, 게임이 닫힌 뒤 JoyPro가 그것을 프로필에 가져올지 묻습니다.
  • 여러분의 언어. 인터페이스가 39개 언어를 지원합니다.
  • 바인딩 그 이상. 장치 이미지와 치트 시트, HUD와 방송용 오버레이, 텔레메트리 기반 포스 피드백, 장치를 하나만 읽는 게임을 위한 가상 조이스틱, Xbox 컨트롤러만 아는 게임을 위한 가상의 컨트롤러(가상 Xbox 패드), 조종석 데이터베이스, 비행 기록 통계.
  • 모든 버튼에 도움말. F1은 어떤 버튼이든 설명하고, 투어는 실제 버튼을 가리키며, 쉬운 말은 설명을 짧게 해 줍니다.
  • 따로 찾아 설치할 런타임이 없습니다. 배포판은 모든 것이 들어 있는 zip 하나입니다. SlimDX도 C++ 런타임도 필요 없습니다.

#기능별 비교

영역 JoyPro 1 JoyPro 2
관계 직접, DCS id 모든 게임을 대상으로 하는 검색, 동의어, 기능 카탈로그, 이유가 붙은 추천, 자동 그룹, 설명별 그룹, 어시스턴트로 직접; DCS 기체별 "같은 id, 다른 의미"
바인딩 버튼이나 축 기록 기록, 입력 따라가기, 장치 이미지에서 바인딩, 모든 장치 조합에 대한 자동 할당, 설정 마법사, AI로 배치
축 튜닝 DCS 곡률, 데드존, 포화 게임마다 자체 응답 모델로, 기체별 범위, 보정, 디텐트 모드
수정키 예 예, 수정키 페이지, 조합, 게임별 변환(BMS shift 등)
내보내기 DCS(clean, nuke) 모든 게임; 네 가지 모드와 "다른 장치도 지우기", 기체별, DCS 기본값과의 최소 차이, 쓰지 못한 바인딩 표시, 백업과 실행 취소
가져오기 DCS 모든 게임, 기본값, 키보드, 장치 병합, 이름/그룹/수정키 다시 가져오기 포함
안전 "직접 백업하세요" 버전별 자동 백업, 게임 실행 중에는 쓰기 거부, 세션을 넘는 실행 취소가 되는 프로필 기록 내역, 테스트의 쓰기 샌드박스
검사 validate 확인: 게임 용어로 된 카드, 클릭 한 번으로 수정, 기록 내역에서 찾은 원인
레이아웃 레이아웃 이미지 내보내기 장치 참고 이미지(VID:PID와 HID 이름으로 정확한 모델), 치트 시트, 장치 3D 뷰
오버레이 게임 내 오버레이 HUD 디자이너, 오버레이, OBS용 스트림 페이지, 실시간 입력
게임 목록 함께 제공되는 데이터베이스(html) 내 설치본을 바탕으로 내 PC에서 만들고, 게임 업데이트 후 새로 고침
감시 없음 알림 영역 호스트가 있는 게임 설정 감시, 게임 종료 후 물어봄
포스 피드백 없음 DCS, IL-2, War Thunder 등을 위한 텔레메트리 포스 피드백(JoyPro.Ffb)
가상 장치 없음 HidHide를 쓰는 vJoy / Xbox 패드 모드, 가상 기능, Joystick Gremlin 가져오기
언어 영어 39
업데이트 직접 다운로드 릴리스 노트가 있는 업데이트 확인, 체크섬으로 검증하는 설치
문제 보고서 Discord에서 질문 로그, 설정, (요청 시) 프로필이 담긴 지원 파일 하나; 사용자 폴더는 치환; 아무것도 업로드하지 않음
기술 정보

#아키텍처와 품질

  • 엔진과 GUI로 분리. JoyPro 1은 로직이 창 코드에 들어 있는 WPF 애플리케이션 하나였습니다. JoyPro 2에는 모든 프로필, 가져오기/내보내기, 데이터베이스 로직을 458개의 명령으로 담은 엔진(engine.exe, .NET Framework 4.8, 순수 C#)과, 모든 동작마다 엔진을 실행하는 Avalonia GUI(.NET 9)가 있습니다. 빠른 대화형 명령은 계속 실행되는 engine serve 하나로 보내므로, 분리를 포기하지 않고도 GUI가 빠르게 유지됩니다. GUI가 하는 모든 일은 스크립트로 할 수 있습니다(엔진 명령줄 참고).
  • 상시 작업은 별도 프로세스로: JoyPro.Ffb.exe(텔레메트리 포스 피드백), JoyPro.VJoy.exe(가상 조이스틱 전달기), JoyPro.Tray.exe(GUI가 닫혀 있는 동안의 감시). 각각 리소스 예산과 장시간 부하 테스트가 있어 백그라운드에서 티가 나지 않습니다.
  • 테스트: 자동 테스트 1,537개(xUnit: 엔진 로직, 뷰 모델, 밝은 테마와 어두운 테마에서 페이지의 오프스크린 렌더), 실제 엔진을 픽스처 폴더에 대해 실행하는 엔진 스모크 테스트 89개 부분, 실제 데이터에 대한 불변 조건 검사가 있는 선택형 품질 게이트, 지원하는 게임의 게임 내 종단 간 실행. 테스트는 실제 폴더 지문 검사가 있는 쓰기 샌드박스에서 실행되므로, 어떤 테스트도 실제 게임 폴더를 건드릴 수 없습니다.
  • 데이터: 게임 명령 목록은 사용자의 PC에서 설치된 게임으로부터 %LOCALAPPDATA%\JoyPro2\GameData에 만들어집니다. JoyPro는 자체 데이터(기능 카탈로그, 장치 카탈로그, 변환 테이블, 조종석 데이터베이스)만 함께 제공합니다.
  • 소스에서 생성되는 문서: 게임 지원 표는 코드(engine games support)에서, CLI 참조는 engine --help에서, 이 사이트는 AXAML, 뷰 모델, 문서에서 만들어집니다.
