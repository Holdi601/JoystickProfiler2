주요 흐름

게임 가져오기

표시:

가져오기는 게임이 저장한 조작 설정을 읽어 JoyPro 프로필로 바꿉니다. 기능 하나마다 버튼이나 축이 있는 관계 하나가 만들어집니다. 가장 빠르게 시작하는 방법입니다. 게임에서 이미 설정한 모든 것이 들어오고, 그때부터 JoyPro가 한곳에서 관리합니다.

초보자용

#클릭 세 번으로 가져오기

  1. 시작(아래쪽 막대의 첫 번째 버튼)을 여세요. 내 게임 아래에 JoyPro가 PC에서 찾은 모든 게임이 이미지가 있는 카드로 표시됩니다. 가장 많이 하는 게임에서 가져오기를 누르세요.
  2. JoyPro가 방식을 묻습니다:
    • **내 프로필에 추가 (권장)**는 기존 내용을 유지하고 게임의 바인딩을 추가합니다.
    • 이 게임에서 다시 시작은 관계를 게임에 있는 것으로 바꿉니다(JoyPro가 먼저 프로필 사본을 보관합니다).
    • 키보드 키도 가져오기를 체크하면 키보드의 비행 명령도 가져옵니다. 장치 바인딩은 항상 가져옵니다.
    • DCS의 경우: 내 모든 DCS 기체를 쓰거나, 체크를 해제하고 기체를 고르세요.
  3. 지금 가져오기를 누르세요. 잠시 후 카드에 "완료: 이제 프로필에 관계가 214개 있습니다(180개 바인딩됨)"라고 표시되고, 내 관계 보기를 누르면 관계가 열립니다. 대신 먼저 확인을 누르면 아무것도 바꾸지 않고 게임에 있는 것을 보여 줍니다.

열린 프로필이 없나요? JoyPro가 하나 만들어 주고, 그때부터 자동으로 저장합니다(저장 버튼은 없습니다. 모든 변경은 저장되며, 재시작한 뒤에도 되돌릴 수 있습니다).

#게임에서는 무엇이 바뀌나요?

아무것도 바뀌지 않습니다. 가져오기는 게임 파일을 읽기만 합니다. 나중에 내보내든 말든 게임의 바인딩은 그대로 유지됩니다.

#가져온 뒤 빈 곳은 JoyPro에게 맡기기

시작 페이지의 "장치 설정" 카드에는 직접 바인딩을 만든 게임이 나와 있습니다. 가져온 후 빈 곳 채우기는 그런 게임을 먼저 가져옵니다. 그런 다음 **지금 빈 곳 채우기...**가 중요한 기능을 아직 비어 있는 버튼에 넣습니다. 직접 만든 바인딩은 그대로 남습니다. 이미 프로필에 있는 게임에는 카드에서 **빈 곳 채우기...**를 제안합니다.

#처음 가져오기 전에: 명령 목록

JoyPro는 게임마다 명령(이름과 ID)을 알아야 합니다. 이 목록은 내 설치 파일에서 한 번 만들어집니다. 목록이 없으면 시작 페이지에 목록 생성(또는 누락된 목록 모두 생성)이 표시되고, 게임 업데이트 후에는 게임 카드에 업데이트가 나타납니다. 몇 초에서 몇 분까지 걸립니다(DCS는 모든 모듈을 읽습니다).

고급

#옵션과 그 기능

옵션 기본값 효과
내 프로필에 추가 / 다시 시작 추가 추가는 열린 프로필에 병합합니다. 다시 시작은 확인과 프로필 사본 생성 후 관계를 교체합니다.
키보드 키도 가져오기 마지막 선택 키에 바인딩된 비행 명령도 가져옵니다.
연결되지 않은 장치도 가져오기 켜짐 지금 연결되지 않은 장치도 가져옵니다(나중에 연결할 스틱에 유용). 끄면: 건너뛰고 개수만 셉니다.
이름이 같은 장치를 하나의 장치로 취급 켜짐 Windows는 가끔 장치에 새 ID를 줍니다. 그 장치의 이전 파일과 새 파일은 연결된 ID의 장치 하나로 읽습니다. 똑같은 장치 두 개가 동시에 연결되어 있으면 따로 유지됩니다.
기본값 포함(DCS, 전문가용) 켜짐 가져온 장치에 대해 DCS에서 활성인 모든 기본 바인딩을 가져오므로, 가져온 뒤 교체 + 지우기로 내보내도 DCS가 원래대로 남습니다. 같은 입력에서는 사용자 자신의 바인딩이 기본값보다 우선합니다.
반전 / 슬라이더 / 곡률 / 데드존 / 포화 값 가져오기(전문가용) 꺼짐 JoyPro가 직접 내보내지 않은 바인딩에 대해 게임에서 설정한 값을 가져옵니다. JoyPro가 내보낸 바인딩은 이 옵션 없이도 튜닝이 되돌아옵니다.
DCS: *_easy 기체 무시 꺼짐 기체의 쉬운 모드 사본은 제외됩니다.

전문가 가져오기(시작 페이지의 카드 아래와 고급 페이지)는 게임마다 모든 엔진 옵션을 검색(미리보기), 가져오기, 내보내기와 함께 제공합니다. 모든 선택은 다음 가져오기를 위해 기억됩니다.

#이름, 그룹, 수정키가 되돌아옵니다

게임 파일에는 장치, 입력, 그리고 경우에 따라 곡선만 들어 있습니다. JoyPro의 내보내기는 그 옆에 자체 데이터를 저장하고, 가져오기가 이를 다시 읽습니다:

게임 JoyPro의 데이터 복원되는 것
DCS <aircraft>\joystick\<device>.jp, modifiers.lua 관계 이름, 그룹(순서대로), 이름이 있는 수정키, 반전, 슬라이더, 데드존, 포화, 곡선
IL-2 Great Battles data\input\jp.actions 이름, 그룹, 별칭, 수정키, 정확한 튜닝
레지스트리 게임(X-Plane, Elite, X4, Arma, MSFS, War Thunder, BMS ...) <config>.joypro-meta.json 이름, 그룹, 별칭, 수정키, 튜닝
Star Citizen actionmaps.jp 이름

게임의 현재 상태가 우선합니다: 내보낸 뒤 DCS에서 바꾼 곡선은 유지됩니다. JoyPro가 한 번도 내보내지 않은 바인딩은 게임의 동작으로 만든 이름과 그룹 DCS, IL2 또는 GENERATED + 게임을 받습니다.

#두 가지 안전장치

  • 아직 내보내지 않은 변경 사항. JoyPro에서 바인딩을 바꾸고 이 게임으로 내보내지 않았다면, 가져오기를 하면 이전 바인딩이 되돌아옵니다. JoyPro가 먼저 묻습니다.
  • 이미 가져왔나요? 프로필에 그 게임이 있으면, 나중에 게임에서 바꾼 것은 게임 감시 기능을 통해 들어옵니다(게임이 종료된 뒤 물어봄). 다시 가져오기도 여전히 클릭 한 번입니다.
게임에서: 게임 종류별로 가져오기가 읽는 내용

가져오기는 게임 폴더에 절대 써넣지 않습니다. 읽는 내용은 다음과 같습니다:

  • DCS: 모든 기체와 장치의 바인딩, 수정키, 그리고 "기본값 포함"을 쓰면 DCS가 장치마다 가진 기본 바인딩.
  • IL-2 Great Battles / Korea: 키 매핑과 축 응답.
  • Star Citizen: 해당 브랜치(LIVE, PTU ...)의 키 바인딩과 js1에 있는 게임의 조이스틱 기본값.
  • 보병이나 차량이 있는 게임(War Thunder, Arma, Reforger, WARDOGS ...): 비행 동작만 읽습니다. 나머지는 무시할 뿐 지우지 않습니다.
  • MSFS: 시뮬레이터(Steam 또는 Microsoft Store 버전)의 입력 프로필, 그리고 요청하면 시뮬레이터의 기본 프리셋.

게임이 구분하지 못하는 장치(일부 게임에서 같은 모델의 장치 두 개)와 축 절반 바인딩(Elite)은 건너뛰며, 결과에 그 이름이 표시됩니다.

기술 정보

#내부 작동 방식

  1. GUI. StartImportWizard → RunImportWizardAsync(MainWindowViewModel.GameHub.cs). AskAboutUnexportedChangesAsync(엔진 sync pending)로 묻고, 다시 시작을 확인한 뒤 프로필 사본을 보관하고(BackupProfileBeforeChange("before-import")), 게임의 가져오기를 호출합니다: ImportDcsAsync, ImportIl2Async, ImportStarCitizenAsync 또는 ImportRegistryGameAsync. 먼저 확인은 같은 과정을 scan(PreviewImportWizardAsync)으로 실행하고 출력 패널을 엽니다.
  2. 엔진. DCS의 경우: engine dcs import [--path <Saved Games\DCS>] --merge --include-defaults [--plane <a> --plane <b>] --include-keyboard true|false --ignore-easy-planes false --only-connected false --merge-same-name true. 가져오기 모듈은 각 장치 파일을 읽고, DirectInput 인스턴스 GUID와 이름으로 장치를 매핑하고, 모든 명령 ID를 게임의 명령 목록(%LOCALAPPDATA%\JoyPro2\GameData의 DB\<game>)에 매핑한 뒤, 기능과 입력마다 관계 하나를 만듭니다. 불러올 때의 보정(--load-corrections, --correction-mode)은 이름이 바뀐 명령 ID를 확신도 점수와 함께 다시 매핑합니다.
  3. 프로필. 관계는 이름과 같은 입력을 기준으로 병합됩니다. 수정키는 modifiers.lua(DCS) 또는 게임의 시프트 설정으로 만들어집니다. 프로필은 원자적으로 저장되며, 저장할 때마다 <data>\ProfileHistory에 버전이 생깁니다(재시작 후에도 실행 취소 가능).
  4. 감시 기능. 동기화 기록이 없는 게임을 가져오면 게임 파일을 기록해 두므로, 나중에 게임에서 바꾼 것이 감지됩니다(<data>\Sync\<game>.json).
