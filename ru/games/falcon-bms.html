Falcon BMS

Показать:

Falcon BMS 4.38 настраивает ваши устройства в своём лаунчере: лаунчер хранит по одному XML-файлу на устройство и собирает из них файл клавиш и настройку осей каждый раз, когда вы нажимаете Запустить. JoyPro записывает именно эти файлы устройств лаунчера, поэтому главным остаётся лаунчер: он превращает привязки JoyPro в файлы, которые читает BMS, как если бы вы сделали их в лаунчере сами. Falcon 4.0 и Allied Force не поддерживаются; используйте Falcon BMS.

Falcon BMS 4.38.2 and newer (launcher 3.x): the launcher keeps your binds in User\Config\JSON, one file per device and aircraft (F-16 and F-15ABCD each have their own), and rebuilds the older XML and key files from them every time it closes or launches. JoyPro reads and writes these JSON files: a button goes into each aircraft whose key file has the command (an F-15 command only into the F-15), an axis into every aircraft of the device. Hat binds, the shifted layer and throttle detents are not written into the JSON files yet; the export lists them so you can set them in the launcher. Older BMS versions keep working with the XML files as below.

Для начинающих

#Запуск за 3 шага

  1. Настроить всё за меня
    на странице «Старт»
  2. Использовать эти кнопки
    сначала посмотрите список
  3. Записать в мою игру
    BMS и её лаунчер должны быть закрыты

До: закройте BMS и её лаунчер.

Затем: запустите лаунчер и нажмите Запустить. Только тогда лаунчер собирает файлы, которые читает BMS.

Вы уже назначали кнопки в Falcon BMS? Тогда страница «Старт» предложит Импортировать, затем заполнить пробелы. Ваши привязки останутся, а новые задачи получат только свободные кнопки. См. Быстрый старт: заставить ручку работать.

#Что JoyPro делает для Falcon BMS

  • Импорт: кнопки, хатки и оси ваших устройств приходят из файлов устройств лаунчера, вместе со слоем Shift как модификатором и с инверсией, мёртвой зоной и шагами насыщения каждой оси.
  • Связки: одна связка — это одна функция во всех ваших играх («Gear» в BMS, DCS и IL-2 на одной кнопке). Команды — это callback-функции BMS из BMS - Full.key.
  • Экспорт: JoyPro записывает файлы устройств лаунчера. При следующем Запустить лаунчер собирает из них файл клавиш и настройку осей.

#Импорт привязок BMS

  1. Откройте Старт. Карточка Falcon BMS показывает картинку игры. Если она просит список команд, нажмите Создать список: JoyPro читает callback-функции установленного BMS - Full.key.
  2. Нажмите Импорт на карточке и выберите Добавить в мой профиль (клавиши клавиатуры остаются в файле клавиш BMS, поэтому флажок клавиатуры здесь не действует).
  3. Нажмите Импортировать. Мои связки открывает то, что пришло.

#Создание и проверка связок

На странице Связки callback-функция BMS в связке стоит рядом с той же функцией ваших других игр. Объедините их с помощью работы со связками, затем нажмите Проверить на странице «Экспорт» (Проверка).

#Экспорт в Falcon BMS

  1. Закройте BMS и её лаунчер. JoyPro отказывается работать, пока запущен Falcon BMS.exe или FalconBMS_Alternative_Launcher.exe.
  2. Откройте Экспорт. Карточка Falcon BMS показывает, сколько её связок привязано.
  3. Оставьте Заменить на моих устройствах вместе с Очистить и другие мои устройства, если вы настраиваете устройства в JoyPro. Нажмите Экспортировать на карточке.
В игре: Что вы видите в Falcon BMS

Запустите лаунчер и нажмите Запустить: лаунчер собирает файл клавиш и настройку осей из файлов устройств JoyPro. В симуляторе Setup > Controllers > Advanced > Flight Control показывает каждую экспортированную ось на вашем устройстве с мёртвой зоной и шагами насыщения, заданными JoyPro, а ваши кнопки и хатки делают то, что написано в профиле.

#Что вы делаете сами в Falcon BMS

  • Нажимайте Launch в лаунчере после каждого экспорта. Только тогда лаунчер записывает файл клавиш, axismapping.dat, joystick.cal и DeviceSorting.txt, которые читает BMS.
  • Оставьте флажок «Launch without any Setup override» снятым, иначе лаунчер не запишет вашу настройку.
  • Клавиши клавиатуры остаются в файле клавиш, которым управляет BMS; задавайте их в лаунчере. JoyPro записывает только входы джойстика.
  • Enable Force Feedback записывается в ваш файл пилота (<callsign>.pop, файл размером 468 байт в BMS 4.36 и новее). Для файла пилота другого размера JoyPro пропускает только эту настройку с предупреждением.

#Частые ошибки

  • «Falcon BMS работает»: закройте симулятор и лаунчер и снова выполните экспорт.
  • Не хватает привязки с модификатором: в BMS один слой Shift для всех устройств, его удерживает кнопка с SimHotasPinkyShift. JoyPro записывает привязки с этим модификатором в слот Shift; любой другой модификатор пропускается с предупреждением.
  • Ось осталась на другом устройстве в режиме «Только добавить»: BMS отдаёт каждую функцию только одной оси, а «Только добавить» никогда её не переносит. Чтобы перенести, используйте режим обновления.
  • Привязки в симуляторе не изменились: после экспорта лаунчер не был запущен через Launch.
Расширенные

#Файлы, которые JoyPro читает и записывает

Файл Что это
<BMS>\User\Config\JSON\DeviceBindings_<aircraft>_<device>.json 4.38.2 and newer: the launcher's file per device and aircraft (buttons, axes)
<BMS>\User\Config\Setup.v100.<device> {<GUID>}.xml before 4.38.2: the launcher's file per device: axes, hats, buttons, throttle detents
<BMS>\User\Config\Falcon BMS User.cfg значения кривых и настройки игры, только выше строки-маркера лаунчера
<BMS>\User\Config\Feedback.ini коэффициенты эффектов Force Feedback и центрирующая пружина
<BMS>\User\Config\<callsign>.pop файл пилота: только байт Enable Force Feedback
<BMS>\User\Config\JoyPro.joypro.json входы, которые записал JoyPro

<BMS> находится через HKLM\SOFTWARE\WOW6432Node\Benchmark Sims\...\baseDir или папку Falcon BMS*. axismapping.dat, joystick.cal, DeviceSorting.txt, файлы клавиш и блок лаунчера в User.cfg пересобираются при каждом Launch; JoyPro их никогда не записывает. Подключённое устройство без файла устройства получает его: из стандартного файла лаунчера для этой модели, иначе — пустой файл в формате лаунчера.

#Режимы экспорта в Falcon BMS

Режим Что происходит в BMS
Только добавить Записывает только свободные слоты; привязка на слоте с другим callback не записывается и попадает в список. Функция, которая в BMS стоит на другой оси, остаётся там (предупреждение).
Обновить, привязки игры сохранить Заменяет callback на вашем слоте (конфликт) и сохраняет всё остальное; функция оси переходит на вашу ось.
Обновить, мой профиль важнее Также освобождает другие слоты нажатия, хатки и оси подключённых устройств, на которых стоит привязанное вами действие.
Заменить на моих устройствах Освобождает всё остальное на записываемых подключённых устройствах (также callback из каталога в слотах отпускания).
+ Очистить и другие мои устройства Подключённые устройства без привязок в экспорте очищаются.

#Что никогда не затрагивается

  • Файлы неподключённых устройств (старое назначение оси там остаётся; лаунчер берёт самое новое).
  • Игнорируемые при импорте устройства и устройство vJoy, в которое передаёт JoyPro.
  • Клавиши клавиатуры и файл клавиш, файлы, которые создаёт лаунчер, и блок лаунчера в User.cfg.

#Кривые, настройки, Force Feedback

  • Детализация: общая, одна настройка для всех ЛА.
  • Оси (модель осей bms): инверсия, шаг мёртвой зоны лаунчера (None, Small, Medium, Large) и шаг насыщения, односторонние оси (РУД, носочные тормоза, яркость, громкость) без мёртвой зоны; для тангажа, крена, рыскания и курсора X/Y также экспоненциальная кривая (от 0 до 100) и экспоненциальное насыщение (от 0 до 99) в User.cfg. Кривая по умолчанию задаёт ближайшие шаги лаунчера, но не экспоненту.
  • Упоры РУД: положения упоров AB и IDLE для каждого устройства РУД, в его файле устройства.
  • Настройки игры (Настройки > Настройки FFB игр): центрирующая пружина, тряска на полосе, зона подавления дрожания, аналоговая отсечка малого газа, щелчок на упоре AB, виртуальный руль направления, ось Depr-Ret как тормоз.
  • Force Feedback: Enable Force Feedback, коэффициенты пушки, отскока, центрирующей пружины, сброса бомб и сваливания, мёртвая зона Force Feedback. Экспорт без привязок BMS всё равно записывает настройки и упоры.
  • Запись телеметрии: только чтение из общей памяти BMS, с положением (трек Tacview возможен). Force Feedback по телеметрии нет.
  • Отслеживание: изменения в файлах устройств, User.cfg, Feedback.ini или файле пилота замечаются после закрытия BMS (отслеживание).
Технические подробности

#Внутри интеграции BMS

Код: engine\Games\FalconBmsIntegration.cs, модель осей bms, модель настроек FalconBMS; телеметрия gui\JoyPro.Ffb.Core\Telemetry\Bms\BmsTelemetry.cs.

  • Файлы устройств: корень <JoyAssgn> с <detentPosition>, 8 записей <axis> (X, Y, Z, Rx, Ry, Rz, Slider0, Slider1: <AxisName>, <AssgnDate>, <Invert>, <Deadzone>, <Saturation>), <pov> (4 хатки × 8 направлений, обычные и со сдвигом) и <dx> (128 кнопок × 4 слота: нажатие, нажатие+shift, отпускание, отпускание+shift). Копия в <profileDefaultF16> записывается так же. Объявление, пробелы, концы строк и BOM сохраняются; записываются только изменённые файлы.
  • Устройства: по GUID экземпляра DirectInput в имени файла.
  • Кнопки: слот нажатия 0; слой shift — это слот 1, он становится модификатором BMS Shift. Слоты отпускания никогда не импортируются. Новый callback получает Invoke = Default.
  • Оси: новое назначение получает AssgnDate = сейчас; более старые назначения той же функции освобождаются (лаунчер отдаёт функцию самому новому назначению).
  • Список команд: engine bms refresh-db: видимые callback из BMS - Full.key (разделы кабины и HOTAS) плюс функции осей лаунчера (без FOV и расстояния камеры).
  • Импорт / экспорт: engine bms paths, engine bms import, engine bms scan, engine bms export (--mode, --nuke-untouched-devices, --dry-run). Сначала резервная копия в .jpbak и в хранилище резервных копий; атрибут «только чтение» восстанавливается.
  • Настройки и упоры: engine ffb set --device * --game FalconBMS --param flightControlsDeadband=0.05, для каждого РУД --device "<throttle>" --param abDetent=80 --param idleDetent=5; engine binds tuning preview --game FalconBMS.

#Известные ограничения

  • Не записываются: устаревший способ работы с файлами клавиш, собственная форма осей (axiscurves.cal), мёртвые зоны, отличные от шагов лаунчера.
  • Формула кривой экспоненты и то, как BMS читает шаги насыщения, пока не подтверждены.
  • Тесты: engine\tests\smoke\bms.ps1 (стандартные файлы); в игре tools\e2e\games\BmsSettings.ps1 (Launch, созданные файлы, Setup > Controllers). Лучший прогон в игре прошёл 20 из 21 шага.
