Project Wingman

表示：

Project Wingman は Unreal Engine 4 製のアーケード空戦ゲームです。複数の DirectInput デバイスを同時に読み、割り当てはプレーンな Input.ini に保存されます。各割り当てにはデバイス名と、ゲームのデバイス一覧での位置が付きます。カーブとデッドゾーンはセーブデータにあります。JoyPro は両方をプロファイルに読み込み、書き戻します。キーボード、マウス、ゲームパッド、ハットはゲームの設定のまま残ります。

初心者向け

#3 ステップで使えるようにする

  1. すべて自動で設定
    スタート ページで
  2. このボタンを使う
    先に一覧を確認
  3. ゲームに書き込む
    Project Wingman は閉じたままで

事前に：ゲームを一度起動してから閉じてください。このゲームの Steam Input はオフにしてください。

その後：割り当てはゲームの Controls に入っています。コントローラーを追加・取り外した場合は、もう一度エクスポートしてください。

以前に Project Wingman でボタンを割り当てていましたか？ それならスタートページに インポートしてから空きを埋める が表示されます。今の割り当てはそのまま残り、空いているボタンだけに新しい役割が付きます。クイックスタート：スティックを使えるようにする を参照してください。

#JoyPro が Project Wingman に対して行うこと

  • インポート：フライトアクション（ピッチ、ロール、ヨー、推力、2 つの視点軸、ボタン）のジョイスティック割り当てがすべて、反転、カーブ、デッドゾーンと一緒に実際のデバイス上でプロファイルに入ります。
  • リレーション：Project Wingman の「Fire missile」を、ほかのゲームの兵装投下と同じリレーションにできます。
  • エクスポート：JoyPro は割り当てを Input.ini に、カーブとデッドゾーンをセーブデータに書き込みます。

#Project Wingman の割り当てをインポート

  1. 一度もゲームを起動していない場合は、フォルダーが作られるように一度起動してください。
  2. 開始 を開きます。Project Wingman のカードがコマンドリストを求めている場合は リスト作成 を押します。JoyPro がゲーム自身のファイルからフライトアクションを読み取ります。
  3. カードの インポート を押し、プロファイルに追加（推奨） のまま 今すぐインポート を押します。

#リレーションの作成と確認

リレーション ページで Project Wingman のアクションをほかのゲームとつなげ（リレーションの流れ）、エクスポートページで 確認 を実行してください。ゲーム内で 1 つのボタンが 2 つの動作をする箇所を見つけます。

#Project Wingman へエクスポート

  1. Project Wingman を閉じてください。 実行中は JoyPro が書き込みを拒否します。
  2. エクスポート を開き、Project Wingman のカードにチェックを入れます。
  3. 自分のデバイスで置き換え と ほかのデバイスもクリア のままにするか、ゲーム内でも割り当てる場合は 更新（ゲームの割り当てを優先） を選びます。カードの 今すぐエクスポート を押します。
ゲーム内: Project Wingman での表示

ゲームの Controls を開きます。KEY BINDINGS と AXIS BINDINGS には、各行の次の空き枠に割り当てが表示されます。名前はスペースを除いたデバイス名と番号で、たとえば「VJOYDEVICE 8 BUTTON 24」や「VJOYDEVICE 8 AXIS 1」となり、反転した軸では Invert にチェックが入っています。CURVES + DEADZONES には、JoyPro が各軸に書き込んだ CURVE と DEADZONE が表示されます。

#Project Wingman で自分で行うこと

  • コントローラーを追加・取り外したら、もう一度エクスポートしてください。 ゲームはデバイス一覧での位置でデバイスに番号を付けるため、コントローラーの接続や取り外しでその位置が変わります。JoyPro はエクスポート時に接続されているデバイスから番号を計算します。
  • ハット：このゲームはハットを割り当てられません。Controls > Miscellaneous で Hat Function 1 / 2（WEAPON または VIEW）を設定してください。
  • このゲームの Steam Input はオフにしてください。Steam Input のパッドが余分なデバイスとして表示されます。

#よくある落とし穴

  • 割り当てが違うデバイスを指している：エクスポート後にコントローラーが追加または取り外されています。いつものデバイスを接続してもう一度エクスポートしてください。デバイスの番号が変わっている場合、インポート時に警告が出ます。
  • ハットの割り当てが拒否される：仕様です。上の Hat Function を参照してください。
  • スロットルの下半分でブレーキがかかる：Project Wingman の「Thrust Axis」は中央基準の軸で、中央より上で加速、下でブレーキになります。
詳細

#JoyPro が読み書きするファイル

ファイル これは何か
%LOCALAPPDATA%\ProjectWingman\Saved\Config\WindowsNoEditor\Input.ini 割り当て。セクション [/Script/Engine.InputSettings] の ActionMappings=(...) 行と AxisMappings=(...) 行
%LOCALAPPDATA%\ProjectWingman\Saved\SaveGames\savegame.sav 軸アクションごとのカーブとデッドゾーン（<Axis>Curve、<Axis>Deadzone）とハットの機能
<install>\ProjectWingman\Content\Paks\pakchunk0-WindowsNoEditor.pak 読み取り専用：DefaultInput.ini。ゲームの既定の割り当てとアクション一覧
...\Input.ini.joypro-meta.json エクスポートした割り当ての JoyPro のデータ（名前、グループ、調整）。次回のインポート用

ゲームはメニューで割り当てが変わった瞬間に Input.ini を書き込みますが、書くのは変更した一覧だけで、ほかは pak の既定値から読みます。書き込まれた一覧は既定値を置き換えるため、JoyPro は足りない一覧の既定値を先に書き込みます。セーブ フォルダーは Steam Cloud が同期します。

#Project Wingman でのエクスポート モード

削除するのは、カタログにある飛行アクションのジョイスティック マッピングだけです。キーボード、ゲームパッド、マウス、メニューの行、接続されていないデバイスはそのままです。

モード どうなるか
追加のみ ゲームが別の飛行アクションに使っている入力への割り当ては書き込みません（「ゲームに書き込まれていません」と表示されます）。ゲーム側の割り当ての形（Invert）はそのままです。
更新（ゲームの割り当てを優先） さらに、プロファイルが別のアクションに使う入力にあるゲームのマッピングも削除します。そのアクションのほかのマッピングは残ります。
更新（プロファイルを優先） さらに、プロファイルが割り当てるすべてのアクションのほかのジョイスティック マッピングも削除するため、移動した割り当ては完全に移ります。
自分のデバイスで置き換え エクスポートしたデバイスは、ほかのジョイスティック マッピングを失います（飛行だけのゲームのため）。
+ ほかのデバイスもクリア 接続中のほかのデバイスでも同じです。

#一切変更しないもの

  • キーボード、マウス、ゲームパッドのマッピング、メニューの行、ハット。
  • 接続されていないデバイス、インポートで無視したデバイス、JoyPro が転送先にしている vJoy デバイス。
  • Input.ini のほかのすべての行（順序と改行もそのまま）と、savegame.sav のほかのすべてのバイト。

#カーブ、デッドゾーン、その他の設定

  • 軸アクションごと、全デバイス共通：ピッチ、ロール、推力、ヨー、2 つの視点軸の CURVE（メニューの 0.00 ～ 2.00、1.00 = 直線）と DEADZONE（0 ～ 100 %）。ゲームの既定値：ピッチとロールは 25 %、視点は 10 %、推力とヨーは 0 %。
  • 割り当てごとの 反転（スロットの Invert ボックス）。
  • ゲームの計算式はわかっていません。JoyPro のプレビューは、デッドゾーンを差し引いて再スケールし、カーブを指数として扱うと仮定しています（まだ未確認）。
  • 全体共通：機体ごとのプロファイルはありません。モディファイアなし（ゲームにないため）、フォースフィードバックなし。
  • 監視機能：ゲームを閉じたあと、Input.ini と savegame.sav を監視します（監視機能）。
  • HUD：ゲームの実行中、HUD が押したボタンごとにそのアクション名を表示します。
技術的な内部情報

#Project Wingman 連携の内部

コード：engine\Games\ProjectWingmanIntegration.cs、engine\Games\ProjectWingmanSaveGame.cs、engine\AxisModels\ProjectWingman.cs（軸モデル projectwingman）。

  • キー：Joystick_<name>_<place>_Axis<n>、..._Button<n>。<name> は空白を除いた DirectInput の製品名で（VPforce Rhino FFB Joystick は VPforceRhinoFFBJoystick になります）、HID の文字列ではありません。<place> はゲームの一覧（Controls > Miscellaneous）でのデバイスの位置で、DirectInput の順序を逆にしたものです。XInput のパッドはこの一覧に入りません。Axis<n> はデバイスに実在する軸を X Y Z Rx Ry Rz Slider Slider の順に 0 から数えます。Button<n> は 0 から数えます。名前にカンマを含むキーは引用符で囲みます。
  • 反転 = Scale=-1.000000。
  • 既定値：pak の既定値にある Android_* キーは残します。メニューはマッピングごとに 1 つのスロットを表示し、それらのキーが空きスロットに当たるためです。
  • savegame.sav：Unreal GVAS。FloatProperty <Axis>Curve（メニューの値の半分）と <Axis>Deadzone（0..1）を、その場で編集するか、末尾の None の前に追加します。チェックサムはありません。
  • コマンド一覧：engine pw refresh-db は pak の DefaultInput.ini と自分の Input.ini を読み込みます。軸 6 個とボタン 14 個です。
  • コマンド：engine pw paths、engine pw catalog、engine pw scan、engine pw import、engine pw export --mode clean|add|merge|merge-overwrite --nuke-untouched-devices --dry-run。

#既知の制限

  • デバイス番号はコントローラーの構成によって変わります。ハードウェアを変えたら、もう一度エクスポートしてください。
  • ハットとモディファイアは受け付けません。
  • カーブの計算式は暫定的な仮定です。
  • ゲーム内でのテストの完全な実行がまだ 1 回残っています。エクスポートとインポートはゲーム内で確認済みです。
  • テスト：engine\tests\smoke\projectwingman.ps1（実物と同じ形のテスト データ）。ゲーム内では tools\e2e\games\ProjectWingmanSettings.ps1（ランダムな軸、ボタン、反転、カーブ、デッドゾーン。操作ページを読み戻して確認し、設定フォルダーとセーブ フォルダーを元に戻します）。
