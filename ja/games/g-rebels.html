G-Rebels

表示：

G-Rebels は Unreal Engine 5 で作られたサイバーパンクのフライト アクション ゲームで、VTOL で巨大都市の上空を飛びます。ゲームはオンにした各ジョイスティックを チャンネル（0～5）に割り当て、各軸の役割（ピッチ、ロール、ヨー、推力、横移動、上下）とボタンの割り当てをチャンネルごとに 2 つのセーブ ファイルに保存します。JoyPro はその役割と割り当てをプロファイルに読み込み、書き戻します。キーボード、ゲームパッド、マウスはゲームの設定のまま残ります。

初心者向け

#3 ステップで使えるようにする

  1. すべて自動で設定
    スタート ページで
  2. このボタンを使う
    先に一覧を確認
  3. ゲームに書き込む
    G-Rebels は閉じたまま

事前準備として、ゲーム内でデバイスごとに一度：OPTIONS > INPUT > DEVICES でチャンネルを割り当てます。その JST タブで軸の役割を 1 つ変更します。ボタンを 1 つ割り当てます（詳しくは以下）。

その後：割り当てはデバイスの JST タブに表示されます。

以前に G-Rebels でボタンを割り当てたことがありますか？ その場合、スタート ページに インポートしてから空きを埋める が表示されます。今の割り当てはそのまま残り、空いているボタンにだけ新しい役割が付きます。クイック スタート：スティックを使えるようにする を参照してください。

#JoyPro が G-Rebels で行うこと

  • インポート：全チャンネルの軸の役割（スティックのどの軸がピッチ、ロール、ヨー、推力、横移動、上下か）を反転設定ごと、そして JoyPro が把握しているボタンの割り当てを、本物のデバイス上でプロファイルに取り込みます。
  • リレーション：G-Rebels の「Pitch」を、ほかのゲームのピッチと同じリレーションにできます。
  • エクスポート：JoyPro は、デバイスのチャンネルに軸の役割とボタンの割り当てを設定します。チャンネルやデバイスを追加することはありません。その部分はゲーム内で一度行います。

#G-Rebels の割り当てをインポート

  1. スタート を開きます。G-Rebels のカードがコマンド リストを求めたら、リスト作成 を押します。JoyPro は、ゲームの軸の役割とボタンについて独自の表を書き出します。
  2. G-Rebels のカードの インポート を押し、プロファイルに追加（推奨） のまま 今すぐインポート を押します。
  3. リレーションを表示 で取り込んだ内容を開けます。

#リレーションの作成と確認

リレーション ページで、リレーションを G-Rebels のアクションに割り当て（リレーションの流れ を参照）、エクスポート ページで 確認 を実行します。G-Rebels では、軸 1 本につき役割は 1 つ、アクションとチャンネルごとにボタンは 1 つです。確認では、2 つのリレーションが同じ入力を使おうとしている箇所を表示します。

#G-Rebels へのエクスポート

  1. G-Rebels を閉じます。 ゲームの起動中は JoyPro が書き込みを拒否します。
  2. エクスポート を開き、G-Rebels のカードにチェックを入れます。
  3. JoyPro でスティックを設定しているなら、自分のデバイスで置き換え と ほかのデバイスもクリア をオンのままにします。カードの 今すぐエクスポート を押します。
ゲーム内: G-Rebels での表示

OPTIONS > INPUT > CONTROLS を開き、デバイスの JST<channel> タブ（チャンネル 0 なら JST0）を開きます。AXIS では、各ジョイスティック軸（X、Y、Z、RX、RY、RZ、Slider、Dial）に JoyPro が設定した役割（YAW、THRUST、ROLL、PITCH、SIDE STRAFE、UP / DOWN、NONE）が表示されます。BUTTONS では、割り当てたアクションにボタンが表示されます（たとえば「Enhanced Raw Input Controller 0 Button 5」）。

#G-Rebels で自分で行うこと

最初のエクスポートの前に、デバイスごとに一度だけ次のことを行います：

  1. デバイスをオンにする：OPTIONS > INPUT > DEVICES には、すべてのジョイスティックが DEACTIVATED として表示されます。使いたい各デバイスにチャンネル（0 - CHANNEL ～ 5 - CHANNEL）を割り当てます。チャンネルのないデバイスは、エクスポートで「switch it on in OPTIONS > INPUT > DEVICES」と表示されてスキップされます。
  2. デバイスの JST タブで 軸の役割を 1 つ変更します。ゲームがそのチャンネルの軸の行を保存するのは、このときだけです。JoyPro はその行をその場で変更するだけで、追加はしません。タブを開くだけでは何も保存されません。
  3. ゲーム内で一度 ボタンを 1 つ割り当てます。最初の割り当てでボタン ファイルが作成されます。

#よくある落とし穴

  • 軸の役割が書き込まれない：そのチャンネルにはまだ保存された軸の行がありません。ゲーム内の JST タブで軸の役割を 1 つ変更し、ゲームを閉じて、もう一度エクスポートしてください。
  • ボタンの割り当てがない：ゲームのボタンのうち、今のところ確認できているのは Primary Fire だけです。ほかのアクションは、名前が分かり次第対応します。
  • 複数の Raw Input デバイスがキーを共有している：仮想ジョイスティック で HOTAS 全体を 1 つのデバイスにまとめると、チャンネルは 1 つで済みます。
詳細

#JoyPro が読み書きするファイル

ファイル これは何か
%LOCALAPPDATA%\G_Rebels\Saved\SaveGames\SaveOptions.sav チャンネル付きのデバイス（HID パスで識別）と、各チャンネルの軸ごとに 1 行の軸の設定：役割、反転、デッドゾーン、倍率
%LOCALAPPDATA%\G_Rebels\Saved\SaveGames\EnhancedInputUserSettings.sav ボタンの割り当て。アクションとチャンネルごとに 1 つのマッピング
...\SaveOptions.sav.joypro-meta.json エクスポートした割り当てについての JoyPro のデータ（名前、グループ）。次回のインポートで読み戻されます

どちらのセーブファイルも、最初の書き込み前にバックアップされます（隣の .jpbak と JoyPro のバックアップ保存領域）。

#G-Rebels のエクスポートモード

軸ごとに 1 つの役割、アクションとチャンネルごとに 1 つのキー。軸の役割とボタンには同じルールが適用されます。

モード どうなるか
追加のみ 役割は、役割のない軸にだけ入ります。別の役割がある軸はスキップされ、「ゲームに書き込まれていません」の印が付きます。
更新（ゲームの割り当てを優先） プロファイルの役割がその軸に入ります（そこにあった役割は外れます）。役割は他の軸にも残ります。ボタン：そのキーにある別のアクションのマッピングは外れます。
更新（プロファイルを優先） 上と同じで、さらに接続されたチャンネルにある、その役割の他の軸は NONE になります。
自分のデバイスで置き換え 書き込むチャンネルの他の役割はすべて NONE になります。
+ ほかのデバイスもクリア JoyPro が書き込まない、有効で接続されたチャンネルにも同じことを行います。

#一切変更しないもの

  • キーボード、ゲームパッド、マウス、ゲームのその他のオプション。
  • デバイスが接続されていないチャンネルは役割を保ちます。
  • インポートで無視したデバイスと、JoyPro が転送先にしている vJoy デバイス。
  • ゲームのデバイス一覧：JoyPro はデバイスのオン/オフを切り替えず、チャンネルを追加することもありません。

#軸とその他の設定

  • グローバル：チャンネルごとに 1 セットの割り当て。機体ごとのプロファイルはありません。
  • 反転 は役割と一緒に書き込まれます。ハット（POV の行）、デッドゾーン、感度はまだ書き込みません。
  • ゲーム全体の設定やフォースフィードバックはありません。
  • 監視：ゲーム内で変更した役割や割り当ては、ゲーム終了後に検出されます（監視）。
  • HUD：G-Rebels の実行中、HUD が押したボタンごとにそのアクション名を表示します。
  • ゲームはデバイスごとに最大 96 個のボタンと 24 本の軸を読み取ります。ハットは読み取りません。
技術的な内部情報

#G-Rebels 連携の内部

コード：engine\Games\GRebelsIntegration.cs、engine\Games\GRebelsSaveOptions.cs、engine\Games\GvasKeyMappings.cs。

  • SaveOptions.sav：Unreal GVAS（UE 5.8、型ツリー付きのプロパティタグ）。Joysticks には S_Controller_Save { DeviceID (HID path), Enabled, MultiID (channel) } が、AxisOptions には S_Input_Axis_Save { Key, Offset, Multiplier, Role, Inverted, DeadZone } が入っています。キーは RawInput_Controller0_AxisY のような名前で、役割は列挙値です（0 Yaw、1 Thrust、2 Roll、3 Pitch、4 Side strafe、5 Up/down、6 None）。チェックサムはないため、JoyPro は固定長の値をその場で編集します。
  • EnhancedInputUserSettings.sav：Unreal Enhanced Input のプレイヤーが割り当てたキー。マッピング名は <ACTION>JST<channel>（PRIMARYFIREJST0）、キーは RawInput_Controller<channel>_Button<n> で、n は DirectInput のボタン番号です。マッピングの一覧は書き直され、他のバイトはすべてそのまま残ります。
  • デバイス：HID パスで、ゲームが割り当てたチャンネルと照合します。
  • コマンド一覧：JoyPro 独自の表（DB\GRebels\actions.tsv、軸の役割とボタン。ゲームのファイルは読み取りません）。engine grebels refresh-db はそれをゲームデータのフォルダーに書き込みます。既にある行はそのエントリを保ちます。
  • コマンド：engine grebels paths、engine grebels catalog、engine grebels scan、engine grebels import、engine grebels export --mode clean|add|merge|merge-overwrite --nuke-untouched-devices --dry-run。

#既知の制限

  • ハット、デッドゾーン、感度は書き込みません。
  • ボタンのうち、ゲーム内で確認済みなのは Primary Fire だけです。
  • エントリは追加しません：チャンネル、軸の行、ボタンのファイルは、ゲームによって作られている必要があります。
  • テスト：engine\tests\smoke\grebels.ps1。ゲーム内では tools\e2e\games\GRebelsSettings.ps1（2 回起動：1 回目で vJoy にチャンネルを割り当てて軸の行を保存し、2 回目でランダムな役割と JST0 の Primary Fire を確認。セーブフォルダーは後で元に戻します）。
