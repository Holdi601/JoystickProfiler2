初心者向け

#3 ステップで使えるようにする

  1. すべて自動で設定
    スタート ページで
  2. このボタンを使う
    先に一覧を確認
  3. ゲームに書き込む
    Elite Dangerous は閉じたまま

事前準備：ゲームで操作設定を一度保存します。艦船の操作を 1 つ変更して保存し、ゲームを閉じます。

その後：ゲームを起動するときは、プリセットのデバイスをすべて接続しておきます。割り当ては Options > Controls にあります。

以前に Elite Dangerous でボタンを割り当てたことがありますか？ その場合、スタート ページに インポートしてから空きを埋める が表示されます。今の割り当てはそのまま残り、空いているボタンにだけ新しい役割が付きます。クイック スタート：スティックを使えるようにする を参照してください。

#JoyPro が Elite Dangerous で行うこと

  • インポート：スティック、スロットル、パネルにある艦船の飛行の割り当てを、反転とデッドゾーン、スロットルが前進のみか後進ありかの設定ごとプロファイルに取り込みます。
  • リレーション：1 つのリレーションは、すべてのゲームで 1 つの機能です。「Landing gear」を Elite、Star Citizen、DCS で同じスイッチにできます。
  • エクスポート：JoyPro は Ship プリセット（Custom.4.x.binds）をその場で編集します。ファイルのほかの内容はそのまま残ります。

#Elite の割り当てをインポート

  1. スタート を開きます。Elite Dangerous のカードがコマンド リストを求めたら、リスト作成 を押します。JoyPro はゲーム付属のプリセットと、あなたが保存したプリセットからゲームのアクションを集めます（読み取りのみ）。
  2. Elite Dangerous のカードの インポート を押します。プロファイルに追加 のままにします。飛行用のキーも JoyPro に取り込みたい場合は、キーボードのキーも取り込む にチェックを入れます。
  3. 今すぐインポート を押します。リレーションを表示 で取り込んだ内容を開けます。

軸の半分をボタンやモディファイアとして使う割り当ては、JoyPro のプロファイルでは扱えません。インポートでは警告付きでスキップされ、エクスポートではゲーム内にそのまま残ります。

#リレーションの作成と確認

リレーションの流れ で各ゲームの同じ機能をまとめます。そのあとエクスポート ページで 確認 を押します。確認では、1 つのボタンが 2 つの役割を持つ箇所のほかに、前回のエクスポートで置き場所がなかった割り当てを ゲームに書き込まれていません の下にすべて表示し、別のボタンへ移動 と このままにする を選べます。

#Elite へのエクスポート

  1. Elite Dangerous を閉じます。 ゲームの起動中は JoyPro が書き込みを拒否します。
  2. エクスポート を開き、Elite Dangerous のカードにチェックを入れます。
  3. JoyPro でスティックを設定しているなら、自分のデバイスで置き換え と ほかのデバイスもクリア をオンのままにします。カードの 今すぐエクスポート を押します。
  4. 結果を確認してください。収まらなかった割り当てと、JoyPro が残した半軸の割り当てが、分かりやすい言葉で表示されます。
ゲーム内: Elite Dangerous での表示

ゲームを起動して Options > Controls を開き、艦船の操作設定を開きます。割り当ては各アクションの Primary 列または Secondary 列に、残しておいたキーボード キーと並んで表示されます。反転した軸には INVERTED が表示され、スロットルの軸範囲には Forward only または Full range が表示されます。ヨーからロールへの変換と頭の向きの行には、JoyPro で設定した値が表示されます。

#Elite で自分で行うこと

  • ゲームで操作設定を一度保存します。 JoyPro が書き込むのは、自分で保存したプリセットだけです。Ship の操作設定がまだゲーム付属のプリセット（Generic Joystick やゲームの HOTAS プリセット）のままなら、Options > Controls（Ship）で操作を 1 つ変更して保存し、ゲームを閉じます。すると Elite が Custom.4.x.binds を作成して使うようになります。
  • ゲームを起動するときは プリセットのデバイスをすべて接続しておきます。見つからないデバイスが含まれるプリセットは、Elite がまるごと無視します。接続されていないデバイスがプリセットに含まれていると、JoyPro が警告します。

#よくある落とし穴

  • 「Elite Dangerous が実行中です」：ゲームを終了し、もう一度エクスポートします。
  • 「No free place in the game」：Elite はアクションごとに入力を 2 つ持ちます。キーボード キーが 1 つの枠を使っていて、2 つのリレーションがそのアクションを 2 つのボタンに割り当てている場合、収まるのは最初のボタンだけです。2 つ目を移動するか、そのままにしてください。
  • 同じスティックが 2 本：Elite はデバイスを USB ID だけで区別します。同じモデルのデバイスを 2 台接続すると、ゲームのインデックスと対応付けられないため、JoyPro は両方をスキップします。
  • ゲームが別のプリセットを読み込んだ：起動時にプリセットのデバイスが 1 台足りませんでした。そのデバイスを接続するか、JoyPro で交換するか、ゲーム内でその割り当てを消してください。
  • Elite には ハットの斜め方向 がありません。ハットごとに 4 方向です。
詳細

#JoyPro が読み書きするファイル

ファイル これは何か
%LOCALAPPDATA%\Frontier Developments\Elite Dangerous\Options\Bindings\<preset>.4.<minor>.binds あなたのプリセット（XML）：Primary と Secondary を持つすべてのアクション、Binding・Inverted・Deadzone を持つ軸、ThrottleRange などの値の設定。JoyPro は Ship プリセットの最新のマイナーバージョンに書き込みます。
...\Bindings\StartPreset.4.start 各カテゴリー（General、Ship、SRV、On Foot）がどのプリセットを使うか。読み取り専用
...\Bindings\<preset>.4.<minor>.binds.joypro-meta.json 書き込んだ割り当ての JoyPro の名前、グループ、モディファイア、チューニング。次回のインポートで読み戻されます
...\Bindings\<preset>.4.<minor>.binds.jpbak 最初の書き込み前のコピーと、JoyPro のバージョン管理されたバックアップ保存領域
<install>\Products\<product>\ControlSchemes\*.binds、DeviceMappings.xml 標準のプリセットとゲームのデバイス名。読み取り専用

ファイルはテキストとして編集されます：改行コード、タブ、宣言、重複した要素、値の設定、キーボードレイアウト、未知の要素はバイト単位でそのまま残ります。JoyPro はインストールフォルダーには書き込まず、StartPreset.4.start も編集せず、古い 3.x クライアントのファイルにも一切触れません。

ギャラクシーマップのアクションは General プリセットに属します。JoyPro がそれを書き込むのは、General と Ship が同じファイルを使う場合だけです。そうでなければ警告付きでスキップします。

#Elite のエクスポートモード

どのモードも、飛行アクションと、接続されたジョイスティックの枠だけを対象に動作します。

モード プリセットで起きること
追加のみ 割り当ては空いている枠にだけ入ります。別の飛行アクションが使っている入力への割り当ては書き込まれず、「ゲームに書き込まれていません」の印が付きます。
更新（ゲームの割り当てを優先） あなたが使う入力にある、別の飛行アクションの枠は解除されます。割り当てはまず空いている枠に入るため、移動したアクションも、空きがある間は古い入力を保ちます。
更新（プロファイルを優先） 上と同じで、さらに割り当てるすべてのアクションが、あなたのジョイスティック上の他の枠を失います（キーボードはキーボードのオプション使用時のみ）。
自分のデバイスで置き換え 書き込むデバイスでは、そのデバイスの割り当てがあってプロファイルにない飛行用の枠をすべて空にします（{NoDevice}。軸は Inverted 0 と Deadzone 0 にもなります）。
+ ほかのデバイスもクリア エクスポートで使わない接続済みジョイスティックの飛行用の枠にも同じことを行います。

キーボードのキー、マウスやゲームパッドの入力、JoyPro が書き込まないデバイスを持つ枠は、決して上書きされません。空いた枠がなければ、割り当ては書き込まれず、プロファイルに印が残ります（「Binds Not Written, No Free Place In The Game」）。唯一の枠にプロファイルの別の軸がある軸アクションも同様です。

#一切変更しないもの

  • SRV、徒歩、カメラ、入植、UI、マウスのアクション（同じファイルにあっても対象外）。
  • キーボード、マウス、ゲームパッドの枠。キーボードはキーボードのオプション使用時にだけ書き込み、空にすることはありません。
  • 接続されていないデバイスの枠、インポートで無視したデバイス、JoyPro が転送先にしている vJoy デバイス。
  • 半分の軸の割り当てと半分の軸のモディファイア：エクスポートはそれらを残し、それぞれを名前で報告します。例：「'Cycle Next Ship': kept the game's bind ... with ... RZ axis, positive half as modifier」。
  • アクションの <Hold> と <ToggleOn> はそのまま残ります。

#艦船、カーブ、ゲーム設定

  • 単位：すべての艦船とファイターで 1 つの Ship プリセット。SRV と徒歩のプリセットには書き込みません。
  • モディファイア：枠ごとに最大 3 つ。キーや任意のデバイスのボタンを使えます。JoyPro はモディファイアをゲームの <Modifier> エントリとして書き込みます。
  • 軸の設定：軸アクションごとに反転とデッドゾーン（0 ～ 1）。Elite には飽和やカーブはありません。反転はリレーションで DCS の向きを保ちます：Elite ではピッチ、スロットル、垂直スラスターの向きが逆なので、これらの軸ではファイルの Inverted はあなたの反転を逆にしたものになります。スロットルのリレーションの スライダー は Throttle Axis Range を決めます：スライダーあり = 前進のみ、スライダーなし = 後退を含む全範囲（複数のスロットルのリレーションで食い違うと警告）。
  • ゲーム設定：ヨーをロールに（通常、フライトアシストオフ、着陸）、その感度、キーボードのスロットル増分、ヘッドルックのモード、増分、感度、スムージング、トグル時のリセット。設定 > ゲームのフォースフィードバック設定（Elite Dangerous を選択）または engine ffb set で設定します。書き込むのはあなたが設定したものだけで、その場で書き換えます。ファイルにない設定は報告するだけで、追加はしません。マウス、SRV、徒歩の設定は管理しません。
  • フォースフィードバック：Elite にはジョイスティック用のものがありません。
  • テレメトリ記録：JoyPro は Status.json とジャーナル（Saved Games\Frontier Developments\Elite Dangerous、読み取り専用）を CSV セッションとして記録できます。ゲームはワールド上の位置を出さないため、Tacview のトラックはありません。
  • 監視：ゲームの操作メニューで変更した割り当てはゲーム終了後に検出され、JoyPro がそれを取り込むかどうかを尋ねます。ゲームがプリセットを書き込むのは、操作メニューで保存したときだけです。
  • HUD：HUD はプロセスからゲームを見つけ、Elite の割り当てを表示します。
技術的な内部情報

#Elite 連携の内部

コード：engine\Games\EliteDangerousIntegration.cs、軸モデル engine\AxisModels\EliteDangerous.cs、設定モデル engine\FfbModels\EliteDangerous.cs。

  • デバイス ID：%04X%04X、USB のベンダー ID とプロダクト ID を大文字の 16 進で表したもの（231D0125）。インストール先の DeviceMappings.xml に載っているデバイスは、代わりにシンボル名で書き込みます（T16000M、ThrustMasterWarthogJoystick、VPCThrottle、Alternatives も含む）。JoyPro が書き込むのは接続済みのデバイスだけです。同一のデバイスが複数あるとゲームの DeviceIndex が必要になりますが、その順序は文書化されていないため、スキップします。
  • 入力名：ボタンは Joy_1 ... Joy_N、Joy_POV<h>Up/Right/Down/Left（ハット 1 ～ 4）、Joy_XAxis ... Joy_RZAxis、スライダーは Joy_UAxis / Joy_VAxis、キーボードは Key_*。Pos_Joy_* / Neg_Joy_*（半分の軸）は作成しません。
  • 反転：ファイルの Inverted = リレーションの反転 XOR アクション本来の向き（PitchAxisRaw、ThrottleAxis、AheadThrust、VerticalThrustRaw、それらの代替と着陸用のコピー、HeadLookPitchAxisRaw、CamTranslateYAxis、ExplorationFSSRadioTuningX_Raw は 1、それ以外の軸は 0）。インポートも同じ方法で読み戻します。軸を逆向きに報告するデバイスは DCS でも反転が必要で、XOR によってそれが引き継がれます。
  • コマンド一覧：engine elite refresh-db は、ゲームが書いた .binds（ゲームが知っているすべての要素名を含む）と標準のプリセットを読み取ります（読み取り専用）。追加されるのは艦船の飛行用の要素だけで、既知のアクションは ID と名前を保ちます。engine elite catalog は一覧を表示し、engine elite paths は JoyPro が見つけたファイルを表示します。
  • インポート / エクスポート：engine elite import と engine elite scan。engine elite export --mode clean|add|merge|merge-overwrite --nuke-untouched-devices --include-keyboard --ignore-device <d> --dry-run。
  • ゲーム設定：engine ffb set --device * --game EliteDangerous --param <key>=<value>（yawToRollMode、yawToRollSensitivity、throttleIncrement、headlookAccumulate など）。

#既知の制限

  • 同一のデバイスが 2 台あるとスキップされます。デバイスが 1 台でも見つからないと、ゲームはプリセット全体を無視します。
  • ゲームのメニューにあるデッドゾーンのスライダーの目盛りと、デッドゾーンの外側をゲームがどう再スケーリングするかは、まだ確認されていません。
  • ボタン：プレイヤーの報告では約 32 個です。それより大きな番号でも動作した例があります。ハットは 4 つで、斜めはありません。
  • ファイルにないアクションは警告付きでスキップされます（追加できるかはまだ確認されていません）。
  • テスト：engine\tests\smoke\elite.ps1。ゲーム内では tools\e2e\games\Elite.ps1（割り当てとモードの組み合わせ）と tools\e2e\games\EliteSettings.ps1（反転の向き、スロットルの範囲、ゲーム設定）。
