War Thunder

表示：

War Thunder は操作設定を machine.blk に保存します。これは、最初に選んだプリセットとの違いだけを持つテキストファイルです。JoyPro は航空機とヘリコプターの操作設定をプロファイルに読み込み、その場で書き戻します。戦車、艦艇、メニューの操作設定はそのまま残ります。ゲームはこのファイルのコピーを Gaijin のサーバーにも保存しています。JoyPro は、次回のログイン時にエクスポートしたファイルが優先されるように書き込みます。

初心者向け

#3 ステップで使えるようにする

  1. すべて自動で設定
    スタート ページで
  2. このボタンを使う
    先に一覧を確認
  3. ゲームに書き込む
    War Thunder は閉じたままで

事前に：一度ログインしてください。デバイスを接続してゲームを起動し、Controls を一度開いてから終了します。

その後：ログインしてください。割り当ては Controls に入っています。

以前に War Thunder でボタンを割り当てていましたか？ それならスタートページに インポートしてから空きを埋める が表示されます。今の割り当てはそのまま残り、空いているボタンだけに新しい役割が付きます。クイックスタート：スティックを使えるようにする を参照してください。

#JoyPro が War Thunder に対して行うこと

  • インポート：デバイス上の航空機とヘリコプターのショートカットと軸が、ゲームの Axis setup ダイアログのすべての値、ゲーム全体の操作オプション（感度、反転、WEP、オートトリム、フォースフィードバック）と一緒にプロファイルに入ります。
  • リレーション：1 つのリレーションは、すべてのゲームで 1 つの機能です。「Gear」を War Thunder、DCS、IL-2 で同じスイッチにできます。
  • エクスポート：JoyPro は machine.blk をその場で編集します。戦車、艦艇、潜水艦、歩兵、メニューには一切触れません。

#War Thunder の割り当てをインポート

  1. 開始 を開きます。War Thunder のカードがコマンドリストを求めている場合は リスト作成 を押します。JoyPro がゲームのアーカイブから航空機とヘリコプターのアクションを読み取ります（読み取りのみ、290 アクション）。設定 > ゲーム でこれをオフにでき、その場合 JoyPro は独自の短いリストを使います。
  2. War Thunder のカードの インポート を押します。プロファイルに追加 のままにします。フライト用のキーも JoyPro に取り込みたい場合は キーボードのキーも取り込む にチェックを入れてください。
  3. 今すぐインポート を押します。リレーションを表示 で取り込んだ内容を開けます。

#リレーションの作成と確認

リレーションの流れ でゲーム間の同じ機能をつなげ、エクスポートページで 確認 を押してください。War Thunder では、飛行機のスロットルとヘリコプターのコレクティブが 1 つの軸にあっても問題ありませんが、1 つのボタンに 2 つの航空機アクションがあるのは問題です。

#War Thunder へエクスポート

  1. War Thunder を閉じてください。 ゲームは実行中にときどき、また終了時にファイルを保存するため、実行中は JoyPro が書き込みを拒否します。
  2. エクスポート を開き、War Thunder のカードにチェックを入れます。
  3. JoyPro でスティックを設定しているなら、自分のデバイスで置き換え と ほかのデバイスもクリア をオンのままにします。カードの 今すぐエクスポート を押します。
ゲーム内: War Thunder での表示

ゲームを起動してログインします。格納庫で Esc を押し、Controls を開きます。割り当ては航空機とヘリコプターのセクションにあります。軸の Axis setup ダイアログには、デッドゾーン、非線形性、倍率、補正、反転が表示されます。感度の行、フォースフィードバックの倍率、オートトリムは Realistic と Full-real の操作モードでのみ表示されます。Mouse aim / Simplified / Realistic / Full-real のタブをクリックすると操作モードが変わります。一覧の絞り込みではありません。

#War Thunder で自分で行うこと

  • ゲームにすべてのデバイスを一度認識させてください。 War Thunder はボタンと軸に、デバイスごとに独自の表で番号を付けます。デバイスを接続してゲームを起動し、Controls を開くと、ゲームがそのデバイスを machine.blk に追加します。ゲームがまだ認識していないデバイスは JoyPro が飛ばします。
  • 最初のエクスポートの前に一度ログインして、アカウントのファイルが作られるようにしてください。

#よくある落とし穴

  • 「War Thunder が実行中です」：ゲームを終了して、もう一度エクスポートしてください。
  • デバイスが飛ばされた：ゲームがそのデバイスをまだ認識していない、接続中の 2 台のデバイスが同じ VID:PID を持っている、またはボタン数や軸数がゲームの記録と違う（すべての番号がずれる）のいずれかです。デバイスを接続した状態でゲームの Controls を開いてください。
  • ログイン後に古い割り当てが戻った：コピーを手動で復元しています。代わりに 前回のエクスポートを元に戻す を使ってください。JoyPro がファイルのバージョンを上げるので、サーバーに置き換えられません。
  • ハットの斜め方向、マウスボタン、軸のモディファイア は書き込めません。
詳細

#JoyPro が読み書きするファイル

ファイル これは何か
%USERPROFILE%\Documents\My Games\WarThunder\Saves\<uid>\production\machine.blk 操作設定（hotkeys{}、axes{}、params{}、deviceMapping{}）とゲームの設定ブロック。<uid> は自分のアカウントです（Saves\lastlogin.blk に書かれています。ログイン前は Saves\last）
...\production\machine.blk.joypro-meta.json 書き込んだ割り当ての JoyPro の名前、グループ、チューニング。次回のインポートで読み戻されます
machine.blk.jpbak 最初の書き込み前のコピーと、JoyPro のバージョン管理されたバックアップ保存領域
エクスポートされた操作プリセット（先頭に controls{}） これもインポートとエクスポートができます。ゲーム全体のオプションは machine.blk にだけ書き込みます

machine.blk は、basePresetPaths に書かれた基本プリセットとの差分です。ショートカットの最初のブロックは、そのショートカットのプリセットの一覧全体を置き換えます。空の ID_X{} は未割り当てを意味し、軸の属性がない場合は「プリセットの値」を意味します。JoyPro が書き込むのは、カタログにあるショートカットのブロック、axisId とカタログにある軸の軸の値、そして設定した個々のオプション キーです。ほかのすべての行は元のテキストのままです。deviceMapping{} は読み込むだけです。

#War Thunder でのエクスポート モード

対象になるのは、カタログにある航空機とヘリコプターの操作だけです。競合とは、同じ入力にある別のこれらの操作のことです。

モード machine.blk で起きること
追加のみ ショートカットは、ほかの航空機やヘリコプターの操作がその入力を使っていない場合にだけ書き込みます。ブロックを削除したり、割り当て済みの軸を置き換えたりすることはありません。読み飛ばした割り当てには「ゲームに書き込まれていません」と表示されます。
更新（ゲームの割り当てを優先） 自分のショートカットは、その操作のほかのショートカットと並べて入れます。削除するのは競合だけです（自分の軸にある別の操作の軸は axisId -1 になります）。
更新（プロファイルを優先） 上記に加え、割り当てた操作は、ゲームが一覧に載せている接続中のデバイスでほかのショートカットを失います（キーボードはキーボードのオプションを使う場合のみ）。
自分のデバイスで置き換え 上記に加え、書き込んだデバイスのほかの航空機とヘリコプターのショートカットと軸が解除されます。
+ ほかのデバイスもクリア プロファイルに割り当てのない接続済みデバイスにも同じことを行います。

空の ID_X{} は、JoyPro がその操作を割り当てると置き換えられます。ファイルにない操作には警告が出ます。その場合、自分のショートカットが基本プリセットの既定値を置き換えます。

#一切変更しないもの

  • 戦車、艦船、潜水艦、歩兵、メニューのショートカットと軸。
  • deviceMapping{}、config{}、そして JoyPro が設定しないすべての設定行。
  • マウスの割り当て、接続されていないデバイス、インポートで無視したデバイス、JoyPro が入力を送り込む vJoy デバイス。
  • キーボード（キーボードの割り当てをエクスポートする場合を除く）。
  • 相対操作、値の保持、軸の範囲は、自分で設定しない限りファイルのままです。

#機体、カーブ、ゲームのオプション

  • 適用範囲：すべての航空機に 1 セット、すべてのヘリコプターに 1 セットの操作です（ゲームに機体ごとの割り当てはありません）。
  • モディファイア：ショートカットの最後のボタンがメインの入力で、ブロック内のほかのボタンやキーはそのモディファイアです。1 つのショートカットにつき、代わりの組み合わせは最大 3 つです。
  • 軸カーブ：Axis setup ダイアログに表示されるとおり、ゲーム自身の単位で扱います：デッドゾーン（0 ～ 0.5）、非線形性（0 ～ 3、表示は 1 ～ 4）、倍率、補正、反転、相対操作とその感度とステップ、無効な軸の値の保持。War Thunder の値を持たないリレーションは、JoyPro のカーブを近似して変換します：倍率 = 1 / 飽和 X、デッドゾーンはそれに合わせて拡大し、非線形性は最も近い値になります。スライダーは、デッドゾーンと飽和の間の動きを全範囲に割り当てます。基本プリセットと同じ値の行は、ゲーム自身の保存方法と同じく削除します。
  • ゲームのオプション：航空機用とヘリコプター用のロール、ピッチ、ヨーの感度、Y 軸反転（航空機、ヘリコプター）、スロットル反転、WEP のためのスロットル保持、オートトリム、フォースフィードバックのオン（ゲームの再起動が必要）とその倍率。設定 > ゲームのフォースフィードバック設定（War Thunder を選択）か engine ffb set で設定します。War Thunder の割り当てがないエクスポートでも書き込まれます。インポートはファイルの値を取り込みます。
  • クラウドのコピー：ゲームはログイン時に、ファイルの 1 行目 version:i=N をサーバーのものと比べます。JoyPro はバージョンを保つので、新しい内容がアップロードされます。前回のエクスポートを元に戻す は、復元したファイルに置き換え前より大きいバージョンを付けるため、サーバーのコピーが戻ってくることはありません。
  • テレメトリによるフォースフィードバック：フォースフィードバック ページは、ゲームのローカル Web サーバー（127.0.0.1:8111。実行中のゲームが提供し、設定は不要）からフォースフィードバック スティックを動かします。そのスティックでは、ゲーム自身のフォースフィードバックをオフにしてください。
  • テレメトリ記録：JoyPro は同じサーバーから出撃を記録し、CSV または Tacview 用にエクスポートできます（ゲームに実際の地理的な位置がないため、0/0 を中心とした平面の地図になります）。
  • 監視機能：ゲームで変えた割り当て、軸の値、オプションは、ゲームを閉じたあとに検出されます。キーの並び替えやゲームの差分の書き方の違いは、変更と見なしません。
  • HUD：HUD はプロセスからゲームを見つけ、War Thunder の割り当てを表示します。
技術的な内部情報

#War Thunder 連携の内部

コード：engine\Games\WarThunderIntegration.cs、engine\Games\WarThunderVromfs.cs、軸モデル engine\AxisModels\WarThunder.cs、設定モデル engine\FfbModels\WarThunder.cs。

  • デバイス：deviceMapping{ joystick{ devId:t="0738:2215" name:t="..." buttonsOffset:i= buttonsCount:i= axesOffset:i= axesCount:i= } }。devId は DirectInput の製品の VID:PID です。ゲームは devId だけでデバイスを照合するため、同じデバイスが 2 台あると 1 台にまとめられます。joyButton = buttonsOffset + デバイス内の番号（ボタン、続いてハットごとに 4 つ：上、右、下、左）。axisId = axesOffset + DirectInput の順序（X、Y、Z、Rx、Ry、Rz、スライダー 2 つ）でのデバイス内の番号で、そのあとにハットごとに 2 つ続きます。engine games devices は、JoyPro がデバイスごとに何を認識しているかを表示します。
  • 形式：BLK テキスト、name:type=value。ブロック名は繰り返し出てきます（順序付きリストとして解析）。改行は CRLF です。controls.version が 5 未満のファイルは旧形式なので読み込みません。
  • コマンド一覧：engine warthunder refresh-db は gui.vromfs.bin から shortcutsgroupaircraft.nut と shortcutsgrouphelicopter.nut を、lang.vromfs.bin（lang/controls.csv）からタイトルを読み込みます。これらは一時フォルダーに展開され、あとで削除されます。残るのは ID とタイトルだけです。--no-game-archives（設定 > ゲーム で「War Thunder: ゲームのアーカイブから完全なコマンド リストを読み込む」のチェックを外す）は、JoyPro 独自の 116 アクションの一覧を使います。ID_ の付かない ID は軸です。--path には、操作スクリプトを通常のファイルとして置いたフォルダーを指定します。
  • インポート / エクスポート：engine warthunder import、engine warthunder scan。engine warthunder export --mode clean|add|merge|merge-overwrite --nuke-untouched-devices --include-keyboard --ignore-device <d> --dry-run。
  • 基本プリセット：公式プリセットの値の表がないため、エクスポートは調整したすべての軸の属性を明示的に書き込みます（「基本と同じ」として行を削除することはありません）。そのため、基本プリセットが何であってもファイルは正しくなります。インポートは、ファイルが設定していない属性にコードの既定値を使います。
  • ゲームのオプション：engine ffb set --device * --game WarThunder --param <key>=<value>（joyFX、forceGain 0..100、aileronsMultiplier など（% 単位）、invertY、invertYHelicopter、invertT、holdThrottleForWEP、autotrim）。
  • テレメトリ：engine ffb telemetry setup と engine telemetry record。JoyPro はゲームの実行中だけ、/state を 1 秒に 20 回、/indicators を 2 回に 1 回の割合で問い合わせます。

#既知の制限

  • 基本プリセットの値の表は同梱していません（上記を参照）。
  • 監視機能の実行で「WEP のためのスロットル保持」の変更を 1 回見逃したことがあり、感度の 1 つが 1 ずれて読み戻されたことがあります。
  • デバイスごとにボタン 128 個とハット 4 つまで読み込みます。ハットの斜め方向、マウス ボタン、軸のモディファイアは書き込みません。
  • テスト：ゲーム内で tools\e2e\games\WarThunderSettings.ps1（vJoy 軸への割り当て、ピッチとスロットルの Axis setup ダイアログ、Controls ページの値、ゲームが書き直したファイルのインポート）。
