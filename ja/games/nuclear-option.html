Nuclear Option

表示：

Nuclear Option は、ジェット機、VTOL、ヘリコプターが登場する空戦フライト ゲームで、割り当てはすべての機体で共通の 1 セットです。操作設定はファイルではなく Windows のレジストリに保存され、デバイスごとに 1 つの Rewired ジョイスティック マップを、ゲームの Control Mapper が書き込みます。JoyPro はこれらのマップをプロファイルに読み込み、Flight Controls の割り当てを書き戻します。カメラ、ゲームプレイ、チャットの割り当てはそのまま残ります。

初心者向け

#3 ステップで使えるようにする

  1. すべて自動で設定
    スタート ページで
  2. このボタンを使う
    先に一覧を確認
  3. ゲームに書き込む
    Nuclear Option は閉じたまま

事前準備：Nuclear Option を一度起動し、閉じます。

その後：割り当ては Settings > Controls > Open Control Bindings Menu の、デバイスのタブにあります。

以前に Nuclear Option でボタンを割り当てたことがありますか？ その場合、スタート ページに インポートしてから空きを埋める が表示されます。今の割り当てはそのまま残り、空いているボタンにだけ新しい役割が付きます。クイック スタート：スティックを使えるようにする を参照してください。

#JoyPro が Nuclear Option で行うこと

  • インポート：接続中のデバイスのジョイスティック マップを取り込みます。反転設定付きの軸、ボタン、軸上のボタン（たとえば「Increase Throttle」）が対象です。
  • リレーション：1 つのリレーションは 1 つの機能です。Nuclear Option には機体別の一覧がないため、リレーションはすべての機体に適用されます。
  • エクスポート：JoyPro は各デバイスのマップをその場で編集し、書き込むのは Flight Controls のアクションだけです。ゲームに保存済みのマップがないデバイスには、割り当てを入れた新しいマップを作ります。

#割り当てをインポート

  1. Nuclear Option を一度起動し（レジストリ キーを作成させるため）、閉じます。
  2. スタート を開き、Nuclear Option のカードの インポート、続いて 今すぐインポート を押します。

#リレーションの作成と確認

ほかのゲームと同じようにリレーションを作ります（リレーションの流れ）。セットアップ ウィザードと自動割り当ては、このゲームの機能を知っています。そのあと、エクスポート ページで 確認 を実行します。

#Nuclear Option へのエクスポート

  1. Nuclear Option を閉じます。 ゲームの実行中は JoyPro が書き込みを拒否します。ゲームは、割り当てメニューを閉じたときとデバイスを取り外したときにマップを書き込むためです。
  2. エクスポート を開き、自分のデバイスで置き換え と ほかのデバイスもクリア のまま、Nuclear Option のカードの 今すぐエクスポート を押します。
ゲーム内: Nuclear Option での表示

Settings > Controls > Open Control Bindings Menu を開きます。Control Mapper にはデバイスごとにタブがあります。上部で自分のデバイスをクリックすると、Flight Controls の割り当てがゲームの名前（たとえば Pitch、Roll、Yaw、Throttle）で表示されます。カメラ、ゲームプレイ、チャットの割り当ては変わりません。

#Nuclear Option で自分で行うこと

  • 最初のインポートまたはエクスポートの前に ゲームを一度起動 し、レジストリ キーを作成させます。
  • ゲームの操作設定にある Use Throttle Axis Negative Region：スロットル軸の全範囲を使うにはオンのままにします。これがオフで、プロファイルでスロットル軸を割り当てていると、JoyPro が警告します。
  • ハット：今のところ、ハットの方向はゲーム内で割り当ててください。JoyPro はまだ書き込みません。

#よくある落とし穴

  • 「Nuclear Option が実行中です」：ゲームを閉じて、もう一度エクスポートします。
  • デバイスがスキップされる：同じモデルのデバイスを 2 台接続している場合（またはゲーム コントローラーとしても認識されるキーボードがある場合）、ゲームのマップでは区別できません。JoyPro は警告を表示してそれらを除外します。
  • デバイスにゲームの既定の割り当てが残る：ゲームに保存済みのマップがない接続デバイスは、ゲームの既定のマップを使いますが、JoyPro はそれを読み取れません。ほかのデバイスもクリア でもそのデバイスには触れません。JoyPro でそのデバイスに何か割り当てるか、Control Mapper でそのタブを一度空にしてください。
  • スロットルが中央で止まる：Use Throttle Axis Negative Region を確認してください（上記参照）。
詳細

#JoyPro が読み書きするもの

場所 これは何か
HKCU\Software\Shockfront\NuclearOption レジストリにあるゲームの Unity 設定。Rewired の値はバイナリー（UTF-8 テキストと 1 バイトのゼロ）で、名前は _h<hash> で終わります
デバイスごとの値で、名前に dataType=ControllerMap とデバイスの hardwareIdentifier を含みます 1 つのデバイスのジョイスティック マップ（Rewired XML）。プレイヤー Player0 用
同じ名前で dataType=ControllerMap_KnownActionIds のもの マップが知っているアクション ID。JoyPro は新しいマップと一緒に書き込みます
<install>\NuclearOption_Data\resources.assets ゲームの Rewired アクション一覧。読み取り専用で、コマンド一覧に使います
%LOCALAPPDATA%\JoyPro2\GameMetadata\HKCU_Software_Shockfront_NuclearOption.joypro-meta.json エクスポートした割り当ての JoyPro での名前、グループ、調整。次回のインポート用

最初に書き込む前に、JoyPro は Player0 のコントローラー マップの値のスナップショットをバックアップ保管場所に取ります。前回のエクスポートを元に戻す はそれを書き戻し、JoyPro が追加したマップの値を削除します。値の名前には 255 文字を超えるものがあるため、JoyPro はレジストリ API を使います（Regedit や reg export ではすべては表示されません）。

#Nuclear Option でのエクスポート モード

モード デバイスのマップで起きること
追加のみ ゲームの内容は何も変わりません。ボタンや軸がすでに別のアクション（または軸の反対側）を動かしている割り当ては除外され、一覧に表示されます。
更新（ゲームの割り当てを優先） 別のアクションに割り当てた入力にある Flight Controls のアクションは、その入力を失います。そのアクションのほかの入力は残ります。
更新（プロファイルを優先） 上記に加え、割り当てたすべてのアクション（または軸の片側）は、JoyPro が読み込める接続中のすべてのデバイスで、ほかの入力を外されます。
自分のデバイスで置き換え 書き込んだデバイスのほかの Flight Controls アクションはすべて解除されます。
+ ほかのデバイスもクリア 接続中のデバイスのほかの保存済みマップにある Flight Controls アクションが解除されます。保存済みマップのないデバイスは、ゲームの既定のマップのままです。

#一切変更しないもの

  • Flight Controls 以外のすべてのアクション：カメラ、ゲームプレイ、チャット、デバッグ、ミッション エディターの割り当て。
  • キーボードとマウスのマップ、キャリブレーションのマップ、入力の動作、コントローラーの割り当て先、そしてすべてのゲーム設定（グラフィック、ThrottleUseNegative やその他の操作オプション）。
  • 接続されていないデバイス、同じモデルが 2 台以上あるデバイス、インポートで無視したデバイス、JoyPro が入力を送り込む vJoy デバイス。
  • 編集したマップのうち、JoyPro が変更する要素マップ以外のすべて。MOD のアクションの割り当ても含みます。

#適用範囲、カーブ、その他

  • 適用範囲：全体共通で、すべての機体に 1 セットの割り当てです（Throttle アクションはヘリコプターのコレクティブも兼ねます）。
  • 軸カーブ：書き込みません。ゲームのキャリブレーションのデッドゾーンはそのままです。
  • キーボードとモディファイア：書き込みません。ゲームのジョイスティック割り当てにはモディファイアがありません。
  • ハット：まだ読み書きしません。スライダーは警告付きで書き込みます。
  • フォースフィードバック、テレメトリ：なし。
  • 監視機能：ゲームのキーに対するレジストリの変更通知を使います。フィンガープリントの対象は Player0 のコントローラー マップのみです（監視機能）。
  • HUD：HUD はプロセス（NuclearOption）からゲームを見つけます。
技術的な内部情報

#Nuclear Option 連携の内部

コード：engine\Games\NuclearOptionIntegration.cs（レジストリの保存先、このゲーム固有の処理、カタログの構成）が、engine\Games\RewiredMapIntegration.cs（Rewired のジョイスティック マップの読み書き。Tiny Combat Arena と共通）の上に乗っています。

  • 値の名前：Unity はすべてのキーに _h<hash> を付けます（UTF-8 のキーに対する XOR 版 djb2、10 進数）。
  • デバイス：一般的な HOTAS デバイスはどれもゲームの Rewired に認識されないため、そのマップの hardwareGuid はゼロで、hardwareIdentifier は WindowsRawInput + 空白を除いた HID の製品文字列 + PID + VID（それぞれ大文字の 16 進 4 桁）です。duplicate は同じモデルのデバイスの数を数えます。JoyPro はモデルごとに 1 台だけを扱います。
  • 要素：軸 X、Y、Z、Rx、Ry、Rz が 0 ～ 5、スライダーが 6 と 7、ボタン n が 31 + n です。軸アクションに割り当てたボタンは <Action>.Positive / .Negative（axisContribution 0 / 1）になります。ゲームの既定のマップは、Pitch、Roll、Yaw、Throttle、Brake を軸 0 ～ 4 に、さらに 11 個のボタンを割り当てています。
  • 書き込み：変更するのは触れた ActionElementMap ブロックだけです（ボタンは <buttonMaps>、軸は <axisMaps>）。新しいマップは sourceMapId が -1 で、既知のアクション ID の一覧を持つため、ゲームが既定の割り当てを追加することはありません。
  • コマンド一覧：engine nuclearoption refresh-db は resources.assets の中から最初のアクション（"Pitch"）を手がかりに Rewired の InputManager を見つけ、DB\NuclearOption\actions.tsv を書き出します（アクション名、タイトル、カテゴリー、Rewired の ID。軸アクションには片側ごとの行も付きます）。
  • コマンド：engine nuclearoption paths、engine nuclearoption catalog、engine nuclearoption scan、engine nuclearoption import、engine nuclearoption export。元に戻すのは engine backups restore です。

#既知の制限

  • ゲームの Rewired が認識するデバイス（hardwareGuid がゼロでないもの。たとえば T.16000M）は扱いません。
  • 保存済みマップでハットの要素 ID が確認できなかったため、ハットは読み飛ばします。スライダーの ID は Rewired の汎用定義に従います。
  • 割り当てはゲームのメニューで確認しましたが、飛行中ではまだ確認していません。ゲームが Pitch に期待する軸の向き（符号）もまだ確定していません。
  • テスト：engine\tests\smoke\nuclearoption.ps1（実際の vJoy マップに、カメラとゲームプレイの割り当てを加えたもの）。ゲーム内では tools\e2e\games\NuclearOptionSettings.ps1（ランダムな vJoy 軸に割り当てた Pitch、Roll、Yaw が Control Mapper の vJoy タブに表示され、ゲームが再保存したあとのインポートで読み戻せること）。
