主な流れ

ゲームへエクスポート

表示：

エクスポートは、スティックをゲームで使えるようにする手順です。JoyPro はリレーションと割り当てを各ゲームの操作設定ファイルに書き込みます。ゲーム自身の操作設定メニューが保存するのと同じファイルです。飛行中にバックグラウンドで動くものはありません。エクスポートが済めば、ゲームはいつもどおり自分のファイルを読みます。

初心者向け

#3 ステップでエクスポート

下部のバーで エクスポート を開きます。ページには上から下へ、番号付きのカードが 3 つあります：

  1. プロファイルを確認します。 今すぐ確認 を押します。JoyPro は、同じ機体で 1 つのボタンが 2 つの動作をするなど、ゲーム内で問題になることを探します。見つかったものは修正する（問題ごとにワンクリック）か、そのままにします。確認がエクスポートを妨げることはありません。確認 を参照してください。
  2. JoyPro がゲームに書き込む方法。 4 つの選択肢から 1 つを選びます。迷ったら最初の選択肢のまま：自分のデバイスで置き換え で ほかのデバイスもクリア にチェックを入れた状態にしてください。スティックはプロファイルのとおりに動き、それ以外の動作はしません。
  3. ゲームにエクスポート。 プロファイルに割り当てがあるゲームごとに、画像付きのカードが表示されます。ゲームにチェックを入れて 選択したゲームをエクスポート を押すか、1 つのカードで 今すぐエクスポート を押します。

先にゲームを閉じてください。 ゲームは終了時に操作設定ファイルを書き込むため、JoyPro は実行中のゲームへのエクスポートを拒否し、その旨を表示します。

#どの選択肢を選べばいい？

選択肢 選ぶ場面 ゲーム自身の割り当てはどうなるか
自分のデバイスで置き換え スティックの設定を JoyPro で行っている プロファイル内のデバイスには、あなたの割り当てだけが残ります（エクスポートする機体で）。
更新（ゲームの割り当てを優先） ゲーム内でも割り当てをしていて、それを残したい あなたの割り当てが入ります。ゲームの割り当てが削除されるのは、別の用途に使っているボタンにある場合だけです。
更新（プロファイルを優先） 上と同じだが、JoyPro でアクションを別のボタンに移した 上と同じうえで、割り当てたアクションはゲーム内のほかのボタンから外れるため、移動が本当に移動になります。
追加のみ JoyPro を初めて試す 何も削除されません。ゲームがすでにボタンを別の用途に使っている場合、あなたの割り当ては入らず、確認で知らせます。

ほかのデバイスもクリア（選択肢の下のチェック）：プロファイルに割り当てのない接続中のデバイスは、エクスポートする機体で割り当てを失います。きれいな状態から始めたいならチェックしたまま、2 台目のデバイスをゲーム内だけで使うならチェックを外してください。

#安全な設計

  • JoyPro はゲームのファイルを変更する前に バックアップにコピーします。各カードには 前回のエクスポートを元に戻す があり、ファイルをバイト単位で元どおりに戻します。
  • 独自の割り当てがすでにあるゲームへの 最初のエクスポート では、一度だけ「先にインポートしますか?」と聞かれます。ゲームで作ったものを残したいなら 先にインポート、置き換えるなら このままエクスポート を選んでください。
  • 接続されていない デバイスは割り当てを保ちます。マウス と ゲームパッド の割り当てには一切触れません。

#ゲーム内で気づくこと

ゲームを起動して操作設定メニューを開くと、各デバイスの列に、ゲームが使う名前で割り当てが入っています。DCS では機体ごと、Star Citizen では機体のアクションごと、IL-2 では Key mapping に表示されます。下の ゲーム内 のセクションに、すべての種類のゲームを記載しています。

#割り当てをゲームに届けるほかの方法

方法 内容
ゲームに書き込む（クイックセットアップ） クイックセットアップのエクスポートです。セットアップしたゲームに、同じバックアップ付きで書き込みます。クイックスタート を参照してください。
仮のコントローラー（仮想 Xbox パッド） ACE COMBAT 8 と Hell Let Loose: Vietnam には何も書き込みません。エクスポートでもそう表示されます。開始 がオンの間、スティックが仮のコントローラーを動かします。Xbox 専用ゲーム を参照してください。
DCS のニーボード 割り当てのエクスポートではありません。コックピット内で、ボタンが何をするかを機体ごとに 1 ページで一覧表示します。ニーボード を参照してください。

#ゲームごとのオプション

オプションとパス（上級者向け） の中にあります：

  • DCS：DCS カードの 機体... の一覧（チェックした機体だけを書き込みます）。DCS: キーボードの既定を維持（オン）。自分のデバイスはほかのすべての機体でも DCS の既定の割り当てを失う（オフ）。
  • Star Citizen：SC: キーボードの既定を維持、ローカルの順序を優先。
  • そのほかのゲーム：書き込まずに何が変わるかを表示する ドライ ラン のボックス。
  • パス：ゲームごとに別の Saved Games フォルダーや設定フォルダーを指定できます。このプロファイル専用のパスと無視するデバイス を使うと、PC 全体のものではなく、開いているプロファイル専用のものになります。

#印：「ゲームに書き込まれていません」

「追加のみ」（および、ゲームにもう 1 つの入力を入れる空きがないモード。たとえばアクションごとに入力が 2 つの Elite Dangerous）では、一部の割り当てが除外されます。プロファイルは、その入力を持っているゲームのアクションと日付と一緒に、それぞれを記憶します。確認では印ごとにカードが表示され、「更新」でエクスポートして置き換える、別のボタンへ移動、このままにする があります。エクスポートのたびにそのゲームと機体の印が置き換えられるため、あとのエクスポートで割り当てが書き込まれれば印は消えます。

#記憶される設定

モード、ほかのデバイスもクリア のチェック、ゲームごとのオプション、パスは JoyPro の設定に保存されます。自分でチェックしたゲームと DCS の機体は、プロファイルごとに保存されます。「置き換え」と「ほかのデバイスもクリア」はエクスポートのたびに確認します（設定 > 確認 でこの質問をオフにできます）。

#エクスポートのあと

  • カードの 前回のエクスポートを元に戻す は、そのゲームの最新のバックアップを復元します。すべての一覧は、エクスポート ページ下部の ゲーム設定のバックアップ にあります。
  • エクスポートはゲームのファイルを ゲーム監視 用に記録します。JoyPro 自身のエクスポートについて、あとで「変更を取り込みますか？」と尋ねることはありません。そのあとゲーム内で変更した場合は尋ねます（監視機能）。
  • JoyPro はゲームのファイルの隣に独自のデータを置くため、あとでインポートすると、リレーション名、グループ、モディファイア、カーブが戻ってきます（再インポート）。

#ゲーム内

エクスポート後にプレイヤーに見えるものは、ゲームの種類によって異なります。以下のゲームはすべて同じルールに従います。JoyPro はコマンドリストにあるアクションだけを書き込み、ゲームの実行中は書き込みを拒否し、先にファイルをバックアップし、照合できないデバイスやアクションを推測することはありません（警告を出して飛ばします）。

ゲーム内: フライトシミュレーター：DCS、IL-2（Great Battles、Korea、1946、Cliffs of Dover）、Falcon BMS、X-Plane、MSFS、FSX、Prepar3D

JoyPro は書き込むデバイスを引き継ぎます。置き換え では、エクスポートした機体でそれらのデバイスのほかの割り当てがすべて消えます。ほかのデバイスもクリア では、接続中のほかのデバイスもクリアされます（DCS：DCS の既定の割り当ても）。

  • DCS World：Options > Controls で機体を選ぶと、デバイスの列に割り当てが入っており、削除した既定の割り当ては空のセルで表示され、モディファイアはモディファイアの一覧にあります。変わるのはチェックした機体だけです。JoyPro は DCS 自身と同じく、DCS の既定との違いだけを書き込みます。
  • IL-2 Great Battles：Settings > Key mapping に割り当てと軸の応答が表示されます。マウスの行や JoyPro が知らない行はそのまま残ります。
  • IL-2 Korea：キーマッピングのプロファイル「General」です。
  • Falcon BMS：ランチャーが次の Launch 時にキーファイルと軸のマッピングを作成するので、BMS はランチャーから起動してください。
  • MSFS 2024 / 2020：Controls でデバイスに JoyPro のプリセットが表示されます。
  • X-Plane 11 / 12：Settings > Joystick に割り当てが表示されます。
ゲーム内: 歩兵、車両、メニューがあるゲーム：Star Citizen、War Thunder、Arma 3 / 2、Arma Reforger、WARDOGS、Nuclear Option、Hell Let Loose、Battlefield

JoyPro が触れるのは 飛行アクションだけ（航空機、ヘリコプター、宇宙船）です。徒歩、車両、メニューの割り当てはバイト単位でそのまま残ります。置き換え と ほかのデバイスもクリア で解除されるのも、JoyPro が知っている飛行アクションだけです。

  • Star Citizen：Options > Keybindings に、ジョイスティック（js1、js2、...）上の機体のアクションが表示されます。置き換え または ほかのデバイスもクリア では、js1 に書き込むか js1 が未使用の場合、js1 にあるゲーム自身のジョイスティックの既定がオフになります。
  • War Thunder：Controls に航空機の割り当てが表示されます。戦車と艦艇の操作設定は変わりません。
  • Arma 3 / Arma 2：プロファイルのキー設定です。変わるのは航空機とヘリコプターのアクションだけです。
ゲーム内: 宇宙ゲーム：Elite Dangerous、X4: Foundations
  • Elite Dangerous はアクションごとに 2 つの入力（Primary と Secondary）を持ちます。空きのない割り当てには「ゲームに書き込まれていません」の印が付き、「別のボタンへ移動」または「このままにする」を選べます。徒歩と SRV の割り当てはそのまま残ります。
  • X4：ゲームの入力設定です。変わるのは、カタログにある機体のアクションだけです。
ゲーム内: デバイスを 1 台しか読まない、または Xbox コントローラーしか読まないゲーム
  • vJoy に設定したゲーム（少数のデバイスしか読まないゲーム）：エクスポートは割り当てを vJoy デバイスに書き込みます。プレイ中は JoyPro がスティックの入力を vJoy デバイスにコピーし、HidHide がそのゲームからだけ実デバイスを隠します。ゲームからは、すべてが入った 1 台のデバイスに見えます。仮想ジョイスティック を参照してください。
  • Xbox 専用ゲーム（ACE COMBAT 8、Hell Let Loose: Vietnam）：何も書き込まず、エクスポートでもそう表示されます。開始 がオンの間、スティックが仮のコントローラー（仮想 Xbox パッド）を動かします。HidHide は不要です。Xbox 専用ゲームを HOTAS で遊ぶ を参照してください。

#内部の仕組み

クリックからファイルの書き込みまでの、1 回のエクスポート：

# 誰が どうなるか
1 あなた エクスポート ページで 選択したゲームをエクスポート を押します。
2 JoyPro エンジンにゲームの状態を問い合わせます（profile game-state --game <id>）：インポート済みか、エクスポート済みか、割り当てがあるか。
3 JoyPro 必要なときに確認します：最初のエクスポート（「先にインポートしますか？」）や、割り当てを削除するモード（設定 > 確認）のとき。
4 エンジン <game> export --mode <m> --nuke-untouched-devices <b> ... を実行します：ゲームの実行中は拒否し、すべてのファイルをバックアップし（GameBackups と .jpbak）、カタログにあるアクションだけを書き込みます。
5 エンジン 同期記録（フィンガープリントとベースライン）とエクスポートの印を保存し、結果を返します：書き込み、スキップ、SkippedTakenInputs。
6 JoyPro ゲームのカードに「エクスポート済み 14:02」と表示され、前回のエクスポートを元に戻す が使えるようになります。
  1. GUI。 ExportSelectedGamesAsync / ExportGameNowAsync（MainWindowViewModel.ExportGames.cs）は AskAboutFirstExportAsync（engine profile game-state）と ConfirmRiskyExportAsync で確認し、そのあと ExportGameAsync がカードのエクスポーターを選びます：dcs、il2、starcitizen、またはレジストリのゲーム。コマンドはページの設定から作られます。たとえば RunDcsExportAsync では engine dcs export --mode clean --keep-keyboard-defaults true --nuke-untouched-devices true --clean-all-aircraft false --ignore-device <d> --planes F-16C_50|FA-18C_hornet です。エンジンの呼び出しはすべて 1 か所の RunEngineAsync を通り、--profile と --status true（処理中エリアの進行状況とキャンセル）が付きます。2 つのコマンドが同時に書き込むことがないよう、順番に実行されます。
  2. エンジン。 engine\Program.cs は dcs / il2 / starcitizen をそれぞれのエクスポーターに、ほかのすべてのゲームを Games.GameRegistry（ゲームごとに 1 つの GameIntegration）に振り分けます。DCS：EngineDcsExport.Modes.cs は、デバイスのファイルごとに DCS で有効な割り当て（クリーンなプロファイルから removed を引き、added と changed を足したもの）を計算し、どれを有効にするかを決めて、既定値との実際の違いだけを書き込みます。
  3. 安全対策。 GameExportSafety.BackupBeforeOverwrite は、各ファイルを <file>.jpbak と、バージョン付きのバックアップ保管場所（%LOCALAPPDATA%\JoyPro2\GameBackups\<date-time>_<game>\、manifest.json 付き。ゲームごとに最新の 30 セットを保持）にコピーします。レジストリのゲーム（Nuclear Option）では、変更する可能性のある値のスナップショットを取ります。エクスポートで新しく作ったファイルは「存在しなかった」と記録されるため、復元するとまた削除されます。
  4. そのあと。 同期の記録（<data>\Sync\<game>.json：ファイルごとのサイズ、時刻、SHA-256 と、すべての割り当てのハッシュ）により、JoyPro 自身の変更には監視機能が反応しません。ExportSkippedBinds.cs が SkippedTakenInputs を埋め、エクスポート コマンドがそれをプロファイルの印に変えます。プロファイルの履歴には、エクスポートのたびにその前のチェックポイントが残ります。

#コマンドラインでのすべてのモード

GUI での選択 エンジンのオプション
自分のデバイスで置き換え + ほかのデバイスもクリア（既定） --mode clean --nuke-untouched-devices true
自分のデバイスで置き換え --mode clean --nuke-untouched-devices false
更新（プロファイルを優先）（+ ほかのデバイスもクリア） --mode merge-overwrite --nuke-untouched-devices true|false
更新（ゲームの割り当てを優先）（+ ほかのデバイスもクリア） --mode merge --nuke-untouched-devices true|false
追加のみ --mode add（nuke は使わない）

ゲームごと：engine dcs export、engine il2 export、engine starcitizen export、そしてすべてのレジストリのゲームには engine <game> export（たとえば engine warthunder export、engine msfs2024 export、engine xplane12 export。どれも --mode、--dry-run、--include-keyboard、--nuke-untouched-devices を受け付けます）。元に戻す：engine backups restore。テスト：engine\tests\smoke\dcsexportmodes.ps1（すべてのモード、往復、元に戻したときバイト単位で一致）と engine\tests\smoke\roundtrip.ps1（インポート、clean + nuke、再インポートしてもゲームが元のまま）。
