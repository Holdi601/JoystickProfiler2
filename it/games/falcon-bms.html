Falcon BMS

Mostra:

Falcon BMS 4.38 configura i tuoi dispositivi nel suo launcher: il launcher tiene un file XML per dispositivo e da questi crea il file dei tasti e la configurazione degli assi ogni volta che premi Launch. JoyPro scrive esattamente questi file dei dispositivi del launcher, così il launcher resta al comando: trasforma le assegnazioni di JoyPro nei file che BMS legge, come se le avessi fatte tu nel launcher. Falcon 4.0 e Allied Force non sono supportati; usa Falcon BMS.

Falcon BMS 4.38.2 and newer (launcher 3.x): the launcher keeps your binds in User\Config\JSON, one file per device and aircraft (F-16 and F-15ABCD each have their own), and rebuilds the older XML and key files from them every time it closes or launches. JoyPro reads and writes these JSON files: a button goes into each aircraft whose key file has the command (an F-15 command only into the F-15), an axis into every aircraft of the device. Hat binds, the shifted layer and throttle detents are not written into the JSON files yet; the export lists them so you can set them in the launcher. Older BMS versions keep working with the XML files as below.

Per principianti

#Funziona in 3 passi

  1. Configura tutto per me
    nella pagina Start
  2. Usa questi pulsanti
    prima guarda l'elenco
  3. Scrivi nel mio gioco
    tieni chiusi BMS e il suo launcher

Prima: chiudi BMS e il suo launcher.

Poi: avvia il launcher e premi Launch. Solo allora il launcher crea i file che BMS legge.

Avevi già assegnato dei pulsanti in Falcon BMS? Allora la pagina Start ti offre Importa, poi riempi i vuoti. Le tue assegnazioni restano, e solo i pulsanti liberi ricevono nuovi compiti. Vedi Avvio rapido: far funzionare la mia cloche.

#Cosa fa JoyPro per Falcon BMS

  • Importa: i pulsanti, gli hat e gli assi dei tuoi dispositivi arrivano dai file dei dispositivi del launcher, con il livello shift come modificatore e, per ogni asse, inversione, zona morta e passi di saturazione.
  • Relazioni: una relazione è una funzione in tutti i tuoi giochi ("Carrello" in BMS, DCS e IL-2 sullo stesso pulsante). I comandi sono i callback di BMS da BMS - Full.key.
  • Esporta: JoyPro scrive i file dei dispositivi del launcher. Al tuo prossimo Launch il launcher crea da questi il file dei tasti e la configurazione degli assi.

#Importa le tue assegnazioni di BMS

  1. Apri Avvia. La scheda di Falcon BMS mostra l'immagine del gioco. Se chiede un elenco comandi, premi Crea elenco: JoyPro legge i callback del BMS - Full.key installato.
  2. Premi Importa sulla scheda e scegli Aggiungi al mio profilo (i tasti della tastiera restano nel file dei tasti di BMS, quindi la casella della tastiera qui non vale).
  3. Premi Importa ora. Vedi le mie relazioni apre ciò che è entrato.

#Crea e verifica le relazioni

Nella pagina Relazioni il callback di BMS di una relazione sta accanto alla stessa funzione negli altri tuoi giochi. Usa il flusso delle relazioni per unirli, poi premi Controlla ora nella pagina Esporta (la Verifica).

#Esportare in Falcon BMS

  1. Chiudi BMS e il suo launcher. JoyPro si rifiuta mentre Falcon BMS.exe o FalconBMS_Alternative_Launcher.exe è in esecuzione.
  2. Apri Esporta. La scheda di Falcon BMS mostra quante delle sue relazioni sono assegnate.
  3. Lascia Sostituisci sui miei dispositivi con Cancella anche gli altri miei dispositivi se configuri i tuoi dispositivi in JoyPro. Premi Esporta ora sulla scheda.
Nel gioco: Cosa vedi in Falcon BMS

Avvia il launcher e premi Launch: il launcher crea il file dei tasti e la configurazione degli assi dai file dei dispositivi di JoyPro. Nel simulatore, Setup > Controllers > Advanced > Flight Control mostra ogni asse esportato sul tuo dispositivo con la zona morta e i passi di saturazione impostati da JoyPro, e i tuoi pulsanti e hat fanno quello che dice il tuo profilo.

#Cosa fai tu in Falcon BMS

  • Premi Launch nel launcher dopo ogni esportazione. Solo allora il launcher scrive il file dei tasti, axismapping.dat, joystick.cal e DeviceSorting.txt che BMS legge.
  • Lascia senza spunta "Launch without any Setup override", altrimenti il launcher non scrive la tua configurazione.
  • I tasti della tastiera restano nel file dei tasti gestito da BMS; impostali nel launcher. JoyPro scrive solo gli input del joystick.
  • Enable Force Feedback viene scritto nel tuo file pilota (<callsign>.pop, il file da 468 byte di BMS 4.36 e successivi). Per un file pilota di un'altra dimensione JoyPro salta solo questa impostazione con un avviso.

#Errori frequenti

  • "Falcon BMS è in esecuzione": chiudi il simulatore e il launcher ed esporta di nuovo.
  • Manca un'assegnazione con modificatore: BMS ha un solo livello shift per tutti i dispositivi, tenuto dal pulsante che ha SimHotasPinkyShift. JoyPro scrive le assegnazioni con quel modificatore nello slot shift; ogni altro modificatore viene saltato con un avviso.
  • Un asse è rimasto su un altro dispositivo con "Aggiungi soltanto": BMS dà ogni funzione a un solo asse, e Aggiungi soltanto non lo sposta mai. Usa una modalità Aggiorna per spostarlo.
  • Le assegnazioni non sono cambiate nel simulatore: dopo l'esportazione il launcher non è stato avviato con Launch.
Avanzate

#File che JoyPro legge e scrive

File Di cosa si tratta
<BMS>\User\Config\JSON\DeviceBindings_<aircraft>_<device>.json 4.38.2 and newer: the launcher's file per device and aircraft (buttons, axes)
<BMS>\User\Config\Setup.v100.<device> {<GUID>}.xml before 4.38.2: the launcher's file per device: axes, hats, buttons, throttle detents
<BMS>\User\Config\Falcon BMS User.cfg valori delle curve e impostazioni del gioco, solo sopra la riga marcatore del launcher
<BMS>\User\Config\Feedback.ini i guadagni degli effetti di force feedback e la molla di centraggio
<BMS>\User\Config\<callsign>.pop il file del pilota: solo il byte Enable Force Feedback
<BMS>\User\Config\JoyPro.joypro.json gli input che JoyPro ha scritto

<BMS> viene trovato tramite HKLM\SOFTWARE\WOW6432Node\Benchmark Sims\...\baseDir o una cartella Falcon BMS*. axismapping.dat, joystick.cal, DeviceSorting.txt, i file dei tasti e il blocco del launcher in User.cfg vengono ricreati a ogni Launch; JoyPro non li scrive mai. Un dispositivo collegato senza file del dispositivo ne riceve uno: dal file di serie del launcher per quel modello, altrimenti un file vuoto nel layout del launcher.

#Le modalità di esportazione in Falcon BMS

Modalità Cosa succede in BMS
Aggiungi soltanto Scrive solo gli slot liberi; un'assegnazione su uno slot con un'altra callback non viene scritta e viene elencata. Una funzione che BMS ha su un altro asse resta lì (avviso).
Aggiorna, mantieni le assegnazioni del gioco Sostituisce la callback sul tuo slot (il conflitto) e mantiene tutto il resto; una funzione di asse passa al tuo asse.
Aggiorna, prevale il mio profilo Libera anche gli altri slot di pressione, gli hat e gli assi dei dispositivi collegati che contengono un'azione che assegni.
Sostituisci sui miei dispositivi Libera tutto il resto dei dispositivi collegati che scrivi (anche le callback catalogate negli slot di rilascio).
+ Cancella anche gli altri miei dispositivi I dispositivi collegati senza assegnazioni nell'esportazione vengono svuotati.

#Cosa non viene mai toccato

  • I file dei dispositivi non collegati (lì resta una vecchia rivendicazione di asse; il launcher prende la più recente).
  • I dispositivi ignorati dall'importazione e il dispositivo vJoy in cui JoyPro inoltra i comandi.
  • I tasti della tastiera e il file dei tasti, i file che il launcher genera e il blocco del launcher in User.cfg.

#Curve, impostazioni, force feedback

  • Granularità: globale, una sola configurazione per tutti i velivoli.
  • Assi (modello degli assi bms): inversione, il livello di zona morta del launcher (None, Small, Medium, Large) e il livello di saturazione, assi a un solo lato (manetta, freni a punta di piede, luminosità, volumi) senza zona morta; per beccheggio, rollio, imbardata e cursore X/Y anche la curva esponenziale (da 0 a 100) e la saturazione esponenziale (da 0 a 99) in User.cfg. La Curva predefinita imposta i livelli del launcher più vicini, ma nessun esponente.
  • Scatti della manetta: le posizioni degli scatti AB e IDLE per ogni dispositivo manetta, nel suo file del dispositivo.
  • Impostazioni del gioco (Impostazioni > Impostazioni force feedback dei giochi): molla di centraggio, vibrazione sulla pista, banda morta anti-jitter, taglio del minimo analogico, clic allo scatto AB, timone virtuale, asse Depr-Ret come freno.
  • Force feedback: Enable Force Feedback, guadagni di cannone, rimbalzo, molla di centraggio, sgancio bombe e stallo, la banda morta del force feedback. Un'esportazione senza assegnazioni di BMS scrive comunque impostazioni e scatti.
  • Registrazione della telemetria: solo lettura dalla memoria condivisa di BMS, con posizione (è possibile una traccia Tacview). Nessun force feedback da telemetria.
  • Monitoraggio: le modifiche nei file dei dispositivi, in User.cfg, in Feedback.ini o nel file del pilota vengono notate dopo la chiusura di BMS (il monitoraggio).
Dettagli tecnici interni

#Dentro l'integrazione di BMS

Codice: engine\Games\FalconBmsIntegration.cs, modello degli assi bms, modello delle impostazioni FalconBMS; telemetria gui\JoyPro.Ffb.Core\Telemetry\Bms\BmsTelemetry.cs.

  • File dei dispositivi: radice <JoyAssgn> con <detentPosition>, 8 voci <axis> (X, Y, Z, Rx, Ry, Rz, Slider0, Slider1: <AxisName>, <AssgnDate>, <Invert>, <Deadzone>, <Saturation>), <pov> (4 hat × 8 direzioni, normale e con shift) e <dx> (128 pulsanti × 4 slot: pressione, pressione+shift, rilascio, rilascio+shift). La copia in <profileDefaultF16> viene scritta allo stesso modo. Dichiarazione, spazi, fine riga e BOM vengono mantenuti; vengono scritti solo i file cambiati.
  • Dispositivi: tramite il GUID di istanza DirectInput nel nome del file.
  • Pulsanti: slot di pressione 0; il livello shift è lo slot 1 e diventa il modificatore BMS Shift. Gli slot di rilascio non vengono mai importati. Una nuova callback riceve Invoke = Default.
  • Assi: una nuova rivendicazione riceve AssgnDate = adesso; le rivendicazioni più vecchie della stessa funzione vengono liberate (il launcher dà una funzione alla rivendicazione più recente).
  • Elenco comandi: engine bms refresh-db: le callback visibili di BMS - Full.key (sezioni cockpit e HOTAS) più le funzioni di asse del launcher (senza FOV e distanza della telecamera).
  • Importazione / esportazione: engine bms paths, engine bms import, engine bms scan, engine bms export (--mode, --nuke-untouched-devices, --dry-run). Prima il backup in .jpbak e nell'archivio di backup; l'attributo di sola lettura viene ripristinato.
  • Impostazioni e scatti: engine ffb set --device * --game FalconBMS --param flightControlsDeadband=0.05, per ogni manetta --device "<throttle>" --param abDetent=80 --param idleDetent=5; engine binds tuning preview --game FalconBMS.

#Limiti noti

  • Non scritti: il vecchio flusso di lavoro con i file dei tasti, la modellazione personalizzata degli assi (axiscurves.cal), zone morte diverse dai livelli del launcher.
  • Non sono ancora confermati la formula della curva dell'esponente e il modo in cui BMS legge i livelli di saturazione.
  • Test: engine\tests\smoke\bms.ps1 (file di serie); nel gioco tools\e2e\games\BmsSettings.ps1 (Launch, i file generati, Setup > Controllers). La migliore esecuzione nel gioco ha superato 20 passi su 21.
