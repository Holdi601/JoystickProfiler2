界面页面

虚拟摇杆

显示：

有些游戏只接受少数几个摇杆，会识别错设备，或者在你插入另一个设备时打乱它们的顺序。在虚拟模式下，JoyPro 会把游戏绑定用到的每个轴、按钮和苦力帽都放到 一个虚拟摇杆（vJoy）上，对于只读取游戏手柄的游戏，则放到 一个虚拟 Xbox 360 手柄 上。游戏看到的是一个输入永远不会变动的设备；你的配置文件保留你的真实设备。此外，虚拟功能 可以做 Joystick Gremlin 能做的事：把轴区间当作按钮、切换、短按/长按、换挡层、宏、模式。

新手入门

#四步开始使用

  1. 在 游戏 下把游戏切换为 vJoy（对于只接受游戏手柄的游戏，选 Xbox 手柄）。已知只读取一个设备的游戏会显示一条建议，带有 使用 按钮。只读取 Xbox 手柄的游戏（ACE COMBAT 8、Hell Let Loose: Vietnam）会自动使用 Xbox 手柄，直到你选择其他模式；页面会说明原因。列表按名称排序。
  2. 在 导出 页面上再次导出该游戏。JoyPro 会把绑定写到虚拟摇杆上；你的配置文件保留你的真实设备。
  3. 按 开始。每类游戏一条规则，在手柄导览、帮助和页面中的说法都相同：
    • Xbox 手柄（ACE COMBAT、Hell Let Loose: Vietnam）：先启动游戏并等待标题画面出现，然后按 开始。按早了？按 停止，再按 开始。这些游戏不需要导出，也不需要切换，所以它们跳过第 1 步和第 2 步。
    • vJoy：在启动游戏之前按 开始。JoyPro 会用 HidHide 对该游戏隐藏你的真实设备（Windows 会请求一次管理员权限），并把每个输入实时复制到虚拟摇杆。
  4. 用完后按 停止。HidHide 会精确恢复到之前的设置；不会有任何东西一直被隐藏。

此页面需要的组件 显示免费驱动程序：vJoy（用于设为 vJoy 的游戏）、ViGEmBus（Xbox 手柄）和 HidHide（用于 vJoy 游戏）。它们不是 JoyPro 的一部分；在那里一键安装你需要的即可。只读取 Xbox 手柄的游戏（ACE COMBAT 8、Hell Let Loose: Vietnam）只需要 ViGEmBus：它永远看不到你的真实设备，所以不需要 HidHide，Windows 也不会请求管理员权限。

只玩只支持 Xbox 手柄的游戏？

那么页面会叫作 模拟手柄，只显示这些游戏需要的内容：ViGEmBus 卡片、测试 和 开始。vJoy、HidHide 和模式列表都在 显示专家详情（vJoy、HidHide、模式） 后面。参见 用 HOTAS 玩只支持 Xbox 手柄的游戏。

先测试

测试 会读取你的设备，并在 实时测试 选项卡上显示游戏将会收到什么，不会动 vJoy 或 HidHide。移动摇杆，观察条形的变化。

在游戏中: 游戏中会有什么变化

游戏的控制设置菜单会显示一个设备“vJoy Device”，你的绑定位于它的按钮和轴上。只有在虚拟摇杆运行期间，你的真实设备才会对该游戏不可见；其他所有程序仍然能看到它们。曲线、死区和反转仍然来自 JoyPro 导出的游戏自身设置。Xbox 手柄 则不同：这些游戏不需要导出，所以 JoyPro 会自己应用每条轴曲线（绑定页面，轴响应）。

高级

#四个选项卡

概览：它是什么以及如何使用；vJoy（版本、设备）、HidHide 和 JoyPro 会话的 状态（刷新；当某个 vJoy 设备缺少轴、按钮或苦力帽时用 按表格设置 vJoy；崩溃后用 恢复 HidHide；将 vJoy 设置为最大配置：8 个轴、128 个按钮、4 个苦力帽，需要重启 Windows）；此页面需要的组件；游戏（每个游戏选择原生 / vJoy / Xbox 手柄，游戏能从一个摇杆读取什么，并在上方显示警告）；选项：隐藏真实设备（HidHide，推荐），在虚拟游戏启动和结束时自动启动和停止（JoyPro 每 3 秒查找一次；对 vJoy 来说，在游戏启动前按开始仍是最稳妥的；上面提到的 Xbox 手柄游戏则需要在标题画面之后再开始）。

映射：即映射表。虚拟游戏使用的每个物理输入在虚拟摇杆上都有固定位置：轴在空闲时保持自己的轴（X 仍是 X），按钮和苦力帽占用下一个空闲编号。已有的位置永远不会移动，因此游戏的绑定每次运行都保持不变。更新映射 为新输入分配位置，并把映射表保存到配置文件中。

功能：虚拟功能、它们的模式、Gremlin 导入和图（见下文）。

实时测试：按转发程序写入的数据，用条形显示每个 vJoy 设备的轴、按下的按钮和苦力帽，并附有转发程序的日志。实时显示虚拟摇杆（对于所有游戏都使用模拟手柄的玩家：实时显示模拟手柄）打开或关闭这些条形显示。对于 Xbox 手柄，每个已映射的控件都会说明它的作用和来源（“A: Fire machine gun (VKB Gunfighter BTN1)”、“LX: Roll (Rhino X)”），按下的按钮会点亮。

#Xbox 手柄

  • 自动：不读取摇杆、只读取 Xbox 手柄的游戏，在你还没有为它选择模式时会使用 Xbox 手柄（“自动使用 Xbox 手柄”）。你的选择优先并会被保留。没有 ViGEmBus 驱动时，游戏 卡片会提示这一点，并提供一键安装。
  • 轴曲线：这些游戏不导出，所以 JoyPro 自己把关联的轴曲线（死区、饱和度、曲率或自定义曲线、反转；游戏自己的曲线，否则用 默认曲线）应用到手柄的摇杆或扳机上。绑定 页面的 轴响应 会为这些游戏注明这一点。vJoy 游戏保留原始数值，因为它们的曲线在导出中。
  • 多个游戏共用手柄：每个游戏都保留自己的手柄表；同一时间只有一个生效。开启自动启动时，使用正在运行的游戏的表；开始 和 测试 使用正在运行的游戏的表，否则使用 “开始”和“测试”使用的Xbox 手柄表 中选择的那个（保存在配置文件中）。
  • 自动设置（来自 ACE COMBAT 8 实测，适用于每个配置文件）：油门同时驱动两个扳机（向前 RT，向后 LT），刹车轴不会占用 LT；LB/RB 上的偏航来自摇杆扭转，否则来自脚舵，大约在 30 % 偏转时触发；ACE COMBAT 8 的干扰弹（L3 + R3 同时按，尚未在游戏中确认）来自你的干扰弹 / CMS 向前按钮；僚机方向键来自你的通信开关或 AI 菜单苦力帽；绑定在 Change target 上的苦力帽方向驱动 Y；你的眼镜蛇按钮（DCS ASC Direct Control）或名为“High-G”的按钮关联会同时按住两个扳机，用于高 G 转弯。一个输入永远不会驱动两个手柄控件，不再有任何关联使用的手柄槽位会自动移除。
  • 手柄上的反转：DCS 的反转永远不会传到手柄上。ACE COMBAT 8 的俯仰默认是反向的（使用游戏默认的 Pitch Controls 时，向前推会让机头向下）。在 轴响应 中翻转某个游戏的轴时，在 应用于 下只勾选该游戏；DCS 保留自己的设置。engine vjoy pad-check 显示一个配置文件能在手柄上实现哪些功能。

#虚拟功能

功能在虚拟摇杆内部运行，位于你的设备和游戏收到的内容之间。选择游戏、类型，点 添加功能，然后在编辑器中设置它的输入和输出。

功能 作用
轴分段 把一个轴分成最多 16 段，每段对应一个按钮（油门卡位）
按钮循环 每按一次切换到下一个输出
切换（锁定） 按一下保持开启，再按一下关闭的按钮
开关转为开/关脉冲 保持型开关在每个位置发送一个脉冲
短按 / 长按 / 双击 一个按钮承担三项任务
Shift 层 按住 shift 按钮时，输入发送到其他输出
合并 / 拆分轴 两个脚舵踏板合成一个方向舵；一个轴拆成两个
轴曲线 死区、饱和度、曲率、反转、滑块
轴两端转按钮、轴转苦力帽、按钮转轴、轴转编码器脉冲 转换
连发、宏 按住时重复；一连串按键和键盘按键
苦力帽转按钮、按钮转苦力帽、重映射 苦力帽和重映射
模式开关 切换模式（切换到、按住、开关、循环、返回）

编辑器：名称、开、键盘输出（让输出和宏步骤可以按下键盘按键；仅在真正运行时生效）、节点视图（输入 → 功能 → 输出，输出触发时点亮）、可拖动边界的轴分段条、曲线、工作模式、要切换到的模式、输入（设备和输入，清除）、输出（vJoy 按钮或轴、Xbox 控件或键盘按键；绑定关联 把一个关联绑定到该输出）、设置和宏步骤。试用 在编辑器中用滑块和按钮运行该功能；不会向 vJoy 或游戏发送任何内容。保存 保存它；正在运行的虚拟摇杆在停止并重新开始后才会使用它。

串联：一个输入可以读取另一个功能的输出，而不是读取设备：在该输入的设备列表中选择 ⚙ f1 ...，或者在 所有功能的图 中从一个输出点（右边缘）拖到一个输入点（左边缘）。循环连接会被拒绝。点击一条连线，再点它的 × 即可断开。

模式（层）：让你的输入在不同情况下承担不同任务（Combat、Landing ……）。一个模式可以继承另一个模式；功能在勾选的模式中工作（不勾选 = 所有模式）。添加模式、重命名、×（删除）、启动时（转发程序启动时所处的模式）。当前运行的模式会实时标出。

#从 Joystick Gremlin 迁移

选择游戏，可选择勾选 替换游戏的功能和模式，点 导入 Gremlin 配置文件... 并选择 .xml（R13 或 R14）。JoyPro 会先显示一份报告：它会把内容转换成什么、哪些 无法实现（激活条件、鼠标操作、Python 插件、声音……），以及哪些 已导入，但有差异。在点 导入 之前不会保存任何内容。模式、重映射、曲线、宏、合并的轴、tempo、chain 和 toggle 容器都会变成功能和模式。然后把游戏设为 vJoy，保留或在 vJoy 输出上绑定关联，导出并点 开始：HidHide 和转发程序会取代 Gremlin 的设备隐藏和它的后台程序。

技术细节

#页面的内部原理

视图模型：MainWindowViewModel.VirtualJoystick.cs（状态、映射表、开始/测试/停止、自动启动、实时视图）、MainWindowViewModel.VirtualFunctions.cs、MainWindowViewModel.VirtualModes.cs（模式、Gremlin 导入）、VirtualFunctionEditorViewModel.cs；视图 VirtualJoystickView.axaml、VirtualFunctionEditorView.axaml、Views/Controls/VirtualFunctionGraphView.cs、VirtualFunctionFlowView.cs、AxisBandEditor.cs。

虚拟摇杆的 开始：

# 谁 会发生什么
1 你 按 开始。
2 引擎 vjoy map：新的输入获得一个槽位；该表保存在配置文件中。
3 引擎 vjoy forwarder-config：解析后的表和函数。
4 引擎 vjoy apply-hidhide 先写入它的日志，然后对 vJoy 游戏隐藏物理设备（HidHide 会请求一次管理员权限）。只读取 Xbox 控制器的游戏：“不需要 HidHide”，不会弹出提示。
5 JoyPro.VJoy run --sink vjoy --parent-pid N：每一轮（例如每秒 144 次）读取设备、运行函数，并写入 vJoy 或 Xbox 手柄。

停止：

# 谁 会发生什么
1 你 按 停止。
2 JoyPro.VJoy 停止：输出回到中立，按键松开。
3 引擎 vjoy restore-hidhide 会准确恢复之前的设置。
  • 映射表：保存在配置文件中（Pr0file.VirtualJoystick）；engine vjoy map（--prune、--reset）、engine vjoy mode（每个游戏 native | virtual | xbox）、engine vjoy status、engine vjoy settings（JoyPro 使用哪些 vJoy 设备）、engine vjoy configure-vjoy（vJoyConfig，除了要避开的轴之外从不移除任何东西）、engine vjoy limits。
  • 导出、导入、同步：在导出、导入或同步虚拟游戏期间，它的绑定指向 vJoy 槽位；完成后，配置文件会恢复为物理设备。缺少 vJoy 设备时，导出会停止并给出提示。
  • HidHide 会话：engine vjoy apply-hidhide、engine vjoy restore-hidhide、engine vjoy recover：每次更改前都会写入日志，因此崩溃后可以恢复（恢复 HidHide）。
  • 功能和模式：engine vjoy functions types、engine vjoy functions list、engine vjoy functions add --game、engine vjoy functions set --game、engine vjoy functions remove --game、engine vjoy functions test（模拟，不会向 vJoy 发送任何内容）、engine vjoy modes list。按游戏保存在配置文件中（VJoySettings.Functions[game]、VJoySettings.Modes[game]）；它们的输出在映射表中预留。引擎的测试、编辑器的预览和转发程序运行的是同一套计算代码；每一轮都按依赖顺序计算功能，每一轮都不分配内存（50 个功能每轮约 10 µs）。
  • Gremlin：engine vjoy import-gremlin（--dry-run 用于报告，--replace，--vjoy-device）。
  • 转发程序：gui/JoyPro.VJoy（JoyPro.VJoy.exe run --config ... --sink vjoy|dry），以非独占方式通过 DirectInput 读入，通过 vJoyInterface.dll / ViGEmBus 输出。测试使用 dry sink，不使用 HidHide。

参考：virtual-joystick，驱动程序：components。
