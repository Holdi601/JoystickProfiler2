FSX 和 Prepar3D

显示：

FSX、FSX: Steam Edition 以及 Prepar3D v4、v5 和 v6 把你的控制设置保存在 %APPDATA% 中的一个 XML 文件里：每个设备一个映射，包含它的轴、按钮和苦力帽，另外还有键盘。JoyPro 会把该文件读入你的配置文件，通过关联把它与你的其他游戏连接起来，并逐块写回，格式、注释和其他映射保持原样。由于每个模拟器都有自己的文件，所以每个模拟器在 JoyPro 中都是一个单独的游戏。

这项集成是根据公开资料编写的，只用一个合成的测试文件进行过测试：这些模拟器都还没有在真实安装上用 JoyPro 测试过。第一次导出后，请打开模拟器的控制设置检查分配情况，如有不同之处请反馈给我们。

#3 步上手

  1. 全部帮我设置好
    在开始页面
  2. 使用这些按钮
    先查看列表
  3. 写入我的游戏
    保持模拟器关闭

之前：在连接好设备的情况下启动一次模拟器，然后关闭它。

然后：打开模拟器的控制设置并检查分配情况。这项集成尚未在真实安装上测试过：如有不同之处请反馈给我们。

你以前在模拟器中绑定过按钮吗？那么开始页面会提供 导入，然后填补空缺。你的绑定会保留，只有空闲的按钮会获得新功能。参见 快速入门：让我的摇杆能用。

#JoyPro 为 FSX 和 Prepar3D 做了什么

  • 导入：你的设备的轴、按钮和苦力帽会连同每个轴的灵敏度和零区一起进入你的配置文件。如果你需要，键盘按键也会一起导入。
  • 关联：一个关联就是你所有游戏中的同一个功能（FSX、MSFS 和 X-Plane 中的“Gear”在同一个按钮上）。命令是模拟器公开的事件名称（GEAR_TOGGLE、AXIS_AILERONS_SET ...）。
  • 导出：JoyPro 会写入你所导出模拟器当前使用的控制文件。

#导入你的绑定

  1. 打开 开始 页面。你的模拟器的卡片会显示它的图片。如果它要求生成命令列表，按 生成列表：JoyPro 会把自己的事件列表与你的控制文件（以及模拟器自带的模板文件）中出现的事件合并。
  2. 在卡片上按 导入。选择 添加到我的配置文件，如果你也需要按键，请勾选 同时获取键盘按键。
  3. 按 立即导入。查看我的关联 会打开导入的内容。

#建立并检查关联

在 关联 页面上，关联中的模拟器事件就在你其他游戏的同一功能旁边。用 关联流程 把它们连接起来，然后在导出页面按 立即检查（检查）。

#导出

  1. 关闭模拟器。 模拟器会在退出时重写该文件；当 fsx.exe 或 Prepar3D.exe 正在运行时，JoyPro 拒绝写入。
  2. 打开 导出 并使用你的模拟器的卡片。
  3. 如果你是在 JoyPro 中设置设备的，请保持选择 在我的设备上替换 并勾选 同时清除我的其他设备。在卡片上按 立即导出。
在游戏中: 你在 FSX 和 Prepar3D 中看到的内容

启动模拟器并打开它的控制设置：你的设备的分配会显示在那里，每个轴的灵敏度和零区显示在它的校准页面上。确切的菜单路径以及模拟器如何显示 JoyPro 写入的文件尚未确认。

#在 FSX 和 Prepar3D 中需要你自己做的事

  • 在连接好设备的情况下 启动一次模拟器，让它写入控制文件。
  • 第一次导出后 检查结果（见上文）。这是这项集成在你电脑上的第一次真实测试。
  • 苦力帽是作为整体分配的，通常用于平移视角（PAN_VIEW）。单个苦力帽方向上的其他事件不会被写入；请在模拟器中绑定它们。

#常见问题

  • “模拟器正在运行”：关闭它，然后重新导出。
  • 重新插拔后某个设备的绑定丢失了：Windows 可能会给设备分配新的 GUID。这时，如果恰好只有一个已连接的设备具有该名称，JoyPro 会按名称找到它的映射（并给出警告）。
  • 某个带修饰键的摇杆绑定不见了：该格式不支持摇杆按钮上的修饰键。按键可以带 Ctrl、Shift 和 Alt。

#JoyPro 读取和写入的文件

模拟器 控制文件
FSX（盒装版） %APPDATA%\Microsoft\FSX\Controls\Standard.XML（当前文件取自 fsx.cfg [CONTROLS] Controls_Current）
FSX: Steam Edition 与盒装 FSX 并存时为 %APPDATA%\Microsoft\FSX-SE\Controls\，单独安装时为 %APPDATA%\Microsoft\FSX\Controls\
Prepar3D v4 / v5 / v6 %APPDATA%\Lockheed Martin\Prepar3D v<N>\Controls\Standard.xml（当前文件取自 Prepar3D.cfg [CONTROLS]）
全部 <file>.joypro.json（JoyPro 写入的输入）、<file>.joypro-meta.json（供下次导入使用的名称、分组和调校）

Prepar3D 的 Standard.xmlx（设备预设）和安装文件夹中 FSX 的模板会被读取用于命令列表，但永远不会被写入。

#FSX 和 Prepar3D 中的导出模式

模式 模拟器中会发生什么
仅添加 从不移除或替换任何块。位于已有其他事件的输入上的绑定不会被写入，并会被列出。
更新，保留游戏的绑定 替换你的输入上的事件（即冲突的那个），其他一切保留。
更新，以我的配置文件为准 此外，还会移除你所绑定事件的其他输入（已连接的设备；键盘只在开启键盘选项时）。
在我的设备上替换 你写入的设备的主映射只保留你的绑定。
+ 同时清除我的其他设备 其他已连接设备的主映射会被清空（映射本身保留）。

#绝不会改动的内容

  • 未连接设备的映射、导入时忽略的设备，以及 JoyPro 转发到的 vJoy 设备。
  • 平移映射（... SLEW {GUID}）、Mouse Yoke、Mouse Look、Prepar3D 的每个 SimObject 映射，以及键盘映射（除非你导出键盘绑定）。
  • 由两个普通按键组成的组合键、注释、格式和未知元素。

#曲线和设置

  • 粒度：全局，所有飞机共用一个文件。
  • 轴设置（轴模型 fsx）：每个设备轴的灵敏度（0 到 127）和零区（0 到 127），与校准页面上的相同。默认曲线 会被换算过去（死区对应零区，饱和度对应灵敏度）；曲线形状没有对应的设置。在“更新”模式下，如果 JoyPro 的值只是普通的默认值，模拟器中设置的值会保留。
  • 反转：负的灵敏度。
  • 没有力反馈、游戏设置或遥测数据。监视器会在模拟器关闭后发现更改。
技术细节

#FSX 和 Prepar3D 集成的内部原理

代码：engine\Games\FsxIntegration.cs（一个类，每个模拟器一个游戏）、engine\Games\FsxControlsFile.cs（以整块为单位的文本编辑）、engine\Games\FsxEvents.cs（JoyPro 的事件列表）。

  • 格式：<SimControls.Map>，包含 <Name>、<Axis>（<Index> 0 到 7 = X、Y、Z、Rx、Ry、Rz、Slider、第二个滑块；<AxEvent>、<AxScale>、<AxNull>）、<Entry>（从 0 开始的按钮 <Index>、<Down> / <Up>，重复事件用 <DownRpt>1）以及 <POV>（整个苦力帽）。文件头 encoding="Windows-1252"。
  • 设备：每个 DirectInput 设备一个映射，名为 <instance name>{<instance GUID>}；按 GUID 匹配，如果只有一个已连接设备有该名称，则按名称匹配。文件中没有的设备会得到一个新映射。每个设备报告 32 个按钮和 8 个轴。
  • 映射：JOY_X .. JOY_SLIDER2 对应 <Index> 0 到 7，JOY_BTN<n> 对应 <Index> n-1，苦力帽放在它的向上方向上（JOY_BTN_POV1_U）。
  • 命令列表：engine fsx refresh-db（以及 fsxse、p3d4、p3d5、p3d6）：约 150 个带 JoyPro 标题的事件，加上你的控制文件和模拟器模板中提到的每个事件；AXIS_* 事件是轴。
  • 导入 / 导出：engine fsx paths（当前文件排在最前）、engine fsx import、engine fsx scan、engine fsx export，engine fsxse export、engine p3d4 export、engine p3d5 export、engine p3d6 export 也一样。首次写入前会备份。

#已知限制

  • 所有内容都需要在真实安装上检查：Prepar3D v4+ 的文件头，以及 <Name> 是否仍然带有 GUID；模拟器写入的确切字节；第二个滑块的轴名称；以及模拟器是否会保留 JoyPro 为它还没见过的设备添加的新映射。
  • FSX: Steam Edition 的配置文件名是推测得出的。
  • 测试：engine\tests\smoke\fsx.ps1，使用根据文档格式构造的合成文件。
