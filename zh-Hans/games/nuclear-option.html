Nuclear Option

显示：

Nuclear Option 是一款包含喷气机、VTOL 和直升机的空战飞行游戏，所有飞机共用一套绑定。它的控制设置不保存在文件中，而是保存在 Windows 注册表里：每个设备一个 Rewired 摇杆映射，由游戏的 Control Mapper 写入。JoyPro 会把这些映射读入你的配置文件，并把你的 Flight Controls 绑定写回其中；相机、玩法和聊天绑定保持原样。

新手入门

#3 步上手

  1. 全部帮我设置好
    在开始页面
  2. 使用这些按钮
    先查看列表
  3. 写入我的游戏
    保持 Nuclear Option 关闭

之前：启动一次 Nuclear Option，然后关闭它。

然后：你的绑定位于 Settings > Controls > Open Control Bindings Menu 中你设备的页签上。

你以前在 Nuclear Option 中绑定过按钮吗？那么开始页面会提供 导入，然后填补空缺。你的绑定会保留，只有空闲的按钮会获得新功能。参见 快速入门：让我的摇杆能用。

#JoyPro 为 Nuclear Option 做了什么

  • 导入：你已连接设备的摇杆映射会进入你的配置文件：带反转设置的轴、按钮，以及轴上的按钮（例如“Increase Throttle”）。
  • 关联：一个关联就是一个功能；Nuclear Option 没有飞机列表，所以一个关联适用于所有飞机。
  • 导出：JoyPro 会就地编辑每个设备的映射，只写入 Flight Controls 操作。游戏中没有已保存映射的设备会获得一个包含你的绑定的新映射。

#导入你的绑定

  1. 启动一次 Nuclear Option（让它的注册表项存在），然后关闭它。
  2. 打开 开始 页面，在 Nuclear Option 卡片上按 导入，然后按 立即导入。

#建立并检查关联

像其他游戏一样建立关联（关联流程）；设置向导和自动分配都认识这个游戏的功能。然后在导出页面运行 检查。

#导出到 Nuclear Option

  1. 关闭 Nuclear Option。 游戏运行时 JoyPro 拒绝写入：游戏会在绑定菜单关闭时以及拔出设备时写入它的映射。
  2. 打开 导出，保持选择 在我的设备上替换 并勾选 同时清除我的其他设备，然后在 Nuclear Option 卡片上按 立即导出。
在游戏中: 你在 Nuclear Option 中看到的内容

打开 Settings > Controls > Open Control Bindings Menu。Control Mapper 中每个设备有一个页签：点击顶部你的设备，就能在那里看到你的 Flight Controls 绑定（使用游戏中的名称，例如 Pitch、Roll、Yaw、Throttle）。相机、玩法和聊天绑定保持不变。

#在 Nuclear Option 中需要你自己做的事

  • 在第一次导入或导出之前 启动一次游戏，让它创建自己的注册表项。
  • 游戏控制设置中的 Use Throttle Axis Negative Region：如果要使用全行程油门轴，请保持开启。当它处于关闭状态而你的配置文件绑定了油门轴时，JoyPro 会发出警告。
  • 苦力帽：目前请在游戏中绑定苦力帽方向；JoyPro 暂时还不写入它们。

#常见问题

  • “Nuclear Option 正在运行”：关闭游戏，然后重新导出。
  • 某个设备被跳过：两个相同型号的已连接设备（或者一个同时显示为游戏控制器的键盘）在游戏的映射中无法区分；JoyPro 会略过它们并给出警告。
  • 某个设备保留了游戏的默认绑定：游戏中没有已保存映射的已连接设备会使用游戏的默认映射，而 JoyPro 无法读取它；同时清除我的其他设备 不会动它。请在 JoyPro 中给它绑定点什么，或者在 Control Mapper 中清空一次它的页签。
  • 油门卡在中间：检查 Use Throttle Axis Negative Region（见上文）。
高级

#JoyPro 读取和写入的内容

位置 这是什么
HKCU\Software\Shockfront\NuclearOption 注册表中该游戏的 Unity 设置；Rewired 的值是二进制的（UTF-8 文本加一个零字节），名称以 _h<hash> 结尾
每个设备一个值，名称中带有 dataType=ControllerMap 和该设备的 hardwareIdentifier 一个设备的摇杆映射（Rewired XML），对应玩家 Player0
同样的名称，但带 dataType=ControllerMap_KnownActionIds 该映射已知的操作 id；JoyPro 在写入新映射时一并写入它
<install>\NuclearOption_Data\resources.assets 游戏的 Rewired 操作列表：只读，用于命令列表
%LOCALAPPDATA%\JoyPro2\GameMetadata\HKCU_Software_Shockfront_NuclearOption.joypro-meta.json JoyPro 为导出的绑定保存的名称、分组和调校，供下次导入使用

在第一次写入之前，JoyPro 会把 Player0 的控制器映射值快照保存到备份库中；撤销上次导出 会把它们写回，并删除 JoyPro 添加的映射值。有些值的名称超过 255 个字符，所以 JoyPro 使用注册表 API（Regedit 和 reg export 无法全部显示它们）。

#Nuclear Option 中的导出模式

模式 你设备的映射中会发生什么
仅添加 游戏的内容不会有任何改变；如果某个绑定的按钮或轴已经在驱动另一个操作（或轴的另一极），该绑定会被略过并列出。
更新，保留游戏的绑定 如果你把某个输入分配给另一个操作，原先在该输入上的 Flight Controls 操作会失去它；该操作保留它的其他输入。
更新，以我的配置文件为准 同上，另外你绑定的每个操作（或极）都会失去其他输入，涉及 JoyPro 能读取的每个已连接设备。
在我的设备上替换 已写入设备上的其他所有 Flight Controls 操作都会被清除。
+ 同时清除我的其他设备 已连接设备的其他已保存映射中的 Flight Controls 操作会被清除。没有已保存映射的设备保留游戏的默认映射。

#绝不会改动的内容

  • Flight Controls 之外的所有操作：摄像机、游戏玩法、聊天、调试和任务编辑器的绑定。
  • 键盘和鼠标映射、校准映射、输入行为、控制器分配以及所有游戏设置（图形、ThrottleUseNegative 和其他控制选项）。
  • 未连接的设备、同一型号的两个或更多设备、导入时被忽略的设备，以及 JoyPro 用于转发的 vJoy 设备。
  • 被编辑映射中 JoyPro 所改动的元素映射之外的一切，包括模组操作的绑定。

#粒度、曲线及其他

  • 粒度：全局，所有飞机共用一套绑定（Throttle 操作同时也是直升机的总距）。
  • 轴曲线：不写入。游戏的校准死区保持不变。
  • 键盘和修饰键：不写入；游戏的摇杆绑定没有修饰键。
  • 苦力帽：目前还不读取也不写入。滑块会写入，但会给出警告。
  • 力反馈、遥测：无。
  • 监视器：监听游戏注册表键的变更通知；指纹只涵盖 Player0 的控制器映射（监视器）。
  • HUD：HUD 通过进程（NuclearOption）识别该游戏。
技术细节

#Nuclear Option 集成的内部机制

代码：engine\Games\NuclearOptionIntegration.cs（注册表存储、该游戏的特殊之处、目录结构），建立在 engine\Games\RewiredMapIntegration.cs（读取和写入 Rewired 摇杆映射，与 Tiny Combat Arena 共用）之上。

  • 值名称：Unity 会在每个键后面附加 _h<hash>（对 UTF-8 键做带 XOR 的 djb2，十进制）。
  • 设备：常见的 HOTAS 设备都不在游戏的 Rewired 已知列表中，因此它们的映射带有为零的 hardwareGuid，而 hardwareIdentifier = WindowsRawInput + 去掉空白的 HID 产品字符串 + PID + VID（各为四位大写十六进制数字）。duplicate 统计同一型号的设备数量；JoyPro 每个型号只处理一个。
  • 元素：轴 X、Y、Z、Rx、Ry、Rz = 0 到 5，滑块为 6 和 7，按钮 n = 31 + n。轴操作上的按钮为 <Action>.Positive / .Negative（axisContribution 0 / 1）。游戏的默认映射把 Pitch、Roll、Yaw、Throttle 和 Brake 绑定在轴 0 到 4 上，另外还有十一个按钮。
  • 写入：只有被改动的 ActionElementMap 块会变化（按钮在 <buttonMaps> 中，轴在 <axisMaps> 中）；新映射的 sourceMapId 为 -1，并带有已知操作 id 列表，这样游戏就不会往里面添加默认绑定。
  • 命令列表：engine nuclearoption refresh-db 通过第一个操作（"Pitch"）在 resources.assets 中找到 Rewired InputManager，并写入 DB\NuclearOption\actions.tsv（操作名称、标题、类别、Rewired id；轴操作还会有各极的行）。
  • 命令：engine nuclearoption paths、engine nuclearoption catalog、engine nuclearoption scan、engine nuclearoption import、engine nuclearoption export；撤销用 engine backups restore。

#已知限制

  • 游戏的 Rewired 能识别的设备（hardwareGuid 不为零，例如 T.16000M）不在处理范围内。
  • 在已保存的映射中没有见过苦力帽的元素 id，因此会跳过苦力帽；滑块 id 遵循 Rewired 的通用定义。
  • 绑定已在游戏菜单中检查过，但尚未在飞行中验证；游戏对 Pitch 所期望的轴方向还没有确认。
  • 测试：engine\tests\smoke\nuclearoption.ps1（一个真实的 vJoy 映射，加上摄像机和游戏玩法绑定）；在游戏中运行 tools\e2e\games\NuclearOptionSettings.ps1（随机 vJoy 轴上的 Pitch、Roll 和 Yaw 会显示在 Control Mapper 的 vJoy 选项卡中，并且在游戏再次保存后导入能把它们读回来）。
