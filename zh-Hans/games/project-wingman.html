Project Wingman

显示：

Project Wingman 是一款基于 Unreal Engine 4 的街机空战游戏。它能同时读取多个 DirectInput 设备，并把绑定保存在一个纯文本的 Input.ini 中，每个绑定都以设备及其在游戏设备列表中的位置命名；曲线和死区保存在存档中。JoyPro 会把两者读入你的配置文件并写回。键盘、鼠标、手柄和苦力帽保持游戏中的设置不变。

新手入门

#3 步上手

  1. 全部帮我设置好
    在开始页面
  2. 使用这些按钮
    先查看列表
  3. 写入我的游戏
    保持 Project Wingman 关闭

之前：先启动一次游戏，然后关闭。为该游戏关闭 Steam Input。

之后：你的绑定会出现在游戏的 Controls 中。添加或移除了控制器？请再次导出。

以前在 Project Wingman 中绑定过按钮？那么开始页面会提供 导入，然后填补空缺。你的绑定会保留，只有空闲的按钮会获得新功能。请参见快速入门：让我的摇杆工作。

#JoyPro 能为 Project Wingman 做什么

  • 导入：飞行操作（俯仰、横滚、偏航、推力、两个视角轴和按钮）的每个摇杆绑定都会以你的真实设备导入你的配置文件，包括反转、曲线和死区。
  • 关联：Project Wingman 中的“Fire missile”可以和你其他游戏中的武器投放是同一个关联。
  • 导出：JoyPro 把你的绑定写入 Input.ini，把曲线和死区写入存档。

#导入你的 Project Wingman 绑定

  1. 如果你从未启动过游戏，请先启动一次，使其文件夹存在。
  2. 打开开始页面。如果 Project Wingman 卡片要求命令列表，请按 生成列表：JoyPro 会从游戏自己的文件中读取飞行操作。
  3. 在卡片上按 导入，保持选择 添加到我的配置文件（推荐），然后按 立即导入。

#建立并检查关联

在 关联 页面上把 Project Wingman 的操作与你的其他游戏合并（关联流程），然后在导出页面上运行 检查：它会找出在游戏中同时执行两件事的按钮。

#导出到 Project Wingman

  1. 关闭 Project Wingman。 游戏运行时 JoyPro 会拒绝写入。
  2. 打开 导出 并勾选 Project Wingman 卡片。
  3. 保持 在我的设备上替换 并勾选 同时清除我的其他设备；如果你也在游戏中绑定，则选择 更新，保留游戏的绑定。在卡片上按 立即导出。
在游戏中: 你在 Project Wingman 中会看到什么

打开游戏的 Controls。KEY BINDINGS 和 AXIS BINDINGS 会在每行的下一个空槽位中显示你的绑定，名称为去掉空格的设备名加编号，例如“VJOYDEVICE 8 BUTTON 24”或“VJOYDEVICE 8 AXIS 1”，你反转过的轴会勾选 Invert 框。CURVES + DEADZONES 会显示 JoyPro 为每个轴写入的 CURVE 和 DEADZONE。

#你在 Project Wingman 中需要自己做的事

  • 添加或移除控制器后请再次导出。 游戏按设备在其设备列表中的位置为设备编号，而控制器接入或移除时这个位置会改变。JoyPro 根据导出时连接的设备计算它。
  • 苦力帽：游戏无法绑定苦力帽。请在 Controls > Miscellaneous 中设置 Hat Function 1 / 2（WEAPON 或 VIEW）。
  • 为该游戏关闭 Steam Input；Steam Input 手柄会显示为一个额外的设备。

#常见问题

  • 绑定指向了错误的设备：导出后添加或移除了控制器。连接你平常使用的设备后再次导出。如果某个设备的编号变了，导入时会发出警告。
  • 苦力帽绑定被拒绝：这是有意设计的，请参见上面的 Hat Function。
  • 油门在下半段会刹车：“Thrust Axis”在 Project Wingman 中是一个中置轴：高于中点时加速，低于中点时刹车。
高级

#JoyPro 读取和写入的文件

文件 这是什么
%LOCALAPPDATA%\ProjectWingman\Saved\Config\WindowsNoEditor\Input.ini 绑定，位于 [/Script/Engine.InputSettings] 节：ActionMappings=(...) 和 AxisMappings=(...) 行
%LOCALAPPDATA%\ProjectWingman\Saved\SaveGames\savegame.sav 每个轴操作的曲线和死区（<Axis>Curve、<Axis>Deadzone）以及苦力帽功能
<install>\ProjectWingman\Content\Paks\pakchunk0-WindowsNoEditor.pak 只读：DefaultInput.ini，即游戏的默认绑定和操作列表
...\Input.ini.joypro-meta.json JoyPro 为导出的绑定保存的数据（名称、分组、调校），供下次导入使用

只要在游戏菜单中更改了绑定，游戏就会立即写入 Input.ini，而且只写入你改过的列表；其他列表来自 pak 中的默认值。因为写入的列表会取代默认值，所以 JoyPro 会先写入缺失列表的默认值。Steam Cloud 会同步存档文件夹。

#Project Wingman 中的导出模式

只会删除已编入目录的飞行操作的摇杆映射；键盘、手柄、鼠标、菜单行以及未连接的设备都保持不变。

模式 会发生什么
仅添加 如果某个绑定所用的输入已被游戏用于另一个飞行操作，该绑定不会被写入（标记为“未写入游戏”）；游戏自己的绑定形式（Invert）保持不变。
更新，保留游戏的绑定 此外，如果配置文件把某个输入分配给另一个操作，游戏在该输入上的映射也会被删除；该操作的其他映射保持不变。
更新，以我的配置文件为准 此外，配置文件所绑定的每个操作的其他摇杆映射也会被删除，这样移动绑定就是彻底移动。
在我的设备上替换 导出的设备会失去其他摇杆映射（这是一个纯飞行游戏）。
+ 同时清除我的其他设备 其他已连接的设备也同样如此。

#绝不会改动的内容

  • 键盘、鼠标和手柄映射、菜单行、苦力帽。
  • 未连接的设备、导入时忽略的设备，以及 JoyPro 转发到的 vJoy 设备。
  • Input.ini 的其他所有行（顺序和换行符保持不变）以及 savegame.sav 的其他所有字节。

#曲线、死区及其他设置

  • 按轴操作设置，所有设备共用：俯仰、横滚、推力、偏航以及两个视角轴的 CURVE（菜单中的 0.00 到 2.00，1.00 = 直线）和 DEADZONE（0 到 100 %）。游戏的默认值：俯仰和横滚 25 %，视角 10 %，推力和偏航 0 %。
  • 每个绑定的 反转（该槽位的 Invert 复选框）。
  • 游戏的计算公式尚不清楚。JoyPro 的预览假定死区会重新缩放，曲线作为指数（尚未确认）。
  • 全局：没有飞机配置文件。没有修饰键（游戏本身没有），没有力反馈。
  • 监视器：游戏关闭后会监视 Input.ini 和 savegame.sav（监视器）。
  • HUD：游戏运行时，HUD 会显示每个按下按钮对应的操作名称。
技术细节

#Project Wingman 集成的内部机制

代码：engine\Games\ProjectWingmanIntegration.cs、engine\Games\ProjectWingmanSaveGame.cs、engine\AxisModels\ProjectWingman.cs（轴模型 projectwingman）。

  • 键：Joystick_<name>_<place>_Axis<n>、..._Button<n>。<name> 是去掉空格的 DirectInput 产品名称（VPforce Rhino FFB Joystick 变为 VPforceRhinoFFBJoystick），而不是 HID 字符串。<place> 是设备在游戏列表（Controls > Miscellaneous）中的位置，即 DirectInput 顺序的倒序；XInput 手柄不在该列表中。Axis<n> 按 X Y Z Rx Ry Rz Slider Slider 的顺序从 0 开始数设备实际存在的轴；Button<n> 从 0 开始数。名称中带逗号的键会加引号。
  • 反转 = Scale=-1.000000。
  • 默认值：pak 默认值中的 Android_* 键会被保留，因为菜单为每个映射显示一个槽位，而这些键就是空槽位。
  • savegame.sav：Unreal GVAS；FloatProperty <Axis>Curve（菜单值的一半）和 <Axis>Deadzone（0..1），就地编辑，或添加在结尾的 None 之前。没有校验和。
  • 命令列表：engine pw refresh-db 读取 pak 中的 DefaultInput.ini 和你的 Input.ini：6 个轴和 14 个按钮。
  • 命令：engine pw paths、engine pw catalog、engine pw scan、engine pw import、engine pw export --mode clean|add|merge|merge-overwrite --nuke-untouched-devices --dry-run。

#已知限制

  • 设备编号会随你的控制器而变：更换硬件后请重新导出。
  • 苦力帽和修饰键会被拒绝。
  • 曲线公式是一个工作假设。
  • 在游戏中完整运行一次测试的工作尚未完成；导出和导入已在游戏中验证过。
  • 测试：engine\tests\smoke\projectwingman.ps1（与真实格式一致的测试数据）；在游戏中运行 tools\e2e\games\ProjectWingmanSettings.ps1（随机的轴、按钮、反转、曲线和死区；读回控制设置页面；恢复配置和存档文件夹）。
