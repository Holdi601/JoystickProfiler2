WARDOGS

显示：

WARDOGS 是一款基于 Unreal Engine 5 的直升机战斗游戏。它自己的摇杆插件会读取每个 DirectInput 设备，并把绑定保存在一个设置文件中：六个飞行轴和各个飞行操作，每个都带有所属的设备。JoyPro 会把这一部分读入你的配置文件并写回，同时写回 HOTAS 页面的灵敏度、死区和 Enable HOTAS 开关。键盘、鼠标以及文件的其他所有部分都保持不变。

新手入门

#3 步上手

  1. 全部帮我设置好
    在开始页面
  2. 使用这些按钮
    先查看列表
  3. 写入我的游戏
    保持 WARDOGS 关闭

之前：在游戏中打开一次 Settings > GAMEPAD > HOTAS。然后关闭游戏。

之后：Enable HOTAS 已开启，你的绑定位于 HOTAS 页面上。

以前在 WARDOGS 中绑定过按钮？那么开始页面会提供 导入，然后填补空缺。你的绑定会保留，只有空闲的按钮会获得新功能。请参见快速入门：让我的摇杆工作。

#JoyPro 能为 WARDOGS 做什么

  • 导入：HOTAS 页面的绑定会导入你的配置文件：Pitch、Roll、Yaw、总距（Throttle）、两个视角轴以及飞行操作（Fire、Flares、Reload、Horn、Ping ……），每个都在其所属设备上，包括反转、灵敏度和死区。
  • 关联：一个关联可以同时服务 WARDOGS 和你的其他游戏：例如，WARDOGS 和 DCS 直升机中油门杆上的“Collective”。
  • 导出：JoyPro 把直升机绑定写入游戏的设置文件，并开启 Enable HOTAS，让游戏使用这些绑定。

#导入你的 WARDOGS 绑定

  1. 打开开始页面。如果 WARDOGS 卡片要求命令列表，请按 生成列表：JoyPro 会根据你自己的设置文件和它自己的轴表生成列表。
  2. 在 WARDOGS 卡片上按 导入。保持选择 添加到我的配置文件（推荐）。
  3. 按 立即导入。查看我的关联 会打开导入的内容。

#建立并检查关联

在 关联 页面上，把 WARDOGS 操作与你其他游戏中的相同功能合并，参见关联流程。然后在导出页面上运行 检查：它会在游戏之前找出在 WARDOGS 中同时执行两件事的按钮。

#导出到 WARDOGS

  1. 关闭 WARDOGS。 游戏退出时会重写整个设置文件，所以游戏运行时 JoyPro 会拒绝写入。
  2. 打开 导出 并勾选 WARDOGS 卡片。
  3. 如果你是在 JoyPro 中设置摇杆的，请保持选择 在我的设备上替换 并勾选 同时清除我的其他设备。在卡片上按 立即导出。
在游戏中: 你在 WARDOGS 中会看到什么

启动 WARDOGS 并打开 Settings > GAMEPAD > HOTAS。Enable HOTAS 已开启，每个轴行都会显示你的设备和轴，以及反转复选框、Sensitivity 和 Deadzone 滑块，各操作会显示你的按钮。菜单中操作按钮从 0 开始计数，而半轴按钮从 1 开始计数，所以同一个按钮可能显示两个不同的编号。

#你在 WARDOGS 中需要自己做的事

  • 第一次导出前，先打开一次 HOTAS 页面。JoyPro 只写入游戏的摇杆部分；如果文件中还没有这一部分，导出会停止，并提示你在游戏中打开该页面。
  • Enable HOTAS 开启时会关闭鼠标和键盘飞行。JoyPro 每次写入绑定时都会开启它。如果想自己控制，请在 设置 > 游戏的力反馈设置（游戏 WARDOGS）中设置：你在那里保存的内容会在每次导出时写入。
  • “Garage / Vendor”和“Free Look Reset”还不在 JoyPro 的列表中。请先在游戏中绑定一次，然后在 WARDOGS 卡片上按 更新：JoyPro 会添加它在你的文件中找到的操作。

#常见问题

  • “WARDOGS 正在运行”：关闭游戏，然后再次导出。
  • 某个设备在游戏中显示 NOT CONNECTED：游戏按 VID:PID 和 DirectInput 名称来命名设备。连接该设备后再次导出：如果名称与具有相同 VID:PID 的已连接设备不同，JoyPro 会修复它。
  • 两个相同的设备：WARDOGS 无法区分它们（它们的名称相同）。请使用虚拟摇杆，或在 WARDOGS 绑定中只保留其中一个。
  • 飞行中绑定没有反应：检查 HOTAS 页面上的 Enable HOTAS；它关闭时，游戏会忽略所有摇杆绑定。
高级

#JoyPro 读取和写入的文件

文件 这是什么
%LOCALAPPDATA%\Wardogs\Saved\Config\WindowsClient\GameUserSettings.ini [/Script/WDJoystick.WDJoystickSettings] 节中的绑定；[/Script/WDGame.WDUserSettings] 中的全游戏开关 Enable HOTAS（bUseHOTASHelicopters）和 Self-Centering Collective（bCollectiveSelfCentering）
...\GameUserSettings.ini.joypro-meta.json JoyPro 为导出的绑定保存的数据（关联名称、分组、调校），下次导入时会读回
...\GameUserSettings.ini.jpbak 第一次写入前的备份（同时也保存在 JoyPro 的备份库中）

同一文件中以及 Saved\SaveGames\EnhancedInputUserSettings.sav 中的键盘绑定不会被读取或写入。JoyPro 不从安装目录读取任何内容：你的设置文件就是命令列表的来源。

#WARDOGS 中的导出模式

游戏每个操作只用一个绑定。每种模式都只作用于 JoyPro 已编入目录的直升机操作；文件中的其他行和节从不改变。

模式 会发生什么
仅添加 只有当操作的槽位空闲，且没有其他已编入目录的操作使用该按钮或轴时，绑定才会写入；否则会被跳过，并标记为“未写入游戏”。已绑定的槽位从不被替换。
更新，保留游戏的绑定 你的绑定会占用该操作的槽位（替换那里的输入）。同一输入上的另一个已编入目录的操作会失去它。该操作的第二行保持不变。
更新，以我的配置文件为准 同上，另外该操作的多余行会被删除，这样移动的操作就是彻底移动。
在我的设备上替换 你写入的设备只保留你为已编入目录的操作所做的绑定。
+ 同时清除我的其他设备 在你的配置文件中没有绑定的已连接设备会失去它们已编入目录的绑定。

导出没有 WARDOGS 绑定的配置文件时，只会写入你保存的全游戏设置。

#绝不会改动的内容

  • 键盘和鼠标绑定、键盘存档文件，以及摇杆节之外的每个节（两个全游戏开关除外）。
  • JoyPro 未编入目录的操作：它们的行保持原样。
  • 未连接的设备、导入时忽略的设备，以及 JoyPro 转发到的 vJoy 设备。
  • 绑定行中的未知字段：保持原样。

#轴、灵敏度、死区

  • 全局：WARDOGS 没有飞机或载具配置文件；绑定对每架直升机都有效。
  • 每个轴：反转、Sensitivity（灵敏度，0.1 到 2.0，1 = 不变）和 Deadzone（死区，0 到 0.5），使用 HOTAS 页面自己的单位，四舍五入到两位小数。导入会把它们保存为该关联的 WARDOGS 调校，这样你的其他游戏会保留各自的曲线。
  • 没有 WARDOGS 数值时，JoyPro 会根据你的基础曲线进行拟合：死区直接沿用，灵敏度跟随到饱和点为止的斜率。滑块的死区不会沿用，因为 WARDOGS 把总距当作居中的轴。曲率和用户曲线无法表达；导出会给出警告。
  • 游戏不显示预览，其计算公式也不清楚。JoyPro 的预览假定先反转，再重新缩放死区，然后乘以灵敏度，在满偏转处截断（尚未确认）。
  • 游戏设置：Enable HOTAS 和 Self-Centering Collective（用于双摇杆设置：松手后总距回到悬停位置；使用油门杆时请保持关闭），位于 设置 > 游戏的力反馈设置。只有当文件中已有该键时才会写入。WARDOGS 没有力反馈。
  • 监视器：你在 HOTAS 页面上更改的绑定会在游戏关闭后被发现；JoyPro 会询问是否接受该更改（监视器）。
  • HUD：WARDOGS 运行时，HUD 会显示每个按下按钮对应的操作。
技术细节

#WARDOGS 集成的内部机制

代码：engine\Games\WardogsIntegration.cs、engine\AxisModels\Wardogs.cs（轴模型 wardogs）、engine\FfbModels\Wardogs.cs（两个全游戏开关）。

  • 文件：ASCII、CRLF、无 BOM，第一行为 ;METADATA=(Diff=true, UseCommands=true)。轴行总是全部六行，顺序为 Pitch、Throttle、Roll、Yaw、LookPitch、LookYaw；每个已绑定的操作一行 ActionBindings=(Action=<action>,Binding=(...))，新行加在最后一行之后。解除轴的绑定用 DeviceIdentifier=""；解除操作的绑定则删除它的行。浮点数保留六位小数。名称保持 ASCII（非 ASCII 名称会让引擎以 UTF-16 保存）。
  • 字段名称：大多数字段是哈希后的标记（_aaaa...）。JoyPro 从不把它们写死：它根据字段相对于可读锚点（DeviceIdentifier、bInvert、Positive、Sensitivity、DeadZone）的位置找到每个字段，一旦结构发生变化就停止。
  • 设备：DeviceIdentifier="VID:PID:<DirectInput instance name>"，VID 和 PID 取自 DirectInput 产品 GUID，名称与 DirectInput 报告的完全一致，包括两端的空格（从不修剪）。轴编号是 DIJOYSTATE2 的槽位（0 X、1 Y、2 Z、3 Rx、4 Ry、5 Rz、6/7 滑块）；按钮从 0 开始数。
  • 命令列表：engine wardogs refresh-db 根据你的设置文件加上 JoyPro 的轴来生成它；engine wardogs catalog 列出它，engine wardogs paths 显示 JoyPro 在哪里查找。
  • 导入 / 导出：engine wardogs scan、engine wardogs import、engine wardogs export --mode clean|add|merge|merge-overwrite --nuke-untouched-devices --ignore-device <d> --dry-run。
  • 游戏设置：engine ffb set --device * --game Wardogs --param enableHotas=true（或 selfCenteringCollective）。

#已知限制

  • 完整的操作列表尚不清楚；JoyPro 列出在真实文件中见到的操作。
  • 苦力帽方向作为操作：编码方式尚未确认。
  • Sensitivity 和 Deadzone 的响应公式尚不清楚。
  • 相同的设备会得到同一个标识符，从而发生冲突。
  • 测试：engine\tests\smoke\wardogs.ps1；在游戏中运行 tools\e2e\games\Wardogs.ps1（绑定）、WardogsSettings.ps1（HOTAS 页面的数值）和 Watchdog.ps1（监视器）。
