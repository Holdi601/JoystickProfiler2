新手入门

#3 步上手

  1. 全部帮我设置好
    在开始页面
  2. 使用这些按钮
    先查看列表
  3. 写入我的游戏
    保持 War Thunder 关闭

之前：登录一次。插上你的设备，启动游戏并打开一次 Controls。然后退出。

之后：登录。你的绑定会出现在 Controls 中。

以前在 War Thunder 中绑定过按钮？那么开始页面会提供 导入，然后填补空缺。你的绑定会保留，只有空闲的按钮会获得新功能。请参见快速入门：让我的摇杆工作。

#JoyPro 能为 War Thunder 做什么

  • 导入：你设备上的飞机和直升机快捷键及轴会导入你的配置文件，包括游戏 Axis setup 对话框中的每个值，以及全局游戏控制选项（灵敏度、反转、WEP、自动配平、力反馈）。
  • 关联：一个关联就是所有游戏中的同一个功能。“起落架”可以是 War Thunder、DCS 和 IL-2 中的同一个开关。
  • 导出：JoyPro 就地编辑 machine.blk。坦克、舰船、潜艇、步兵和菜单永远不会被改动。

#导入你的 War Thunder 绑定

  1. 打开开始页面。如果 War Thunder 卡片要求命令列表，请按 生成列表：JoyPro 会从游戏的存档包中读取飞机和直升机操作（只读；290 个操作）。可以在 设置 > 游戏 中关闭此功能；JoyPro 随后会使用它自己较短的列表。
  2. 在 War Thunder 卡片上按 导入。保持选择 添加到我的配置文件。如果你也想把飞行按键放进 JoyPro，请勾选 同时获取键盘按键。
  3. 按 立即导入。查看我的关联 会打开导入的内容。

#建立并检查关联

用关联流程把你各个游戏中的相同功能合并起来，然后在导出页面上按 检查。在 War Thunder 中，飞机的油门和直升机的总距放在同一个轴上没有问题；但同一个按钮上有两个飞机操作则不行。

#导出到 War Thunder

  1. 关闭 War Thunder。 游戏在运行期间会不时保存该文件，退出时也会保存，所以游戏运行时 JoyPro 会拒绝写入。
  2. 打开 导出 并勾选 War Thunder 卡片。
  3. 如果你是在 JoyPro 中设置摇杆的，请保持选择 在我的设备上替换 并勾选 同时清除我的其他设备。在卡片上按 立即导出。
在游戏中: 你在 War Thunder 中会看到什么

启动游戏并登录。在机库中按 Esc 并打开 Controls。你的绑定位于飞机和直升机部分；某个轴的 Axis setup 对话框会显示它的死区、非线性、倍率、校正和反转。灵敏度行、力反馈倍率和自动配平只在 Realistic 和 Full-real 控制模式下列出。点击 Mouse aim / Simplified / Realistic / Full-real 标签页会改变你的控制模式，而不是筛选列表。

#你在 War Thunder 中需要自己做的事

  • 先让游戏把每个设备列出一次。 War Thunder 在它自己的表中按设备为按钮和轴编号。插上设备，启动游戏并打开 Controls：游戏随后会把该设备添加到 machine.blk。游戏尚未列出的设备会被 JoyPro 跳过。
  • 第一次导出前先登录一次，让你账号的文件存在。

#常见问题

  • “War Thunder 正在运行”：退出游戏，然后再次导出。
  • 某个设备被跳过：游戏还没有列出它，或者有两个已连接的设备共用它的 VID:PID，或者它的按钮或轴数量与游戏记录的不同（所有编号都会错位）。请在插着该设备的情况下在游戏中打开 Controls。
  • 登录后旧绑定又回来了：你手动恢复了一个副本。请改用 撤销上次导出：JoyPro 会提高该文件的版本号，这样服务器就不会替换它。
  • 苦力帽斜向方向、鼠标按钮和轴修饰键 无法写入。
高级

#JoyPro 读取和写入的文件

文件 这是什么
%USERPROFILE%\Documents\My Games\WarThunder\Saves\<uid>\production\machine.blk 你的控制设置（hotkeys{}、axes{}、params{}、deviceMapping{}）以及游戏的设置块；<uid> 是你的账号（由 Saves\lastlogin.blk 指明；登录之前为 Saves\last）
...\production\machine.blk.joypro-meta.json JoyPro 为已写入的绑定保存的名称、分组和调校，下次导入时会读回
machine.blk.jpbak 首次写入之前的副本，以及 JoyPro 带版本的备份存储
导出的控制预设（顶层为 controls{}） 也可以导入和导出；全游戏范围的选项只写入 machine.blk

machine.blk 是相对于 basePresetPaths 中所指基础预设的差异：某个快捷操作的第一个块会替换预设中该操作的整个列表，空的 ID_X{} 表示未绑定，缺少某个轴属性则表示“使用预设的值”。JoyPro 写入已编入目录的快捷操作块、axisId 和已编入目录的轴的数值，以及你设置的单个选项键。其他每一行都保持原文；deviceMapping{} 只读取。

#War Thunder 中的导出模式

只有已编入目录的飞机和直升机控制才算在内。冲突是指同一输入上有另一个这类控制。

模式 machine.blk 中会发生什么
仅添加 只有当没有其他飞机或直升机控制使用某个输入时，才会写入快捷操作；它从不删除块，也不替换已绑定的轴。被跳过的绑定会被标记为“未写入游戏”。
更新，保留游戏的绑定 你的快捷操作会与该控制的其他快捷操作并存；只删除冲突项（你的轴上另一个控制的轴会得到 axisId -1）。
更新，以我的配置文件为准 同上，另外你绑定的控制会失去它在游戏所列出的已连接设备上的其他快捷操作（键盘只有在开启键盘选项时才会）。
在我的设备上替换 同上，另外已写入设备上的其他飞机和直升机快捷操作及轴都会被清除。
+ 同时清除我的其他设备 对配置文件中没有绑定的已连接设备也是如此。

当 JoyPro 绑定某个控制时，空的 ID_X{} 会被替换。如果文件中缺少某个控制，会给出警告：这时你的快捷操作会取代基础预设中该控制的默认设置。

#绝不会改动的内容

  • 坦克、舰船、潜艇、步兵和菜单的快捷操作及轴。
  • deviceMapping{}、config{} 以及 JoyPro 没有设置的每一行设置。
  • 鼠标绑定、未连接的设备、导入时被忽略的设备，以及 JoyPro 用于转发的 vJoy 设备。
  • 键盘，除非你导出键盘绑定。
  • 相对控制、保持数值和轴范围保持文件中的原样，除非你设置了它们。

#飞机、曲线、游戏选项

  • 粒度：所有飞机共用一套控制设置，所有直升机共用一套（游戏没有按飞机区分的绑定）。
  • 修饰键：快捷操作的最后一个按钮是主输入，块中的其他按钮和按键是它的修饰键。每个快捷操作最多三个备选。
  • 轴曲线使用游戏自己的单位，与轴设置对话框中显示的一致：死区（0 到 0.5）、非线性（0 到 3，显示为 1 到 4）、乘数、校正、反转、相对控制及其灵敏度和步长、轴禁用时保持数值。没有 War Thunder 数值的关联会根据其 JoyPro 曲线进行拟合：乘数 = 1 / 饱和度 X，死区随之缩放，取最接近的非线性值；滑块会把死区和饱和度之间的行程映射到整个范围上。与基础预设相同的数值会省略该行，与游戏自己保存的方式一样。
  • 游戏选项：飞机和直升机的横滚、俯仰和偏航灵敏度，反转 Y 轴（飞机、直升机），反转油门，按住油门开启 WEP，自动配平，开启力反馈（需要重启游戏）及其乘数。可在 设置 > 游戏的力反馈设置（选择 War Thunder）中或用 engine ffb set 设置它们。即使导出的配置文件中没有 War Thunder 绑定，也会写入它们；导入时会采用文件中的数值。
  • 云端副本：登录时，游戏会把文件第一行 version:i=N 与服务器上的进行比较。JoyPro 会保留这个版本号，所以你的新内容会被上传。撤销上次导出 会给恢复的文件一个比被替换文件更高的版本号，这样服务器上的副本就不会回来。
  • 遥测力反馈：力反馈页面利用游戏的本地 Web 服务器（127.0.0.1:8111，由运行中的游戏提供；无需任何设置）来驱动你的力反馈摇杆。请为该摇杆关闭游戏自身的力反馈。
  • 遥测录制：JoyPro 可以从同一服务器录制一次出击，并导出为 CSV 或 Tacview 格式（以 0/0 为中心的平面地图，因为游戏没有真实的地理位置）。
  • 监视器：你在游戏中更改的绑定、轴数值或选项会在游戏关闭后被发现；按键顺序变化或游戏的差异写法不算更改。
  • HUD：HUD 通过进程识别该游戏，并显示你的 War Thunder 绑定。
技术细节

#War Thunder 集成的内部机制

代码：engine\Games\WarThunderIntegration.cs、engine\Games\WarThunderVromfs.cs、轴模型 engine\AxisModels\WarThunder.cs 以及设置模型 engine\FfbModels\WarThunder.cs。

  • 设备：deviceMapping{ joystick{ devId:t="0738:2215" name:t="..." buttonsOffset:i= buttonsCount:i= axesOffset:i= axesCount:i= } }。devId 是 DirectInput 产品的 VID:PID；游戏只按 devId 匹配设备，所以两个相同的设备会合并为一个。joyButton = buttonsOffset + 本地索引（先是按钮，然后每个苦力帽四个：上、右、下、左）；axisId = axesOffset + 按 DirectInput 顺序的本地索引（X、Y、Z、Rx、Ry、Rz、两个滑块），然后每个苦力帽两个。engine games devices 显示 JoyPro 对每个设备看到的内容。
  • 格式：BLK 文本，name:type=value，块名称可以重复（解析为有序列表），CRLF 换行。controls.version 低于 5 的文件属于旧格式，不会被读取。
  • 命令列表：engine warthunder refresh-db 从 gui.vromfs.bin 中读取 shortcutsgroupaircraft.nut 和 shortcutsgrouphelicopter.nut，从 lang.vromfs.bin（lang/controls.csv）中读取标题，这些文件会解包到一个临时文件夹，之后删除；只保留 id 和标题。--no-game-archives（设置 > 游戏：取消勾选“War Thunder：从游戏存档中读取完整的命令列表”）使用 JoyPro 自带的 116 个操作的列表；不带 ID_ 的 id 是轴。--path 接受一个以普通文件形式存放控制脚本的文件夹。
  • 导入 / 导出：engine warthunder import、engine warthunder scan；engine warthunder export --mode clean|add|merge|merge-overwrite --nuke-untouched-devices --include-keyboard --ignore-device <d> --dry-run。
  • 基础预设：由于没有官方预设数值表，导出会显式写入每个调校过的轴属性（从不因为“与基础预设相同”而省略某一行），因此无论基础预设是什么，文件都是正确的；对于文件没有设置的属性，导入使用代码中的默认值。
  • 游戏选项：engine ffb set --device * --game WarThunder --param <key>=<value>（joyFX、forceGain 0..100、aileronsMultiplier ……以 % 为单位、invertY、invertYHelicopter、invertT、holdThrottleForWEP、autotrim）。
  • 遥测：engine ffb telemetry setup 和 engine telemetry record；JoyPro 每秒轮询 /state 20 次，每隔一次请求轮询一次 /indicators，而且只在游戏运行时轮询。

#已知限制

  • 没有附带基础预设的数值表（见上文）。
  • 有一次监视器运行时漏掉了“按住油门开启 WEP”的更改，还有一项灵敏度读回时差了一。
  • 每个设备读取 128 个按钮和 4 个苦力帽；苦力帽斜向、鼠标按钮和轴修饰键不会被写入。
  • 测试：在游戏中运行 tools\e2e\games\WarThunderSettings.ps1（vJoy 轴上的绑定、俯仰和油门的轴设置对话框、Controls 页面的数值，以及导入游戏重写后的文件）。
