新手入门

#3 步上手

  1. 全部帮我设置好
    在开始页面
  2. 使用这些按钮
    先查看列表
  3. 写入我的游戏
    保持 Arma Reforger 关闭

之前：先启动一次 Arma Reforger 并打开 Settings > Controllers，然后关闭游戏。

然后（只需一次）：在游戏中打开 Settings > Controllers。在 Joystick preset 下选择 JoyPro。重启游戏。之后再导出时，只需重启即可。

你以前在 Arma Reforger 中绑定过按钮吗？那么开始页面会提供 导入，然后填补空缺。你的绑定会保留，只有空闲的按钮会获得新功能。参见 快速入门：让我的摇杆能用。

#JoyPro 为 Arma Reforger 做了什么

  • 导入：摇杆预设中的直升机绑定会连同倍率和反转设置一起进入你的配置文件。
  • 关联：一个关联就是所有游戏中的同一个功能。“Collective”可以是 Reforger、Arma 3 和 DCS 中的同一根拉杆。
  • 导出：JoyPro 写入的 JoyPro.conf 只包含直升机飞行操作和你的摇杆，并把你的设备分配到游戏的四个摇杆槽位中。步兵和载具控制、键盘、鼠标和手柄保持游戏原样。

#导入你的 Reforger 绑定

  1. 打开 开始 页面。如果 Arma Reforger 卡片要求生成命令列表，按 生成列表：JoyPro 会从游戏文件中读取直升机操作及其名称（只读）。
  2. 在 Arma Reforger 卡片上按 导入，保持选择 添加到我的配置文件。
  3. 按 立即导入。查看我的关联 会打开导入的内容。

在 Reforger 中，键盘绑定和修饰键不会被导入或导出：JoyPro 只管理你的摇杆。

#建立并检查关联

用 关联流程 把你各个游戏中的同一功能连接起来，然后在导出页面按 检查。原版游戏只有直升机（UH-1H、Mi-8）；固定翼飞机操作只有通过模组才会出现。

#导出到 Arma Reforger

  1. 关闭 Arma Reforger。 游戏会在你更改设置时写入设置，因此游戏运行时 JoyPro 拒绝写入。
  2. 打开 导出 并勾选 Arma Reforger 卡片。
  3. 如果你是在 JoyPro 中设置摇杆的，请保持选择 在我的设备上替换 并勾选 同时清除我的其他设备。在卡片上按 立即导出。
在游戏中: 你在 Arma Reforger 中看到的内容

启动游戏并打开 Settings > Controllers。在 Joystick preset 下选择 JoyPro（只需一次），然后重启游戏。设备 列表会显示你的摇杆位于 JoyPro 选择的槽位中。预设的绑定不会显示在 Settings > Controls 中：该页面只列出键盘和手柄两列。

#在 Arma Reforger 中需要你自己做的事

  • 选择一次预设：Settings > Controllers > Joystick preset > JoyPro，然后重启。之后再导出时，只需重启即可。如果在那里选择一个手柄的 Controller preset，它会替换摇杆预设：两者只能有一个处于启用状态。
  • 第一次导出之前，启动一次游戏并打开 Settings > Controllers。JoyPro 只会把设备顺序写入游戏已保存的设置文件；如果没有这个文件，它会按游戏的方式为你的设备编号并发出警告。
  • 最多四个摇杆。 游戏会使用启动后最先发送输入的四个设备；之后的任何设备都会替换第四个。如果设备更多，玩 Reforger 时请拔掉或隐藏其他设备（例如用 HidHide）。虚拟摇杆 模式可以把你的设备合并成一个，但在四次启动中，vJoy 设备都没有出现在游戏里。

#常见问题

  • 飞行中没有任何反应：没有选择 JoyPro 预设，或者导出后没有重启游戏。
  • 少了一个摇杆：发送输入的摇杆超过了四个，或者在游戏窗口获得焦点时该设备从未发送过输入。让游戏窗口位于前台，然后移动它的某个轴或按一个按钮。
  • 两个相同的设备：游戏通过名称区分设备，因此两个相同型号的设备只有一条槽位规则；第二个设备得不到槽位。
  • 稳定版和测试版：这两个版本使用各自独立的设置文件夹。JoyPro 会把设备顺序写入它找到的每一个设置文件夹。
高级

#JoyPro 读取和写入的文件

文件 这是什么
%USERPROFILE%\Documents\My Games\ArmaReforger\profile\.save\settings\customInputConfigs\JoyPro.conf JoyPro 自己的摇杆预设（Enfusion 文本）：每个直升机操作一个 Action 块，包含它的摇杆来源和过滤器
...\profile\.save\app<id>_user<steam id>\settings\ReforgerEngineSettings.conf 游戏的引擎设置；JoyPro 只编辑 DeviceOrderRules 下的 JoystickOrderRule 条目
...\app<id>_user<steam id>\settings\ReforgerGameSettings.conf 游戏设置；JoyPro 只在你设置时编辑 HOTAS 总距模式和力反馈强度
JoyPro.conf.joypro-meta.json JoyPro 为已写入的绑定保存的名称、分组和调校，下次导入时会读回
*.jpbak 首次写入之前的副本，以及 JoyPro 带版本的备份存储

游戏自己的重新绑定文件 InputUserSettings.conf 永远不会被改动，customInputConfigs 中你的其他预设也不会。旧版本中这两个设置文件名为 EngineUserSettings.conf 和 GameUserSettings.conf（内容相同）。

#设备顺序规则

游戏最多列出四个摇杆（joystick0 到 joystick3），当某条规则的名称是设备名称的一部分时，就给该设备分配一个槽位。导出时 JoyPro 会：

  1. 把你为某个槽位选择的设备放到该槽位（joystickSlot 设置，0 到 3；-1 = 自动）；
  2. 保留现有规则给设备的槽位（包括游戏自己那些名称较长的规则）；
  3. 给其他设备分配没有规则占用的最低槽位。

每条规则使用设备的 HID 产品名称（游戏中的名称包含它）。JoyPro 会就地更改槽位或添加规则，并且只写入槽位 0 到 3。当使用的设备超过四个、没有剩余槽位或两个选定的槽位相同时，它会发出警告。导入时通过同样的规则把 joystickN 映射回来。

#Arma Reforger 中的导出模式

只有预设中的飞行 Action 块会改变。键盘、鼠标和手柄来源以及未连接的摇杆始终保持不变。

模式 JoyPro.conf 中会发生什么
仅添加 所有来源都保留。如果某个绑定所用的摇杆输入已被另一个飞行操作使用，该绑定不会被写入，并标记为“未写入游戏”。
更新，保留游戏的绑定 写入你的来源；同一输入上另一个飞行操作的来源会被移除。该操作原有的来源保留。
更新，以我的配置文件为准 同上，此外，你绑定的操作会失去已连接设备上的其他摇杆来源。
在我的设备上替换 你写入的设备上的飞行来源会被丢弃，换成你的来源。
+ 同时清除我的其他设备 对配置文件中没有绑定的已连接设备也是如此。

没有剩余来源的块会被移除。

#绝不会改动的内容

  • InputUserSettings.conf、你的其他预设，以及所有步兵、载具和菜单操作。
  • 键盘、鼠标和手柄来源；未连接的摇杆；导入时忽略的设备，以及 JoyPro 转发到的 vJoy 设备。
  • 两个设置文件中除顺序规则和 JoyPro 管理的两项设置以外的每一行。缺失的设置块不会被创建（JoyPro 会警告：请在游戏中更改一次该设置）。
  • 不会读取创意工坊模组。

#直升机、曲线、设置

  • 粒度：所有直升机共用一套绑定（游戏的 Helicopter 上下文）。
  • 轴设置：每个绑定一个倍率和反转，以游戏的值过滤器形式写入轴的两半。Reforger 每个设备轴的死区和曲线不会被写入（其格式尚不清楚）。
  • 按钮的行为与游戏按键相同：按钮会获得与游戏中该操作默认来源相同的预设和过滤器（单击、按住、重复），所以“Engine start”是按住，“Sight range down”会重复。
  • 游戏设置：HOTAS 总距模式（Default、Manual、Sticky、Direct；游戏对 HOTAS 的默认值是 Direct）和力反馈强度（0 到 3）；每个设备的 joystickSlot。在 设置 > 游戏的力反馈设置（选择 Arma Reforger）中或用 engine ffb set 设置。即使导出中没有 Reforger 的绑定，也会写入这些设置。
  • 监视器：预设或游戏设置中的更改会在游戏关闭后被发现；JoyPro 会询问是否采用这些更改。
  • HUD：HUD 通过进程识别游戏，并显示你的 Reforger 绑定。
技术细节

#Reforger 集成的内部原理

代码：engine\Games\ArmaReforgerIntegration.cs、engine\Games\ReforgerCatalogSource.cs、engine\Games\EnfusionPak.cs，轴模型 engine\AxisModels\ArmaReforger.cs 和设置模型 engine\FfbModels\ArmaReforger.cs。

  • 格式：Enfusion 文本，一个空格缩进，Key Value，对象 Class "{16 hex digits}" {；每个新对象都会获得一个唯一的随机 id。输入：joystick0:button4（从 0 开始）、joystick0:axis6，半轴 joystickN:axisA+ / axisA-，苦力帽 joystickN:pov_up|pov_down|pov_left|pov_right；轴 0 到 7 = X、Y、Z、Rx、Ry、Rz、Slider 0、Slider 1。整轴操作写成 joystickN:axisA（用负的 Multiplier 反转）。
  • 设备：游戏通过原始输入（usage page 1、usage 4）识别摇杆，条件是该设备在游戏窗口拥有焦点时第一次发送报告；手柄和多轴控制器在这里永远不算摇杆。它的表有四个条目；第五个新设备会覆盖第四个。
  • 命令列表：engine reforger refresh-db 从游戏的 .pak 归档中（只读）读取 Configs/System/chimeraInputCommon.conf、keyBindingMenu.conf 的菜单标题和 localization.en_us.conf，再加上你的预设中的操作；只计入 Helicopter / Airplane 上下文。engine reforger catalog 列出它们，engine reforger paths 显示找到的文件。
  • 导入 / 导出：engine reforger import、engine reforger scan；engine reforger export --mode clean|add|merge|merge-overwrite --nuke-untouched-devices --ignore-device <d> --dry-run。
  • 设置：engine ffb set --device * --game ArmaReforger --param hotasCollective=<0..3>（还有 forceFeedbackIntensity）；--device "<device>" --param joystickSlot=<0..3>；大于 3 的槽位会被拒绝。

#已知限制

  • 导出尚未在运行中的游戏里检查过；设置菜单已经检查过。
  • 只有倍率和反转；没有死区或曲线。
  • 最多四个摇杆；vJoy 设备在四次启动中都没有出现在游戏中，因此只有在设备超过四个时才建议使用虚拟摇杆。
  • 预设是替换还是补充游戏默认的键盘来源，尚未确认。
  • 测试：engine\tests\smoke\arma.ps1（过滤器、顺序规则、游戏设置、拒绝情况）。
