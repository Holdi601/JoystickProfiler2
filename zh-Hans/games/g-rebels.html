G-Rebels

显示：

G-Rebels 是一款基于虚幻引擎 5 的赛博朋克飞行战斗游戏：你驾驶 VTOL 飞越巨型城市。游戏会把你开启的每个摇杆放到一个 通道（0 到 5）上，并在两个存档文件中按通道保存每个轴的角色（俯仰、滚转、偏航、推力、平移、上 / 下）和按钮绑定。JoyPro 会把这些角色和绑定读入你的配置文件并写回；键盘、手柄和鼠标保持游戏原样。

新手入门

#3 步上手

  1. 全部帮我设置好
    在开始页面
  2. 使用这些按钮
    先查看列表
  3. 写入我的游戏
    保持 G-Rebels 关闭

之前，在游戏中对每个设备各做一次：在 OPTIONS > INPUT > DEVICES 下给它分配一个通道。在它的 JST 页签上更改一个轴角色。绑定一个按钮。（详情见下文。）

然后：你的绑定会显示在设备的 JST 页签上。

你以前在 G-Rebels 中绑定过按钮吗？那么开始页面会提供 导入，然后填补空缺。你的绑定会保留，只有空闲的按钮会获得新功能。参见 快速入门：让我的摇杆能用。

#JoyPro 为 G-Rebels 做了什么

  • 导入：每个通道的轴角色（哪个摇杆轴是俯仰、滚转、偏航、推力、侧向平移、上 / 下）连同反转设置，以及 JoyPro 已知的按钮绑定，都会进入你配置文件中对应的真实设备。
  • 关联：G-Rebels 中的“Pitch”可以和你其他游戏中的俯仰是同一个关联。
  • 导出：JoyPro 会在你设备的通道上设置轴角色和按钮绑定。它从不添加通道或设备：这部分需要你在游戏中做一次。

#导入你的 G-Rebels 绑定

  1. 打开 开始 页面。如果 G-Rebels 卡片要求生成命令列表，按 生成列表：JoyPro 会写入自己的游戏轴角色和按钮表。
  2. 在 G-Rebels 卡片上按 导入，保持选择 添加到我的配置文件（推荐），然后按 立即导入。
  3. 查看我的关联 会打开导入的内容。

#建立并检查关联

在 关联 页面上把你的关联绑定到 G-Rebels 的操作（参见 关联流程），然后在导出页面运行 检查。G-Rebels 每个轴只允许一个角色，每个操作和通道只允许一个按钮；检查会显示两个关联想要同一个输入的地方。

#导出到 G-Rebels

  1. 关闭 G-Rebels。 游戏运行时 JoyPro 拒绝写入。
  2. 打开 导出 并勾选 G-Rebels 卡片。
  3. 如果你是在 JoyPro 中设置摇杆的，请保持选择 在我的设备上替换 并勾选 同时清除我的其他设备。在卡片上按 立即导出。
在游戏中: 你在 G-Rebels 中看到的内容

打开 OPTIONS > INPUT > CONTROLS 以及你设备的 JST<channel> 页签（通道 0 对应 JST0）。在 AXIS 下，每个摇杆轴（X、Y、Z、RX、RY、RZ、Slider、Dial）会显示 JoyPro 设置的角色（YAW、THRUST、ROLL、PITCH、SIDE STRAFE、UP / DOWN 或 NONE）。在 BUTTONS 下，已绑定的操作会显示你的按钮，例如“Enhanced Raw Input Controller 0 Button 5”。

#在 G-Rebels 中需要你自己做的事

在第一次导出之前，对每个设备各做一次：

  1. 开启设备：OPTIONS > INPUT > DEVICES 会列出每个摇杆，并显示 DEACTIVATED。给你想用的每个设备分配一个通道（0 - CHANNEL ... 5 - CHANNEL）。没有通道的设备会在导出时被跳过，并提示“请在 OPTIONS > INPUT > DEVICES 中开启它”。
  2. 在设备的 JST 页签上 更改一个轴角色。只有这样，游戏才会保存该通道的轴行；JoyPro 会就地修改它们，从不添加。只打开页签不会保存任何内容。
  3. 在游戏中 绑定一个按钮，只需一次。按钮文件会在第一次绑定时出现。

#常见问题

  • 某个轴角色没有写入：该通道还没有保存的轴行。在游戏中该通道的 JST 页签上更改一个轴角色，关闭游戏，然后重新导出。
  • 某个按钮绑定不见了：到目前为止，游戏的按钮中只有 Primary Fire 得到了确认；其他操作会在知道其名称后陆续支持。
  • 多个原始输入设备共用按键：用 虚拟摇杆 把整套 HOTAS 放到一个设备上；这样只需要一个通道。
高级

#JoyPro 读取和写入的文件

文件 这是什么
%LOCALAPPDATA%\G_Rebels\Saved\SaveGames\SaveOptions.sav 设备及其通道（按 HID 路径），以及每个通道每个轴一行轴数据：角色、反转、死区、倍率
%LOCALAPPDATA%\G_Rebels\Saved\SaveGames\EnhancedInputUserSettings.sav 按钮绑定，每个操作和通道一个映射
...\SaveOptions.sav.joypro-meta.json JoyPro 保存的已导出绑定的数据（名称、分组），下次导入时会读回

两个存档文件在首次写入前都会备份（旁边的 .jpbak 和 JoyPro 的备份存储）。

#G-Rebels 中的导出模式

每个轴一个角色，每个操作和通道一个按键。轴角色和按钮遵循相同的规则。

模式 会发生什么
仅添加 角色只会放到还没有角色的轴上；已有其他角色的轴会被跳过，并标记为“未写入游戏”。
更新，保留游戏的绑定 配置文件中的角色放到它的轴上（那里原有的角色被移除）；该角色在其他轴上的设置保留。按钮：该按键上另一个操作的映射被移除。
更新，以我的配置文件为准 同上，此外，该角色在已连接通道上的其他轴会被设为 NONE。
在我的设备上替换 已写入通道的其他每个角色都会变成 NONE。
+ 同时清除我的其他设备 JoyPro 不写入的、已启用且已连接的通道也是如此。

#绝不会改动的内容

  • 键盘、手柄、鼠标和游戏的其他选项。
  • 设备未连接的通道会保留它的角色。
  • 导入时忽略的设备，以及 JoyPro 转发到的 vJoy 设备。
  • 游戏的设备列表：JoyPro 从不开启或关闭设备，也从不添加通道。

#轴和其他设置

  • 全局：每个通道一套绑定，没有飞机配置。
  • 反转 会随角色一起写入。苦力帽（POV 行）、死区和灵敏度目前还不会写入。
  • 没有全局游戏设置，没有力反馈。
  • 监视器：你在游戏中更改的角色或绑定会在游戏关闭后被发现（监视器）。
  • HUD：G-Rebels 运行时，HUD 会显示每个按下按钮对应的操作名称。
  • 游戏每个设备最多读取 96 个按钮和 24 个轴，不支持苦力帽。
技术细节

#G-Rebels 集成的内部原理

代码：engine\Games\GRebelsIntegration.cs、engine\Games\GRebelsSaveOptions.cs、engine\Games\GvasKeyMappings.cs。

  • SaveOptions.sav：Unreal GVAS（UE 5.8，带类型树的属性标签）。Joysticks 包含 S_Controller_Save { DeviceID (HID path), Enabled, MultiID (channel) }；AxisOptions 包含 S_Input_Axis_Save { Key, Offset, Multiplier, Role, Inverted, DeadZone }，键名如 RawInput_Controller0_AxisY，角色为枚举值（0 Yaw、1 Thrust、2 Roll、3 Pitch、4 Side strafe、5 Up/down、6 None）。没有校验和：JoyPro 就地编辑固定大小的值。
  • EnhancedInputUserSettings.sav：Unreal Enhanced Input 的玩家映射按键。映射名称为 <ACTION>JST<channel>（PRIMARYFIREJST0），按键为 RawInput_Controller<channel>_Button<n>，n 是 DirectInput 按钮编号。映射列表会被重写；其他每个字节保持不变。
  • 设备：按 HID 路径匹配到游戏分配给它们的通道。
  • 命令列表：JoyPro 自己的表（DB\GRebels\actions.tsv，轴角色和按钮；不读取游戏文件）。engine grebels refresh-db 把它写入游戏数据文件夹；已有的行保留其条目。
  • 命令：engine grebels paths、engine grebels catalog、engine grebels scan、engine grebels import、engine grebels export --mode clean|add|merge|merge-overwrite --nuke-untouched-devices --dry-run。

#已知限制

  • 苦力帽、死区和灵敏度不会被写入。
  • 按钮中只有 Primary Fire 在游戏中得到了确认。
  • 从不添加条目：通道、轴数据行和按钮文件必须由游戏创建。
  • 测试：engine\tests\smoke\grebels.ps1；游戏内测试 tools\e2e\games\GRebelsSettings.ps1（启动两次：第一次给 vJoy 分配通道并保存轴数据行，第二次检查 JST0 上的随机角色和 Primary Fire；之后会恢复存档文件夹）。
