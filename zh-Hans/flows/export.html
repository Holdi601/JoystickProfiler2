主要流程

导出到你的游戏

显示：

导出是让你的摇杆在游戏中工作的那一步。JoyPro 会把你的关联和绑定写入每个游戏的控制设置文件，也就是游戏自己的控制菜单所保存的那些文件。飞行时后台不会运行任何东西：导出之后，游戏像往常一样读取它自己的文件。

新手入门

#三步完成导出

打开底部栏中的 导出。该页面从上到下是三张带编号的卡片：

  1. 检查你的配置文件。 按 立即检查。JoyPro 会查找在游戏中会出问题的地方，例如同一架飞机中一个按钮做两件事。修复它找到的问题（每个问题点一下）或者不管它；检查从不阻止导出。请参见检查。
  2. JoyPro 如何写入游戏。 从四种选择中选一种。如果不确定，就保持第一种：在我的设备上替换 并勾选 同时清除我的其他设备。这样你的摇杆就会完全按照配置文件工作，不会有别的功能。
  3. 导出到游戏。 配置文件中有绑定的每个游戏都会有一张带图片的卡片。勾选游戏并按 导出勾选的游戏，或在某张卡片上按 立即导出。

请先关闭游戏。 游戏在退出时会写入控制文件，所以 JoyPro 会拒绝导出到正在运行的游戏，并告诉你原因。

#哪种选择适合我？

选项 适合在以下情况选择 游戏自己的绑定会怎样
在我的设备上替换 你在 JoyPro 中设置你的摇杆 在配置文件中的设备上，只保留你的绑定（针对你导出的飞机）。
更新，保留游戏的绑定 你也在游戏中绑定，并且想保留它们 你的绑定会写入；只有当游戏绑定位于你用作其他功能的按钮上时，才会被移除。
更新，以我的配置文件为准 与上一种类似，但你在 JoyPro 中把操作移到了其他按钮上 与上面相同，此外你绑定的每个操作都会在游戏中失去它的其他按钮，所以移动就是真正的移动。
仅添加 你第一次试用 JoyPro 不会删除任何内容。如果游戏已经把某个按钮用于其他功能，你的绑定会被略过，检查会告诉你。

同时清除我的其他设备（选项下方的一个复选框）：在配置文件中没有绑定的已连接设备，会在导出的飞机中失去它们的绑定。如果你想从头开始，请保持勾选；如果你有第二个设备只在游戏中使用，请取消勾选。

#设计上就很安全

  • JoyPro 在更改游戏文件之前会把它复制到备份中。每张卡片都有 撤销上次导出：它会把文件逐字节恢复到原来的样子。
  • 第一次导出到一个已经有自己绑定的游戏时，会询问一次：“先导入？”。如果你想保留在游戏中做的设置，请选择 先导入；要替换它们，请选择 仍然导出。
  • 没有插上的设备会保留它们的绑定。你的鼠标和手柄绑定永远不会被改动。

#你在游戏中会注意到什么

启动游戏并打开它的控制菜单：你的绑定就在那里，位于每个设备的列中，使用游戏自己的名称。在 DCS 中按飞机显示；在 Star Citizen 中按飞船操作显示；在 IL-2 中位于 Key mapping。下面的在游戏中一节列出了每类游戏。

#让绑定进入游戏的其他方式

方式 作用
写入我的游戏（快速设置） 快速设置的导出。它会写入它设置过的游戏，并同样先做备份。请参见快速入门。
模拟手柄（虚拟 Xbox 手柄） ACE COMBAT 8 和 Hell Let Loose: Vietnam 不会写入任何内容。它们的导出会说明这一点。开始 开启时，你的摇杆会驱动一个模拟手柄。请参见仅支持 Xbox 手柄的游戏。
DCS 膝板 不是绑定的导出：而是每架飞机一页，在座舱中列出你的按钮的作用。请参见膝板。
高级

#各游戏的选项

在 选项和路径（供专家使用） 下：

  • DCS：DCS 卡片上的 飞机... 列表（只写入勾选的飞机）；DCS：保留键盘默认设置（开启）；DCS：我的设备在其他所有飞机中也失去 DCS 默认绑定（关闭）。
  • Star Citizen：SC：保留键盘默认设置、SC：优先使用本地顺序。
  • 其他游戏：一个 试运行 复选框，显示将会更改的内容而不实际写入。
  • 路径：每个游戏可以使用不同的 Saved Games 或配置文件夹；此配置文件专用的路径和忽略的设备 让打开的配置文件使用自己的设置，而不是这台电脑的设置。

#标记：“未写入游戏”

“仅添加”（以及游戏没有空位容纳另一个输入的任何模式，例如每个操作只有两个输入的 Elite Dangerous）会略过一些绑定。配置文件会记住每一个被略过的绑定，以及占用该输入的游戏操作和日期；检查会为每个标记显示一张卡片，提供 用“更新”导出以替换、移到另一个按钮 和 保持原样。每次导出都会替换其游戏和飞机的标记，所以当之后的导出写入了该绑定时，标记就会消失。

#会记住的设置

模式、同时清除 勾选项、各游戏的选项和路径都保存在 JoyPro 的设置中；你自己勾选的游戏和 DCS 飞机按配置文件保存。“替换”和“同时清除”在每次导出前都会询问（可在“设置 > 确认”中关闭该询问）。

#导出之后

  • 卡片上的 撤销上次导出 会恢复该游戏最新的备份。完整列表位于导出页面底部的 游戏配置备份 中。
  • 导出会为 游戏监视器 记录游戏的文件：JoyPro 自己的导出之后不会询问“是否接受更改？”；你之后在游戏中做的更改则会询问（监视器）。
  • JoyPro 会在游戏文件旁边保存自己的数据，因此之后导入时能恢复关联名称、分组、修饰键和曲线（重新导入）。

#在游戏中

导出后玩家看到的内容取决于游戏的类型。下面的每个游戏都遵循相同的规则：JoyPro 只写入其命令列表中的操作，游戏运行时拒绝写入，先备份文件，并且从不猜测它无法匹配的设备或操作（会跳过并给出警告）。

在游戏中: 飞行模拟器：DCS、IL-2（Great Battles、Korea、1946、Cliffs of Dover）、Falcon BMS、X-Plane、MSFS、FSX、Prepar3D

JoyPro 会接管它写入的设备。使用 替换 时，这些设备的其他所有绑定都会在导出的飞机中消失；使用 同时清除 时，其他已连接的设备也会被清除（DCS：包括它们的 DCS 默认绑定）。

  • DCS World：在 Options > Controls 中选择飞机：你的绑定位于设备的列中，被移除的默认绑定显示为空单元格，你的修饰键位于修饰键列表中。只有勾选的飞机会改变。JoyPro 只写入与 DCS 默认值不同的部分，与 DCS 自己的做法相同。
  • IL-2 Great Battles：Settings > Key mapping 会显示你的绑定和轴响应。鼠标相关的行和 JoyPro 不认识的行保持不变。
  • IL-2 Korea：按键映射配置“General”。
  • Falcon BMS：启动器会在下次 Launch 时生成按键文件和轴映射，所以请通过启动器启动 BMS。
  • MSFS 2024 / 2020：在 Controls 中，设备会显示 JoyPro 的预设。
  • X-Plane 11 / 12：Settings > Joystick 会显示分配情况。
在游戏中: 带有步兵、载具或菜单的游戏：Star Citizen、War Thunder、Arma 3 / 2、Arma Reforger、WARDOGS、Nuclear Option、Hell Let Loose、Battlefield

JoyPro 只改动飞行操作（飞机、直升机、飞船）。你的步行、载具和菜单绑定会逐字节保持不变。替换 和 同时清除 只会释放 JoyPro 认识的飞行操作。

  • Star Citizen：Options > Keybindings 会显示你摇杆（js1、js2 ……）上的飞船操作。使用 替换 或 同时清除 时，如果 js1 被写入或未被使用，游戏自己在 js1 上的摇杆默认绑定会被关闭。
  • War Thunder：Controls 会显示飞机绑定；坦克和舰船的控制保持不变。
  • Arma 3 / Arma 2：配置档案的按键设置；只有飞机和直升机操作会改变。
在游戏中: 太空游戏：Elite Dangerous、X4: Foundations
  • Elite Dangerous 为每个操作保留两个输入（Primary 和 Secondary）。没有空位的绑定会被标记为“未写入”，并提供“移到另一个按钮”或“保持原样”。步行和 SRV 绑定保持不变。
  • X4：游戏的输入设置；只有已收录的飞船操作会改变。
在游戏中: 只读取一个设备或只支持 Xbox 控制器的游戏
  • 设为 vJoy 的游戏（只读取少数几个设备的游戏）：导出会把绑定写到 vJoy 设备上。你玩游戏时，JoyPro 会把你的摇杆复制到它上面，HidHide 只对该游戏隐藏你的真实设备。游戏看到的是一个包含所有内容的设备。请参见虚拟摇杆。
  • 仅支持 Xbox 手柄的游戏（ACE COMBAT 8、Hell Let Loose: Vietnam）：不会写入任何内容，导出会说明这一点。开始 开启时，你的摇杆会驱动一个模拟手柄（虚拟 Xbox 手柄）。不需要 HidHide。请参见用 HOTAS 玩仅支持 Xbox 手柄的游戏。

#内部工作原理

一次导出，从点击到写入文件：

# 谁 会发生什么
1 你 在导出页面上按 导出勾选的游戏。
2 JoyPro 向引擎询问该游戏的情况（profile game-state --game <id>）：是否已导入、已导出、有绑定。
3 JoyPro 需要时询问你：首次导出（“先导入？”），或会删除绑定的模式（设置 > 确认）。
4 引擎 运行 <game> export --mode <m> --nuke-untouched-devices <b> ...：游戏运行时会拒绝，先备份每个文件（GameBackups 和 .jpbak），并只写入目录中收录的操作。
5 引擎 保存同步记录（指纹和基线）以及导出标记，然后回答：已写入、已跳过、SkippedTakenInputs。
6 JoyPro 游戏的卡片显示“已导出 14:02”，并且 撤销上次导出 可以使用。
  1. GUI。 ExportSelectedGamesAsync / ExportGameNowAsync（MainWindowViewModel.ExportGames.cs）先询问 AskAboutFirstExportAsync（engine profile game-state）和 ConfirmRiskyExportAsync，然后由 ExportGameAsync 选择该卡片的导出器：dcs、il2、starcitizen 或某个注册表中的游戏。命令根据页面上的设置构建，例如 RunDcsExportAsync：engine dcs export --mode clean --keep-keyboard-defaults true --nuke-untouched-devices true --clean-all-aircraft false --ignore-device <d> --planes F-16C_50|FA-18C_hornet。每次引擎调用都经过同一个地方 RunEngineAsync，带有 --profile 和 --status true（忙碌区域的进度和取消），并且串行执行，因此两个命令绝不会同时写入。
  2. 引擎。 engine\Program.cs 把 dcs / il2 / starcitizen 交给各自的导出器，其他所有游戏交给 Games.GameRegistry（每个游戏一个 GameIntegration）。DCS：EngineDcsExport.Modes.cs 针对每个设备文件计算 DCS 当前生效的绑定（干净的配置减去 removed，加上 added 和 changed），决定哪些应当生效，并且只写入与默认值真正不同的部分。
  3. 安全。 GameExportSafety.BackupBeforeOverwrite 会把每个文件复制为 <file>.jpbak，并复制到带版本的备份库中（%LOCALAPPDATA%\JoyPro2\GameBackups\<date-time>_<game>\，带 manifest.json；每个游戏保留最新的 30 组）。注册表中的游戏（Nuclear Option）会对可能更改的值做快照。导出新建的文件会被记录为“原本不存在”，因此恢复时会把它再次删除。
  4. 之后。 同步记录（<data>\Sync\<game>.json：每个文件的大小、时间和 SHA-256，以及所有绑定的哈希）让监视器对 JoyPro 自己的更改保持安静。ExportSkippedBinds.cs 填写 SkippedTakenInputs；导出命令把它们转换为配置文件中的标记。配置文件的历史记录会在每次导出前保存一个检查点。

#命令行中的各种模式

GUI 选项 引擎选项
在我的设备上替换 + 同时清除我的其他设备（默认） --mode clean --nuke-untouched-devices true
在我的设备上替换 --mode clean --nuke-untouched-devices false
更新，以我的配置文件为准（+ 同时清除） --mode merge-overwrite --nuke-untouched-devices true|false
更新，保留游戏的绑定（+ 同时清除） --mode merge --nuke-untouched-devices true|false
仅添加 --mode add（不使用 nuke）

各游戏：engine dcs export、engine il2 export、engine starcitizen export，以及每个注册表中的游戏使用 engine <game> export（例如 engine warthunder export、engine msfs2024 export、engine xplane12 export；每个都接受 --mode、--dry-run、--include-keyboard 和 --nuke-untouched-devices）。撤销：engine backups restore。测试：engine\tests\smoke\dcsexportmodes.ps1（每种模式、往返、逐字节撤销）和 engine\tests\smoke\roundtrip.ps1（导入、clean + nuke、再次导入后游戏保持原样）。
