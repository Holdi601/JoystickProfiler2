#engine hllv paths

written
engine hllv paths
For beginners

Shows where JoyPro finds Hell Let Loose: Vietnam's key binds on this PC: %LOCALAPPDATA%\HLLVietnam\Saved\SaveGames\EnhancedInputUserSettings.sav. Detect in the import wizard's Expert import section runs it.

engine hllv paths --text
Advanced
  • No options. Listed: your own config location of engine games config set first, then the file when it exists.
  • The gamepad layout you picked (SelectedGamepadLayout in ...\Saved\Config\Windows\GameUserSettings.ini) is read for the virtual pad; that file is not listed.
  • Read-only; also works when the game is not installed or switched off.
Technical internals
  • Output: JSON (Game, DisplayName, ConfigPaths, Warnings), or with --text Hell Let Loose: Vietnam Config Paths, Paths: <n> and the files. Exit code 0; an unknown option fails with Unknown HLLVietnam paths argument(s): ....
  • Related: engine hllv scan, engine games paths; game page hll-vietnam.

What it does Lists where JoyPro looks for this game's controls on this machine: files, folders or registry keys (your config location from games config set first). A file the game has not written yet can be listed (e.g. Arma Reforger's JoyPro.conf, Project Wingman's Input.ini).

Example

engine hllv paths --text

#engine hllv catalog

written
engine hllv catalog
For beginners

Lists the Hell Let Loose: Vietnam actions JoyPro knows: the keyboard pilot keys of the helicopter and the helicopter actions of the gamepad, each with the pad control it has in the layouts A, B and C.

engine hllv catalog --text
Advanced
  • No options; read-only, also when the game is not installed.
  • Two categories: Helicopter keyboard (the pilot keys, written with --include-keyboard) and Helicopter gamepad (ids Pad_...; your HOTAS reaches them through the virtual Xbox pad, engine vjoy mode HLLVietnam xbox).
  • A fresh install has no list yet; the first scan, import, export or engine hllv refresh-db builds it. Until then the command lists no action and warns Hell Let Loose: Vietnam action catalog not found: <path>.
Technical internals
  • Output: JSON (Game, Source, Actions with Id, Title, IsAxis, Category, Warnings), or with --text one line per action <id> | axis|button | <category> | <title>. Exit code 0.
  • File: %LOCALAPPDATA%\JoyPro2\GameData\DB\HLLVietnam\actions.tsv; the fifth column of a pad action holds its pad control per layout (A:Gamepad_LeftY|B:Gamepad_RightY|C:Gamepad_LeftY), which the virtual pad uses.
  • Related: engine hllv refresh-db, engine vjoy map; game page hll-vietnam.

What it does Lists every action of JoyPro's command list of this game with its kind and category: <data>\GameData\DB\<Game>\actions.tsv, else the program folder's DB\<Game>.

Example

engine hllv catalog --text

#engine hllv scan

written
engine hllv scan [<config-path>] [--path <config-path>] [--ignore-device <name>] [--ignore-devices <csv>]
For beginners

Shows the keyboard pilot keys Hell Let Loose: Vietnam has, without changing your profile or the game. The game stores no joystick binds, so keys are all a scan can show. Look first in the import wizard runs it.

engine hllv scan --text
Advanced
  • Reads the keys of the pilot actions you changed in EnhancedInputUserSettings.sav; a path (positional or --path) names another file. The keys are listed without --include-keyboard (the import takes them only with it).
  • A key JoyPro has no name for is skipped with a warning.
  • --ignore-device Keyboard leaves the keys out.
  • Safety: reads only, also while the game runs; a fresh install first builds and saves JoyPro's command list. Refused when the game is not installed or switched off in Settings > Games.
Technical internals
  • Output: JSON (Game, Action scan, ConfigPath, BindingsRead, Bindings on device Keyboard, Steps, Warnings, Errors), or a text report with --text.
  • Exit code 0; 1 on an error (No Hell Let Loose: Vietnam config file found. Pass the path explicitly., an unreadable save file). Unknown options fail with Unknown HLLVietnam scan argument(s): ....
  • Related: engine hllv import, engine hllv catalog, engine vjoy mode; game page hll-vietnam.

What it does Reads the game's controls (its control file or folder, or registry values for Nuclear Option and Tiny Combat Arena; Ace Combat 8 stores none) and shows the joystick binds, without changing the profile. Without a command list yet (fresh install) it first builds the list from the game and saves it.

OptionValuesMeaning
--path<config-path>Optional explicit path override. Use when you prefer option form over positional path.
--ignore-device<name>Leave the binds of this device out (one per flag; a name without {GUID} means every device of that name). Example: --ignore-device 'vJoy Device'.
--ignore-devices<csv>Leave the binds of these devices out (separated by commas, | or ;). Example: --ignore-devices 'vJoy Device,Old Pedals'.

In the game Reads Hell Let Loose: Vietnam's files only; nothing changes in the game. A scan only shows what an import would bring and does not change the profile. Hell Let Loose: Vietnam details · what each mode changes

Example

engine hllv scan --text
How the options interact
  • --ignore-device / --ignore-devices leave the binds of those devices out of the scan or import (the result names how many).

#engine hllv import

written
engine hllv import [<config-path>] [--path <config-path>] [--replace] [--include-keyboard] [--ignore-device <name>] [--ignore-devices <csv>]

--ignore-device(s): the binds of these devices are left out

For beginners

Reads the keyboard pilot keys of Hell Let Loose: Vietnam into your JoyPro profile, when you ask for the keyboard. The game stores no joystick binds, so without --include-keyboard nothing comes in. Nothing in the game changes. The GUI runs it with Import on the Hell Let Loose: Vietnam card of the Start page.

engine hllv import --include-keyboard --profile "C:\Users\Pilot\Documents\JoyPro\My Sticks.pr0file" --text
Advanced

It reads the keys you changed in %LOCALAPPDATA%\HLLVietnam\Saved\SaveGames\EnhancedInputUserSettings.sav; the pad layout (SelectedGamepadLayout in GameUserSettings.ini) is read for the virtual pad, not imported.

  • Default: adds to the open profile (--merge means the same). --replace replaces every relation of the profile by what comes in, which is nothing without --include-keyboard.
  • The helicopter on the pad needs no import: bind your HOTAS to the pad actions and use engine vjoy mode HLLVietnam xbox.
  • Safety: reads only, not refused while the game runs; the profile is kept as "Before import from Hell Let Loose: Vietnam" first.
  • --ignore-device <name> / --ignore-devices <a;b> leave the binds of those devices out (a name without {GUID} means every device of that name); a step line says how many binds were left out.
Technical internals
  • Output: JSON of the import result or a text report with --text (a step counts the keyboard binds left out); exit code 1 on an error (No Hell Let Loose: Vietnam config file found. Pass the path explicitly.).
  • Without a path it reads the file engine hllv paths lists first; the command list is JoyPro's table of the three pad layouts and the pilot keys (engine hllv refresh-db, engine hllv oodle).
  • With --profile the profile is saved afterwards; a game JoyPro never exported to is watched from now on.
  • Related: engine hllv scan, engine hllv export, engine vjoy mode; game page hll-vietnam.

What it does Imports the game's joystick binds into the loaded profile (merged by default; --replace starts from an empty relation list). Without a command list yet it first builds the list from the game.

OptionValuesMeaning
--path<config-path>Optional explicit path override. Use when you prefer option form over positional path.
--replaceswitch (no value)For game import: start from an empty relation list instead of merging into the loaded profile.
--include-keyboardswitch (no value)
--ignore-device<name>Leave the binds of this device out (one per flag; a name without {GUID} means every device of that name). Example: --ignore-device 'vJoy Device'.
--ignore-devices<csv>Leave the binds of these devices out (separated by commas, | or ;). Example: --ignore-devices 'vJoy Device,Old Pedals'.

In the game Reads Hell Let Loose: Vietnam's files only; nothing changes in the game. The binds come into the profile as relations; JoyPro's own data next to the game file brings back names, groups, modifiers and curves. Hell Let Loose: Vietnam details · what each mode changes

Example

engine --profile 'C:\JoyPro\profiles\pilot_main.pr0file' hllv import --text
How the options interact
  • --ignore-device / --ignore-devices leave the binds of those devices out of the scan or import (the result names how many).

#engine hllv export

written
engine hllv export [<config-path>] [--path <config-path>] [--mode clean|add|merge|merge-overwrite] [--dry-run] [--include-keyboard] [--nuke-untouched-devices] [--ignore-device <name>] [--ignore-devices <csv>]

Writes only the keyboard pilot keys, with --include-keyboard; the gamepad binds reach the game through the virtual Xbox pad (engine vjoy mode HLLVietnam xbox), nothing is written for them

For beginners

Writes the keyboard pilot keys of your profile into Hell Let Loose: Vietnam, only with --include-keyboard. Pad binds are never written: the virtual Xbox pad carries them. Close the game first. The GUI's Export now on the Hell Let Loose: Vietnam tile runs it.

engine hllv export --mode merge --include-keyboard --profile "C:\Users\Pilot\Documents\JoyPro\My Sticks.pr0file" --text
Advanced

It writes %LOCALAPPDATA%\HLLVietnam\Saved\SaveGames\EnhancedInputUserSettings.sav, one key per pilot action. A mouse button on a pilot action always stays; infantry and common keys never change.

--mode Pilot keys
add the game's key stays; a key another pilot action has gets a mark "Not written to the game"
merge, merge-overwrite the profile's key is set; another pilot action on that key loses it (the game then uses its default there)
clean (GUI default) the other pilot keys you changed in the game go back to the game's defaults
  • --nuke-untouched-devices: nothing to clear, the game stores no joystick binds.
  • Without --include-keyboard no key is written; gamepad action binds are counted in a step line ("the game's gamepad layouts are fixed, so nothing is written for them").
  • The game reads no joystick: outside the virtual mode, binds on a joystick get the warning "... reads no joystick ..." with the command that switches it to the virtual pad.
  • Never touched: the pad layouts, infantry and vehicle keys, mouse buttons, every other byte of the save file, GameUserSettings.ini.
  • Safety: refused while HLLVietnam-Win64-Shipping or HLLVietnam runs; backed up first (undo: engine backups list); the profile is kept as "Before export to Hell Let Loose: Vietnam". --dry-run writes nothing.
Technical internals
  • Output: JSON of the export result or a text report with --text; exit code 1 on an error (the game runs, an invalid --mode, the save file cannot be read).
  • Without a path it writes the file engine hllv paths lists first.
  • After a real run: EnhancedInputUserSettings.sav.joypro-meta.json, the watcher's fingerprint, the export marks (engine export-marks list).
  • The help note says "writes only the keyboard pilot keys, with --include-keyboard"; the gamepad binds reach the game through the virtual Xbox pad.
  • Related: engine hllv import, engine vjoy mode; game page hll-vietnam.

What it does Writes the profile's binds for this game. Only the flight actions JoyPro manages are changed, the game must be closed, and the game's files are backed up first (engine backups). Without a command list yet it first builds the list from the game.

OptionValuesMeaning
--path<config-path>Optional explicit path override. Use when you prefer option form over positional path.
--modeclean add merge merge-overwriteExport mode for DCS/IL2 export commands: clean, add, merge, merge-overwrite.
--dry-runswitch (no value)Report what the export would write; the game's files are not changed.
--include-keyboardswitch (no value)
--nuke-untouched-devicesswitch (no value)DCS export only: delete untouched device .diff.lua/.jp files under Config\\Input (true/false).
--ignore-device<name>Exclude one device per flag. Example: --ignore-device Keyboard.
--ignore-devices<csv>Exclude devices, separated by commas, | or ;. Example: --ignore-devices Keyboard,Mouse.
Every value as a command line
engine hllv export --mode clean
engine hllv export --mode add
engine hllv export --mode merge
engine hllv export --mode merge-overwrite

In the game Writes into Hell Let Loose: Vietnam's control files while the game is closed (refused while it runs), after a backup. Arcade flight games and shooters that read one joystick, only Xbox pads, or a fixed layout (docs: one-device-games.md). Bind file: %LOCALAPPDATA%\HLLVietnam\Saved\SaveGames\EnhancedInputUserSettings.sav (GVAS; keyboard keys only). Hell Let Loose: Vietnam details · what each mode changes

Example

engine --profile 'C:\JoyPro\profiles\pilot_main.pr0file' hllv export --dry-run --text engine --profile 'C:\JoyPro\profiles\pilot_main.pr0file' hllv export --mode merge-overwrite --text

#engine hllv refresh-db

written
engine hllv refresh-db [<source-path>] [--path <source-path>] [--dry-run] [--oodle-dll <path>]

Rebuilds the catalog from the installed game or <source-path>: actions the game no longer has are dropped; writes it only when it changes

For beginners

Builds JoyPro's Hell Let Loose: Vietnam command list: from the game's input files when JoyPro can read them, else from JoyPro's own table of the pilot keys and the three default gamepad layouts. Update on the game's card of the Start page runs it and asks you first whether JoyPro may use another game's Oodle library (engine hllv oodle).

engine hllv refresh-db --text
Advanced
  • Reads the input container HLLVietnam\Content\Paks\HLLVietnam-Windows.utoc of the detected installation; a path (positional or --path) may be the game folder or the .utoc file.
  • The container can only be read with an Oodle library: the game's own oo2core_*_win64.dll when its folder has one, else the one --oodle-dll <path> names (an existing oo2core_<n>_win64.dll, used where it is, never copied, only for this run). Without either, or when reading fails, JoyPro's built-in table is used and a step line says so.
  • --oodle-dll with a wrong file gives the warning --oodle-dll must name an existing oo2core_<n>_win64.dll; JoyPro's own list is used.
  • The list is rebuilt each time. --dry-run writes nothing; otherwise the list is written only when it changed.
  • Refused when the game is not installed or switched off in Settings > Games; the game may run.
Technical internals
  • Output: JSON of the refresh (DryRun, FilesWritten, Steps such as Catalog read from <utoc> (...; Oodle: <dll>). or Catalog: JoyPro's built-in table of the default helicopter gamepad layouts A, B, C ..., Actions: <old> -> <new>, Warnings), or a text report with --text.
  • Exit code 0 (the built-in table always gives a list); 1 only for a refusal or an unknown option.
  • Writes %LOCALAPPDATA%\JoyPro2\GameData\DB\HLLVietnam\actions.tsv. After a pad layout change in the game, run engine vjoy map.
  • Related: engine hllv oodle, engine hllv catalog, engine vjoy mode; game page hll-vietnam.

What it does Rebuilds the catalog from the installed game or <source-path>: actions the game no longer has are dropped; writes it only when it changes.

OptionValuesMeaning
--path<source-path>Same as <source-path>: the game's installation or a file of the game to read the actions from.
--dry-runswitch (no value)Report what the command would do; nothing is written or changed.
--oodle-dll<path>

Example

engine hllv refresh-db --text

#engine hllv oodle

written
engine hllv oodle [--path <game folder>]

The game's own Oodle library, or one another installed game ships; refresh-db --oodle-dll <path> uses that one only with the user's consent, from where it is, never copied; without it JoyPro's own list of the pad keys

For beginners

Reports how JoyPro can read Hell Let Loose: Vietnam's packed files: whether the game has its own Oodle library, or which other installed game has one. Before a command list refresh of the game, the GUI runs it and asks you once whether JoyPro may use the other game's library.

engine hllv oodle --text
Advanced
  • --path <game folder> (or a positional path) looks there instead of the detected installation.
  • Reports the game's container file, the game's own library, and when it has none, another installed game's library with that game's name.
  • With your yes the GUI passes that library to engine hllv refresh-db as --oodle-dll <path>; it is used where it is, never copied. Without it JoyPro uses its own list of the gamepad keys. Ask again in Settings > Games forgets the answer.
  • Read-only; not refused when the game is not detected.
Technical internals
  • Output: JSON (Container, OwnDll, ForeignDll, ForeignGame, Maker, Warnings), or with --text the lines Container:, Own library:, Another game's library:. Exit code 0.
  • Related: engine hllv refresh-db.

What it does The game's own Oodle library, or one another installed game ships; refresh-db --oodle-dll <path> uses that one only with the user's consent, from where it is, never copied; without it JoyPro's own list of the pad keys.

OptionValuesMeaning
--path<game folder>Optional explicit path override. Use when you prefer option form over positional path.

Used by the GUI Start: RefreshDbUpdateCommand · Start: Build All Missing Lists · Start: Update

Example

engine hllv oodle --text
