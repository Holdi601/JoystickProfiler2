#engine dcs scan

written
engine dcs scan [<saved-games-path>] [--path <saved-games-path>] [--plane <name>] [--planes <csv>] [--device <name>] [--devices <csv>] [--ignore-device <name>] [--ignore-devices <csv>] [--include-keyboard true|false] [--ignore-easy-planes true|false] [--include-defaults] [--import-inverted] [--import-slider] [--import-curvature] [--import-deadzone] [--import-saturation-x] [--import-saturation-y] [--only-connected true|false] [--merge-same-name true|false] [--confirm true|false]
For beginners

Shows what an import from DCS would bring, without changing your profile or DCS. Use it to look before you import, for example to see which aircraft and devices JoyPro finds. The Start page's Look first / Scan runs it.

engine dcs scan "C:\Users\Pilot\Saved Games\DCS" --only-connected true --text
Advanced

Takes the same filters and settings as engine dcs import (--plane(s), --device(s), --ignore-device(s), --include-defaults, --include-keyboard, --ignore-easy-planes, the --import-* axis settings, --only-connected, --merge-same-name, --confirm) and reports what they would match. Nothing is written: no profile change, no file in DCS, no backup.

Technical internals
  • Output: the same result as the import (JSON, or a text report with --text); exit code 0, 1 on an error (dcs scan failed: ...).
  • --save-profile and --save-last are import options and refused here, as are the export options (--mode ...).
  • Related: engine dcs import, engine games paths.

#engine dcs import

written
engine dcs import [<saved-games-path>] [--path <saved-games-path>] [--merge] [--save-profile <path.pr0file>] [--save-last] [--plane <name>] [--planes <csv>] [--device <name>] [--devices <csv>] [--ignore-device <name>] [--ignore-devices <csv>] [--include-keyboard true|false] [--ignore-easy-planes true|false] [--include-defaults] [--import-inverted] [--import-slider] [--import-curvature] [--import-deadzone] [--import-saturation-x] [--import-saturation-y] [--only-connected true|false] [--merge-same-name true|false] [--confirm true|false]
For beginners

Reads the binds you already have in DCS into your JoyPro profile, one relation per function and button. Use it once at the start, or after you changed binds inside DCS; nothing in DCS changes. The GUI's Import on the Start page runs it.

engine dcs import "C:\Users\Pilot\Saved Games\DCS" --merge --include-defaults --profile "C:\Users\Pilot\Documents\JoyPro\My Sticks.pr0file"
Advanced

Reads Saved Games\DCS\Config\Input (or --path) into the profile: one relation per function and input, modifiers from modifiers.lua, tuning from the files, names and groups from JoyPro's .jp files.

  • --merge adds to the open profile instead of replacing it.
  • --include-defaults brings every default bind DCS has active for an imported device (so a clean + nuke export afterwards leaves DCS as it was).
  • --plane(s), --device(s) limit what is read; --ignore-device(s) leaves devices out (the --vjoy-tunnel device is always left out). A device name that does not match exactly is resolved to the closest one; --confirm false takes the suggestion without asking.
  • --include-keyboard (default true) reads the keyboard too; --ignore-easy-planes true skips the _easy variants.
  • --import-inverted, --import-slider, --import-curvature, --import-deadzone, --import-saturation-x, --import-saturation-y bring that axis setting into the profile.
  • --only-connected true skips devices that are not plugged in; --merge-same-name (default true) reads one device under several Windows IDs as one.
  • Safety: reads only; the profile is kept as the version "Before import from DCS" first.
Technical internals
  • Output: JSON of the import result, or a text report with --text (paths, matched aircraft and devices, files and entries parsed); exit code 0, 1 on an error (dcs import failed: ...).
  • --save-profile <file> saves the result to that profile file, --save-last to the last used one; with --profile the profile is saved after the import.
  • Export options (--mode, --nuke-untouched-devices ...) are refused here. A successful import marks DCS as imported for engine profile game-state.
  • Files read: Config\Input\<aircraft>\joystick|keyboard\*.diff.lua, the .jp files beside them, modifiers.lua.
  • Related: engine dcs scan (the same without changing the profile), engine dcs export, engine sync pending.

#engine dcs export

written
engine dcs export [<saved-games-path>] [--path <saved-games-path>] [--mode clean|add|merge|merge-overwrite] [--keep-keyboard-defaults true|false] [--clear-keyboard-defaults true|false] [--nuke-untouched-devices true|false] [--clean-all-aircraft true|false] [--plane <name>] [--planes <csv>] [--ignore-device <name>] [--ignore-devices <csv>]

Only these aircraft; writes .diff.lua + .jp backup + modifiers.lua named as DCS names the device; the .diff.lua holds only differences from DCS's defaults (added non-default binds, removed defaults, defaults with other tuning as changed); add never deletes and lists binds whose button the game uses for another function (SkippedTakenInputs); merge removes a game bind on a button the profile puts another function on; merge-overwrite also takes the profile's actions off their other buttons in that aircraft; clean replaces the written devices in the exported aircraft, with --clean-all-aircraft true (default false) also in every other aircraft; nuke: connected devices without binds in an exported plane lose all binds there, DCS defaults included (--ignore-device(s) and --vjoy-tunnel devices are never cleared); the keyboard is never cleared or nuked: --keep-keyboard-defaults false writes the profile's keyboard binds and removes only the DCS default keys they take, --clear-keyboard-defaults true also removes every other DCS keyboard default of those aircraft

For beginners

Writes your profile's binds into DCS, so the game's controls menu shows them. Use it after you changed binds in JoyPro and want to fly with them; the GUI's Export now on the DCS tile runs it. Close DCS first.

engine dcs export --mode clean --nuke-untouched-devices true --planes "F-16C_50|FA-18C_hornet" --profile "C:\Users\Pilot\Documents\JoyPro\My Sticks.pr0file" --text
Advanced

For each device and aircraft it computes the binds DCS has active (the device's defaults minus the file's removals, plus its additions and changes), decides which shall be active by the mode, and writes only real differences from DCS's defaults into <aircraft>\joystick\<device>.diff.lua, with JoyPro's .jp beside it and the aircraft's modifiers.lua.

--mode --nuke-untouched-devices In DCS, in the exported aircraft
clean true (GUI default) your devices hold exactly your binds; connected devices without binds are emptied (defaults too)
clean false your devices hold exactly your binds; other devices unchanged
merge-overwrite (engine default) true / false your binds win on their inputs, each bound action loses its other inputs; other binds stay; nuke as above
merge true / false your binds win on their inputs; the game's other binds and defaults stay (a moved action keeps its old input)
add (not used) nothing removed; a bind on an input DCS uses for another function is not written and reported (SkippedTakenInputs)
  • --clean-all-aircraft true (default false) also clears the written devices in every other installed aircraft (not UiLayer or Camera).
  • Keyboard: never cleared or nuked. --keep-keyboard-defaults false writes the profile's keyboard binds and removes only the DCS default keys they take; --clear-keyboard-defaults true removes every DCS keyboard default of those aircraft.
  • --plane / --planes limit the export to these aircraft (several names separated by |, , or ;).
  • Never touched: devices passed with --ignore-device(s) and the --vjoy-tunnel device are never cleared.
  • Safety: refused while DCS runs; every file is backed up first (undo: engine backups restore) and the profile is kept as the version "Before export to DCS".
Technical internals
  • Output: JSON of the export result, or a text report with --text (written to --out when given); exit code 0, 1 when the export reports an error (dcs export failed: ... on stderr) or DCS runs.
  • Without a path it uses the detected Saved Games folder (Auto-detected DCS Saved Games path: ... on stderr); none found fails with a hint to engine games paths.
  • Import options (--device, --include-defaults, --confirm ...) are refused here.
  • After a successful run it records the export for engine sync pending and stores the binds an "Only add" run could not write as export marks (engine export-marks list); the profile is saved quietly when those marks changed.
  • Related: engine dcs import, engine dcs verify-clean, engine profile game-state, engine backups list.

#engine dcs defaults cut

written
engine dcs defaults cut [<saved-games-path>] [<dcs-install-path>] [--path <saved-games-path>] [--install-path <dcs-install-path>] [--backup-path <path>] [--dry-run]

Older way, the GUI uses dcs device-luas remove: in every <install>\Mods\aircraft\<module>\Input\<input>\joystick folder every file except default.lua is moved into BACKUP_JOYSTICK_DEFAULTS, default.lua is copied there; refused while DCS or DCS_updater runs; --dry-run only counts

For beginners

The older way to move DCS's device-specific default files out of the DCS installation: into Saved Games\DCS\BACKUP_JOYSTICK_DEFAULTS. The GUI no longer runs it; its switch Remove DCS's device-specific default files from the install uses engine dcs device-luas, which keeps the files in JoyPro's own folder and moves them again after a DCS update. Close DCS first.

engine dcs defaults cut --path "C:\Users\Pilot\Saved Games\DCS" --install-path "D:\DCS World" --text
Advanced
  • Paths: the Saved Games folder (first positional, --path or --saved-games) and the DCS installation (second positional or --install-path); missing ones are detected (Auto-detected DCS ... path: ... on stderr). The installation may also be given as its Mods or Mods\aircraft folder.
  • --backup-path <folder> moves the files into another folder (default <Saved Games>\BACKUP_JOYSTICK_DEFAULTS).
  • In every Mods\aircraft\<aircraft>\Input\<input>\joystick folder, default.lua is copied into the backup folder (it stays in DCS) and every other file of the folder is moved there, under <aircraft>\Input\<input>\joystick. A file of the same name in the backup folder is replaced.
  • Safety: every moved file and every file it creates or replaces in the backup folder goes into a game backup set first (undo: engine backups restore, or engine dcs defaults restore for the backup folder). --dry-run counts the files it would move and copy and changes nothing (also while DCS runs). Refused while DCS or DCS_updater runs, and when DCS is not installed or switched off in Settings > Games.
Technical internals
  • Output: JSON of the result (Action cut, the paths, AircraftRoot, AircraftScanned, JoystickFoldersScanned, DefaultFilesCopied, StickSpecificFilesMoved, DryRun, Warnings, Errors), or text with --text ("DCS Stick Defaults", Dry Run: true ... on a dry run).
  • Exit code 0; 1 with dcs defaults cut failed: ... (for example Couldn't find DCS install aircraft path under: <path> or a file that could not be moved; the result is printed first), DCS is running (...). Close DCS and its updater before dcs defaults cut., when a path is missing (... requires a DCS Saved Games path. Try: engine games paths --game DCS --text) or with Unknown dcs defaults argument(s): ....
  • Only Mods\aircraft of the installation is looked at, not Saved Games\DCS\Mods.
  • Related: engine dcs defaults restore, engine dcs device-luas, engine dcs strip-defaults; game page dcs.

What it does The older way to take DCS's device default files out of the installation (the GUI uses dcs device-luas remove): in every <install>\Mods\aircraft\<module>\Input\<input>\joystick folder every file except default.lua is moved into BACKUP_JOYSTICK_DEFAULTS, and default.lua is copied there. Refused while DCS or DCS_updater runs; --dry-run only counts.
