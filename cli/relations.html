#engine relations list

written
engine relations list [filter] [--titles]

--titles: each relation with the titles of its actions

For beginners

Lists the relations of the profile, one line each with its type, bind, modifiers, games, aircraft count and groups. Add a word to show only the relations that contain it. The GUI's Relations page loads its list with it, and Refresh relations there reads it again. It changes nothing.

engine relations list Gear --profile "C:\Users\Pilot\Documents\JoyPro\My Sticks.pr0file" --text
Advanced
  • [filter]: all words after list form one text. A relation is listed when the text is part of (case ignored) its name, a group, its bind (device, input, device::input, alias, modifiers) or one of its actions (game, id or aircraft).
  • --titles adds to each relation the titles of its actions (JSON field; the GUI uses it for the relation search and runs relations list --titles).
  • The relations come sorted by name. Read-only: neither the profile nor a game changes.
Technical internals
  • Output: JSON (the relations document with every relation, its actions, aircraft and bind), or --text: Relations: <n> and one line per relation name | type=axis|button | bind=<device>::<input> | mods=<n> | games=... | planes=<n> | groups=.... --out <file> writes it to a file.
  • Exit code 0; the filter never fails, it only lists fewer relations.
  • Related: engine relations show (one relation in detail), engine relations search (actions of the games, not of the profile), engine relations group list.

What it does Lists relations (logical actions) in the profile.

OptionValuesMeaning
--titlesswitch (no value)

Used by the GUI Relations: AddTickedMissingReviewCommand · Profile bar: Reload · Profile bar: Merge · Profile bar: Take them out · Relations: Run Mass Operation · Relations: Add · Relations: Remove Selected · Relations: Remove All · Relations: Rename · Relations: Refresh relations · Relations: Merge Profile · Relations: Apply selected

Example

engine relations list 'Gear' --text

#engine relations show

written
engine relations show <relation-name>
For beginners

Shows one relation in detail: type, groups, games, its bind with modifiers and axis settings, and every action with its aircraft. Show selected in output on the Relations page prints it into the Output panel, and the GUI reads it whenever it opens a relation. It changes nothing.

engine relations show "Gear Toggle" --profile "C:\Users\Pilot\Documents\JoyPro\My Sticks.pr0file" --text
Advanced
  • The name may be the exact name (case ignored) or a part of it that only one relation has. Several matches are refused with the list of names.
  • The actions carry the titles the profile stored for them (per aircraft).
  • Read-only.
Technical internals
  • Output: JSON of the relation, or --text (Relation:, Type:, Groups:, Games:, Planes Covered:, Bind:, Bind Reformers:, inversion, slider, curve, dead zone and saturation, then Nodes: <n> with each action).
  • Exit code 1 with relations show requires a relation name., No relation matched query: ... or Ambiguous relation query '...'. Matches: ....
  • The commands that change one relation (engine relations group add, engine relations item remove, engine relations item move) answer with this same view of the changed relation.

What it does Shows one relation in detail.

Used by the GUI Profile bar: Take them out · Relations: Show selected in output · Relations: OnlyWhereSameMeaningCommand · Relations: Switch them all off · Relations: OpenAircraftCheckRelationCommand · Relations: Move to the top · Relations: Move to the bottom · Relations: Remove from the relation · Relations: Apply · Relations: OpenOtherRelationsTagCommand · Relations: OpenRelationFromSearchCommand · Relations: OpenAssistantRelationCommand

Example

engine relations show 'Gear Toggle' --text

#engine relations add

written
engine relations add <name> [--axis|--button|--type axis|button] [--node game:id[:plane1|plane2]] [--from relation] [--group g] [--device d --input i --modifier m]
For beginners

Creates a new relation: one button or axis of yours with the actions it shall do in your games. The Relations page uses it when you create a relation.

engine relations add "Gear" --button --node "DCS:gear_up_down:F-16C_50|FA-18C_hornet" --group "Systems" --profile "C:\Users\Pilot\Documents\JoyPro\My Sticks.pr0file"
Advanced
  • --node Game:Id:Plane1|Plane2 per action (DCS: the aircraft; other games: the game id once); --id with --game and --planes is the same for one action.
  • --from <relation> takes the actions of an existing relation.
  • --axis, --button or --type axis|button sets the kind; without them it comes from --from or the actions. Axes and buttons in one relation are refused.
  • --group <g> puts it into a group; --device, --input and --modifier bind it right away.
  • One undo step.
Technical internals
  • Output: the result as JSON, or text with --text; with --profile the profile is saved.
  • Errors: no name, no source (--node, --id with --game, or --from), a malformed --node, an unknown option.
  • Related: engine relations search, engine relations show, engine relations suggest, engine binds set.

What it does Creates a relation with node targets and optional bind/group data.

OptionValuesMeaning
--axisswitch (no value)Set relation type to axis (explicit override).
--buttonswitch (no value)Set relation type to button (explicit override).
--typeaxis buttonSet relation type via value token (`axis` or `button`).
--nodeswitch (no value)Node token format: game:id[:plane1|plane2]. Example: DCS:d3007pnilu3007cd16vd1vpnilvu0:F-16C_50|FA-18C_hornet.
--fromswitch (no value)Copy structure from existing relation(s).
--groupswitch (no value)Attach relation group tag. Example: --group Startup.
--deviceswitch (no value)Include one device per flag. Example: --device LEFT VPC Throttle.
--inputswitch (no value)Input token. Example: --input JOY_BTN1 or --input joy0_b0.
--modifierswitch (no value)Modifier key token. Example: --modifier LShift.
Every value as a command line
engine relations add --type axis
engine relations add --type button

Used by the GUI Relations: AddCheckedCatalogCommand · Relations: AddCheckedBuilderResultsCommand

Example

engine relations add 'Gear Toggle' --node DCS:d3007pnilu3007cd16vd1vpnilvu0 --group 'Startup' --text
engine relations add 'Pitch Axis' --type axis --node IL2Game:mc_pitch --text
How the options interact
  • You need at least one source: --node, --id/--game, or --from.
  • Type is inferred from source relation (--from) or node IDs when possible.
  • Use --axis / --button / --type only when you want an explicit override.

#engine relations group list

written
engine relations group list [relation-name]
For beginners

Lists the groups of one relation, or every group of the profile with the relations that use it. Groups only sort and filter your relations in JoyPro; no game sees them. On the Relations page, List Groups (Selected or All) under Groups prints it into the Output panel.

engine relations group list --profile "C:\Users\Pilot\Documents\JoyPro\My Sticks.pr0file" --text
Advanced
  • With a relation name (exact, or a part only one relation has): that relation's groups, sorted, each once.
  • Without: every group (case ignored) with its relations and their count.
  • More than one name is refused. Read-only.
Technical internals
  • Output: JSON (Scope relation or global, Groups, and for global the Entries with Relations and RelationCount), or --text.
  • Exit code 1 with relations group list accepts at most one relation name. or the name messages of engine relations show.
  • Related: engine relations group add, engine relations group remove, engine relations group rename.

What it does Lists groups on one relation, or all groups across all relations.

Used by the GUI Relations: List Groups (Selected or All)

Example

engine relations group list --text
engine relations group list 'Gear Toggle' --text
How the options interact
  • Without a relation name, lists all groups and where they are used.

#engine relations item add

written
engine relations item add <relation-name> --node game:id[:plane1|plane2] [--node ...] [--force]  (or --id/--game/--planes; an action its game's list does not have, or an axis in a button relation or the other way round, is refused unless --force)
For beginners

Puts one or more game actions into an existing relation, so they go on the relation's button or axis with the next export. Use it to give a bind more games or aircraft, for example the F-16's gear handle next to the F/A-18's.

engine relations item add "Gear Toggle" --node "DCS:d3007pnilu3007cd16vd1vpnilvu0:F-16C_50" --profile "C:\Users\Pilot\Documents\JoyPro\My Sticks.pr0file" --text
Advanced
  • --node game:id[:plane1|plane2], repeatable: the game (empty = DCS), the action id and the aircraft (|, , or ; between them). An action the relation has already gets the named aircraft switched on.
  • --id <id> with --game <game> (default DCS) and --planes <list> is the same as one --node.
  • DCS without aircraft: the aircraft where the id has its most common meaning are switched on; aircraft where the same id means something else are left out (a note on the error stream says how many). Other games without aircraft: the action is for the whole game (Default stands for the game too).
  • MSFS 2024: an action the command list has only for some aircraft (an add-on's own) comes in for those aircraft alone unless the node names aircraft.
  • The action must fit: an id its game's command list does not have (checked when JoyPro has that list) and an axis in a button relation or a button in an axis relation are refused, nothing is added. --force adds it anyway (the suggestions then flag it under "Looks wrong").
  • One profile version (one undo step). The game files change only with the next export.
Technical internals
  • Output: the changed relation as engine relations show prints it; the profile is saved with --profile.
  • Exit code 1 with relations item add requires at least one target via --node or --id., Invalid --node value '...'. Use --node <game:id[:plane1|plane2]>., Unknown relations item argument(s): ..., <game>:<id> is not an action of <game>'s command list ..., <game>:<id> is a button; '<relation>' is an axis relation. (or the other way round; both end with Nothing was added (--force adds it anyway).), No relation items were changed. or the name messages.
  • Related: engine relations item remove, engine relations item enable, engine relations suggest apply (adds with a kind check), engine relations search (find the id).

What it does Adds actions (node targets) to an existing relation. An action its game's list does not have, or an axis in a button relation (or the other way round), is refused unless --force.

OptionValuesMeaning
--nodeswitch (no value)Node token format: game:id[:plane1|plane2]. Example: DCS:d3007pnilu3007cd16vd1vpnilvu0:F-16C_50|FA-18C_hornet.
--forceswitch (no value)Add the actions even when their game's list does not have them or they are of the other kind (axis / button) than the relation.
--idswitch (no value)Node ID. Example: --id d3007pnilu3007cd16vd1vpnilvu0.
--gameswitch (no value)Game filter value. Example: DCS or IL2Game.
--planesswitch (no value)Include planes/modules as CSV. Example: --planes A-10C_2,FA-18C_hornet.

Example

engine relations item add 'Gear Toggle' --id d3007pnilu3007cd16vd1vpnilvu0 --game DCS --planes F-16C_50 --text
How the options interact
  • At least one target (--node or --id) is required.

#engine relations item enable

written
engine relations item enable <relation-name> --node game:id[:plane1|plane2] [--node ...]
For beginners

Switches aircraft of an action in a relation on again. The action stays in the relation either way; switched-off aircraft simply do not get it on the relation's button at the next export.

engine relations item enable "Gear Toggle" --node "DCS:d3007pnilu3007cd16vd1vpnilvu0:F-16C_50" --profile "C:\Users\Pilot\Documents\JoyPro\My Sticks.pr0file" --text
Advanced
  • --node game:id[:plane1|plane2] (repeatable) or --id <id> --game <game> --planes <list>; at least one is needed.
  • With aircraft: exactly those are switched on, also aircraft the action did not list yet. Without aircraft: every aircraft the action lists.
  • Games without aircraft keep the action under the game's name; Default in the spec means the same.
  • An old game id of a game split into versions (MSFS, X-Plane) matches the actions of every version.
  • One profile version (one undo step). Nothing changes in the game until the next export.
Technical internals
  • Output: the changed relation as engine relations show prints it; the profile is saved with --profile.
  • Exit code 1 with relations item enable requires at least one target via --node or --id., Invalid --node value '...', No relation items were changed. (nothing matched, or everything was on already) or the name messages.
  • Related: engine relations item disable, engine relations aircraft set (on and off in one step, with the meaning check of engine relations aircraft).

engine relations item enable 'Gear Toggle' --node DCS:d3007pnilu3007cd16vd1vpnilvu0:F-16C_50 --text
