#engine layout render

written
engine layout render [--path <export-folder>] [--device <name>] [--devices <csv>] [--layout-map <joystick>=<path.layout>] [--game <name>] [--games <csv>] [--plane <name>] [--planes <csv>] [--include-overview true|false] [--include-planes true|false] [--skip-missing-layouts true|false] [--draw-markers true|false] [--draw-legend-table true|false] [--marker-size <n>] [--legend-width <n>] [--legend-max-rows <n>] [--legend-font-size <n>] [--button-symbol circle|square|triangle|diamond|bar] [--axis-symbol circle|square|triangle|diamond|bar] [--pov-symbol circle|square|triangle|diamond|bar] [--slider-symbol circle|square|triangle|diamond|bar] [--sheet-style joypro|print|high-contrast|dark-sheet|<style.json>] [--font <family>] [--font-size <n>] [--font-weight normal|semibold|bold] [--text-color <#RRGGBB|#AARRGGBB>] [--outline-color <color|none>] [--label-background <color|none>] [--page-background <color>] [--table-background <color>] [--table-border <color>] [--header-background <color>] [--header-text <color>] [--table-text <color>] [--line-color <color>] [--marker-color-button <color>] [--marker-color-axis <color>] [--marker-color-hat <color>] [--marker-color-slider <color>] [--modifier-colors <modifier=#RRGGBB,...>] [--style dark|light] [--print-width <px>] [--combine true|false] [--drawing-style lines|cel] [--drawing-preset joypro|manual|blueprint|print|custom] [--drawing-ink <#RRGGBB>] [--drawing-paper <#RRGGBB>] [--drawing-accent <#RRGGBB>]

A --layout-map to a device layout .json with tables and lines draws JoyPro 1 style sheets; the sheet style options colour the page, tables, lines, markers and labels, a device's own style in its layout wins; the --drawing-* options paint JoyPro's own drawings, default: the GUI's settings

For beginners

Draws the cheat sheets: a picture of each device with every bind written at its button, as PNG files, one overview per device and one per aircraft. Create cheat sheets on the Layout page (Cheat sheets) runs it.

engine layout render --path "C:\Users\Pilot\Documents\JoyPro\Cheat sheets" --game DCS --plane F-16C_50 --profile "C:\Users\Pilot\Documents\JoyPro\My Sticks.pr0file" --text
Advanced
  • Each device needs a layout: the profile's layout file for it (engine layout image, engine layout suggest) or --layout-map <device>=<file>. A JoyPro 1 .layout, a device layout .json with tables and lines, or a page with several views. --skip-missing-layouts true (default) skips a device without one with a warning; false fails.
  • --device(s), --game(s), --plane(s) limit what is drawn.
  • --include-overview and --include-planes (both default true; not both false).
  • Look: --draw-markers, --draw-legend-table (default false), --marker-size (10), --legend-width (460), --legend-max-rows (20), --legend-font-size (11), symbols (default circle, diamond, triangle, bar), --sheet-style and the colour and font options, --style dark|light, --print-width (default 3508, at most 12000), --combine true (one All devices.png per folder), --drawing-* (default: the GUI's drawing settings).
  • Writes only pictures; the profile and the games are not touched.
Technical internals
  • Files: <path>\<device>.png (overview) and <path>\<game>\<plane>\<device>.png. --path default: the profile's cheat sheet folder, else LayoutExport.
  • Output: the render result (rendered devices, written files, warnings), or text; exit code 0, 1 on layout render failed: ... (for example layout render produced no images. Ensure joystick layout mappings exist ...).
  • Related: engine layout titles, engine layout multiview, engine layout callouts.

What it does Renders joystick layout images per game/plane (command descriptions) and overview images (relation names) from JoyPro .layout mappings.

#engine layout callouts

written
engine layout callouts (--model <catalog id> | --layout <device-layout.json>) [--picture <file>] [--schematic] [--drawing-style lines|cel] [--drawing-preset <p>] [--drawing-ink|--drawing-paper|--drawing-accent <#RRGGBB>] [--arrange] [--device <name>] [--game <name> --plane <name>] [--sample] [--png <file>] [--light] [--print-width <px>] [--save <file.json>] [--sheet-style joypro|print|high-contrast|dark-sheet|<style.json>] [--font <family>] [--font-size <n>] [--font-weight normal|semibold|bold] [--text-color <#RRGGBB|#AARRGGBB>] [--outline-color <color|none>] [--label-background <color|none>] [--page-background <color>] [--table-background <color>] [--table-border <color>] [--header-background <color>] [--header-text <color>] [--table-text <color>] [--line-color <color>] [--marker-color-button <color>] [--marker-color-axis <color>] [--marker-color-hat <color>] [--marker-color-slider <color>] [--modifier-colors <modifier=#RRGGBB,...>]

Tables around the device picture with orthogonal lines; exit code 1 when the sheet check finds problems, the picture and file are written all the same; --check-all [query] checks every model

For beginners

Arranges the tables around a device picture with right-angled leader lines, for a model of the device catalog or a saved device layout, checks the sheet, and can draw it as a PNG with your binds in the tables.

engine layout callouts --model thrustmaster-warthog-stick --device "Joystick - HOTAS Warthog" --game DCS --plane F-16C_50 --png "C:\Users\Pilot\Documents\JoyPro\Warthog.png" --profile "C:\Users\Pilot\Documents\JoyPro\My Sticks.pr0file" --text
Advanced
  • Source: --model <catalog id> (or the first word) takes JoyPro's line drawing of the model with its positions and its shipped sheet when there is one, else (or with --schematic) JoyPro's schematic drawing; --picture <file> puts your own picture behind it (without positions). --layout <device layout .json> takes a saved layout with its tables.
  • --arrange arranges the tables anew even when the layout has some.
  • Table text: --device <name> writes that device's binds (relation names; with --game and --plane, which go together, that aircraft's binds); --sample fills sample text; without either the tables stay empty.
  • --png <file> draws the sheet: --light, --print-width (default 3508, at most 12000), --sheet-style and the font and colour options as for engine layout render (a layout's own style wins), --drawing-style lines|cel, --drawing-preset, --drawing-ink, --drawing-paper, --drawing-accent (default: the GUI's drawing settings).
  • --save <file.json> writes the layout with the arranged sheet.
  • --check-all [words] arranges and checks the sheet of every catalog model with inputs.
  • Writes only the files you name; the profile and the games are not touched.
Technical internals
  • Output: JSON Model, Check, Warnings, Sheet, or text Layout Callouts: <model> | picture ... | sheet ..., Check: ..., Result: ok|problems, a line per table, problems and warnings. Exit code 0, or 1 when the check finds problems (the picture and the file are written all the same).
  • --check-all: exit code 1 when a sheet has overlapping tables, slanted lines, something outside the canvas, a line through a table or a placed part without a line.
  • Failures (exit 1): layout callouts needs --model <catalog id> or --layout <device layout .json>., layout callouts needs --game and --plane together., Unknown device model: ..., Device layout not found: ..., layout callouts failed: ...
  • Reference: device-reference. Related: engine layout render, engine devices reference.

#engine layout titles

written
engine layout titles --device <name>

The game's own menu titles of the device's binds, per game and aircraft

For beginners

Lists, for every game and aircraft a device's binds are active in, the game's own menu title of each bound input, and the device's main modifier. The Layout page reads it for the preview box of Tables (one game and aircraft with the game's menu titles).

engine layout titles --device "Joystick - HOTAS Warthog" --profile "C:\Users\Pilot\Documents\JoyPro\My Sticks.pr0file" --text
Advanced
  • --device (required): the device name as in the binds.
  • Inputs with a modifier are listed as Modifier+JOY_BTN5.
  • Read-only; needs the profile.
Technical internals
  • Output: JSON Device, Modifier, Targets (game, plane, titles), or text; exit code 0.
  • Failures (exit 1): layout titles needs --device <JoyPro device name>.

What it does The game's own menu titles of the device's binds, per game and aircraft.

#engine layout image

written
engine layout image <device> [--set <layout file>|--clear]

The layout file the profile uses for a device; --clear: JoyPro's picture again, --set puts one back

For beginners

Shows or changes the layout file the profile uses for a device (your own layout, a JoyPro 1 layout, a picture you chose). Reset to JoyPro's default... on the Layout page clears it, Undo the reset puts it back.

engine layout image "Joystick - HOTAS Warthog" --clear --profile "C:\Users\Pilot\Documents\JoyPro\My Sticks.pr0file" --text
Advanced
  • No option: prints the mapping. --clear: forgets it, JoyPro's picture shows again. --set <file>: sets it.
  • The device matches with or without its GUID.
  • Only the profile changes.
Technical internals
  • Output: Device, Previous, Current, or text <device>: <file> (was: ...); exit code 0.
  • Failures (exit 1): the usage layout image <device> [--set <layout file>|--clear].
  • One undo step with --profile when it changed something. Related: engine layout render.

What it does The layout file the profile uses for a device; --clear: JoyPro's picture again, --set puts one back.

OptionValuesMeaning
--set<layout file>
--clearswitch (no value)

#engine layout multiview

written
engine layout multiview <file.json> [--views <folder>] [--png <file>] [--device <name>] [--game <g> --plane <p>] [--light] [--print-width <px>] [--sheet-style joypro|print|high-contrast|dark-sheet|<style.json>] [--font <family>] [--font-size <n>] [--font-weight normal|semibold|bold] [--text-color <#RRGGBB|#AARRGGBB>] [--outline-color <color|none>] [--label-background <color|none>] [--page-background <color>] [--table-background <color>] [--table-border <color>] [--header-background <color>] [--header-text <color>] [--table-text <color>] [--line-color <color>] [--marker-color-button <color>] [--marker-color-axis <color>] [--marker-color-hat <color>] [--marker-color-slider <color>] [--modifier-colors <modifier=#RRGGBB,...>]

A page with several views of a device: each view as view-<n>.png, the page as one picture; layout render draws it when --layout-map points to it

For beginners

Draws a page with several views of one device (front and side): each view as its own picture and the whole page as one picture. The Layout page runs it to draw the views of Several views.

engine layout multiview "C:\Users\Pilot\Documents\JoyPro\Warthog views.json" --png "C:\Users\Pilot\Documents\JoyPro\Warthog.png" --device "Joystick - HOTAS Warthog" --profile "C:\Users\Pilot\Documents\JoyPro\My Sticks.pr0file"
Advanced
  • --views <folder>: each view as view-<n>.png. --png <file>: the page.
  • --device: whose binds are written; --game with --plane: one aircraft (else relation names).
  • --light, --print-width (default 3508), the sheet style options; a view's own style wins.
  • Writes only pictures.
Technical internals
  • Output: always JSON: Model, Page, Width, Height, Views (index, file, size), Png, Warnings; exit code 0.
  • Failures (exit 1): Not a page with several views: ..., the usage line.
  • Related: engine layout render (draws such a page as the device's cheat sheet).

What it does A page with several views of a device: each view as view-<n>.png, the page as one picture; layout render draws it when --layout-map points to it.

#engine layout suggest

engine layout suggest [--device <name>] [--devices <csv>] [--connected] [--profile-devices] [--legacy-layout-dir <path>] [--legacy-output-dir <path>] [--catalog <path.json>] [--apply true|false] [--apply-min-score <n>] [--backdrop <picture-file-or-image-url>]
For beginners

Finds a picture with button positions for each device: a fitting layout template, else JoyPro's drawing of the model, else a generated layout. With --apply true it stores the choice in the profile for the cheat sheets. Suggest and Find my devices on the Layout page run it, Use picture with your own picture (--backdrop).

engine layout suggest --connected --apply true --profile "C:\Users\Pilot\Documents\JoyPro\My Sticks.pr0file" --text
Advanced
  • Devices: --device(s); else --connected (the connected game controllers); --profile-devices adds the profile's. None: it fails.
  • Templates: the device layout catalog (--catalog) and your layout folders (--legacy-layout-dir, --legacy-output-dir; found by themselves when not given). A template only fits the same product (VID:PID, a known alias or the same model words of the same vendor). Below a score of 45 it uses a picture of the product or a generated layout instead.
  • --backdrop <file or image URL>: your picture of the device with markers from its real inputs (one device only).
  • --apply true (default false) stores layouts with a score from --apply-min-score (default 55).
Technical internals
  • Output: the suggestions (device, layout file, score, vendor, model, VID:PID, search link), counts, warnings; exit code 0, 1 on layout suggest failed: ... (No devices available to suggest layouts for. ..., --backdrop needs exactly one device (--device <name>).).
  • Generated layouts go into JoyPro's AutoLayouts folder. One undo step with --profile when --apply stored one.
  • Related: engine layout identify, engine layout image, engine layout render.

#engine layout template-inspect

written
engine layout template-inspect --source <path.layout-or-image> [--max-markers <n>]

For beginners

Reads a layout file (JoyPro 1 .layout) or a picture for the layout-file editor: size, font, colour and every marker with its position, plus its tables and lines. The Layout page runs it when it opens a layout file in the editor.

engine layout template-inspect --source "C:\Users\Pilot\Documents\JoyPro\Layouts\Warthog.layout" --text
Advanced
  • --source (also --template, or the first word): the file.
  • --max-markers (default 2000; the GUI passes 10000; at most 20000, 0 or less means 5000) limits the marker list; more gives a warning.
  • Tables and lines come from <file>.tables.json and <file>.connectors.json beside it.
  • Does not change the profile.
Technical internals
  • Output: source, size, device name, font, text colour, preview picture path, Markers (token, type, modifier, x, y), Tables, Connectors; exit code 0.
  • Failures (exit 1): layout template-inspect requires --source <path.layout-or-image>., layout template-inspect failed: Layout source not found: ....
  • Related: engine layout template-save.

#engine layout template-save

written
engine layout template-save --source <path.layout-or-image> --out <path.layout> [--markers-json <file.json> | --markers <json-array-or-object>] [--tables-json <file.json> | --tables <json-array-or-object>] [--connectors-json <file.json> | --connectors <json-array-or-object>] [--replace-all true|false]
For beginners

Saves a layout file from a source layout or picture with the markers, tables and lines you give it. The layout-file editor on the Layout page runs it for Save, and before Create cheat sheets when the editor has a file open.

engine layout template-save --source "C:\Users\Pilot\Pictures\warthog.png" --out "C:\Users\Pilot\Documents\JoyPro\Layouts\Warthog.layout" --markers-json "C:\Users\Pilot\Documents\JoyPro\markers.json"
Advanced
  • --source (also --template, or the first word) and --out (also --output, --path, the global --out, or the second word); .layout is added when missing.
  • Markers, tables, lines: --markers-json <file> or --markers <json>, --tables-json / --tables, --connectors-json / --connectors.
  • --replace-all true (default): the file gets exactly the given markers; false: the source's markers stay, given ones are added or moved.
  • Writes the .layout plus <out>.tables.json and <out>.connectors.json; the profile is not touched.
Technical internals
  • Output: source, output path, marker, table and connector counts, warnings; exit code 0.
  • Failures (exit 1): layout template-save requires --source ..., ... requires --out <path.layout>., markers json file not found: ..., layout template-save invalid markers payload: ..., layout template-save failed: ....
  • Related: engine layout template-inspect, engine layout render.
