#engine binds list

written
engine binds list [filter]
For beginners

Lists the binds of the profile: for each relation its device, input, modifiers and axis settings. An optional text filters the list. The Binds page runs it to build its cards (Refresh binds under More, and after every change).

engine binds list "Warthog" --profile "C:\Users\Pilot\Documents\JoyPro\My Sticks.pr0file" --text
Advanced
  • The filter (all words after list, joined) matches, case-insensitive and as a part of the text: the relation name, the device, the button or axis, the device alias, device::input and the modifiers.
  • Sorted by relation name. Relations without a bind are not listed (engine binds show tells you more).
  • Read-only.
Technical internals
  • Output: the binds document as JSON (FormatVersion, GeneratedUtc, Binds), or a text list with --text; exit code 0.
  • binds list without an action is the same as binds.
  • Related: engine binds show, engine binds export (the same document into a file), engine binds edit.

What it does Lists bind entries (hardware mapping layer).

Used by the GUI Profile bar: Reload · Profile bar: Merge · Start: Import now · Start: Import · Start: Import · Start: Import · Start: Import · Relations: Duplicate · Relations: Duplicate without bind · Relations: Run Mass Operation · Relations: Merge Profile · Relations: Apply selected

Example

engine binds list 'Throttle' --text

#engine binds show

written
engine binds show <bind-or-relation>
For beginners

Shows one bind in full: device, input, modifiers, axis settings and the relation with its actions. Show selected in output under More on the Binds page runs it and prints the answer into the Output panel.

engine binds show "Gear Up/Down" --profile "C:\Users\Pilot\Documents\JoyPro\My Sticks.pr0file" --text
Advanced
  • The selector is a relation name, a bound input (JOY_BTN22) or device::input; a part of a relation name works when only one bound relation contains it.
  • Read-only.
Technical internals
  • Output: Bind and Relation as JSON, or text; exit code 0.
  • Failures (exit 1): binds show requires a bind name or relation name., No bind matched query: ..., Ambiguous bind query '...'. Matches: ..., Bind not found for relation: ... (the relation has no bind).
  • Related: engine binds list, engine binds set.

What it does Shows one bind in detail.

Used by the GUI Binds: Show selected in output · Binds: Clear Input · Binds: Clear Modifiers · Binds: Attach Selected To Bind · Binds: Detach Selected From Bind · Binds: Create Modifier · Modifiers: Create Modifier

Example

engine binds show 'Gear Toggle' --text

#engine binds set

written
engine binds set <bind-or-relation> [--device <name>] [--input <value>] [--format dcs|il2] [--modifier <name>] [--clear-modifiers] [--clear-input] [--inverted true|false] [--slider true|false] [--curvature <csv>] [--deadzone <value>] [--saturation-x <value>] [--saturation-y <value>] [--double-tap true|false]
For beginners

Puts a relation on a button or axis, or changes its modifiers and axis settings. It creates the bind when the relation has none. The Binds page runs it for Record input and Set Bind, the Layout page for Bind to this input, and the virtual function editor for Bind relation.

engine binds set "Gear Up/Down" --device "Throttle - HOTAS Warthog" --input JOY_BTN22 --profile "C:\Users\Pilot\Documents\JoyPro\My Sticks.pr0file"
Advanced
Option Effect on the bind
--device <name> the device the input belongs to
--input <token> the input; an axis relation stores it as its axis, a button relation as its button (the other field is emptied)
--format dcs|il2 how --input is written: dcs (default, JOY_BTN1) or il2 (joy0_b0, converted to the DCS form); needs --input
--modifier <name> (also --mod, --reformer; repeatable) replaces the bind's whole modifier list
--clear-modifiers empties the modifier list (ignored when --modifier is given)
--clear-input empties the input, the bind and its settings stay
--inverted, --slider true|false axis invert and one-sided axis
--curvature <csv>, --deadzone, --saturation-x, --saturation-y <n> the bind's own (base) axis curve
--double-tap true|false the double-tap flag (kept in the profile)
  • The axis options are refused on a button relation. At least one option is needed.
  • Only the profile changes; the game gets the bind at the next export.
Technical internals
  • Output: the bind after the change, as engine binds show prints it; exit code 0.
  • Failures (exit 1): binds set requires at least one change option (e.g. --device, --input, --curvature, --inverted)., --format requires --input., Invalid --deadzone value '...', Axis tuning options (...) can only be set on axis relations., No relation/bind matched query: ..., Unknown binds set argument(s): ....
  • With --profile the profile is saved afterwards as a new history version (one undo step).
  • Per-game and per-aircraft curves: engine binds tuning set. Related: engine binds clear, engine binds modifier add.

What it does Creates or updates one relation bind (device/input/modifiers and optional tuning values).

OptionValuesMeaning
--device<name>Include one device per flag. Example: --device LEFT VPC Throttle.
--input<value>Input token. Example: --input JOY_BTN1 or --input joy0_b0.
--formatdcs il2Format selector. Example values: dcs/il2 for binds unbind, rl/json for relations mass export.
--modifier<name>Modifier key token. Example: --modifier LShift.
--clear-modifiersswitch (no value)Clears all modifiers from the selected bind.
--clear-inputswitch (no value)Clears bind input token(s) (button/axis) while keeping the bind object.
--invertedtrue falseSet axis inversion flag on selected bind (true/false).
--slidertrue falseSet axis slider flag on selected bind (true/false).
--curvature<csv>Set curvature list. Example: --curvature 0.1,0.2,0.3.
--deadzone<value>Set deadzone numeric value. Example: --deadzone 0.15.
--saturation-x<value>Set saturation X numeric value. Example: --saturation-x 0.9.
--saturation-y<value>Set saturation Y numeric value. Example: --saturation-y 0.8.
--double-taptrue falseSet double-tap behavior flag (true/false).
Every value as a command line
engine binds set --format dcs
engine binds set --format il2
engine binds set --inverted true
engine binds set --inverted false
engine binds set --slider true
engine binds set --slider false
engine binds set --double-tap true
engine binds set --double-tap false

Used by the GUI Binds: Bind here · Binds: Free · Binds: Record input · Binds: Set Bind · Layout: Bind to this input · Layout: Free

Example

engine binds set 'Gear Toggle' --device 'VKB Gladiator NXT' --input JOY_BTN1 --text
engine binds set 'Pitch Axis' --input JOY_Y --inverted true --curvature 0.1,0.2 --deadzone 0.05 --saturation-x 0.9 --saturation-y 0.9 --text
How the options interact
  • If relation has no bind yet, this command creates one.
  • Axis tuning options apply only to axis relations.
  • --format is only meaningful when --input is provided.

#engine binds clear

written
engine binds clear <bind-or-relation> [--input-only]
For beginners

Takes the bind off a relation: by default the whole bind (input, modifiers, axis settings), with --input-only just the input. The relation and its actions stay. Clear Bind on the Binds page runs the full clear, Clear Input the --input-only form; the Layout page's free-marker button also uses it.

engine binds clear "Gear Up/Down" --input-only --profile "C:\Users\Pilot\Documents\JoyPro\My Sticks.pr0file" --text
Advanced
  • Default: the bind is removed from the relation. --input-only: the button and axis are emptied, modifiers and the curve stay on the relation for the next input.
  • A relation without a bind is no error; the result says HadBind: false.
  • After the next export the relation is on no button in the game.
Technical internals
  • Output: Relation, InputOnly, HadBind, ClearedInput, RemovedBind as JSON or text; exit code 0.
  • Failures (exit 1): binds clear requires: <bind-or-relation> [--input-only]., Unknown binds clear argument(s): ..., Relation not found: ....
  • One undo step with --profile. Related: engine binds unbind (free an input in every relation), engine binds set.

What it does Unbinds one relation (remove bind entirely or clear only input token).

OptionValuesMeaning
--input-onlyswitch (no value)For binds clear, clear only input tokens instead of removing whole bind.

Used by the GUI Binds: Bind here · Binds: Free · Binds: Clear Input · Binds: Clear Bind · Layout: Bind to this input · Layout: Free

Example

engine binds clear 'Gear Toggle' --text
engine binds clear 'Gear Toggle' --input-only --text
How the options interact
  • Default behavior removes the entire bind from that relation.
  • Use --input-only to keep bind metadata and clear only button/axis input.

#engine binds modifier list

written
engine binds modifier list [bind-or-relation]
For beginners

Lists modifiers (shift buttons held together with a bind's button): without a selector every modifier name with the relations that use it, with a selector those of one bind. The Binds and Modifiers pages run it when they refresh their modifier lists.

engine binds modifier list --profile "C:\Users\Pilot\Documents\JoyPro\My Sticks.pr0file" --text

  • Global: Modifiers (names, sorted) and Entries (name, relations, BindCount).

  • Read-only.
Technical internals
  • Output: JSON with Scope (global or bind), or text; exit code 0.
  • Failures (exit 1): binds modifier list accepts at most one bind/relation selector., Bind not found for relation: ....
  • Related: engine binds modifier add, engine binds modifier remove, engine binds modifier rename.

What it does Lists modifiers on one bind, or all modifiers across all binds.

Used by the GUI Profile bar: Reload · Profile bar: Merge · Start: Import now · Start: Import · Start: Import · Start: Import · Start: Import · Relations: Merge Profile · Binds: Merge Profile · Binds: Apply · Binds: Clear Input · Binds: Clear Modifiers

Example

engine binds modifier list --text

How the options interact
  • Without a bind/relation selector, lists all modifier names and usage counts.

#engine binds modifier add

written
engine binds modifier add <bind-or-relation> <mod1> [mod2] [...]
For beginners

Adds one or more modifiers to a bind, so its button only does the relation while they are held. Attach Selected To Bind on the Binds page and Create Modifier (with a relation picked) run it.

engine binds modifier add "Gear Up/Down" LShift --profile "C:\Users\Pilot\Documents\JoyPro\My Sticks.pr0file" --text
Advanced
  • Modifiers the bind already has (any case) are not added twice.
  • The relation needs a bind (engine binds set first).
  • The game gets the modifier combination at the next export (DCS shows it in its modifier list).
Technical internals
  • Output: the bind after the change, as engine binds show prints it; exit code 0.
  • Failures (exit 1): binds modifier add requires at least one modifier., Bind not found for relation: ..., Unknown binds modifier option(s): ....
  • One undo step with --profile. Related: engine binds modifier remove, engine binds modifier list.

What it does Adds one or more modifiers to a bind.

Used by the GUI Binds: Attach Selected To Bind · Binds: Create Modifier · Modifiers: Create Modifier

Example

engine binds modifier add 'Gear Toggle' LShift RCtrl --text

#engine binds modifier remove

written
engine binds modifier remove <bind-or-relation> <mod1> [mod2] [...] [--all]
For beginners

Takes modifiers off a bind, or all of them with --all; the bind and its input stay. Detach Selected From Bind and Clear Modifiers (--all) on the Binds page run it, and Delete Selected on the Modifiers page runs it per relation.

engine binds modifier remove "Gear Up/Down" --all --profile "C:\Users\Pilot\Documents\JoyPro\My Sticks.pr0file" --text

  • A name removes every stored form of that modifier on the bind (any device and input).
  • After the next export the button works without holding the shift button; binds that only differed by the modifier now share one button (the Check shows it).
Technical internals
  • Output: the bind after the change; exit code 0.
  • Failures (exit 1): binds modifier remove requires at least one modifier or --all., Bind not found for relation: ....
  • One undo step with --profile. Related: engine binds modifier add.

What it does Removes one or more modifiers (or all) from a bind.

OptionValuesMeaning

engine binds modifier remove 'Gear Toggle' LShift --text

  • Use --all to clear all values instead of specifying individual names.

#engine binds tuning models

written
engine binds tuning models

The axis response models: DCS, IL-2 Great Battles, IL-2 Korea, the per-game models (Arma, Elite, BMS, FSX, IL-2 1946, Cliffs of Dover, MSFS, Project Wingman, Star Citizen, VTOL VR, WARDOGS, War Thunder, X-Plane) and the generic one, with their parameters

For beginners

Lists the axis response models JoyPro knows (how a game turns your stick position into what it uses) with their parameters. The parameter keys are what binds tuning set --param takes.

engine binds tuning models --text
Advanced
  • dcs: dead zone, saturation X/Y, curvature (exponential) or an 11-point user curve, slider, invert. Also il2, il2korea, and generic for games without a model of their own (invert, dead zone, saturation).
  • The games' own models: Arma 2 / Arma 2 OA, Arma 3, Arma Reforger, Elite Dangerous, Falcon BMS, FSX / Prepar3D, IL-2 1946, IL-2 Cliffs of Dover (also Blitz), MSFS 2020 / 2024, Project Wingman, Star Citizen, VTOL VR, Wardogs, War Thunder, X-Plane 11 / 12.
  • Per parameter: key, label, kind (number or switch) and the range of a number. A model whose game takes a curve with free stops also shows the --curve-points line.
  • Read-only; no profile needed. With binds tuning alone it lists the models too.
Technical internals
  • Output: JSON Models (Id, Title, Description, CurvePoints, Parameters with Key, Label, Kind, Min, Max, Step, Default), or text; exit code 0.
  • Reference: axis-curves. Related: engine binds tuning set, engine binds tuning preview.

What it does Lists the axis response models and their parameters: DCS, IL-2 Great Battles, IL-2 Korea, the per-game models (Arma 2 / 3 / Reforger, Elite, BMS, FSX, IL-2 1946, Cliffs of Dover, MSFS, Project Wingman, Star Citizen, VTOL VR, WARDOGS, War Thunder, X-Plane) and the generic one.

Example

engine binds tuning models --text

#engine binds tuning show

written
engine binds tuning show <bind-or-relation> [--game <game>] [--plane <plane>]
For beginners

Shows an axis relation's curves: the base curve every game gets and each scope with its own curve (an aircraft, a game, a game family). With --game (and --plane) it also says which curve that game uses. The axis response panel on the Binds page runs it when it loads a scope (Reload).

engine binds tuning show "Pitch" --game DCS --plane F-16C_50 --profile "C:\Users\Pilot\Documents\JoyPro\My Sticks.pr0file" --text
Advanced
  • The resolved curve: the most specific stored scope (aircraft, game, family), else the base; for a game whose curve differs from DCS's it is fitted to the base curve; in detent mode the detent curve.
  • Values are written as inv=0;sl=0;dz=0.05;sx=1;sy=1;cv=0.2 plus the game's own parameters.
  • Read-only. Axis relations only.
Technical internals
  • Output: JSON Relation, Scopes, Game, Plane, Resolved (Model, Source, Fitted, Tuning, Note), or text; exit code 0.
  • Failures (exit 1): Axis tuning is only for axis relations; '...' is a button relation., No relation/bind matched query: ....
  • Reference: axis-curves. Related: engine binds tuning set, engine binds tuning clear, engine binds tuning preview, engine binds tuning models.

What it does Shows the axis tuning of a bind per scope (base, game, plane, family) and, with --game, what that game (and plane) uses.

OptionValuesMeaning
--game<game>Game filter value. Example: DCS or IL2Game.
--plane<plane>Include one plane/module per flag. Example: --plane A-10C_2.

Used by the GUI Binds: Reload · Binds: Save for this scope · Binds: Inherit (clear) · Binds: Save calibration · Binds: Set · Binds: Game data

Example

engine binds tuning show 'Pitch Axis' --game IL2Korea --text

#engine binds tuning set

written
engine binds tuning set <bind-or-relation> --scope base|game:<game>|plane:<game>:<plane>|family:<family> [--param <name>=<value>]... [--inverted true|false] [--slider true|false] [--deadzone <value>] [--saturation-x <value>] [--saturation-y <value>] [--curvature <csv>] [--curve-points <x:y,...>|none]
For beginners

Stores an axis curve for one scope: the base (every game), a game, an aircraft of a game or a game family. Save for this scope in the axis response panel on the Binds page runs it.

engine binds tuning set "Pitch" --scope plane:DCS:F-16C_50 --deadzone 0.03 --curvature 0.2 --profile "C:\Users\Pilot\Documents\JoyPro\My Sticks.pr0file"
Advanced
Option Values
--scope (required) base, game:<game>, plane:<game>:<plane>, family:<family>
--inverted, --slider true / false
--deadzone, --saturation-x, --saturation-y 0..1
--curvature one value -1..1, or 11 user-curve points 0..1
--param <name>=<value> a parameter of the game's own curve model, checked against its range (engine binds tuning models)
--curve-points x:y,... | none a curve with free stops in 0..1, x increasing, at least two points
  • A scope without values of its own starts from what it uses now (game and aircraft scopes) or from the base.
  • Curve points stay until dead zone, saturation or curvature change without new points.
  • The base scope writes the bind's own values: invert, slider, dead zone, saturation and curvature. --param and --curve-points are not stored there: the result shows only the stored values and a line "Not set: ... do not apply to the base scope"; put them on a game, aircraft or family scope.
