#engine vjoy status

written
engine vjoy status

Virtual joystick mode: vJoy and HidHide installed, vJoy devices, HidHide state and JoyPro's session, games native/virtual, the mapping table, what vJoy must offer; read-only

For beginners

Shows the virtual joystick state: vJoy and HidHide installed, the vJoy devices, HidHide's state and JoyPro's session, each game's mode (native, vJoy, Xbox pad) and the mapping table. Refresh on the Virtual Joystick page's Overview runs it.

engine vjoy status --profile "C:\Users\Pilot\Documents\JoyPro\My Sticks.pr0file" --text
Advanced
  • Per game: mode, relations, executables, suggested mode for one-device games, input limits and warnings, functions, modes.
  • Per vJoy device: what the table needs and what it has.
  • Read-only and without administrator rights: HidHide's hidden-device list usually cannot be read then and shows as unknown, never as empty.
Technical internals
  • Output: the status as JSON, or text; exit code 0.
  • Reference: virtual-joystick. Related: engine vjoy mode, engine vjoy map, engine vjoy limits.

What it does Virtual joystick mode (docs/virtual-joystick.md): vJoy and HidHide installed, the vJoy devices (configuration and DirectInput name), HidHide's state, JoyPro's HidHide session (stale when its owner is gone), the games native/virtual, the mapping table and what vJoy must offer. Read-only.

Used by the GUI Virtual Joystick: Start · Virtual Joystick: Test · Virtual Joystick: Stop · Virtual Joystick: Refresh · Virtual Joystick: Set up vJoy for the table · Virtual Joystick: Restore HidHide · Virtual Joystick: Set up vJoy for maximum · Virtual Joystick: Update mapping · Virtual Joystick: Add function · Virtual Joystick: Add mode · Virtual Joystick: Save · Virtual Joystick: Import

Example

engine --profile 'C:\JoyPro\profiles\pilot_main.pr0file' vjoy status --text
How the options interact
  • Virtual joystick mode: docs/virtual-joystick.md. JOYPRO_VJOY_FAKE= replaces vJoy and HidHide by files (tests).

#engine vjoy mode

written
engine vjoy mode <game> native|virtual|xbox [--dry-run]

Per game: physical devices, the virtual joystick (vJoy, every used input gets a fixed vJoy slot) or the virtual Xbox 360 pad (ViGEmBus, for XInput-only or one-device games: the game's gamepad layout first, then sticks, triggers, buttons, D-pad)

For beginners

Switches one game between your physical devices (native), the virtual joystick (virtual, vJoy) and the virtual Xbox 360 pad (xbox, ViGEmBus). A game's mode buttons on the Virtual Joystick page run it. Export the game again afterwards.

engine vjoy mode DCS virtual --profile "C:\Users\Pilot\Documents\JoyPro\My Sticks.pr0file" --text
Advanced
  • <game>: a game id or name JoyPro knows. Mode: native, virtual (also vjoy) or xbox.
  • virtual: every input the game's relations use (axes, buttons, hats, modifier buttons) gets a fixed place on the vJoy device in the mapping table (engine vjoy map); export, import and sync of the game then work on the vJoy inputs.
  • xbox: for games that read only Xbox controllers or one device. The game's gamepad layout puts actions on their pad controls first, the rest fills the sticks, triggers, 14 buttons and the D-pad; what does not fit is listed.
  • native takes the game out of virtual mode; its places stay in the table until engine vjoy map --prune.
  • A one-device game set to another mode than the suggested one gets a warning with the suggested mode.
  • --dry-run saves nothing. Only the profile changes: vJoy, HidHide and the game's files are untouched until Start and the next export.
Technical internals
  • Output: the plan as for engine vjoy map, with the message <game> now uses the virtual joystick (vJoy). (or the Xbox pad, or the physical devices); exit code 0, 1 when the plan has errors (nothing is saved then).
  • Failures (exit 1): engine vjoy mode <game> native|virtual|xbox, Unknown game: ..., The mode is native, virtual (vJoy) or xbox (virtual Xbox 360 pad)., Unknown vjoy mode argument(s): ...
  • Stored in the profile; one undo step with --profile. Reference: virtual-joystick. Related: engine vjoy status, engine vjoy limits.

What it does Switches a game between its physical devices (native), the virtual joystick (virtual, vJoy) and the virtual Xbox 360 pad (xbox, ViGEmBus: for games that only read XInput or one device; the game's gamepad layout pins actions to their controls, the rest fills sticks, triggers, 14 buttons and the D-pad, what does not fit is listed). Virtual gives every input the game's relations use (axes, buttons, hats, modifier buttons) a fixed vJoy slot; export, import and sync of the game then work on the vJoy slots.

OptionValuesMeaning
--dry-runswitch (no value)Report what the command would do; nothing is written or changed.

Example

engine --profile 'C:\JoyPro\profiles\pilot_main.pr0file' vjoy mode DCS virtual --text
engine --profile 'C:\JoyPro\profiles\pilot_main.pr0file' vjoy mode DCS native --text
engine --profile 'C:\JoyPro\profiles\pilot_main.pr0file' vjoy mode HLLVietnam xbox --text
How the options interact
  • Virtual joystick mode: docs/virtual-joystick.md. JOYPRO_VJOY_FAKE= replaces vJoy and HidHide by files (tests).

#engine vjoy map

written
engine vjoy map [--reset] [--prune] [--dry-run]

Saves the mapping table in the profile; slots never move unless --reset; --prune drops unused slots

For beginners

Gives every input the virtual-mode games use a fixed place on the vJoy device (or the Xbox pad) and saves this table in the profile. Update mapping on the Mapping tab runs it, and Start / Test run it first.

engine vjoy map --dry-run --profile "C:\Users\Pilot\Documents\JoyPro\My Sticks.pr0file" --text
Advanced
  • Places never move: new inputs get a free place (an axis keeps its own axis where free, buttons and hats the next number).
  • --reset plans the table anew; --prune drops places no game uses any more; --dry-run saves nothing.
  • Per vJoy device it says what it needs and whether it fits; a device that lacks something needs engine vjoy configure-vjoy.
  • Only the profile changes; the games get the vJoy inputs at their next export.
Technical internals
  • Output: Message, VirtualGames, XboxGames, Slots, Added, Removed, Unused, Devices, Xbox, Errors, Warnings; exit code 0, 1 when the plan has errors (nothing is saved then).
  • One undo step with --profile. Related: engine vjoy plan (the same, never saved).

What it does Saves the mapping table in the profile: existing slots never move, new inputs get free slots (an axis keeps its own axis where free); --prune drops unused slots, --reset starts over.

OptionValuesMeaning
--resetswitch (no value)
--pruneswitch (no value)
--dry-runswitch (no value)Report what the command would do; nothing is written or changed.

Used by the GUI Virtual Joystick: Start · Virtual Joystick: Test · Virtual Joystick: Update mapping

Example

engine --profile 'C:\JoyPro\profiles\pilot_main.pr0file' vjoy map --text
engine --profile 'C:\JoyPro\profiles\pilot_main.pr0file' vjoy map --prune --dry-run --text

#engine vjoy settings

written
engine vjoy settings [--first-device N] [--last-device N] [--auto-start on|off] [--hide-devices on|off] [--dry-run]

Which vJoy devices JoyPro may use, GUI auto start, HidHide on/off

For beginners

Sets which vJoy devices JoyPro may use, whether the virtual joystick starts and stops by itself with a game in virtual mode, and whether HidHide hides the physical devices. The ticks "Hide the real devices from the games set to Virtual (HidHide)" and "Start and stop by itself when a game set to Virtual starts and ends" on the Virtual Joystick page run it.

engine vjoy settings --first-device 2 --last-device 3 --profile "C:\Users\Pilot\Documents\JoyPro\My Sticks.pr0file" --text
Advanced
  • --first-device N, --last-device N: 1..16 (default 1 to 16), the last not below the first. The mapping table and the function outputs use only these devices.
  • --auto-start on|off (default off), --hide-devices on|off (default on); true/false, yes/no, 1/0 work too.
  • Without options it prints the current settings. --dry-run saves nothing.
Technical internals
  • Output: vJoy devices <first>-<last>, auto start on|off, hide physical devices on|off.; JSON also FirstDevice, LastDevice, AutoStart, HideDevices; exit code 0.
  • Failures (exit 1): --first-device takes 1..16., --last-device takes 1..16., --last-device must not be below --first-device., --auto-start takes on or off.
  • Stored in the profile; one undo step with --profile. Related: engine vjoy map, engine vjoy apply-hidhide.

What it does Which vJoy devices JoyPro may use (--first-device/--last-device), the GUI's auto start, and whether HidHide hides the physical devices.

#engine vjoy exe

written
engine vjoy exe <game> [--add <path>] [--remove <path>]

The game executables HidHide blocks in virtual mode: found in the installation + your own

For beginners

Lists the executables of a game that HidHide blocks in virtual mode, so that game sees only the virtual joystick: the ones found in the game's installation plus your own. Add the game's program when JoyPro does not find it.

engine vjoy exe DCS --add "D:\DCS World\bin-mt\DCS.exe" --text
Advanced
  • <game> is required. --add <path> (repeatable): an existing file, kept with its full path. --remove <path> (repeatable): removes one of yours.
  • Found by JoyPro: the installation's marker executables and the game's process names found a few folder levels deep in the installation folder.
  • Yours are kept outside the profile and used at the next engine vjoy apply-hidhide.
Technical internals
  • Output: JSON Game, Exes, Extra (yours), Warnings, or text with (set by you) after your own; exit code 0.
  • Failures (exit 1): engine vjoy exe <game> [--add <path>] [--remove <path>], Unknown game: ..., Executable not found: ...
  • Your list: %LOCALAPPDATA%\JoyPro2\VirtualJoystick\game-exes.json. Reference: virtual-joystick.

What it does Lists (and adds/removes) the game executables HidHide blocks in virtual mode: found in the game's installation, plus your own.

OptionValuesMeaning
--add<path>
--remove<path>

Example

engine vjoy exe DCS --text

#engine vjoy forwarder-config

written
engine vjoy forwarder-config [--out <file>] [--xbox-game <game>] [--game <game>]

The mapping table for JoyPro.VJoy.exe, the forwarding process; one Xbox game's pad table; with --game only that game's virtual functions

For beginners

Writes the table for JoyPro.VJoy.exe, the process that copies your inputs to the virtual joystick: the devices, the places and the resolved virtual functions. Start and Test on the Virtual Joystick page run it.

engine vjoy forwarder-config --out "C:\Users\Pilot\Documents\JoyPro\forwarder.json" --profile "C:\Users\Pilot\Documents\JoyPro\My Sticks.pr0file" --text

  • Exit code 0, 1 when the plan has errors, the Xbox game does not use the pad or the game is unknown.
  • Related: engine vjoy map, engine vjoy functions list.

What it does Writes the mapping table for JoyPro.VJoy.exe, the process that forwards the physical inputs to vJoy.

#engine vjoy functions add

written
engine vjoy functions add --game <game> --type <type> [--name <name>] [--input role=<device>|<input>]... [--output role=<target>[@<vJoy device>][:hold|enter|leave|both]]... [--param key=value]... [--edges 0.1,0.9] [--count n] [--tuning <axis tuning>] [--keyboard on|off] [--modes <mode,...>] [--switch-modes <mode,...>] [--spec <json>|@<file>] [--no-auto-outputs] [--dry-run]

Adds a function; an input may read another function's output: --input role=fn:<id>|<output>; loops are refused; outputs left empty get free vJoy buttons/axes/hats (or Xbox pad controls), reserved in the table; --modes: the modes it works in (none: every mode)

For beginners

Adds a virtual function to a game: axis bands, toggles, short/long press, shift layers, macros and more, running between your devices and the virtual joystick. Add function on the Functions tab runs it with the game and type.

engine vjoy functions add --game DCS --type bands --input "in=VPC Throttle|JOY_Z" --count 3 --profile "C:\Users\Pilot\Documents\JoyPro\My Sticks.pr0file" --text
Advanced
  • --type (engine vjoy functions types) or --spec <json>|@<file> (a whole function); --name.
  • --input role=<device>|<input> (repeatable; role=fn:<id>|<output> reads another function's output; role= clears). --output role=<target>[@<vJoy device>][:hold|enter|leave|both].
  • --param key=value, --edges 0.1,0.9, --count 1..32, --tuning, --keyboard on|off, --modes a,b (none: every mode), --switch-modes.
  • Outputs left empty get free vJoy buttons, axes or hats (or Xbox controls), reserved in the table; --no-auto-outputs leaves them empty. Loops between functions are refused. --dry-run saves nothing.
  • The function works only while the game is in virtual mode.
Technical internals
