For beginners

JoyPro's cockpit database: real and fictional cockpits with their stick and throttle controls, what each does per mode, the panels and the sources. Use it to see how the real aircraft uses each button. The Cockpits page runs get --json for Use this layout, compare for Compare with my setup and pictures build --game all for Build pictures from my games; the Setup wizard reads get --json of your priority aircraft.

engine cockpits get f-16 f-16c-block-50 --text
Advanced
Verb What it does
list [query] (default) aircraft and variants; filters --game, --era, --role, --nation, `--category fixed-wing
search <text> [--limit n] aircraft and controls by words (default 50 each)
get <aircraft> [<variant>] one variant: devices, controls, functions per mode, panels, sources; the JSON is the joypro-cockpit-layout format
compare <aircraft> [<variant>] [--game G] with --profile: which functions of the variant your relations hold, with relation and input
render <aircraft> [<variant>] --png <file> the grip sheets as PNG (--device, `--style dark
render <aircraft> [<variant>] --page <page> [--png <file>] [--pdf <file>] the Cockpits page's manual pages (all, overview, stick, throttle, a device, panels, panel:<id>, photos, photo); several pages with --png become <file>.<page>.png; --style (default light), --scale 0.1..4, --highlight <words>, `--pictures picture
photos [query] [--coverage] [--verified], photos --needed [--game G], coverage, drawings photo links, the variants that still need photos, what the database covers, the drawings
guide <aircraft> [<variant>] [--lang <code>] [--search <words>] [--no-pictures], guide --coverage [--game G] the cockpit guide as a tree (areas, panels, controls with what each does and the game's commands); per variant what it explains
check [--structure] checks the database, drawings and guide; --structure lists only what is wrong, not what is still missing
`pictures build status
  • Aircraft and variants are found by id, name or alias; a game's own aircraft name (F-16C_50) works too.
  • pictures build [--game <id>|all] [--aircraft <a,b>] [--force] renders the cockpits of the installed games (DCS, X-Plane 12, MSFS 2020, IL-2 Great Battles, Nuclear Option, War Thunder, Star Citizen) into JoyPro's data folder, never into a game folder; DCS needs luae.exe in its folder. A game that is not installed is skipped with a note.
  • Nothing here changes the profile or a game.
Technical internals
  • Output: JSON, or --text; --json is accepted and ignored (JSON is the default).
  • Exit code 1 with No aircraft '...' in the cockpit database (cockpits list)., No variant '...' of ..., cockpits search needs a text ..., cockpits render needs --png <file>., --style is dark or light. or cockpits pictures build --game takes ...; check ends with 1 when it finds problems. pictures build shows progress and can be cancelled (exit code 3).
  • Data: DB\Cockpits\*.json with drawings, guide and photo-labels; pictures in %LOCALAPPDATA%\JoyPro2\GameData\CockpitPictures\<game>.
  • Reference: cockpits. Related: engine setup plan (--cockpit-file).

What it does The cockpit database (DB/Cockpits): stick and throttle of real and fictional aircraft per variant with their functions; list, search, get, check, render (sheets or the Cockpits page's manual pages), compare with the profile, photos, coverage, drawings, the cockpit guide and the pictures built from your installed games.
