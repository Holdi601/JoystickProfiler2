#engine setup devices

written
engine setup devices [--grip <device>=<grip id>]... [--role <device|VID:PID>=<role>]... [--add-device <catalog id>]...
For beginners

Step 2 of the Setup wizard: recognises your connected devices with JoyPro's device catalog and proposes a role for each one (main stick, throttle, pedals, panel ...), with the rules the plan will follow in words. The wizard runs it when it reaches the devices step and on Detect again. It changes nothing.

engine setup devices --role "VPC MongoosT-50CM3 Throttle=throttle" --profile "C:\Users\Pilot\Documents\JoyPro\My Sticks.pr0file" --text
Advanced
  • --role "<device or VID:PID>=<role>" (repeatable) sets a role: main-stick, heli-stick, left-stick, throttle, collective, pedals, panel, keyboard-joystick, virtual or unused.
  • --grip "<device or VID:PID>=<grip id>" picks the grip of a base that takes several grips.
  • --add-device <catalog id> (repeatable) adds a device that is not connected.
  • With --profile the device your profile uses most is proposed as the main stick.
  • Read-only. The same device options work with engine setup plan and engine arrange ask.
Technical internals
  • Output: JSON (Devices with role, proposed role, reason, model, kind, hand, grips and input count, Rules, Roles with titles, Warnings), or --text.
  • Exit code 1 with --grip expects "<device or VID:PID>=<grip id>"., --role expects "<device or VID:PID>=<role>" (...) or an unknown argument.
  • Reference: setup-wizard. Related: engine devices kb.

What it does Setup wizard: the connected devices with the proposed role and the rules the plan follows; --role, --grip and --add-device change them.

OptionValuesMeaning
--grip<device>
--role<device|VID:PID>
--add-device<catalog id>

Used by the GUI Setup wizard: Detect again · Setup wizard: NextCommand

Example

engine setup devices --text

#engine setup aircraft

written
engine setup aircraft --games <g1,g2>

The aircraft / games for the priority list

For beginners

Step 3 of the Setup wizard: lists the aircraft of the chosen games for the priority list (DCS: the modules of your DCS database; other games count as one entry). The wizard runs it when it reaches the priorities step. It changes nothing.

engine setup aircraft --games DCS,StarCitizen --text
Advanced
  • --games <g1,g2> (needed; ,, | or ; between ids): the game ids, for example DCS, StarCitizen, IL2Game.
  • Each entry has its key, game, type, class (fixed wing, helicopter, spaceship ...) and era.
  • Read-only; no profile is needed.
Technical internals
  • Output: JSON (Aircraft with Key, Game, Type, Class, ClassTitle, Era, and Warnings), or --text.
  • Exit code 1 with setup aircraft needs --games <game ids>. or an unknown argument.
  • Related: engine setup plan (--priorities takes these keys).

What it does The aircraft / games for the priority list.

OptionValuesMeaning
--games<g1,g2>Game filter values as CSV. Example: DCS,IL2Game,StarCitizen.

Used by the GUI Setup wizard: NextCommand

Example

engine setup aircraft --games <g1,g2> --text

#engine setup plan

written
engine setup plan --games <g1,g2> [--priorities "A>B|C>D"] [--priority "B|C"]... [--modifiers 0..8] [--prefer-fewer|--use-all-modifiers] [--realism 0..1] [--seed N] [--replace-existing] [--phase-layers on|off|auto] [--role <device|VID:PID>=<role>]... [--grip <device>=<grip id>]... [--add-device <catalog id>]... [--cockpit-file <json>]... [--out-plan <plan.json> | --plan-file <plan.json>]
For beginners

Step 4 of the Setup wizard: makes the whole plan for your games and devices: which relations to make, which input each gets, which modifiers, and a quality score per aircraft. It runs without AI; the same choices always give the same plan. The wizard runs it at step 4 and on Make the plan again. It changes nothing; engine setup apply writes it.

engine setup plan --games DCS --priorities "F-16C_50>FA-18C_hornet|A-10C_2" --modifiers 1 --out-plan "C:\Users\Pilot\Documents\JoyPro\plan.json" --profile "C:\Users\Pilot\Documents\JoyPro\My Sticks.pr0file" --text
Advanced
  • --games <g1,g2> (needed): the games to set up.
  • --priorities "A>B|C>D": > separates rows, | (or =) aircraft of one row; --priority "B|C" (repeatable) adds one row. Aircraft not listed count least.
  • --modifiers 0..8 (default 0) with --prefer-fewer (default: a modifier only when the essential functions do not fit) or --use-all-modifiers.
  • --realism 0..1 or 0..100% (default 0.5): from 50 % aircraft whose real HOTAS has a function elsewhere get their own relation; --cockpit-file <json> (repeatable) adds cockpit layouts from engine cockpits get --json.
  • --phase-layers auto|on|off, --seed <n> (default 1), --replace-existing (lays your bound relations out again).
  • The device options of engine setup devices: --role, --grip, --add-device.
  • --out-plan <file> (or --plan-file) writes the plan file for engine setup check, engine setup render and engine setup apply.
  • Your profile first: commands in your relations stay there, bound relations keep their inputs. Read-only.
Technical internals
  • Output: the plan as JSON, or --text (a summary); the plan file is written indented.
  • Exit code 1 with setup plan needs --games <game ids> ..., No device to plan with: connect your devices (or give them a role with --role)., --modifiers takes 0 to 8., --prefer-fewer and --use-all-modifiers exclude each other., --realism takes 0..1 (or 0..100 %). or --phase-layers takes on, off or auto.
  • Reference: setup-wizard.

What it does Setup wizard: plans relations and binds for the important functions of the chosen games' aircraft on your devices (priorities, modifier budget, realism, phase layers); deterministic for a --seed. Writes nothing to the profile; --out-plan saves the plan for setup check, apply and render.

OptionValuesMeaning
--games<g1,g2>The games to set up (needed), comma-separated. Example: --games DCS,IL2Game.
--prioritiesswitch (no value)Aircraft in order of importance: '>' starts the next row, '|' (or '=') joins aircraft of one row. Example: --priorities 'F-16C_50>FA-18C_hornet|A-10C_2'.
--priorityswitch (no value)One more row of equally important aircraft (repeatable). Example: --priority 'AV8BNA|F-14B'.
--modifiersswitch (no value)How many modifier buttons the plan may use, 0..8 (default 0).
--prefer-fewerswitch (no value)Use a modifier only when the essential functions do not fit (default).
--use-all-modifiersswitch (no value)Use the whole modifier budget.
--realismswitch (no value)0 = group by function, 1 = like the real aircraft's HOTAS (cockpit database or knowledge map); 0..1 or 0..100 %.
--seedswitch (no value)The seed of the plan's local search (default 1): the same seed gives the same plan.
--replace-existingswitch (no value)Lay out your bound relations again; without it they keep their binds.
--phase-layerson off autoTwo combat phases on a latched mode switch: on, off or auto (default: when the inputs are too few for one phase).
--role<device|VID:PID>The role of a device (device or VID:PID = role), as for setup devices.
--grip<device>The grip on a base (device = grip id), as for setup devices.
--add-device<catalog id>A catalog device to plan with although it is not connected.
--cockpit-file<json>A cockpit entry (JSON, e.g. from engine cockpits get --json) used besides DB/Cockpits; repeatable.
--out-plan<plan.json>Save the plan (JSON) here for setup check, apply and render; --plan-file is another name.
--plan-file<plan.json>Another name for --out-plan.
Every value as a command line
engine setup plan --phase-layers on
engine setup plan --phase-layers off
engine setup plan --phase-layers auto

Used by the GUI Setup wizard: Make the plan again · Setup wizard: NextCommand

Example

engine setup plan --games DCS --priorities 'F-16C_50>FA-18C_hornet' --modifiers 1 --realism 0.5 --out-plan 'C:\JoyPro\setup-plan.json' --text

#engine setup check

written
engine setup check --plan <plan.json> [--modifiers N]

The rules every plan keeps: conflicts, modifiers, trigger/pinky, MFD OSB order, panel labels, slew vs TMS, CMS, one device per hand, phase layers; exit code 1 when a rule fails

For beginners

Checks a saved Setup wizard plan against the rules every plan keeps: no input does two things in one aircraft, few modifiers, trigger and pinky only for their own functions, MFD keys in order, slew not on the TMS hat, and more. It changes nothing.

engine setup check --plan "C:\Users\Pilot\Documents\JoyPro\plan.json" --text
Advanced
  • --plan <file> (needed): a plan of engine setup plan --out-plan.
  • --modifiers N (default 2): how many shift modifiers are allowed; a plan that asked for more allows its own number.
  • The rules, C1 to C11: no input serves two relations of one aircraft (also across phase layers); at most the allowed modifiers and two phase layers; trigger, weapon release and pinky only take their own functions; MFD keys only MFD functions, in OSB order; printed panel labels only the functions they name; slew on slew controls and TMS on its hat; CMS forward dispenses and left / right change the program; one device per hand; phase layers only functions of their phase; modifier layers only for games that handle them; directional sets together on one hat.
  • Also measured: relations placed and not placed, essential functions of the top aircraft placed, time-critical functions on the grips.
  • Read-only.
Technical internals
  • Output: JSON (Checks with Id, Title, Passed, Problems, the counts, Passed), or --text (Checks: all passed or <n> failed, PASS / FAIL per rule with up to 8 problems, a Placed: line).
  • Exit code 0 when every rule passes, 1 when a rule fails (the report is printed first), or with setup check needs --plan <plan.json> (from engine setup plan --out-plan)., The plan could not be read: ... or Unknown setup check argument(s): ...; a non-number for --modifiers ends with engine error: Invalid value for option --modifiers ... (no crash report).
  • Reference: setup-wizard. Related: engine setup apply, engine setup render.

What it does Checks a saved plan against the rules every plan keeps (conflicts, modifiers, trigger/pinky, MFD OSB order, panel labels, slew vs TMS, CMS, one device per hand, phase layers); exit code 1 when a rule fails.

OptionValuesMeaning
--plan<plan.json>
--modifiersswitch (no value)

Example

engine setup check --plan <plan.json> --text

#engine setup apply

written
engine setup apply --plan <plan.json> [--dry-run] [--force]

Writes the plan's relations, binds and modifiers in one step

For beginners

Writes a plan of the Setup wizard into the profile in one step: it creates or extends the relations, sets their binds and adds the modifiers. The wizard's Apply to my profile runs it with the plan as you edited it in the review. In the game: the binds arrive with the next export.

engine setup apply --plan "C:\Users\Pilot\Documents\JoyPro\plan.json" --dry-run --profile "C:\Users\Pilot\Documents\JoyPro\My Sticks.pr0file" --text
Advanced
  • --plan <file> (needed): a plan file of engine setup plan --out-plan.
  • New relations get the group Setup. A command another relation got in the meantime stays there and is listed as skipped.
  • Refused when two relations with an aircraft in common share an input, unless --force.
  • --dry-run counts without changing the profile.
  • One profile version "Setup wizard: N relations, M binds" (Undo takes all of it back).
Technical internals
  • Output: JSON (DryRun, Created, Extended, NodesAdded, Bound, ModifiersAdded, Skipped, Problems), or --text. The profile is saved with --profile unless --dry-run.
  • Exit code 1 with setup apply needs --plan <plan.json> (from engine setup plan --out-plan)., The plan could not be read: ... or The plan puts functions of the same aircraft on one input: ... Fix them in the review (or apply with --force).
  • Related: engine setup check, engine setup render, engine profile history restore.

What it does Writes the plan's relations, binds and modifiers in one step.

OptionValuesMeaning
--plan<plan.json>
--dry-runswitch (no value)Report what the command would do; nothing is written or changed.
--forceswitch (no value)

Used by the GUI Setup wizard: Apply to my profile

Example

engine setup apply --plan <plan.json> --text

#engine setup render

written
engine setup render --plan <plan.json> --out-dir <folder> [--aircraft <name>] [--light] [--width <px>] [--drawing-style lines|cel] [--drawing-preset joypro|manual|blueprint|print|custom] [--drawing-ink <#RRGGBB>] [--drawing-paper <#RRGGBB>] [--drawing-accent <#RRGGBB>]

A callout sheet per device; --aircraft: only the binds of that aircraft, labelled with its function names; --width: picture width, default 1800; the --drawing-* options paint JoyPro's drawings of the devices, default: the GUI's settings

For beginners

Draws a callout sheet per device of a saved Setup wizard plan: the device picture with every planned bind labelled. With --aircraft only that aircraft's binds, labelled with its own function names. The wizard's review draws its sheets with it.

engine setup render --plan "C:\Users\Pilot\Documents\JoyPro\plan.json" --out-dir "C:\Users\Pilot\Documents\JoyPro\sheets" --aircraft F-16C_50 --text
Advanced
  • --plan <file> and --out-dir <folder> are needed; the folder is created, and files of the same name are overwritten.
  • --aircraft <name>: only binds that cover that aircraft. --width <px>: picture width (default 1800, at most 6000; the wizard uses 1600). --light: light sheets instead of dark.
  • The drawing options of the device pictures work here too: --drawing-style lines|cel, --drawing-preset, --drawing-ink, --drawing-paper, --drawing-accent (colours as #RRGGBB); otherwise the drawing style of Settings.
  • Devices with a role that takes binds are drawn; a device that is not in the device catalog gets no sheet and a warning. With several modifiers each label names its modifier.
  • The profile is not touched.
Technical internals
  • Files: <out-dir>\<nn>-<device>.png, or <nn>-<device>-<aircraft>.png with --aircraft.
  • Output: JSON (Sheets with Device and File, Warnings), or --text (Setup Sheets: <n> with <device> => <file> lines and Warning: lines).
  • Exit code 1 with setup render needs --plan <plan.json> and --out-dir <folder>., The plan could not be read: ..., Unknown setup render argument(s): ...; a non-number for --width ends with engine error: Invalid value for option --width ... (no crash report). A sheet that cannot be drawn is a warning, not an error.
  • Reference: setup-wizard. Related: engine layout render, engine setup check.

What it does Draws a callout sheet per device of a saved plan into --out-dir; with --aircraft only the binds that cover that aircraft, labelled with its function names. The --drawing-* options paint JoyPro's drawings of the devices (default: the GUI's settings).

OptionValuesMeaning
--plan<plan.json>
--out-dir<folder>
--aircraft<name>Only the binds that cover this aircraft, labelled with its function names (default: every bind with the relation names).
--lightswitch (no value)
--width<px>Width of each sheet in pixels (default 1800).
--drawing-stylelines celJoyPro's drawings of the devices: lines (line art) or cel (shaded). Default: the GUI's setting.
--drawing-presetjoypro manual blueprint print customThe colours of JoyPro's drawings: joypro, manual, blueprint, print or custom (then --drawing-ink / --drawing-paper / --drawing-accent). Default: the GUI's setting.
--drawing-ink<#RRGGBB>Line colour of JoyPro's drawings (#RRGGBB, preset custom).
--drawing-paper<#RRGGBB>Paper colour of JoyPro's drawings (#RRGGBB, preset custom).
--drawing-accent<#RRGGBB>Accent colour of JoyPro's drawings (#RRGGBB, preset custom).
Every value as a command line
engine setup render --drawing-style lines
engine setup render --drawing-style cel
engine setup render --drawing-preset joypro
engine setup render --drawing-preset manual
engine setup render --drawing-preset blueprint
engine setup render --drawing-preset print
engine setup render --drawing-preset custom

Example

engine setup render --plan 'C:\JoyPro\setup-plan.json' --out-dir 'C:\JoyPro\sheets' --aircraft F-16C_50 --text
