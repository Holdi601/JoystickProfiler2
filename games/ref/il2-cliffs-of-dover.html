Partly verified (2026-10-12). Both games are installed on a test PC. Checked: Blitz 5.050 starts to its main menu without any prompt and on its first start creates Documents\1C SoftClub\il-2 sturmovik cliffs of dover with copies of the install's conf.ini, confs.ini and confUser.ini (GAME); the install's default confUser.ini of both games (file shape of the fixtures); Blitz's device naming, seen in its installed binaries (CODE, see Devices). Not yet checked in the game: binds made on Blitz's controls page and the game's rewrite of an export (tools/e2e/games/IL2CoDBlitz.ps1 is written but has not run: Windows' foreground lock blocked all input that night). The original game (63950) does not start on a test PC: Launcher.exe exits after about 4 s with code 0, no window, no log, no user folder, also when started directly; its integration is checked against the install's default file and a user's own Steam Cloud file from 2015 only.

Evidence tags: [GAME] seen on the installed games; [CODE] seen in Blitz's installed binaries, looked at for interoperability only, nothing modified or copied; [FILE] complete confUser.ini files posted by players (Steam discussions of both apps, the ControllerBuddy profile for Blitz) and the user's own Steam Cloud copy of the original's file; [DOC] Team Fusion patch notes and the TF Beginner's Guide, [FORUM] forum statements (Team Fusion developers, ATAG), [INF] inferred.

CLI: engine il2codblitz ... (aliases codblitz, blitz, game id IL2CoDBlitz) and engine il2cod ... (aliases cod, cliffsofdover, game id IL2CoD) with paths|catalog|scan|import|export|refresh-db.

#Bind lines

Sections JoyPro manages: [HotKey pilotMove] (axes), pilot, common, turret, view, viewSet, viewPan, viewSnap, timeSpeed, orders, BOB, vehicle (FILE). Line: <trigger> [<trigger> ...]=<command> — all triggers held together, the last one fires, so the others become JoyPro modifiers (keys or joystick buttons) (FILE).

Input Line key Example (FILE)
Button <device>+Key<b> (b 0-based; 128 buttons since patch 5.025) vJoy_Device-5A479A63+Key0=trigger1
Axis `+AXE_<X Y
Hat Pov<angle> <device>+Pov (the first hat) Pov90 Controller_(XBOX_One_For_Windows)-5AD3D7F+Pov=cste_lights
Key `[Control Shift
Chord several triggers Joystick+Key12 Joystick+Key18=autorudder_off

Lines without a device (Pov0=PanUp) are defaults the game could not resolve; JoyPro leaves them alone.

#Devices

  • Blitz (4.5+): <product name>-<id> (FILE: T.Flight_Hotas_4-AA417BA7, _VKB-Sim_Gladiator_-ABD81779, Controller_(XBOX_One_For_Windows)-5AD3D7F). Seen in Blitz's installed binaries (CODE, 2026-10-12): the name is DirectInput's tszProductName with every blank and + as _ (leading/trailing blanks kept); the id is not part of the instance GUID but a hash of the device's interface path (IDirectInputDevice8::GetProperty(DIPROP_GUIDANDPATH), e.g. \\?\hid#vid_1234&pid_bead#..., converted to ANSI): h = ((h << 8) | byte) ^ T[h >> 24] over the bytes, T = the MSB-first CRC table of polynomial 0x23788D5E with every entry masked to 31 bits, printed %X (no zero padding). That is why the id changes with the USB port (FORUM, TF developer). JoyPro computes the same id from the path (engine games devices shows the path), matches a file name to a connected device by name and id, else by name alone when only one connected device has that name (the device on another port), and an export writes the current id (a line with an older id of the device is renamed, with a warning).
  • Original game / TF 4.x: Joystick (first game controller), Joystick1, Joystick2 ... in DirectInput order (FILE). engine il2cod writes this form.
  • Several devices at once: up to 16 since Blitz 5.026, 8 before (DOC) — not a one-device game (MaxJoysticks 16 / 8).

#Axis settings ([Config pilotMove], model il2cod)

Per command, not per device axis (FILE): aileron=0.15 0.12 0.02, rudder=1 0.25 0, throttle=0 1 0 0 0, pitch=0 0. Three values on aileron / elevator / rudder: sensitivity (0 linear .. 1 most curved), dead zone at the centre, dead zone at the ends; two values on the other axes: dead zone at the low and the high end; five on the throttles (meaning unknown; JoyPro keeps them as imported) (FORUM explanation of the sliders, INF for the order). Import stores them as game:IL2CoDBlitz / game:IL2CoD tuning; export writes the line of each exported axis command in the line's own format, keeps the game's digits when the value did not change (0.997872340425532), and in merge mode keeps values set in the game when JoyPro's are all zero. The base fit maps dead zone → centre (sliders: low end), 1 − saturation X → end, a positive curvature → sensitivity. The preview's formula (linear-to-cubic blend) is an assumption.

#Catalog

engine il2codblitz|il2cod refresh-db [<confUser.ini or folder>]: JoyPro's own command list (the ids the files use, JoyPro's titles; pilotMove.aileron, pilot.trigger0 ...) plus every command of the user's file and the install's default confUser.ini. Mission builder sections are not taken.

#Export rules

Flight game (also vehicles, but JoyPro manages the listed sections only): clean takes over the connected devices it writes, nuke clears the other connected devices; a device that is not connected, a line the import cannot read, the mouse, keyboard lines and the vehicle section (ground vehicles, not flight) are never cleared. Add never removes and does not write a bind on an input the game uses for another command (listed as a skipped multi bind); merge removes the game's bind on an input the profile gives another command and keeps the rest; merge-overwrite also takes the other inputs of every command the profile binds away (keyboard only with --include-keyboard). Backup before the first write; JoyPro's inputs are remembered in confUser.ini.joypro.json.
