IL-2 Sturmovik: 1946

The game page in plain words: IL-2 Sturmovik: 1946. Full matrix: Game support. What an export does in this kind of game: Export flow, in the game.

From docs/games/il2-1946.md in the repository (generated, always the current text).

Verified in the game (Steam 15320, version 4.13.4m, 2026-10-12): binds made on the Controls page with vJoy (button, hat, axis), the axis response set on the Input page, JoyPro's export shown on both pages, the game's rewrite and JoyPro's import of it (tools/e2e/games/IL21946.ps1, see "In-game test" below). Tag [GAME] = seen in the game.

Evidence tags: [GAME] checked in the installed game; [FILE] real files published by players (GitHub dotfiles of 4.12.2m/HSFX, ControllerBuddy's configuration script, a Steam install copy, forum posts); [CODE] the game's input classes as modders publish them with their patch sources on GitHub (UP3 / Engine Mod; read for the file format only, nothing copied); [INF] inferred.

CLI: engine il21946 paths|catalog|scan|import|export|refresh-db (aliases il2-1946, 1946), game id IL21946.

#Files

What Where Tag
Install Steam steamapps\common\IL 2 Sturmovik 1946, il2fb.exe GAME
Binds of a pilot <install>\Users\<pilot>\settings.ini (folder Users; the shipped pilot "John 'Mad' Doe" = Users\doe, its settings.ini installed as a copy of default.ini) GAME
Current pilot <install>\Users\all.ini: [list] lines <folder> <name> <callsign> <surname>, [current] the 0-based index GAME
Template for new pilots <install>\Users\default.ini (same sections; blanks around =, indented lines) GAME
Axis response, game settings <install>\conf.ini [rts], [rts_joystick] / [rts_joystick<k>] GAME

engine il21946 paths lists the current pilot's settings.ini first, then the other pilots'. The game rewrites the whole settings.ini when Apply is clicked on the Controls page (its own format: blank lines first, no blanks around =, its section order) and conf.ini on exit (GAME): export only while il2fb.exe is closed (JoyPro refuses while it runs). Both files are plain ini; JoyPro edits lines in place and keeps every other byte (single-byte text kept as is). Steam Auto-Cloud syncs the Users folder (Users\steam_autocloud.vdf, userdata\<id>\15320) when the game exits (GAME); a file changed while the game is closed is uploaded at the next start.

#Bind lines (settings.ini)

Sections [HotKey <env>]: move (axes), pilot, gunner, misc, aircraftView, SnapView, PanView, HeadMove, orders, timeCompression (CODE UserCfg.nameHotKeyEnvs, FILE). Line: <trigger>[ <trigger>]=<command>, at most two triggers; the game reads them in either order and keeps the order a line has (its default axes JoystickDevice0 AXE_U=-power), a bind made on its Controls page is written input first (GAME: AXE_Z JoystickDevice3=-power4, Joystick6 JoystickDevice3=Gear, Pov90 JoystickPov13=cockpitUp); JoyPro writes new lines the same way. One input per section line; a command may have several inputs (the Controls page keeps one axis per axis command and two inputs per other command).

Input Line key Example (GAME)
Axis `AXE_<X Y
Inverted axis - before the command AXE_Z JoystickDevice3=-power4
Button Joystick<b> JoystickDevice<d> (b 0-based, up to 127) Joystick6 JoystickDevice3=Gear
Hat Pov<angle> JoystickPov<d*4+h> (angle 0, 45 .. 315; four hats per device) Pov90 JoystickPov13=cockpitUp
Key [<modifier> ]<key>; modifiers Ctrl, Shift, Alt or any key Ctrl T=AIRCRAFT_DROP_TANKS, Shift 4=Step90

JoyPro maps U/V to JOY_SLIDER1/2, hats to JOY_BTN_POV<h+1>_<dir>, buttons to JOY_BTN<b+1>. Key names follow the game's table; every name in the game-written file of an English install is in JoyPro's table (GAME: Equals, Underscore, OpenBracket, CloseBracket, Quote, BackQuote, Backspace, Comma, Period, Slash, NumPad-0..NumPad-9, NumPad+, NumPad-, PageDown, Delete, End, Pause, Up/Down/Left/Right, Ctrl, Shift, Alt). No joystick chords: a key held while a joystick button is pressed is ignored when binding (GAME), so JoyPro skips joystick binds with modifiers with a warning. Mouse inputs (MouseAXE_X, MouseLeft) are not JoyPro inputs and stay as they are.

The Controls page (Main Menu > Controls) shows a joystick input as JoyButton 7 ID4 (button 7 of JoystickDevice3: ID = device + 1, no ID for device 0), Hat Switch -135 ID14 (ID = device × 4 + hat; angles 0, 45, 90, 135, 180, -135, -90, -45), axes at the end of the list as U Slider axis ID4, Z-Axis Rotation, -Z-Axis ID4 (a - when the axis was moved down while binding = an inverted command) (GAME).

#Devices

Identified by index only: JoystickDevice<d> = the d-th game controller in DirectInput order (GAME: vJoy, the fourth device of engine games devices, is JoystickDevice3); the name is never stored. JoyPro maps it to the connected device with that enumeration index. The index can change when devices are plugged in another order (FILE: forum reports) — re-export then. Steam's 4.13.4m reads 4 devices (GAME: conf.ini gets response lines for JoystickDevice0..3 only, with 12 game controllers connected), 8 axes and 128 buttons each; several devices work at the same time, so this is not a one-device game (MaxJoysticks = 4 on the integration; a device at index 4 or later is refused on export). Lines of a device that is not connected are kept.

#Axis response (conf.ini, model il21946)

[rts] JoyProfile=k selects the section: [rts_joystick] (k = 0) or [rts_joystick<k>]. Key per device axis: 1<axis>[<device>] (1X = device 0, 1U3 = device 3; the shipped conf.ini has only the old keys without the leading 1 and 11/12 values, the game adds the 1 keys for every axis of devices 0..3 on its first exit and keeps the old ones). Value: 13 integers (CODE Joy.readConfig/saveConfig; GAME: dead band 7 and the third slider at 80 on the Input page gave 1U3=7 100 100 80 100 100 100 100 100 100 100 0 0):

# Meaning
0 dead band in raw units of the half travel (±1023), Input page 0..50; cut, not rescaled
1..10 curve points at 10 % .. 100 % stick, percent of the linear output (all 100 = linear; 0 10 20 .. 100 = quadratic)
11 filter (smoothing 0..100, the page shows /10)
12 one-sided axis: 0 centred, 1 one-sided, 2 one-sided reversed (set with a - command)

Import stores the values as the relation's game:IL21946 tuning (deadBand, c1..c10, filter, oneSided); export writes the line of each exported axis (one per device axis; a second command on the same axis gets a warning), keeps the other lines and, in merge mode, keeps a curve set in the game when JoyPro's is the plain default. A base (DCS) tuning is fitted: dead zone → dead band (≤ 50), the shape → ten points (capped at linear: curves above linear, e.g. a saturation below 1, cannot be expressed), sliders → one-sided. The preview follows the game's code.

The Input page (Controls > Input) edits these values per bound axis command (its list shows only commands with an axis), i.e. per device axis the command is on: ten curve sliders (value boxes below; one step per Down/Up key), Dead Band 0..50 (Home/Right keys after a click on the track), Filtering, Symmetrical; Back, then the file is written on exit (GAME).

#Export rules

Flight-only game: clean takes over the connected devices the export writes (all their lines in the managed sections), nuke clears the other connected devices; a device that is not connected, a line the import cannot read, the mouse and keyboard lines are never cleared. Add never removes and does not write a bind on an input the game uses for another command (listed as a skipped multi bind). Merge removes the game's bind on an input the profile gives another command and keeps the rest (a moved command keeps its old input too, as far as the game's two inputs per command allow); merge-overwrite also takes the other inputs of every command the profile binds away (keyboard only with --include-keyboard). JoyPro remembers the inputs it wrote (settings.ini.joypro.json). settings.ini and conf.ini are backed up before the first write.

#Catalog

engine il21946 refresh-db [<install folder or settings.ini>]: JoyPro's own command list (ids the game's files use, JoyPro's titles; move.aileron, pilot.Gear ...) plus every command the install's Users\default.ini, conf.ini and the pilots' settings.ini name (134 commands in JoyPro's own list; 188 actions after a refresh from Steam's install, 2026-10-12, the development list in EngineOnly_Runtime\DB\IL21946). Ids are <env>.<command>; move.* are axes. Controls page rows seen in the game: Gear Up/Down = pilot.Gear, Flaps Up = pilot.AIRCRAFT_FLAPS_NOTCH_UP, Toggle Gunsight = aircraftView.cockpitAim, Toggle Seat Position = aircraftView.cockpitUp, Mixture = move.mixture, Engine 4 Power = move.power4.

#In-game test

tools/e2e/games/IL21946.ps1 (RunAll name il21946), unattended: waits until the PC is idle and no other game runs, snapshots Users and conf.ini, runs the game windowed 1920x1080 without intro, binds a random vJoy button (Gear), hat (Toggle Seat Position) and axis (Mixture) on the Controls page and sets a random dead band and curve point on the Input page; checks the files and engine il21946 scan / import against that; imports, adds a random button, hat and axis with a response and exports (clean); starts the game again and reads every vJoy bind on the Controls page and both responses on the Input page; Apply / quit; imports the game's rewrite; restores the snapshots. Game quirks the script handles: the game draws its own arrow from relative mouse input (about 1 px per mickey) and takes input only after a click on its window; while it is not the active window it stops answering Windows (a title bar click activates it).

#Open points

  • Key names under a non-English game locale (the key table is a localisable resource).
  • Whether -cmd and one-sided 2 both reverse the axis (the preview reverses once).
