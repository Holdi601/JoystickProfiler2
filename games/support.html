Game support

From docs/games/support.md in the repository (generated, always the current text).

Last updated: 2026-11-01. How far JoyPro supports each game: 57 titles, 36 of them handled by JoyPro (every version separately), 21 only researched and documented. The marks come from the code (what each game integration implements); verification results, footnotes and the facts per title come from the hand-kept support-notes.json. In the app: Start page, Supported games next to Your games.

#Legend

  • ✓ supported; ◐ partial or experimental (see the numbered note); ✗ not supported; — not applicable (the game has no such thing, or JoyPro does not handle the title).
  • Support level: native = JoyPro reads and writes the game's own bind files for your real devices; virtual vJoy = the game reads too few joysticks, JoyPro feeds it one virtual joystick (vJoy, devices hidden with HidHide); virtual Xbox pad = the game reads no joystick, JoyPro feeds it a virtual Xbox 360 pad (ViGEmBus); documented only = researched, see the linked page, JoyPro has no integration.
  • Numbers: Setup wizard / Auto Assign = rows in JoyPro's function table of the game; Cockpits = cockpits of the game's aircraft in the cockpit database; In-game test = passed / total steps of the best run.
  • In-game test: ✓ a green in-game end-to-end run (JoyPro's test kit drives the real game); ◐ a run in game that was not fully green or covered only the menus; ✗ checked against installed game files only, or implemented blind from public files (the details say which).
  • Every export backs up the files first, refuses to write while the game runs and writes only cataloged actions; see README.md and ../export.md.
  • Anti-cheat: JoyPro reads no game memory and injects nothing; it writes config files (or registry values) while the game is closed. vJoy, ViGEmBus and HidHide are signed drivers that anti-cheat normally accepts, but a game may refuse virtual devices.
  • Import: reads the binds made in the game into a profile.
  • Export: writes binds into the game's files (modes clean, add, merge, merge-overwrite).
  • Keyboard: keyboard binds on request (--include-keyboard).
  • Modifiers: binds with modifier buttons.
  • List refresh: builds the command list on the user's PC from the installed game (refresh-db).
  • Watcher: config watcher: engine sync status / diff / apply.
  • Axis tuning: curves and dead zones written in the game's own response model.
  • Game settings: game-wide control settings (engine ffb set --device *).
  • In-game FFB: the game's own force feedback settings (DCS FF Tune, IL-2 feedback power ...).
  • Telemetry FFB: JoyPro's force feedback from the game's telemetry (JoyPro.Ffb).
  • Telemetry recording: records every session's telemetry, Tacview ACMI and CSV export (engine telemetry, docs/telemetry-recording.md).
  • vJoy mode: virtual joystick (engine vjoy mode virtual).
  • Xbox pad: virtual Xbox 360 pad (engine vjoy mode xbox).
  • Virtual functions: engine vjoy functions for the game.
  • Setup wizard / Auto Assign: JoyPro's function table for the game (DB\Functions<game>.tsv), used by Auto Assign and the setup wizard.
  • Cockpits: cockpits of the game's aircraft in JoyPro's cockpit database (DB\Cockpits).
  • Cheat sheet: layout pictures / cheat sheets per game and aircraft (engine layout render).
  • In-game test: JoyPro's in-game end-to-end test: result of the best run.

#Details per title

Bind file and command list: where JoyPro reads and writes on your PC and what it builds the game's command list from (list size measured on the development PC, see README.md). Device limits: what the game reads of your devices; the input limits with their confidence (verified = from the game's files or JoyPro's own code, documented = the game's docs, reported = players) warn in the virtual joystick planner (../virtual-joystick.md).

#Keeping this page true

  • powershell -ExecutionPolicy Bypass -File tools/game_support.ps1 writes this page; -CheckOnly fails when it is out of date (the engine smoke test runs it).
  • engine games support prints the same facts as JSON (--markdown, --html for the page; --notes <file> reads other notes than the ones built into engine.exe).
  • The check also fails when a registered game has no entry in the notes, a note names an unknown game or cell, or a note claims more than the code (notes may only turn ✓ into ◐, ✗ or —, each with a reason).
  • After an in-game test run: update test of the game in the notes (level, result, date), then run the tool.
