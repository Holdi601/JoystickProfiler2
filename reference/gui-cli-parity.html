GUI / CLI parity

From docs/gui-cli-parity.md in the repository (generated, always the current text).

Question: can everything the engine command line does also be done in the GUI, well and simply, by the least technical user imaginable?

Short answer: yes for everything a normal user needs. Every engine command a player uses has a button, picker or wizard in the GUI with plain words, safe defaults, a question before anything that removes binds or changes files, and a way back (backups, "Undo export", a copy of the profile before a merge, device removal or a start-over import). What is left on the command line only are developer tools (fake servers, test helpers, wiki generation) and expert listings that a player never needs. A raw "Advanced console" box exists but is not counted as GUI support anywhere in this table.

Checked against engine/docs/ENGINE_CLI_WIKI.md and the usage text of engine/Program.cs (engine at 7a2b84a), GUI after the novice pass (Start page game cards and import wizard, export in three steps, device cards, icons).

#How each command was judged

Rating Meaning
FULL Findable from a page or card, labelled in plain words, no typed paths, ids or JSON, safe default, feedback (status symbol or text), a question and backup/undo where something is removed. Was already so before this pass.
IMPROVED Was in the GUI but technical (typed paths/names, raw keywords, hidden, no confirmation or undo); fixed in this pass. Now FULL.
EXPERT In the GUI, in an "(for experts)" expander or the expert import form: works without typing commands, but uses technical words or typed paths. Only experts need it; the normal path is FULL elsewhere.
CLI-ONLY Not in the GUI (the Advanced console does not count). The reason is given.

Where the GUI parts live: the page navigation at the bottom (Start, Relations, Modifiers, Binds, Layout, Export, HUD, Force Feedback, Settings, Advanced), the profile bar at the top, and the confirmation dialog (ConfirmWindow).

#What the novice pass changed (summary)

  • Icons everywhere: gui/JoyPro.Gui/Styles/Icons.axaml is one shared icon set (Material-style path data, no downloaded images) with status colors; Styles/IconStyles.axaml gives icon buttons (Classes="icon", Tag="{StaticResource Icon.X}"), the icon navigation, status symbols (PathIcon.ok/.warn/.error/.info), cards and wizard step numbers. Other pages (watcher settings, Group by description, vJoy) can reuse them.
  • Start page: "Your games" cards with cover, installed / game-updated symbols and Import, Export, Update, Undo export; the import wizard; the old form is "Expert import".
  • Export page: three numbered steps, the export mode as described choices, tiles with status symbols, Preview and Undo last export.
  • Settings: device cards with product pictures, pickers instead of typed device names, plain DCS sections, expert listings in expanders.
  • Safety: a confirmation dialog before restore/undo, clean or nuke exports, device remove/exchange, profile merge, start-over import, DCS defaults and clearing all DCS FFB settings; profile copies before profile-changing merges, device changes and start-over imports.

#Open points

  • The offscreen render tests show layout, not exact colors (text and plain icons are drawn oddly offscreen); check the real window once on screen in light and dark mode.
  • Registry games with a DB source other than the game's own file still take a typed source path (expert form).
  • The Relations, Binds and Layout pages got icons on their titles only; their inner panels are unchanged (the Relations "Group by description / LLM" area belongs to parallel work).
  • Localization (release plan) is not part of this pass; all new texts are English and short.
