The Check: "Problems found by the check"

From docs/ui/check.md in the repository (generated, always the current text).

The Export page's Check (the bottom bar's "Check" goes there) lists what would go wrong in the game, in words a first-time PC user understands. Since 2.5.0 every card says what is wrong in game words (the aircraft, the buttons as "device · button", the commands as the game calls them), why it matters in the game, and what to click. No card shows an id, "node", "relation item key" or another internal word (one exception: the details of an unknown command name its game id for a support question).

Code: gui/JoyPro.Gui/Views/Controls/CheckProblemsPanel.axaml, ViewModels/MainWindowViewModel.CheckCards.cs (the cards), MainWindowViewModel.Duplicates.cs (sections, search, order, fixes for many), Models/CheckIssueModels.cs. Engine: relations duplicates and relations conflicts (CLI wiki, relation builder).

#Sections

Errors first (red, with their own icon), then warnings (amber), then notes:

Section Kind What it is
One button does two things error an input is bound in two relations that both have a command of the same aircraft on: one press runs both
One button runs two commands error one relation has two commands of the same aircraft (or game) on
Other errors error the rest of the check's errors (a modifier button that is also a normal button, ...)
Same command on two buttons warning one command of an aircraft is on in two relations: the game gets it on two buttons
Copied relations warning an import made copies of a relation on the same button
Not written to the game warning "Only add" left a bind out: the game already uses the button for something else; or the game has no free place for another input of the command (Elite: Primary and Secondary in use)
Notes note harmless, worth a look

The counts at the top count cards ("To look at: 9 errors, 167 warnings, 0 notes"). The search finds cards by relation, aircraft, button and command; the kind filter shows one kind; the order ("By relation", "By aircraft", "By game", "By confidence") also groups the cards under a header (the relation, the aircraft) where a group has several cards. "Ignored warnings (n)" next to them (only while there are some) opens the list of the warnings you ignored (see Ignored warnings).

#Ignored warnings

"Ignore" (2.6.1; "Keep both" before, which was the wrong word for three or more buttons) is on every card of "Same command on two buttons", "One button does two things" and "One button runs two commands". The binds stay as they are; the card goes away and JoyPro remembers it in the profile (KeptDuplicates, one undo step). It stays hidden while the same buttons (relations, commands) or fewer of them have it. When the command lands on one more button (one more relation on the button, one more command in the relation) the card comes back on its own, marked New and with a line "Shown again: now also on MOZA AB9 FFB Base · BTN 3 ('Trim Nose Down')" ("...now also runs 'Gear Up'" for the errors), so you can work through the warnings once and only see what is new afterwards. Ignoring it again hides it with the new set.

"Ignored warnings (n)" (only while there are some) opens the list of the hidden ones in the cards' words: the title, the buttons with their relations, the sentence (aircraft and command), the table where a card has several commands. Each has Show again (the card comes back, one undo step); Show all again brings every ignored warning back (one undo step). The Check's search filters the list too, and finds the list itself by what people call it ("ignore list", "hidden warnings", "dismissed", "muted", "keep both"): it opens.

Old entries clean up after themselves: when a fix of the check runs, an ignored warning whose command is on one button only now (the button runs one command) is forgotten, so it comes back as a new warning if it ever happens again. The check itself never changes the profile. Engine: relations duplicates --ignore | --list-kept | --forget-kept [--keys], relations conflicts --ignore | --list-kept | --forget-kept [--keys] (ShownAgain, NowAlsoIn, engine/EngineIgnoredWarnings.cs).
