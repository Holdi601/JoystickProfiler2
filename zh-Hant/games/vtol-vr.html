VTOL VR

顯示：

VTOL VR 是一款只能用 VR 玩的空戰飛行遊戲：您用 VR 控制器操作虛擬的搖桿和油門來飛行。遊戲本身只綁定實體裝置的三個軸：方向舵和兩個腳尖煞車，並把它們存在一個所有飛機共用的檔案中。完整的 HOTAS 支援（搖桿、油門、每個開關，依飛機和座位區分）來自免費的 BYOJoystick 模組。JoyPro 把兩者當成兩款遊戲處理：VTOL VR (BYOJoystick mod) 寫入模組的綁定檔，VTOL VR (native rudder and brakes) 寫入遊戲自己的檔案及其控制設定。

給新手

#3 個步驟就能用

  1. 全部幫我設定好
    在「開始」頁面
  2. 使用這些按鈕
    先查看清單
  3. 寫入我的遊戲
    保持 VTOL VR 關閉

之前：按 VTOL VR 卡片上的 安裝 BYOJoystick（只需一次，見下文）。在連接腳舵的情況下啟動 VTOL VR 一次，並按 OK 離開 Settings。

之後：在遊戲設定中開啟 Hardware Control Rudder，否則遊戲會忽略您的方向舵。

您之前在 VTOL VR 中綁定過按鈕嗎？那麼開始頁面會提供 匯入，然後填補空缺。您的綁定會保留，只有空著的按鈕會被指派新功能。請參閱快速入門：讓我的搖桿能用。

#JoyPro 能為 VTOL VR 做什麼

  • 使用 BYOJoystick：模組為每個載具和座位提供的所有目標（搖桿和油門軸、起落架、襟翼、武器、反制措施、雷達、燈光、MFD 按鈕等），都可以由您的搖桿、油門和鍵盤操作。
  • 不使用模組：遊戲自己的 Rudder、Wheel Brake L 和 Wheel Brake R，以及其 Controls 選單中的設定（Hardware Control Rudder、VR 死區、觸覺回饋）。
  • 關聯：一個關聯就是一個功能；BYOJoystick 匯出時會把它寫入每個其載具擁有該目標的座位檔案。

#安裝 BYOJoystick（只需一次）

  1. 開啟 開始，按 VTOL VR 卡片上的 安裝 BYOJoystick。面板會顯示這個模組是什麼、它的官方來源（Steam 工作坊、GitHub 上的原始碼）、大小，以及這台電腦上是否已有 VTOL VR Mod Loader 和該模組。
  2. 勾選方塊，表示您已閱讀 BYOJoystick 的說明並想從 Steam 工作坊安裝它，然後按 安裝 BYOJoystick。JoyPro 會備份您的 BYOJ 檔案並開啟 Steam：如果 Steam 要求，請安裝 Mod Loader，然後在 BYO Joystick 頁面按 Subscribe。Steam 會下載模組；JoyPro 不會複製其中任何內容。
  3. 按 重新檢查：JoyPro 會找到模組，並從中建立 VTOL VR 的指令清單。

#匯入您的綁定

按 VTOL VR 卡片（BYOJoystick）或原生部分卡片上的 匯入，再按 立即匯入。對於 BYOJoystick，同時取得鍵盤按鍵 會一併帶入您的鍵盤綁定。

#建立並檢查關聯

和其他遊戲一樣建立關聯（關聯流程）；設定精靈和自動指派都認得 BYOJoystick 的目標。接著在匯出頁面執行檢查。

#匯出到 VTOL VR

  1. 關閉 VTOL VR。 遊戲執行時（處理程序 VTOLVR）JoyPro 會拒絕寫入。
  2. 開啟 匯出，如果您是在 JoyPro 中設定裝置，請保持 取代我的裝置上的綁定 並搭配 同時清除我的其他裝置。
  3. 按 VTOL VR 卡片（BYOJoystick）上的 立即匯出，腳舵則按原生卡片上的。
在遊戲中: 您在 VTOL VR 中會看到什麼

在遊戲中，當您的設定檔設定了 Hardware Control Rudder 時，Settings 會顯示它已開啟，而 Bindings 會列出 Rudder、Wheel Brake L 和 Wheel Brake R，以及您的裝置和它的軸。BYOJoystick 的綁定位於模組自己的視窗中，依載具座位區分；它的 Load 會重新讀取檔案。

#您需要在 VTOL VR 中自己做的事

  • 在連接腳舵的情況下啟動 VTOL VR 一次，並按 OK 離開 Settings。遊戲接著會列出您的裝置並建立 gameSettings.cfg；原生匯出只會寫入遊戲已列出的裝置，而且絕不會建立這個設定檔案。
  • Hardware Control Rudder 必須開啟，否則遊戲會忽略方向舵和煞車軸。請在遊戲中開啟它，或將它存在 JoyPro 中（進階），讓原生匯出寫入它。
  • BYOJoystick 需要 Steam 上的 VTOL VR Mod Loader；JoyPro 只會開啟 Steam 頁面。

#常見問題

  • 方向舵沒有作用：Hardware Control Rudder 沒有開啟。遊戲會在載具生成時讀取這項設定。
  • 只有一個腳尖煞車有作用，或兩個都跟著油門扳機動：只有在 Wheel Brake L 已綁定時，遊戲才會從您的腳舵取得煞車。請兩個都綁定。
  • 腳尖煞車只在後半段行程才煞車：遊戲把煞車讀成 0 到 1。請把該關聯的軸範圍設為 正向（進階）；JoyPro 會針對這種情況發出警告。
  • 兩組相同的腳舵：遊戲每個裝置型號只保留一個對應表，所以兩者會控制同一個動作。
  • 某個 BYOJoystick 綁定消失了：模組載入檔案時，會捨棄載具沒有的目標。
進階

#JoyPro 讀取和寫入的檔案

檔案 這是什麼
<install>\SaveData\BYOJ_<seat>.xml 一個載具座位的 BYOJoystick 綁定：AV42C、FA26B、F45A、AH94Front、AH94Rear、T55Front、T55Rear、EF24GFront、EF24GRear
%APPDATA%\Boundless Dynamics, LLC\VTOLVR\SaveData\inputbindings.cfg 遊戲本身的綁定：文字檔中的 Rewired joystick 對應表；由 Steam Cloud 同步
%APPDATA%\Boundless Dynamics, LLC\VTOLVR\SaveData\gameSettings.cfg Settings > Controls 的值（HARDWARE_RUDDER 等）；由 Steam Cloud 同步
<library>\steamapps\workshop\content\3018410\3276352374\BYOJoystick.dll 已安裝的模組：唯讀，用來取得它的目標清單
<install>\VTOLVR_Data\level0 遊戲的 Rewired 動作清單：唯讀，用於原生指令清單

舊版檔案 <install>\SaveData\inputbindings.cfg 從不寫入。每次寫入前都會先備份，並以不可分割的方式完成（先寫暫存檔再取代）：遊戲會把損壞的 inputbindings.cfg 換成空檔案。

#VTOL VR 的匯出模式

模式 BYOJoystick（每個座位一個檔案） 原生（inputbindings.cfg）
僅新增 不覆蓋座位既有的綁定：如果某個綁定所在的輸入已被另一個目標使用（修飾鍵狀態相同），會列為未寫入。 只使用空閒的軸；已被佔用的軸會列為未寫入。
更新，保留遊戲的綁定 原本在您輸入上的另一個目標會失去它；其他一切保留，包括已搬移目標的舊輸入。 您的軸上原有的動作會被取代；其他一切保留。
更新，以我的設定檔為準 同上，而且您的目標會在已連接裝置上失去其他輸入（按鍵只在開啟鍵盤選項時）。 同上，而且您的動作會在已連接裝置上失去其他軸。
取代我的裝置上的綁定 JoyPro 寫入的裝置只保留您的綁定。 已寫入裝置的其他動作會被清除。
+ 同時清除我的其他裝置 沒有綁定的已連接裝置會被清除。 沒有綁定的已連接裝置會被清除。

#永遠不會變更的內容

  • 未連接的裝置、匯入時忽略的裝置，以及 JoyPro 轉送輸入的 vJoy 裝置。
  • BYOJoystick：JoyPro 無法讀取的輸入，以及座位的修飾鍵按鈕（除非您的設定檔自帶一個）。
  • 原生：按鈕對應表、鍵盤和滑鼠的對應表、輸入行為、校正對應表、控制器指派，以及 System 玩家。BYOJoystick 匯出不會寫入 gameSettings.cfg。
  • 鍵盤，除非您匯出鍵盤綁定（僅限 BYOJoystick）。

#座位、軸、設定

  • 細分程度：BYOJoystick 依載具座位區分（一個目標會寫入每個有該目標的座位）；原生部分是全域的。
  • BYOJoystick 軸：每個綁定有反向和模組唯一的一個 死區 數值。在 Joystick Pitch、Roll、Yaw 以及 Throttle、Power、Collective 上，它不是死區，而是在多人遊戲中 HOTAS 從另一位機組員手上接過控制所需的偏移量；在 SOI Slew X/Y 和 Articulate Tilt 上，它會截掉小的數值但不重新縮放；其他地方模組不使用它。沒有曲線。請參閱 axis-curves。
  • 原生軸：反向，以及腳煞車的軸範圍（Full 或 Positive）。死區和曲線無法寫入。
  • 修飾鍵：BYOJoystick 每個座位檔案支援一個修飾鍵按鈕（需要它的綁定只在按住時作用）；鍵盤綁定可以有一個修飾鍵。原生部分沒有修飾鍵。
  • 控制設定：設定 > 遊戲的力回饋設定，遊戲選 VTOL VR (control settings, VR haptics)：Hardware Control Rudder、Thumb Control Rudder、Twist Rudder Deadzone、Thumbstick Deadzone、Thumbstick Mode、Toggle Grip、Flight Control Haptics、Overall Haptics。原生匯出會把它們寫入 gameSettings.cfg，即使設定檔沒有原生綁定也一樣。
  • 力回饋：VTOL VR 沒有 joystick 力回饋；觸覺回饋來自 VR 控制器。
  • 監看程式：BYOJ 檔案，以及原生部分的 gameSettings.cfg（監看程式）。
技術細節

#VTOL VR 整合的內部運作

程式碼：engine\Games\VtolVrIntegration.cs（BYOJoystick）、VtolVrMod.cs（安裝狀態、目標清單）、ClrMetadata.cs、VtolVrNativeIntegration.cs、engine\AxisModels\VtolVr.cs（byoj、vtolnative）、engine\FfbModels\VtolVr.cs（控制設定）。

  • BYOJoystick 格式：.NET XML 序列化，根元素 <Bindings>，內含 <KeyboardBindings>（Target、Key、ModifierKey，使用 Unity KeyCode 名稱）和 <JoystickBindings>（Target、JoystickId、Input、RequiresModifier、Invert、Deadzone、POVDirection）。Input：X Y Z RX RY RZ、S1 S2、PoV1..PoV4、B1..B128。裝置以 DirectInput 執行個體 GUID（JoystickId）識別。
  • 原生格式：根為 RewiredSaveData、由 {key} = {value} 行組成的文字檔；joystick 對應表是 Rewired XML（在 UTF-8 檔案中宣告為 UTF-16）。動作：0 Rudder、5 Wheel Brake L、6 Wheel Brake R。對應表以裝置型號為鍵：hardwareIdentifier = WindowsRawInput + 去掉空格的 HID 產品字串 + 十進位 PID + 產品 GUID，Rewired 不認得的裝置 hardwareGuid 為零。元素是裝置的第 n 個軸。
  • 指令清單：engine vtolvr refresh-db 從已安裝的 BYOJoystick.dll 讀取目標，但不載入也不執行它（只讀取其中繼資料和字串常值），然後再讀取您自己的 BYOJ_*.xml；沒有安裝模組就沒有清單。engine vtolvr-native refresh-db 從 level0 讀取 Rewired 動作清單。
  • 指令：engine vtolvr mod（status、prepare --accept-license）、engine vtolvr scan、engine vtolvr import、engine vtolvr export、engine vtolvr-native scan、engine vtolvr-native import、engine vtolvr-native export，設定則用 engine ffb set --device * --game VTOLVR。

#已知限制

  • 尚未在遊戲中實際執行；BYOJoystick 是用替代的 DLL 測試的。模組能否在目前的遊戲版本中載入，尚未確認。
  • 原生：Rewired 不認得的裝置的軸順序以及確切的裝置識別碼，是從遊戲的程式碼得知的，還沒有從遊戲寫出的檔案中確認。
  • BYOJoystick：帽子開關的斜向、軸目標上的按鈕，以及按鈕目標上的軸，都會被略過並出現警告。
  • JoyPro 不附帶 BYOJoystick 的任何部分；只有安裝了模組，才會有它的指令清單。
  • 測試：engine\tests\smoke\vtolvr.ps1（匯入往返、自訂值、遊戲全域設定、只匯出設定）。
