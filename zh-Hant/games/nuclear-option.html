Nuclear Option

顯示：

Nuclear Option 是一款有噴射機、VTOL 和直升機的空戰飛行遊戲，所有飛機共用一組綁定。它的操控設定不是存在檔案中，而是在 Windows 登錄中：每個裝置一個 Rewired 搖桿對應表，由遊戲的 Control Mapper 寫入。JoyPro 會把這些對應表讀入您的設定檔，並把您的 Flight Controls 綁定寫回其中；攝影機、遊戲玩法和聊天的綁定會保持原樣。

給新手

#3 個步驟就能用

  1. 全部幫我設定好
    在「開始」頁面
  2. 使用這些按鈕
    先查看清單
  3. 寫入我的遊戲
    保持 Nuclear Option 關閉

事前準備：啟動 Nuclear Option 一次，然後關閉它。

接著：您的綁定會出現在 Settings > Controls > Open Control Bindings Menu 中您裝置的頁籤上。

您之前在 Nuclear Option 中綁定過按鈕嗎？那麼「開始」頁面會提供 匯入，然後填補空缺。您的綁定會保留，只有空閒的按鈕會被指派新功能。請參閱 快速入門：讓我的搖桿能用。

#JoyPro 為 Nuclear Option 做了什麼

  • 匯入：您已連接裝置的搖桿對應表會進入您的設定檔：軸及其反向設定、按鈕，以及軸上的按鈕（例如「Increase Throttle」）。
  • 關聯：一個關聯就是一個功能；Nuclear Option 沒有飛機清單，所以一個關聯適用於所有飛機。
  • 匯出：JoyPro 會直接編輯每個裝置的對應表，只修改它寫入的 Flight Controls 動作。遊戲沒有已儲存對應表的裝置，會取得一個包含您綁定的新對應表。

#匯入您的綁定

  1. 啟動 Nuclear Option 一次（讓它的登錄機碼存在），然後關閉它。
  2. 開啟 開始 頁面，在 Nuclear Option 卡片上按 匯入，然後按 立即匯入。

#建立並檢查關聯

和其他遊戲一樣建立關聯（關聯流程）；設定精靈和自動指派都認得這款遊戲的功能。然後在「匯出」頁面執行 檢查。

#匯出到 Nuclear Option

  1. 關閉 Nuclear Option。 遊戲執行期間 JoyPro 會拒絕寫入：遊戲會在綁定選單關閉時，以及拔除裝置時寫入它的對應表。
  2. 開啟 匯出，保留 取代我的裝置上的綁定 和 同時清除我的其他裝置，然後在 Nuclear Option 卡片上按 立即匯出。
在遊戲中: 您在 Nuclear Option 中會看到什麼

開啟 Settings > Controls > Open Control Bindings Menu。Control Mapper 每個裝置有一個頁籤：點選上方的您的裝置，就能在那裡看到您的 Flight Controls 綁定（使用遊戲的名稱，例如 Pitch、Roll、Yaw、Throttle）。攝影機、遊戲玩法和聊天的綁定不會改變。

#您在 Nuclear Option 中需要自己做的事

  • 在第一次匯入或匯出之前 啟動遊戲一次，讓它建立登錄機碼。
  • 遊戲操控設定中的 Use Throttle Axis Negative Region：若要使用全行程油門軸，請保持開啟。如果它是關閉的，而您的設定檔綁定了油門軸，JoyPro 會發出警告。
  • 帽子開關：目前請在遊戲中綁定帽子開關方向；JoyPro 還不會寫入它們。

#常見問題

  • 「Nuclear Option 正在執行」：關閉遊戲，然後重新匯出。
  • 裝置被略過：兩個已連接的同型號裝置（或同時顯示為遊戲控制器的鍵盤）在遊戲的對應表中無法區分；JoyPro 會略過它們並顯示警告。
  • 某個裝置保留了遊戲的預設綁定：遊戲沒有已儲存對應表的已連接裝置，會使用遊戲的預設對應表，而 JoyPro 無法讀取它；同時清除我的其他裝置 不會動到它。請在 JoyPro 中為它綁定一些東西，或在 Control Mapper 中清除一次它的頁籤。
  • 油門卡在中間：請檢查 Use Throttle Axis Negative Region（見上文）。
進階

#JoyPro 讀寫哪些內容

位置 這是什麼
HKCU\Software\Shockfront\NuclearOption 遊戲在登錄檔中的 Unity 設定；Rewired 的值是二進位資料（UTF-8 文字加一個零位元組），名稱以 _h<hash> 結尾
每個裝置一個值，名稱中含有 dataType=ControllerMap 和該裝置的 hardwareIdentifier 一個裝置的 joystick 對應表（Rewired XML），屬於玩家 Player0
相同名稱，但帶有 dataType=ControllerMap_KnownActionIds 對應表已知的動作 ID；JoyPro 會在建立新對應表時一併寫入
<install>\NuclearOption_Data\resources.assets 遊戲的 Rewired 動作清單：唯讀，用於指令清單
%LOCALAPPDATA%\JoyPro2\GameMetadata\HKCU_Software_Shockfront_NuclearOption.joypro-meta.json 已匯出綁定的 JoyPro 名稱、群組和調校，供下次匯入使用

第一次寫入前，JoyPro 會把 Player0 的控制器對應表值快照存入備份區；復原上次匯出 會把它們寫回，並移除 JoyPro 新增的對應表值。有些值的名稱超過 255 個字元，所以 JoyPro 使用登錄檔 API（Regedit 和 reg export 無法全部顯示）。

#Nuclear Option 的匯出模式

模式 您裝置的對應表會發生什麼事
僅新增 遊戲的內容完全不變；如果某個綁定的按鈕或軸已經控制另一個動作（或軸的另一個方向），該綁定就會被略過並列出。
更新，保留遊戲的綁定 如果您把某個輸入指派給另一個動作，原本在該輸入上的 Flight Controls 動作會失去它；該動作保留其他輸入。
更新，以我的設定檔為準 同上，而且您綁定的每個動作（或方向）都會在 JoyPro 能讀取的每個已連接裝置上失去其他輸入。
取代我的裝置上的綁定 已寫入裝置的其他所有 Flight Controls 動作都會被解除。
+ 同時清除我的其他裝置 已連接裝置的其他已存對應表中的 Flight Controls 動作會被解除。沒有已存對應表的裝置保留遊戲的預設對應表。

#永遠不會變更的內容

  • Flight Controls 以外的每個動作：攝影機、遊戲玩法、聊天、除錯和任務編輯器的綁定。
  • 鍵盤和滑鼠的對應表、校正對應表、輸入行為、控制器指派，以及每一項遊戲設定（圖形、ThrottleUseNegative 和其他控制選項）。
  • 未連接的裝置、同一型號的兩個以上裝置、匯入時忽略的裝置，以及 JoyPro 轉送輸入用的 vJoy 裝置。
  • 已編輯對應表中 JoyPro 所變更的元素對應以外的所有內容，包括模組動作的綁定。

#細分程度、曲線及其他

  • 細分程度：全域，所有飛機共用一組綁定（Throttle 動作同時也是直升機的總距桿）。
  • 軸曲線：不寫入。遊戲校正中的死區保持不變。
  • 鍵盤和修飾鍵：不寫入；遊戲的 joystick 綁定沒有修飾鍵。
  • 帽子開關：目前還不讀取也不寫入。滑桿會寫入，但附帶警告。
  • 力回饋、遙測：無。
  • 監看程式：監聽遊戲機碼的登錄檔變更通知；指紋只涵蓋 Player0 的控制器對應表（監看程式）。
  • HUD：HUD 透過遊戲的處理程序（NuclearOption）找到遊戲。
技術細節

#Nuclear Option 整合的內部運作

程式碼：engine\Games\NuclearOptionIntegration.cs（登錄檔存放、遊戲的特殊處理、目錄結構），建構在 engine\Games\RewiredMapIntegration.cs 之上（讀寫 Rewired joystick 對應表，與 Tiny Combat Arena 共用）。

  • 值名稱：Unity 會在每個機碼後面加上 _h<hash>（以 XOR 對 UTF-8 機碼計算的 djb2，十進位）。
  • 裝置：常見的 HOTAS 裝置都不在遊戲的 Rewired 已知清單中，因此它們的對應表帶有為零的 hardwareGuid，而 hardwareIdentifier = WindowsRawInput + 去掉空白的 HID 產品字串 + PID + VID（各四位十六進位數字，大寫）。duplicate 計算同一型號的裝置數；JoyPro 每個型號只處理一個。
  • 元素：軸 X、Y、Z、Rx、Ry、Rz = 0 到 5，滑桿為 6 和 7，按鈕 n = 31 + n。軸動作上的按鈕是 <Action>.Positive / .Negative（axisContribution 0 / 1）。遊戲的預設對應表把 Pitch、Roll、Yaw、Throttle 和 Brake 綁定在軸 0 到 4，另外還有十一個按鈕。
  • 寫入：只有受影響的 ActionElementMap 區塊會變更（按鈕在 <buttonMaps> 中，軸在 <axisMaps> 中）；新的對應表的 sourceMapId 為 -1，並帶有已知動作 ID 清單，所以遊戲不會再替它加上預設綁定。
  • 指令清單：engine nuclearoption refresh-db 以第一個動作（"Pitch"）在 resources.assets 中找到 Rewired InputManager，並寫入 DB\NuclearOption\actions.tsv（動作名稱、標題、類別、Rewired ID；軸動作另外會有各方向的列）。
  • 指令：engine nuclearoption paths、engine nuclearoption catalog、engine nuclearoption scan、engine nuclearoption import、engine nuclearoption export；復原用 engine backups restore。

#已知限制

  • 遊戲的 Rewired 能辨識的裝置（hardwareGuid 不為零，例如 T.16000M）不在處理範圍內。
  • 在已存的對應表中還沒看過帽子開關的元素 ID，因此會略過帽子開關；滑桿 ID 依照 Rewired 的通用定義。
  • 綁定已在遊戲選單中檢查過，但還沒在飛行中驗證；遊戲對 Pitch 所預期的軸方向正負也尚未確認。
  • 測試：engine\tests\smoke\nuclearoption.ps1（一個真實的 vJoy 對應表，加上攝影機和遊戲玩法綁定）；在遊戲中執行 tools\e2e\games\NuclearOptionSettings.ps1（隨機 vJoy 軸上的 Pitch、Roll 和 Yaw 會出現在 Control Mapper 的 vJoy 分頁中，而且在遊戲再次存檔後匯入時能讀回）。
