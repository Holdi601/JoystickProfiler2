Falcon BMS

顯示：

Falcon BMS 4.38 在它的啟動器中設定您的裝置：啟動器為每個裝置保存一個 XML 檔案，每次您按 Launch 時，都會根據這些檔案產生按鍵檔案和軸設定。JoyPro 寫入的正是這些啟動器裝置檔案，所以仍由啟動器負責：它會把 JoyPro 的綁定轉成 BMS 讀取的檔案，就像您自己在啟動器中設定的一樣。不支援 Falcon 4.0 和 Allied Force；請使用 Falcon BMS。

Falcon BMS 4.38.2 and newer (launcher 3.x): the launcher keeps your binds in User\Config\JSON, one file per device and aircraft (F-16 and F-15ABCD each have their own), and rebuilds the older XML and key files from them every time it closes or launches. JoyPro reads and writes these JSON files: a button goes into each aircraft whose key file has the command (an F-15 command only into the F-15), an axis into every aircraft of the device. Hat binds, the shifted layer and throttle detents are not written into the JSON files yet; the export lists them so you can set them in the launcher. Older BMS versions keep working with the XML files as below.

給新手

#3 個步驟就能用

  1. 全部幫我設定好
    在「開始」頁面
  2. 使用這些按鈕
    先查看清單
  3. 寫入我的遊戲
    保持 BMS 及其啟動器關閉

事前準備：關閉 BMS 及其啟動器。

接著：啟動啟動器並按 Launch。啟動器要到這時才會產生 BMS 讀取的檔案。

您之前在 Falcon BMS 中綁定過按鈕嗎？那麼「開始」頁面會提供 匯入，然後填補空缺。您的綁定會保留，只有空閒的按鈕會被指派新功能。請參閱 快速入門：讓我的搖桿能用。

#JoyPro 為 Falcon BMS 做了什麼

  • 匯入：您裝置的按鈕、帽子開關和軸會從啟動器的裝置檔案匯入，Shift 層會變成修飾鍵，並包含每個軸的反向、死區和飽和度級距。
  • 關聯：一個關聯就是您所有遊戲中的同一個功能（BMS、DCS 和 IL-2 中的「Gear」都在同一個按鈕上）。指令是 BMS - Full.key 中 BMS 的 callback。
  • 匯出：JoyPro 會寫入啟動器的裝置檔案。下次您按 Launch 時，啟動器會根據這些檔案產生按鍵檔案和軸設定。

#匯入您的 BMS 綁定

  1. 開啟 開始 頁面。Falcon BMS 卡片會顯示遊戲的圖片。如果卡片要求指令清單，請按 建立清單：JoyPro 會讀取已安裝的 BMS - Full.key 中的 callback。
  2. 在卡片上按 匯入，並選擇 加入我的設定檔（鍵盤按鍵保存在 BMS 的按鍵檔案中，所以這裡的鍵盤方塊不適用）。
  3. 按 立即匯入。查看我的關聯 會開啟匯入的內容。

#建立並檢查關聯

在 關聯 頁面上，關聯的 BMS callback 會和您其他遊戲中的同一功能並列。使用 關聯流程 將它們連結起來，然後在「匯出」頁面按 立即檢查（檢查功能）。

#匯出到 Falcon BMS

  1. 關閉 BMS 及其啟動器。 當 Falcon BMS.exe 或 FalconBMS_Alternative_Launcher.exe 正在執行時，JoyPro 會拒絕寫入。
  2. 開啟 匯出。Falcon BMS 卡片會顯示其中有多少關聯已綁定。
  3. 如果您是用 JoyPro 設定裝置，請保留 取代我的裝置上的綁定 和 同時清除我的其他裝置。然後在卡片上按 立即匯出。
在遊戲中: 您在 Falcon BMS 中會看到什麼

啟動啟動器並按 Launch：啟動器會根據 JoyPro 的裝置檔案產生按鍵檔案和軸設定。在模擬器中，Setup > Controllers > Advanced > Flight Control 會顯示您裝置上每個匯出的軸，以及 JoyPro 設定的死區和飽和度級距；您的按鈕和帽子開關也會照設定檔的內容運作。

#您在 Falcon BMS 中需要自己做的事

  • 每次匯出後，在啟動器中按 Launch。啟動器要到這時才會寫入 BMS 讀取的按鍵檔案、axismapping.dat、joystick.cal 和 DeviceSorting.txt。
  • 不要勾選「Launch without any Setup override」，否則啟動器不會寫入您的設定。
  • 鍵盤按鍵 保存在 BMS 管理的按鍵檔案中；請在啟動器中設定。JoyPro 只寫入搖桿輸入。
  • Enable Force Feedback 會寫入您的飛行員檔案（<callsign>.pop，BMS 4.36 及之後版本的 468 位元組檔案）。如果飛行員檔案大小不同，JoyPro 會略過這一項設定並顯示警告。

#常見問題

  • 「Falcon BMS 正在執行」：關閉模擬器和啟動器，然後重新匯出。
  • 缺少一個修飾鍵綁定：BMS 所有裝置共用一個 Shift 層，由綁定了 SimHotasPinkyShift 的按鈕按住啟用。JoyPro 會把使用這個修飾鍵的綁定寫入 Shift 欄位；其他修飾鍵則會被略過並顯示警告。
  • 在「僅新增」模式下，某個軸仍留在另一個裝置上：BMS 每個功能只能給一個軸，而「僅新增」永遠不會移動它。請使用其中一種「更新」模式來移動它。
  • 模擬器中的綁定沒有變更：匯出後沒有用 Launch 啟動啟動器。
進階

#JoyPro 讀取和寫入的檔案

檔案 這是什麼
<BMS>\User\Config\JSON\DeviceBindings_<aircraft>_<device>.json 4.38.2 and newer: the launcher's file per device and aircraft (buttons, axes)
<BMS>\User\Config\Setup.v100.<device> {<GUID>}.xml before 4.38.2: the launcher's file per device: axes, hats, buttons, throttle detents
<BMS>\User\Config\Falcon BMS User.cfg 曲線值和遊戲設定，只寫在啟動器的標記行之上
<BMS>\User\Config\Feedback.ini 力回饋效果增益和回中彈簧
<BMS>\User\Config\<callsign>.pop 飛行員檔案：只有 Enable Force Feedback 位元組
<BMS>\User\Config\JoyPro.joypro.json JoyPro 寫入的輸入

<BMS> 透過 HKLM\SOFTWARE\WOW6432Node\Benchmark Sims\...\baseDir 或 Falcon BMS* 資料夾找到。axismapping.dat、joystick.cal、DeviceSorting.txt、按鍵檔，以及 User.cfg 中啟動器的區塊，每次按 Launch 都會重新產生；JoyPro 永遠不會寫入它們。沒有裝置檔的已連接裝置會得到一個：取自啟動器內建的該型號檔案，否則以啟動器的格式建立一個空檔案。

#Falcon BMS 的匯出模式

模式 BMS 中會發生什麼
僅新增 只寫入空閒的槽位；放在已有其他 callback 的槽位上的綁定不會寫入，並會列出。BMS 放在另一個軸上的功能會留在那裡（發出警告）。
更新，保留遊戲的綁定 取代您槽位上的 callback（衝突的那個），其他一切保留；軸功能會移到您的軸上。
更新，以我的設定檔為準 還會釋放已連接裝置上保存您所綁定動作的其他按下槽位、帽子開關和軸。
取代我的裝置上的綁定 釋放您寫入的已連接裝置上的其他所有內容（包括放開槽位中已編目的 callback）。
+ 同時清除我的其他裝置 匯出中沒有綁定的已連接裝置會被清除。

#永遠不會變更的內容

  • 未連接裝置的裝置檔（那裡較舊的軸宣告會保留；啟動器採用最新的）。
  • 匯入時忽略的裝置，以及 JoyPro 轉送輸入的 vJoy 裝置。
  • 鍵盤按鍵和按鍵檔、啟動器產生的檔案，以及 User.cfg 中啟動器的區塊。

#曲線、設定、力回饋

  • 細緻度：全域，所有飛機共用一套設定。
  • 軸（軸模型 bms）：反向、啟動器的死區級距（None、Small、Medium、Large）和飽和度級距，單向軸（油門、腳尖煞車、亮度、音量）沒有死區；俯仰、滾轉、偏航和游標 X/Y 在 User.cfg 中還有指數曲線（0 到 100）和指數飽和度（0 到 99）。預設曲線 會設定最接近的啟動器級距，但不設定指數。
  • 油門檔位：每個油門裝置的 AB 和 IDLE 檔位位置，寫在其裝置檔中。
  • 遊戲設定（設定 > 遊戲的力回饋設定）：回中彈簧、跑道震動、防抖動死帶、類比慢車切斷、在 AB 檔位的喀嚓感、虛擬方向舵、Depr-Ret 軸作為煞車。
  • 力回饋：Enable Force Feedback、機砲、彈跳、回中彈簧、投彈和失速增益，以及力回饋死帶。即使匯出時沒有 BMS 綁定，仍會寫入設定和檔位。
  • 遙測錄製：從 BMS 的共用記憶體唯讀讀取，含位置資訊（可產生 Tacview 航跡）。沒有遙測力回饋。
  • 監看程式：裝置檔、User.cfg、Feedback.ini 或飛行員檔案的變更會在 BMS 關閉後被偵測到（監看程式）。
技術細節

#BMS 整合的內部運作

程式碼：engine\Games\FalconBmsIntegration.cs、軸模型 bms、設定模型 FalconBMS；遙測 gui\JoyPro.Ffb.Core\Telemetry\Bms\BmsTelemetry.cs。

  • 裝置檔：根元素 <JoyAssgn>，含 <detentPosition>、8 個 <axis> 項目（X、Y、Z、Rx、Ry、Rz、Slider0、Slider1：<AxisName>、<AssgnDate>、<Invert>、<Deadzone>、<Saturation>）、<pov>（4 個帽子開關 × 8 個方向，一般與 Shift）和 <dx>（128 個按鈕 × 4 個槽位：按下、按下+Shift、放開、放開+Shift）。<profileDefaultF16> 中的副本也以相同方式寫入。宣告、空白、換行符號和 BOM 都會保留；只會寫入有變更的檔案。
  • 裝置：依檔案名稱中的 DirectInput 執行個體 GUID。
  • 按鈕：按下槽位 0；Shift 層是槽位 1，會成為修飾鍵 BMS Shift。放開槽位永遠不會匯入。新的 callback 會取得 Invoke = Default。
  • 軸：新的宣告會取得 AssgnDate = 現在；同一功能的較舊宣告會被釋放（啟動器會把功能交給最新的宣告）。
  • 指令清單：engine bms refresh-db：BMS - Full.key 中可見的 callback（座艙和 HOTAS 區段），加上啟動器的軸功能（不含 FOV 和攝影機距離）。
  • 匯入 / 匯出：engine bms paths、engine bms import、engine bms scan、engine bms export（--mode、--nuke-untouched-devices、--dry-run）。會先備份到 .jpbak 和備份庫；唯讀屬性會被還原。
  • 設定與檔位：engine ffb set --device * --game FalconBMS --param flightControlsDeadband=0.05，每個油門 --device "<throttle>" --param abDetent=80 --param idleDetent=5；engine binds tuning preview --game FalconBMS。
