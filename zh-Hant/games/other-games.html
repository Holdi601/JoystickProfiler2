摘自支援矩陣（由引擎程式碼產生）： 所有遊戲.

給新手

#3 個步驟就能用

  1. 找到您的遊戲
    在下方表格中
  2. 在遊戲中綁定
    使用遊戲自己的控制選單
  3. 提出您想要的遊戲
    在 Discord 或 GitHub 上

JoyPro 目前還無法替這些遊戲完成設定。請在遊戲自己的控制選單中綁定您的搖桿。有些遊戲只在連接一個控制器時才運作良好：表格中會註明是哪些。

#JoyPro 目前能為這些遊戲做什麼

在遊戲本身目前還什麼都做不了。這些遊戲不在 JoyPro 的遊戲清單中，因此您無法從它們匯入、匯出到它們，也無法在虛擬 Joystick頁面將它們切換到虛擬 joystick。您的設定檔仍可保存您的搖桿、關聯，以及已支援遊戲的綁定；一旦某款遊戲獲得支援，它的動作就會加入相同的關聯。

遊戲 如何讀取裝置 JoyPro 預計的做法
Flyout 任何 joystick 都可以，但全部合併成一個；無法區分搖桿和油門 一個 vJoy 裝置，在遊戲中綁定
No Man's Sky 不支援飛行搖桿；鍵盤、滑鼠和手把（Steam Input 或 XInput） 虛擬 Xbox 手把
Kerbal Space Program 多支 joystick；依裝置名稱和編號綁定 原生整合；用 vJoy 避免編號變動
Kerbal Space Program 2 joystick 支援缺少或有問題 虛擬 Xbox 手把，或社群模組
Star Wars: Squadrons 依名稱支援 3 到 4 個裝置，不穩定 一個 vJoy 裝置
Rising Storm 2: Vietnam 不支援 joystick，只支援 Xbox 手把 虛擬 Xbox 手把加上遊戲的手把綁定
H.A.W.X / H.A.W.X 2 只支援一個裝置 一個 vJoy 裝置，在遊戲中綁定

#Flyout

一款仍在搶先體驗階段的 Unity 飛行遊戲。它接受任何 joystick，但會把所有裝置的軸當成同一個裝置讀取，所以社群的原則是「只連接一個遊戲控制器」。起落架和配平可以綁定。遊戲把綁定存在哪裡目前尚未確認。目前：只連接一個控制器，並在遊戲中綁定。

#No Man's Sky

這款遊戲不支援飛行搖桿。手把透過 Steam Input（Options > Controls > "Remap via Steam Input"）或 XInput 運作；鍵盤綁定存在一個文字檔中。計畫：虛擬 Xbox 手把讓您的 HOTAS 在遊戲預設的手把配置上擁有兩個搖桿和兩個扳機；無法保留真正的油門軸，因為扳機分別是推力和煞車。沒有可寫入的檔案。

#Kerbal Space Program 1 和 2

KSP 1 可讀取多支 joystick；每個軸有主要和次要兩個欄位，按鈕的名稱中帶有裝置編號，裝置順序改變時就會跟著移動，而啟動時若有裝置未開啟，綁定就會遺失。計畫：依裝置名稱的原生整合；用虛擬 joystick 避免編號變動。目前：在遊戲中綁定，或使用 AFBW Revived 模組。KSP 2 的 joystick 支援缺少或有問題，而且已停止開發：可行的做法是虛擬 Xbox 手把或 Inputbinder 模組；JoyPro 不打算整合它。

#Star Wars: Squadrons

可讀取 DirectInput 搖桿和手把，依名稱列出 3 到 4 個裝置，但玩家回報會跳過裝置、不同裝置的 Z 軸互相混淆、重新啟動後油門綁定遺失，以及未選取的裝置也會產生輸入。綁定使用 Battlefield 系列的文字格式，並與 EA 的伺服器同步。計畫：一個 vJoy 裝置，作為遊戲的第一支 joystick 寫入，這樣就能避開裝置清單和混淆問題。目前：玩家會用曲線抵銷遊戲固定的搖桿死區（約 15-20 %）。

#Rising Storm 2: Vietnam

一款有直升機的 Unreal Engine 3 射擊遊戲；它讀取鍵盤、滑鼠和 Xbox 手把，不支援 joystick。手把綁定是 ROInput.ini 中的純文字行。計畫：和 hll-vietnam 一樣，使用遊戲手把按鍵的手把動作，把直升機指令的手把綁定寫入 ROInput.ini，並搭配虛擬 Xbox 手把。

#H.A.W.X 和 H.A.W.X 2

兩款都只讀取一個裝置：如果您有搖桿和油門，只能用其中一個。綁定存在一個沒人破解過的二進位設定檔中，所以 JoyPro 無法寫入。H.A.W.X 2 第一次啟動時需要登入 Ubisoft Connect 帳號。計畫：把整套 HOTAS 放在一個 vJoy 裝置上，用 HidHide 隱藏實體裝置，並在遊戲的控制選單中綁定。JoyPro 最多只能設定 H.A.W.X 2 的 settings.ini 中的死區。

在遊戲中: 您在這些遊戲中會看到什麼

目前透過 JoyPro 不會改變這些遊戲中的任何東西。當某款遊戲支援虛擬 joystick 後，它的控制選單會顯示一個裝置「vJoy Device」，以及您在那裡設定的綁定；使用虛擬 Xbox 手把時則會顯示一個 Xbox 控制器。

#您需要自己做的事

  • 使用遊戲自己的控制選單，並在遊戲需要時只連接一個控制器。
  • 已支援的單裝置遊戲請參閱 battlefield（vJoy）以及 ace-combat / hll-vietnam（Xbox 手把）：這裡預計採用相同的虛擬模式。
  • 在 JoyPro 的 Discord 或 GitHub 上提出想要的遊戲：要支援一款遊戲，通常只需要看一下它啟動一次後產生的實際綁定檔。

#常見問題

  • JoyPro 的清單中沒有這款遊戲：這是正常的；它只有文件說明。
  • 多個裝置在遊戲中運作不良：這是遊戲的限制，不是您的裝置有問題；一次使用一個裝置就能運作。

#匯出模式、絕不更動的內容

JoyPro 不會寫入這些遊戲的任何內容，所以不適用任何匯出模式，也絕不會更動它們的任何東西。等這些遊戲整合後，JoyPro 每次匯出的規則（先關閉遊戲、第一次寫入前先備份、只寫入已編目的動作、絕不寫入未連接的裝置）同樣適用：請參閱匯出流程。

#細分程度、軸、監看程式

  • 這些遊戲沒有已知的各飛機專屬綁定：每個遊戲一組綁定（Rising Storm 2 的直升機指令和步兵指令放在同一個檔案中）。
  • 遊戲本身提供的軸設定：KSP 1 每個軸各自設定（靈敏度、死區、反轉），H.A.W.X 2 一個死區，Squadrons 一個固定的搖桿死區。JoyPro 不會寫入其中任何一項。
  • 這些遊戲沒有監看程式、HUD 動作或力回饋：JoyPro 在其中沒有要管理的東西。

#已記錄的遊戲如何成為支援的遊戲

這裡的每個遊戲都遵循相同的範本（virtual-joystick 以及儲存庫中關於單一裝置的說明）：

  1. 偵測：Steam 應用程式 ID 或登錄機碼、處理程序名稱（供監看程式和 HidHide 的封鎖清單使用）、設定路徑、Steam Cloud 或伺服器同步的副本。
  2. 輸入能力：是否使用 DirectInput、支援幾個裝置、上限（按鈕、帽子開關、軸）、帶有 Rx / Ry 的裝置是否會被當成手把；XInput；GameInput。
  3. 目標：vJoy（可寫入 DirectInput 綁定）、Xbox 手把（僅 XInput；以遊戲的手把配置為優先），或只記錄文件。整合會宣告 IGameDeviceLimit（MaxJoysticks、SuggestedMode、DeviceLimitNote、AvoidVJoyAxes），讓 engine vjoy status、虛擬 Joystick 頁面和匯出功能建議使用虛擬模式。
  4. 指令清單：DB\<Game>\actions.tsv，由 engine <game> refresh-db 根據遊戲本身的檔案建立；手把遊戲的第 5 欄存放預設手把按鍵的 Unreal 按鍵名稱。
  5. 寫入程式，只在理解檔案格式後才做：保留未知的行、只在遊戲關閉時寫入、先備份、寫入每一種設定檔變體，並在啟動一次後確認遊戲或雲端副本沒有把變更還原。
  6. 虛擬模式：engine vjoy mode <game> virtual|xbox；規劃器會安排輸入的位置，並列出放不下的部分；HidHide 只對該遊戲隱藏實體裝置。

#已知限制

  • 研究時並未安裝 Flyout、No Man's Sky、KSP 1 和 2、Squadrons 以及 Rising Storm 2；它們的資訊來自公開資料。
  • H.A.W.X 2 已安裝但尚未啟動（需要登入 Ubisoft Connect）；它的控制選單是否會列出 vJoy 裝置，以及設定檔存放在哪裡，都尚未確認。
  • KSP 1 在做出寫入程式之前，需要一份帶有已知綁定的真實 settings.cfg（Unity 的軸編號方式）。
  • Squadrons 需要像 Battlefield 那樣先調查它的 joystick 編號方式。
  • engine vjoy mode 只接受 JoyPro 遊戲清單中的遊戲，所以這些遊戲目前都還無法切換到虛擬模式。
