給新手

#3 個步驟就能用

  1. 全部幫我設定好
    在「開始」頁面
  2. 使用這些按鈕
    先查看清單
  3. 寫入我的遊戲
    保持 Arma Reforger 關閉

事前準備：啟動 Arma Reforger 一次並開啟 Settings > Controllers。然後關閉遊戲。

接著，只需一次：在遊戲中開啟 Settings > Controllers。在 Joystick preset 下選擇 JoyPro。重新啟動遊戲。之後再匯出時，只需重新啟動即可。

您之前在 Arma Reforger 中綁定過按鈕嗎？那麼「開始」頁面會提供 匯入，然後填補空缺。您的綁定會保留，只有空閒的按鈕會被指派新功能。請參閱 快速入門：讓我的搖桿能用。

#JoyPro 為 Arma Reforger 做了什麼

  • 匯入：搖桿預設檔中的直升機綁定會連同倍率與反向設定一起進入您的設定檔。
  • 關聯：一個關聯就是所有遊戲中的同一個功能。「Collective」在 Reforger、Arma 3 和 DCS 中可以是同一根桿。
  • 匯出：JoyPro 寫入的 JoyPro.conf 只包含直升機飛行動作和您的搖桿，並將您的裝置排入遊戲的四個搖桿欄位。步兵與載具操作、鍵盤、滑鼠和遊戲手把則維持遊戲原本的設定。

#匯入您的 Reforger 綁定

  1. 開啟 開始 頁面。如果 Arma Reforger 卡片要求指令清單，請按 建立清單：JoyPro 會從遊戲檔案讀取直升機動作及其名稱（唯讀）。
  2. 在 Arma Reforger 卡片上按 匯入，並保留 加入我的設定檔。
  3. 按 立即匯入。查看我的關聯 會開啟匯入的內容。

Reforger 中不會匯入或匯出鍵盤綁定和修飾鍵：JoyPro 只管理您的搖桿。

#建立並檢查關聯

使用 關聯流程 將各遊戲中的同一功能連結起來，然後在「匯出」頁面按 檢查。原版遊戲只有直升機（UH-1H、Mi-8）；固定翼飛機的動作只有透過模組才會出現。

#匯出到 Arma Reforger

  1. 關閉 Arma Reforger。 遊戲在您變更設定時就會寫入設定，因此遊戲執行期間 JoyPro 會拒絕寫入。
  2. 開啟 匯出，並勾選 Arma Reforger 卡片。
  3. 如果您是用 JoyPro 設定搖桿，請保留 取代我的裝置上的綁定 和 同時清除我的其他裝置。然後在卡片上按 立即匯出。
在遊戲中: 您在 Arma Reforger 中會看到什麼

啟動遊戲並開啟 Settings > Controllers。在 Joystick preset 下選擇 JoyPro（只需一次），然後重新啟動遊戲。Devices 清單會在 JoyPro 選定的欄位中顯示您的搖桿。預設檔的綁定不會顯示在 Settings > Controls 中：該頁面只列出鍵盤和遊戲手把欄。

#您在 Arma Reforger 中需要自己做的事

  • 選擇預設檔一次：Settings > Controllers > Joystick preset > JoyPro，然後重新啟動。之後再匯出時，只需重新啟動即可。在那裡選擇遊戲手把的 Controller preset 會取代搖桿預設檔：兩者只能有一個生效。
  • 第一次匯出前，請啟動遊戲一次並開啟 Settings > Controllers。JoyPro 只會把裝置順序寫入遊戲已儲存的設定檔；若沒有該檔案，JoyPro 會依遊戲的方式為您的裝置編號並發出警告。
  • 最多四支搖桿。 遊戲會採用啟動後最先送出輸入的四個裝置；之後的任何裝置都會取代第四個。如果裝置較多，玩 Reforger 時請拔除或隱藏其他裝置（例如使用 HidHide）。虛擬 Joystick 模式可以把您的裝置合併成一個，但在四次啟動中，vJoy 裝置都沒有出現在遊戲中。

#常見問題

  • 飛行時沒有任何反應：未選擇 JoyPro 預設檔，或匯出後沒有重新啟動遊戲。
  • 少了一支搖桿：有超過四支搖桿在送出輸入，或該裝置在遊戲視窗取得焦點時從未送出輸入。請在遊戲視窗位於最前方時，移動它的某個軸或按一個按鈕。
  • 兩個相同的裝置：遊戲以名稱區分裝置，因此兩個同型號裝置只會得到一條欄位規則；第二個裝置得不到欄位。
  • 穩定版與實驗版：這兩個版本使用各自的設定資料夾。JoyPro 會把裝置順序寫入它找到的每個設定資料夾。
進階

#JoyPro 讀取和寫入的檔案

檔案 這是什麼
%USERPROFILE%\Documents\My Games\ArmaReforger\profile\.save\settings\customInputConfigs\JoyPro.conf JoyPro 自己的搖桿預設集（Enfusion 文字）：每個直升機動作一個 Action 區塊，含有其搖桿來源和篩選器
...\profile\.save\app<id>_user<steam id>\settings\ReforgerEngineSettings.conf 遊戲的引擎設定；JoyPro 只編輯 DeviceOrderRules 下的 JoystickOrderRule 項目
...\app<id>_user<steam id>\settings\ReforgerGameSettings.conf 遊戲設定；JoyPro 只在您設定時編輯 HOTAS 總距桿模式和力回饋強度
JoyPro.conf.joypro-meta.json JoyPro 為已寫入綁定保存的名稱、群組和調校，下次匯入時會讀回
*.jpbak 首次寫入前的副本，以及 JoyPro 的版本化備份庫

遊戲自己的重新綁定檔 InputUserSettings.conf 永遠不會被變更，您在 customInputConfigs 中的其他預設集也不會。較舊的組建版本將這兩個設定檔命名為 EngineUserSettings.conf 和 GameUserSettings.conf（內容相同）。

#裝置順序規則

遊戲最多列出四個搖桿（joystick0 到 joystick3），當某條規則的名稱包含在裝置名稱中時，就會給該裝置一個槽位。匯出時 JoyPro 會：

  1. 將您已選好槽位的裝置放到該槽位（joystickSlot 設定，0 到 3；-1 = 自動）；
  2. 保留現有規則給裝置的槽位（包括遊戲自己那些使用長名稱的規則）；
  3. 將其他裝置放到沒有規則佔用的最低槽位。

每條規則使用裝置的 HID 產品名稱（遊戲中的名稱包含它）。JoyPro 會就地變更槽位或新增規則，並且只寫入槽位 0 到 3。當使用超過四個裝置、沒有剩餘槽位，或兩個選定的槽位相同時，它會發出警告。匯入時會透過相同的規則將 joystickN 對應回去。

#Arma Reforger 的匯出模式

只有預設集中的飛行 Action 區塊會變更。鍵盤、滑鼠和遊戲手把來源，以及未連接的搖桿，一律保留。

模式 JoyPro.conf 中會發生什麼
僅新增 每個來源都保留。如果綁定的搖桿輸入已被另一個飛行動作使用，就不會寫入，並標示為「未寫入遊戲」。
更新，保留遊戲的綁定 寫入您的來源；同一輸入上另一個飛行動作的來源會被移除。該動作的舊來源保留。
更新，以我的設定檔為準 同上，而且您綁定的動作會失去已連接裝置上的其他搖桿來源。
取代我的裝置上的綁定 您寫入的裝置的飛行來源會被捨棄，並由您的來源取代。
+ 同時清除我的其他裝置 在您設定檔中沒有綁定的已連接裝置也一樣。

沒有任何來源的區塊會被移除。

#永遠不會變更的內容

  • InputUserSettings.conf、您的其他預設集，以及所有步兵、載具和選單動作。
  • 鍵盤、滑鼠和遊戲手把來源；未連接的搖桿；匯入時忽略的裝置，以及 JoyPro 轉送輸入的 vJoy 裝置。
  • 兩個設定檔中除了順序規則和 JoyPro 管理的兩項設定之外的每一行。缺少的設定區塊不會被建立（JoyPro 會警告：請在遊戲中變更一次該設定）。
  • 不會讀取 Workshop 模組。

#直升機、曲線、設定

  • 細緻度：所有直升機共用一組綁定（遊戲的 Helicopter 情境）。
  • 軸設定：每個綁定有一個倍數和反向，以遊戲的值篩選器寫入軸的兩半。Reforger 每個裝置軸的死區和曲線不會寫入（其格式尚不清楚）。
  • 按鈕的行為與遊戲按鍵相同：按鈕會取得與該動作的遊戲預設來源相同的預設集和篩選器（點按、按住、重複），因此「Engine start」需要按住，「Sight range down」會重複。
  • 遊戲設定：HOTAS 總距桿模式（Default、Manual、Sticky、Direct；遊戲對 HOTAS 的預設值是 Direct）和力回饋強度（0 到 3）；以及每個裝置的 joystickSlot。請在 設定 > 遊戲的力回饋設定 中設定（選擇 Arma Reforger），或使用 engine ffb set。即使匯出時沒有 Reforger 綁定，仍會寫入這些設定。
  • 監看程式：預設集或遊戲設定的變更會在遊戲關閉後被偵測到；JoyPro 會詢問是否採用。
  • HUD：HUD 會依據遊戲的處理程序找到遊戲，並顯示您的 Reforger 綁定。
技術細節

#Reforger 整合的內部運作

程式碼：engine\Games\ArmaReforgerIntegration.cs、engine\Games\ReforgerCatalogSource.cs、engine\Games\EnfusionPak.cs、軸模型 engine\AxisModels\ArmaReforger.cs 和設定模型 engine\FfbModels\ArmaReforger.cs。

  • 格式：Enfusion 文字，一個空格的縮排，Key Value，物件為 Class "{16 hex digits}" {；每個新物件都會取得唯一的隨機 ID。輸入：joystick0:button4（從 0 起算）、joystick0:axis6，半軸為 joystickN:axisA+ / axisA-，帽子開關為 joystickN:pov_up|pov_down|pov_left|pov_right；軸 0 到 7 = X、Y、Z、Rx、Ry、Rz、Slider 0、Slider 1。整軸動作寫為 joystickN:axisA（以負的 Multiplier 反向）。
  • 裝置：遊戲視窗取得焦點時，裝置第一次送出報告，遊戲就會從原始輸入（usage page 1、usage 4）偵測到搖桿；在這裡，遊戲手把和多軸控制器永遠不算搖桿。它的表可容納四個項目；第五個新裝置會覆寫第四個。
  • 指令清單：engine reforger refresh-db 會從遊戲的 .pak 封存檔（唯讀）讀取 Configs/System/chimeraInputCommon.conf、keyBindingMenu.conf 的選單標題和 localization.en_us.conf，再加上您預設集中的動作；只計入 Helicopter / Airplane 情境。engine reforger catalog 會列出它們，engine reforger paths 會顯示找到的檔案。
  • 匯入 / 匯出：engine reforger import、engine reforger scan；engine reforger export --mode clean|add|merge|merge-overwrite --nuke-untouched-devices --ignore-device <d> --dry-run。
  • 設定：engine ffb set --device * --game ArmaReforger --param hotasCollective=<0..3>（還有 forceFeedbackIntensity）；--device "<device>" --param joystickSlot=<0..3>；大於 3 的槽位會被拒絕。

#已知限制

  • 匯出尚未在執行中的遊戲裡檢查過；設定選單則已檢查過。
  • 只有倍數和反向；沒有死區或曲線。
  • 最多四個搖桿；vJoy 裝置在四次啟動中都沒有出現在遊戲裡，因此只有在超過四個裝置時才會建議使用虛擬 joystick。
  • 預設集會取代還是附加到遊戲預設的鍵盤來源，目前尚未確認。
  • 測試：engine\tests\smoke\arma.ps1（篩選器、順序規則、遊戲設定、拒絕情況）。

此遊戲的所有技術說明（由儲存庫產生）： arma-reforger.md.
